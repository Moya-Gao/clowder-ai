# 决策权矩阵（漏斗模式）

> 来源：F-Swarm-4，2026-02-24 四猫+铲屎官讨论确认。
> 铲屎官原则：**越宏观越关注，越细节越放手。**

## 铲屎官拍板（宏观层）

必须等铲屎官确认后才能执行：

| 类别 | 示例 |
|------|------|
| 重要架构决策 | 新 ADR、存储方案变更、协议变更 |
| 安全与数据不可逆 | 生产 Redis 操作、删除用户数据、权限模型变更 |
| 成本显著变化 | 引入新付费 API、大幅增加 token 消耗 |
| 对外行为变化 | UX 变化、API 契约变更 |
| 新增外部依赖 | 新 npm 包、第三方服务 |
| 优先级与路线图 | Feat 排序调整、Phase 计划变更 |

## 三猫讨论（中间层）

猫猫之间讨论达成共识，重大分歧升级给铲屎官：

| 类别 | 示例 |
|------|------|
| 设计方向 | 多视角方案选型 |
| 工作流/SOP 变更 | 流程规则调整 |
| 新协作规则 | 猫猫指引文件规则新增 |
| 跨猫职责边界 | 谁负责什么的调整 |

## 猫猫自治（细节层）

猫猫自行判断即可：

| 类别 | 示例 |
|------|------|
| 实现细节 | 算法、数据结构、内部 API |
| 重构择优 | 不改外部行为的代码重组 |
| 测试补齐 | 补测试、提高覆盖率 |
| Bug 修复方案 | 不涉及架构变更的修复 |
| 代码风格 | 命名、格式、注释 |
| 文档跟随更新 | 跟随代码变更的文档同步 |
