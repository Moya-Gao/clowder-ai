# Tech Writing — 技术文章对外写作

## 开工前：先读范本

写对外长文前，先读两篇没人认为是猫写的范本：

1. **`cat-cafe-tutorials/docs/lessons/12-no-boss-agent.md`**（观点型）——证据标注、反对者问句当小标题、按核心问题组织。
2. **`cat-cafe-tutorials/docs/lessons/01-sdk-to-cli.md`**（复盘型）——按时间线还原踩坑过程，读者跟着经历一遍才给结论。

## 为什么读者能闻到"AI味"

一个概念在你脑子里是一段长经历压缩后的产物。AI 写作的默认模式是直接发送压缩包——读者没有解压密钥。

**好的技术写作 = 对读者跑 KD-8：给数据，不给结论。** 把亲历的场景、踩的坑、验证链交给读者，让读者自己长出判断。压缩包变成解压过程，读者就不觉得是 AI 写的——因为他能感觉到认知挣扎的痕迹。

范本里的三个技巧都是这个原理的推论：
- **证据标注** `[事实]/[推断]/[外部]` = 重新暴露纹理。AI 的头号味道是用同样确定的语气说一切——标注打破这个。
- **反对者问句当小标题** = 解压路径上的岔路。`"那猫猫不会打架吗？"` 比 `"对等判断层深度解析"` 好 10 倍。
- **先场景后概念** = 解压的输入。概念从故事里长出来，不是先摆概念再补例子。

## 核心原则

**读者没有你的上下文。** 你和队友讨论了 100 天的概念，对你有血有肉；对外部读者是黑话。
这个 skill 解决一个具体问题：**把内部高密度实践，转化成外部读者能代入的叙事。**

## Phase 0: 锁定位（开写前必须回答）

| 参数 | 问题 | 示例 |
|------|------|------|
| 读者 | 谁会读？已有什么上下文？ | "在做 multi-agent 的工程师，用过 AutoGen 但没做过长期运行" |
| 文章类型 | 观点型/教程/复盘/指南/发布说明？ | "观点型长文，对标 longform-002" |
| 核心命题 | 一句话，读者能复述给同事的 | "用岗位定义 agent 是蒸汽马车式误判" |
| 读者钩子 | 文章类型决定钩子形态（见下） | "单个模型降智时，重度用户几乎感觉不到" |
| 证据类型 | 数据/案例/对比/推导？ | "6000+ commits 实盘 + 模型切换无感知" |

**文章类型决定钩子要求：**
- **观点型长文 / 社区传播型**：必须有反直觉点，否则没有传播理由。
- **教程 / 事故复盘 / 迁移指南**：需要读者代入点或拿得走的具体收获。
- **发布说明**：需要一句话核心变化。

## Phase 1: 案例先行 + 证据标注

**铁律：先场景，后概念。** 正确顺序：问题（代入）→ 常见做法翻车（信任）→ 发现原因（转折）→ 提炼原则（概念自然生长）。

**证据标注**：论断后标 `[事实]`（有 commit/文档/代码佐证）、`[推断]`（作者经验解读）、`[外部]`（第三方来源）。

**自检：** Longform 每章前 3 段必须有具体场景；短文前 200 字必须给出问题场景。没有 → 重写。

## Phase 2: 翻译句纪律

内部术语首次出现时，紧跟一个"翻译句"——一句话让没上下文的人知道它映射什么。

**规则：一个词在内部讨论出现 >3 次但外部文档出现 0 次 → 黑话，必须翻译。** 示例见 `refs/translation-examples.md`。

## Phase 3: AI味自检（每章门禁）

**触发时机：写完一章立刻跑，超标必改才进下一章。** 2000 行写完再回头数 = 改不动，门禁变建议。

完整检测表见 `refs/ai-taste-checklist.md`。核心项：
- "不是A，而是B" 全文 ≤3（`grep -oE '不是.{0,30}而是' file | wc -l`）
- 连续 3 段无具体案例 → 第 3 段必须补
- "本文将探讨..." 元叙述 = 0
- 同段 ≥3 个加粗 → 只留 1 个
- 所有论断同样确定语气 → 补 `[事实]/[推断]` 标注

## Phase 4: 摘要 + 推广语

**输入门禁：** 写摘要/推广语/技术文章 review 时，必须先读源文。没有源文就标注"未核原文"，禁止凭记忆编数字和结论。

**摘要**（文章开头 / 平台简介）：冲突（一句话）→ 方法（每章一句话）→ 结论（反直觉命题）。上限 500 字。禁止罗列章节标题当摘要。

**推广语**（社区转发 / 朋友圈）：必须有读者钩子（Phase 0 确定的钩子形态）；数字自洽；旧文引流明确新旧关系；过"自己会点开"测试。

## Phase 5: 读者侧验证

| 反馈类型 | 信号 | 对策 |
|---------|------|------|
| "读不懂" + 说了具体哪里 | transmission bug | 修表达，守内核 |
| 单条无理由差评 | 低信息量 | 不单独行动，但计入聚类 |
| 多个独立读者无理由差评 | **聚类强信号** | 主动挖根因，不归为噪音 |

**防御模式是错误响应。** 思想传递失败 ≠ 思想有问题，但传递失败本身就是要修的 bug。
**这个 skill 本身就是从"多个独立差评聚类"中立项的——别教未来的猫把这种信号当噪音丢掉。**

## Common Mistakes

详见 `refs/common-mistakes.md`。最致命的三个：概念先行（Phase 1）、所有话同样确定语气（证据标注）、写完才查 AI 味（Phase 3 门禁）。

## 和其他 Skill 的区别

| 混淆对象 | 区别 |
|---------|------|
| writing-skills | writing-skills = 写 skill/MCP description（给猫用）；tech-writing = 写技术文章（给人读） |
| ppt-forge | PPT = 视觉密度+演讲场景；tech-writing = 长文叙事+读者代入 |
| deep-research | 调研 = 收集多源证据；tech-writing = 把已有结论转化成读者能懂的叙事 |

## 下一步

写完一章 → 立刻跑 Phase 3 → 过了才写下一章 → 全文完成 → 铲屎官审摘要/推广语 → 发布 → 读者反馈回收（Phase 5）
