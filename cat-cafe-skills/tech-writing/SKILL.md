# Tech Writing — 技术文章对外写作

## 开工前：先读范本

**写对外长文前，先读 `cat-cafe-tutorials/docs/lessons/12-no-boss-agent.md`。** 这篇没人认为是猫写的。它做对了三件事（本 skill 的 Phase 1-2 从此提炼）：
1. **证据标注**：每句论断标 `[事实]/[推断]/[外部]`——直接杀 AI 头号味道：用同样平滑语气讲一切。
2. **反对者问句当小标题**：`"那猫猫不会打架吗？"` 而不是 `"对等判断层深度解析"`。用读者的怀疑，不是作者的总结。
3. **按核心问题组织**：每课一个"核心问题"，标题是故事钩子（"消失的 28 秒""100% Pass，铲屎官说不是我要的"）。

## 核心原则

**读者没有你的上下文。** 你和队友讨论了 100 天的概念，对你有血有肉；对外部读者是黑话。
这个 skill 解决一个具体问题：**把内部高密度实践，转化成外部读者能代入的叙事。**

## Phase 0: 锁定位（开写前必须回答）

| 参数 | 问题 | 示例 |
|------|------|------|
| 读者 | 谁会读？已有什么上下文？ | "在做 multi-agent 的工程师，用过 AutoGen 但没做过长期运行" |
| 文章类型 | 观点型/教程/复盘/指南/发布说明？ | "观点型长文，对标 longform-002" |
| 核心命题 | 一句话，读者能复述给同事的 | "用岗位定义 agent 是蒸汽马车式误判" |
| 读者钩子 | 文章类型决定钩子形态（见下） | "单个模型降智时，重度用户几乎感觉不到" |
| 证据类型 | 数据/案例/对比/推导？ | "6000+ commits 实盘 + 模型切换无感知" |

**文章类型决定钩子要求：**
- **观点型长文 / 社区传播型**：必须有反直觉点，否则没有传播理由。
- **教程 / 事故复盘 / 迁移指南**：需要**读者代入点**——"你也会遇到这个坑"，或**读者拿得走的具体收获**。
- **发布说明**：需要一句话核心变化。

## Phase 1: 案例先行 + 证据标注

**铁律：先场景，后概念。概念从故事里长出来，不是先摆概念再补例子。**

正确顺序：
```
我遇到了什么问题（读者代入）
→ 常见做法翻了什么车（建立信任：我也踩过你的坑）
→ 我发现原因是什么（转折）
→ 所以提炼出这个原则（概念自然生长）
```

错误顺序：
```
这里有一个原则（读者：你谁？）
→ 很重要因为...（读者：不关我事）
→ 举个例子...（读者已经走了）
```

**证据标注**：论断后标 `[事实]`（有 commit/文档/代码佐证）、`[推断]`（作者经验解读）、`[外部]`（第三方来源）。AI 的头号味道是用同样确定的语气说一切——标注直接打破这个。

**小标题用读者的怀疑**：`"那不就是一堆 System Prompt 吗？"` 比 `"系统提示词架构设计"` 好 10 倍。用读者会问的问题，不是作者的结论。

**自检：**
- **Longform**：每章前 3 段是否有一个读者能代入的具体场景？没有 → 重写开头。
- **短文/推广语/摘要**：前 200 字内是否给出了问题场景或读者代入点？没有 → 补场景。

## Phase 2: 翻译句纪律

内部术语首次出现时，紧跟一个"翻译句"——一句话让没上下文的人知道它映射什么。

| 内部黑话 | 翻译句示例 |
|---------|-----------|
| 蒸汽马车 | 用旧世界的形态想象新物种——给 agent 分"产品经理/开发/测试"岗位 |
| 能力画像 | 不问 agent 是什么角色，问它擅长什么、什么条件下容易出错 |
| 方差吸收 | 单个模型犯了蠢，系统里有另一个模型接住——用户感觉不到波动 |
| harness | 把多个 AI 组织在一起的运行框架——相当于操作系统，模型是应用 |

**规则：一个词在内部讨论出现 >3 次但外部文档出现 0 次 → 黑话，必须翻译。**

## Phase 3: AI味自检（每章门禁，不是写完再查）

**触发时机：写完一章立刻跑，超标必改才进下一章。** 2000 行写完再回头数 = 改不动，门禁变建议。

| 检测项 | 阈值 | 验证命令 | 超标修法 |
|--------|------|---------|---------|
| "不是A，而是B" 句式 | 全文 ≤3 | `grep -oE '不是.{0,30}而是' file \| wc -l` | 改成直接陈述 |
| 排比（被X、被Y、被Z） | 每段 ≤2 组 | 肉眼：同段内相同句式 ≥3 | 拆成独立句，砍到 2 个 |
| 连续段落无具体案例 | ≤2 段 | 肉眼：连续 3 段没有场景/数据/对话/截图 | 第 3 段必须补案例 |
| "本文将探讨..." 元叙述 | 0 | `grep -c '本文将' file` | 直接删 |
| 小标题含"深度解析/全面解读" | 0 | `grep -cE '深度解析\|全面解读' file` | 换成读者会问的问题 |
| 同一段落内 ≥3 个加粗短语 | 0 | 肉眼 | 只留最重要的 1 个加粗 |
| 所有论断用同样确定语气 | 0 | 检查：有没有 `[事实]/[推断]` 标注？ | 补证据标注 |

## Phase 4: 摘要 + 推广语

**输入门禁：** 写摘要、推广语、或做技术文章 review 时，必须先读源文/草稿。没有源文就标注"未核原文"，禁止凭记忆编数字和结论。

**摘要**（文章开头 / 平台简介）：
- 结构：冲突（一句话）→ 方法（每章一句话）→ 结论（反直觉命题）
- 上限 500 字
- 禁止：罗列章节标题当摘要

**推广语**（社区转发 / 朋友圈）：
- 必须有一个读者钩子（Phase 0 确定的钩子形态）
- 数字自洽：标题说"三只猫50天"正文说"四只猫100天"= 读者第一眼困惑
- 旧文引流要明确新旧关系："XX 作者带来新长文——"，把数字差变成正面叙事
- 过"自己会点开"测试：你会点开自己写的这条吗？

## Phase 5: 读者侧验证

发布后的反馈 = 读者侧 eval。

| 反馈类型 | 信号 | 对策 |
|---------|------|------|
| "读不懂" + 说了具体哪里 | transmission bug | 修表达，守内核 |
| 单条"别发了" / 无具体理由 | 低信息量 | 不单独行动，但计入聚类 |
| 多个独立读者无理由差评 | **聚类强信号** | 有共性问题没说清——主动挖根因，不归为噪音 |
| "先讲问题再讲方案" | Phase 1 没做好 | 回去重排叙事入口 |
| "AI味" / "像工程备忘录" | Phase 3 没做好 | 跑 AI味清单 |

**防御模式是错误响应。** "这是猫猫和我一起写的"不解决任何读者侧问题。
思想传递失败 ≠ 思想有问题，但传递失败本身就是要修的 bug。
**这个 skill 本身就是从"多个独立差评聚类"中立项的——别教未来的猫把这种信号当噪音丢掉。**

## Common Mistakes

| 错误 | 后果 | 修复 |
|------|------|------|
| 概念先行，案例后补 | 读者第 3 段就走了 | Phase 1：先场景后概念 |
| 内部术语不翻译 | 外部读者觉得是黑话 | Phase 2：翻译句纪律 |
| 排比句/对仗满天飞 | "AI味"，读者反感 | Phase 3：AI味自检 |
| 所有话用同样确定语气 | 头号 AI 味 | Phase 1：证据标注 `[事实]/[推断]` |
| 写完全文才跑 AI味检查 | 改不动，门禁变建议 | Phase 3：每章写完立刻检查 |
| 摘要 = 章节标题列表 | 没有传递任何思想 | Phase 4：冲突→方法→结论 |
| 推广语数字打架 | 读者第一眼困惑 | Phase 4：数字自洽 |
| 被批"读不懂"就防御 | 错过最好的 eval 信号 | Phase 5：修表达守内核 |
| 多人差评归为"噪音忽略" | 丢掉聚类强信号 | Phase 5：多个独立差评 = 主动挖根因 |
| 教程硬塞反直觉点 | 为了钩子扭曲叙事 | Phase 0：按文章类型选钩子 |
| 凭记忆写推广语/摘要 | 数字编错、结论失真 | Phase 4：先读源文再动手 |
| 用结构化三点分析回应"AI味"批评 | 用被批评的方式回应批评 | 先说人话，克制结构化冲动 |

## 和其他 Skill 的区别

| 混淆对象 | 区别 |
|---------|------|
| writing-skills | writing-skills = 写 skill/MCP description（给猫用）；tech-writing = 写技术文章（给人读） |
| ppt-forge | PPT = 视觉密度+演讲场景；tech-writing = 长文叙事+读者代入 |
| deep-research | 调研 = 收集多源证据；tech-writing = 把已有结论转化成读者能懂的叙事 |
| writing-plans | 拆代码实施步骤；tech-writing = 写对外文章 |
| knowledge-engineering | 编码内部知识给猫用；tech-writing = 把实践传递给外部人类 |

## 下一步

写完一章 → 立刻跑 Phase 3 → 过了才写下一章 → 全文完成 → 铲屎官审摘要/推广语 → 发布 → 读者反馈回收（Phase 5）
