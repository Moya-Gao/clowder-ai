# Bug Report: 提及菜单将“暹罗猫”错误显示为“暄罗猫”

## 1) 报告人

- 报告人：铲屎官（截图反馈）
- 接收与定位：缅因猫（砚砚）
- 发现时间：2026-02-14

## 2) 复现步骤（期望 vs 实际）

复现：
1. 在聊天输入框输入 `@`，触发提及菜单。
2. 观察第三项（Gemini）显示名称。

期望：
- 显示 `@暹罗猫`，插入文本为 `@暹罗 `。

实际：
- 菜单显示 `@暄罗猫`，插入文本也为 `@暄罗 `。

## 3) 根因分析

- 前端提及菜单选项是静态常量 `CAT_OPTIONS`，并未直接复用 `CAT_CONFIGS.displayName`。
- `packages/web/src/components/chat-input-options.ts` 中 Gemini 的 `label` 与 `insert` 被硬编码为 `@暄罗猫` / `@暄罗 `，导致 UI 显示与插入都错误。

## 4) 修复方案（含取舍）

- 方案：将 Gemini 选项改为 `@暹罗猫` / `@暹罗 `，保持其余逻辑不变。
- 取舍：
  - 优点：最小改动，风险低，直接修正用户可见错误。
  - 代价：当前仍是静态常量方案，长期可考虑改为从统一配置派生，减少手写拼写漂移。

## 5) 验证方式

1. 新增回归测试：断言 Gemini 提及选项的 `label` 与 `insert`。
2. 先跑红（当前应失败），再修复代码，跑绿通过。
3. 执行现有 `ChatInput` 相关测试，确认无回归。
