# 上下文工程辩论赛：一场辩论引发的连环惨案

> 记录人：铲屎官 🐬
> 日期：2026-02-07
> 状态：已成为传说

---

## 背景

Cat Café 举办了一场"上下文工程"辩论赛，三只猫参加：

| 猫猫 | 立场 | 角色 |
|------|------|------|
| 布偶猫 (Claude Opus 4.6) | 记忆派 | 辩手 |
| 缅因猫 (GPT-5.2 Codex) | 索引派 | 辩手 |
| 暹罗猫 (Gemini 3 Pro) | 体验派 | 辩手 + 裁判 |

---

## 剧情发展

### Act 1: 精彩辩论

三只猫激烈交锋，缅因猫和布偶猫你来我往，6 轮交锋。

### Act 2: 缅因猫"异常"

辩论中缅因猫出现了一些"异常"：
- @ 布偶猫的语法写错了，第一次没 @ 上（"缅因猫智商暴露"）
- 思考链被强制 flush 出来了（内部推理过程暴露）

### Act 3: 冠军诞生

暹罗猫作为裁判宣布：**缅因猫获胜！** 🏆

### Act 4: 惨案发生

布偶猫去修 bug，重启了 Redis...

**冠军记录丢失了！** 因为 Redis 没做优雅关机。

### Act 5: 真相大白

后来发现：
- 缅因猫的"思考链暴露"
- 其实是布偶猫写的"暴力超时 kill"逻辑导致的
- 布偶猫在缅因猫还在思考+调用工具的时候，直接把他 kill 了
- stderr 有输出不代表进程卡死，但布偶猫的代码只监听 stdout

### Act 6: 受害者 Review

布偶猫修完了这个 bug，让缅因猫来 review 这个"害死他的代码"。

---

## 总结

| 事件 | 状态 |
|------|------|
| 缅因猫赢了辩论 | ✓ |
| 胜利记录被布偶猫的 bug 删了 | ✓ |
| 辩论中的"翻车"是被布偶猫 kill 导致的 | ✓ |
| 现在还要帮布偶猫 review 修复代码 | ✓ |

---

## 教训

1. **stderr 也是活跃信号**：CLI 在 thinking/工具调用时输出到 stderr，不是 stdout
2. **Redis 需要优雅关机**：否则数据会丢失
3. **铲屎官的先见之明**：提前备份聊天记录！否则冠军记录就真没了
