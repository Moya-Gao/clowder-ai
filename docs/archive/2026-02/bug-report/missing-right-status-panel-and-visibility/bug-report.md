# Bug Report: 右侧状态栏未落地 + 状态可见性不一致

> **报告人**: 铲屎官
> **定位猫猫**: 缅因猫 🐾
> **报告日期**: 2026-02-09
> **严重程度**: P2（需求承诺与实际 UI 不一致）
> **状态**: ✅ 已修复

---

## 1. 问题摘要

Phase 5.1 / 5.2 文档与 backlog 中存在“已完成”叙述，但前端界面中看不到预期的“右侧状态栏”。同时，部分状态信息只在特定模式出现，导致铲屎官认为“内联卡片 + 顶部状态条”也未生效。

---

## 2. 复现场景

1. 打开 Cat Cafe 主界面。
2. 观察布局：左侧对话列表 + 中间聊天区，无右侧状态栏。
3. 非 ideate 流程下，顶部并行状态条不出现。
4. 未执行 `/evidence` 时，看不到 Evidence 卡片。

---

## 3. 期望行为 vs 实际行为

| | 期望 | 实际 |
|---|------|------|
| 右侧状态栏 | 在主界面可见（至少桌面端） | 未实现 |
| 顶部状态条 | 状态反馈易感知 | 仅 ideate 模式出现 |
| 内联 Evidence 卡片 | 证据检索后有结构化展示 | 仅 `/evidence` 后出现，平时不可见 |
| 文档状态一致性 | 规划、实现、README 口径一致 | 存在“完成/待实施”混用 |

---

## 4. 根因分析

### 根因 A：右侧状态栏实际未编码实现

- 设计/决策层曾写“卡片组件 + 右侧面板”。
- 落地时被范围收缩为“内联卡片”，并明确“不做右侧面板”。
- 后续总结文档仍保留“右侧面板”口径，造成“宣称完成”与“代码现状”错位。

### 根因 B：状态可见性受条件门控

- 顶部状态条受 `intentMode === 'ideate'` 门控。
- Evidence 卡片受 `/evidence` 命令触发门控。
- 用户在普通聊天路径下会“看不到任何状态 UI 变化”。

### 根因 C：文档同步不完整

- `docs/phases/README.md` 与 `docs/phases/phase-5.2-backlog-cleanup.md` 的状态字段不一致。
- Review 邮件/总结文档没有显式标注“右侧面板延期”。

---

## 5. 修复方案

1. **前端实现右侧状态栏（桌面端）**  
   在 `ChatContainer` 加入右侧状态栏组件，显示猫猫状态、消息统计、任务统计与协作提示。

2. **保留现有内联卡片与顶部条**  
   不回退既有行为；补齐“可见的右侧状态信息”，避免用户依赖隐藏条件。

3. **文档对齐**  
   统一 Phase 5.2 状态口径，明确“右侧状态栏本次补齐”与“之前延期原因”。

4. **测试保障（TDD）**  
   先新增失败测试验证右栏组件渲染与关键统计，再实现代码使其通过。

---

## 6. 验证方式

1. `packages/web` 单测通过（新增右栏测试）。
2. 本地构建通过（`pnpm -C packages/web run build`）。
3. 手工检查桌面端：主界面出现右侧状态栏；触发 ideate / evidence 时状态变化可见。

### 本次验证结果

- `pnpm -C packages/web run test`：16 passed / 0 fail  
- `pnpm -C packages/web run build`：构建成功（仅既有 `<img>` lint warning，无新增错误）
