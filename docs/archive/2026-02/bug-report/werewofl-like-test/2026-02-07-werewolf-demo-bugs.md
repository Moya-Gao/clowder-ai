## Bug 1: 单猫 @mention 无加载提示 (UX)

### 现象
当只 @一只猫时，用户发送消息后没有任何视觉反馈，不知道是猫在思考还是系统出 bug 了。

### 对比
- **多猫并行模式** → 有 `🐾独立观点采样中` 横幅 (IdeateHeader)
- **单猫模式** → 只有输入框变为 disabled，没有明确的"思考中"提示

### 根因
`ChatContainer.tsx:264` 只在 `intentMode === 'ideate'` 时显示 IdeateHeader。
单猫场景下 intentMode 不是 ideate，所以没有任何加载指示器。

### 建议修复
添加通用的 loading 状态反馈，例如：
1. 在消息列表底部显示"猫猫思考中..."占位消息
2. 或在输入框区域显示 spinner + 猫名
3. 参考其他聊天应用的 typing indicator

### 严重度
P2 — 用户体验差，但不影响功能

## Bug 2: 上下文消息截断导致猫猫"记忆丢失"

### 现象
缅因猫和布偶猫在第二轮都说"暹罗猫的不喜欢角色部分被截断了"。

### 实际存储 vs 上下文
- **存储**：暹罗猫的完整回复（~1200+ 字符）已正确保存到 Redis
- **上下文**：`ContextAssembler` 截断到 500 字符，导致其他猫看不到完整内容

### 代码位置
```typescript
// packages/api/src/domains/cats/services/ContextAssembler.ts:27
const DEFAULT_MAX_CONTENT_LENGTH = 500;
```

### 建议
这是 **设计如此** (feature) 不是 bug，但需要权衡：
1. 500 字符对于猫猫的表达可能太短（暹罗猫比较话痨 😂）
2. 考虑按 token 计数而非字符
3. 或增加到 1000-1500 字符

### BACKLOG 状态
已登记：P2 #6 `上下文预算管理 (token 截断) - Phase 3.7 Step 3.2`

## Bug 3: 多猫场景无法感知每只猫的状态

### 现象
第二轮回复中暹罗猫 5 分钟没回来，但铲屎官无法感知：
- 暹罗猫是在思考中？
- 还是出 bug 了？
- 还是超时了？
- 进度到哪了？

### 根因
当前只有**全局** `isLoading` 状态，没有**每只猫独立**的状态追踪。

前端无法知道：
- 哪只猫已经开始回复
- 哪只猫还在等待
- 哪只猫出错了

### 建议修复
1. **后端**：emit 事件时带上 `catId` + 状态 (pending/streaming/done/error)
2. **前端**：维护 `Map<catId, CatStatus>` 状态
3. **UI**：在并行模式下显示每只猫的头像 + 状态 (转圈/打勾/叹号)

### 相关 BACKLOG
- P2 #16: `isFinal 丢失防护` — 超时兜底
- P3 #20: `冷/热状态视觉反馈 (猫头像发光)` — 暹罗猫提议

### 严重度
P2 — 多猫协作场景的核心体验问题

## Bug 4: 暹罗猫第二轮卡住/超时

### 现象
第一轮三猫都正常回复 (02:34-02:35)，第二轮暹罗猫 5 分钟未响应。

### 时间线分析
```
02:39 - 铲屎官第二轮发问
02:40 - 缅因猫回复 ✅
02:40 - 布偶猫回复 ✅
02:44:51 - 导出时间 (~5分钟后)
暹罗猫：无回复 ❌
```

### 可能原因

#### 假设 A: Gemini CLI 超时被杀
- `cli-spawn.ts` 有 5 分钟超时 (`DEFAULT_TIMEOUT_MS = 300_000`)
- 如果 Gemini 模型响应慢，会被 SIGTERM 终止
- 但前端可能没有收到明确的错误消息

#### 假设 B: Gemini CLI 进程挂起
- 网络问题导致 CLI 卡住但没退出
- 等待 5 分钟超时

#### 假设 C: 并行调用竞态问题
- 三猫并行调用时可能有资源竞争
- 暹罗猫的请求被阻塞

### 需要调查
1. 查看 API 日志是否有暹罗猫的错误输出
2. 确认超时后是否正确 yield error 事件
3. 确认前端是否收到了 error 事件并显示

### 建议改进
1. 添加**调用级别日志**：每次 CLI spawn 记录开始/结束/超时
2. **超时提前警告**：3 分钟时 emit warning 事件
3. **错误消息传达**：确保超时错误在 UI 上明确显示

### 严重度
P1 — 功能性问题，用户无法获得预期的响应
