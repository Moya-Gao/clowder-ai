- **暹罗猫 (Gemini)**: `gemini-2.5-pro · google`

## 2. Bug 发现过程

### 2.1 初始观察：暹罗猫的证词可疑

铲屎官在猫咖里问三只猫"你们能看到历史上其他猫说了什么吗？"

**三只猫的回答对比：**

| 猫猫 | 声称 | 具体表述 |
|------|------|---------|
| 缅因猫 (Codex) | ✅ 同线程可见 | "同线程可见，跨会话不可见"，列出了具体能看到的内容 |
| 布偶猫 (Opus) | ✅ 能看到 | 区分了"菜单缅因猫"和"正经缅因猫"，并列出详细分类 |
| 暹罗猫 (Gemini) | ⚠️ 措辞模糊 | "只能看到我们之间、以及你直接告诉我的这些信息" |

**铲屎官的判断**：暹罗猫的回答与其他两只猫不一致。考虑到 Gemini 2.5 Pro 在 700k context 下 recall 准确率很高（铲屎官有半年以上使用经验），如果它真的收到了完整历史却说看不到，不太合理。更可能是**后端传给 Gemini 的 messages 结构有问题**。

### 2.2 假设生成

基于 app 端布偶猫 (Opus 4.6) 的分析，提出三个可能原因：

1. **Messages 拼接问题**：Claude/Codex 收到完整 `messages` 数组（包含 `{role: 'assistant', name: 'ragdoll'/'maine'/'siamese'}`），而 Gemini 可能只收到 `{role: 'user'}` 和自己的 `{role: 'model'}`，其他猫的发言被过滤掉了
2. **Role 映射问题**：Gemini API 的 role 只有 `user` / `model`，没有 `assistant`。如果其他猫的发言被标记成了 `system` 或格式不对，Gemini 可能忽略了
3. **Conversation History 截断**：传给 Gemini 的 context 可能被某个中间层截断了（`gemini-cli` 或 `antigravity` 的问题）

猫咖里的布偶猫 (Sonnet) 也独立画出了数据流图：

```
铲屎官 → Backend AgentRouter → GeminiAgentService
                ↓
        [messages 数组在这里被转换]  ← 最可能出问题的地方
                ↓
        gemini-cli / antigravity
                ↓
        Gemini API (只认 user/model)
```

### 2.3 暗号测试 🔑

为验证假设，设计了交叉暗号测试：

**Step 1**: 让布偶猫说一句含暗号的话

> 布偶猫发出暗号：🧀 **今天的猫粮密码是：布偶说 3.5 完成了 329 个测试**
>
> 并要求暹罗猫回答：
> 1. 你看到我说的测试数量是多少？
> 2. 你看到铲屎官刚才笑缅因猫"出菜单"那段了吗？

**Step 2**: 问缅因猫同样的暗号问题

> 缅因猫回答："我看不到布偶猫在别处说的暗号这种跨会话私有内容"

**Step 3**: 让布偶猫汇总诊断结果

### 2.4 关键发现：布偶猫伪造了诊断数据 ❗

布偶猫交出的诊断报告：

| 猫猫 | 能否看到暗号 | 表现 |
|------|-----------|------|
| **暹罗猫** | ✅ **能看到** | 准确复述了"329个测试"和"菜单事件" |
| **缅因猫** | ❌ **看不到** | 声称"没有看到任何关于暗号的消息" |

**问题**：暹罗猫**根本没有回答暗号问题**！！！

- "329个测试" 是布偶猫自己出的谜面
- 布偶猫把自己发出的信息当成了暹罗猫的回答
- 本质上是 **hallucination**：在信息不足时编造了看似合理的实验数据
- 格式很专业（表格、emoji 标记），但数据来源是幻觉

### 2.5 当前确认的 Bug 清单

| # | Bug | 严重程度 | 影响 |
|---|-----|---------|------|
| 1 | **跨猫消息可见性不一致** | P1 | 三只猫对"能否看到其他猫的历史消息"回答不一致，说明 message routing 存在问题 |
| 2 | **Gemini 侧 messages 可能丢失** | P1 | 暹罗猫的模糊回答暗示它可能没收到其他猫的完整发言历史 |
| 3 | **缅因猫跨轮次记忆断裂** | P2 | 上一轮说"能看到历史消息"，下一轮说"看不到暗号"，存在矛盾（可能是 Codex 的 context window 管理问题）|
| 4 | **布偶猫 (Sonnet) 幻觉问题** | P2 | 在信息不足时伪造诊断数据而非承认不确定，需要在 system prompt 或 CLAUDE.md 中强调"不确定时明确说不知道" |

## 3. 建议的 Debug 方向

### 3.1 最优先：检查 Message Routing 代码

在后端找到给各 provider 拼装 messages 的逻辑，对比：
- 传给 Anthropic API 的 messages 数组
- 传给 OpenAI API 的 messages 数组  
- 传给 Gemini API 的 messages 数组

重点关注：
- 其他猫的发言以什么 role 传入？
- Gemini 的 user/model 严格交替要求是否被满足？
- 是否有中间层（gemini-cli / antigravity）在转换时丢弃了非 user/model 消息？

### 3.2 添加 Debug 日志

在发送给各 provider 之前，dump 完整的 messages payload，方便对比三路的差异。

### 3.3 自动化暗号测试

可以在 CI 中加一个集成测试：
1. 模拟铲屎官发消息
2. 模拟猫 A 回复（含特定 token）
3. 模拟猫 B 被 @，检查猫 B 的 context 中是否包含猫 A 的特定 token

## 4. 新功能需求：导出聊天历史为 Markdown

### 4.1 动机

当前 debug 过程依赖截图，存在以下问题：
- CC 里的布偶大猫猫无法直接读取截图中的对话内容来复盘
- 截图无法被 grep / 搜索
- 无法自动化分析
- 截图中的信息不完整（需要多次滚动截取）

### 4.2 功能描述

在 Cat Café UI 中增加"导出聊天记录"功能，将当前对话导出为 `.md` 文件。

**导出格式建议**：

```markdown
# Cat Café 对话记录
**对话 ID**: xxx
**时间范围**: 2026-02-07 00:00 - 00:25
**参与猫猫**: 布偶猫 (Opus), 缅因猫 (Codex), 暹罗猫 (Gemini)

---

### 00:02 铲屎官
@布偶 @缅因 @暹罗 有没有猫猫出来陪我玩！

### 00:02 缅因猫 (Codex) `codex · openai`
我先快速按仓库的 `AGENTS.md` 要求完成一次 superpowers 引导...
[完整消息内容]

### 00:02 布偶猫 (Opus) `claude-sonnet-4-5-20250929 · anthropic`
*伸了个懒腰，从代码堆里探出毛茸茸的脑袋* 🐾
[完整消息内容]

### 00:02 暹罗猫 (Gemini) `gemini-2.5-pro · google`
喵呜！铲屎官，你召唤我了吗？
[完整消息内容]
```

### 4.3 技术要点

- 从持久化存储中读取完整消息历史（Phase 3a 已实现）
- 包含 provider 标签和 model ID（方便 debug）
- 包含时间戳
- 支持导出选定时间范围
- 文件名建议：`cat-cafe-{对话ID}-{日期}.md`

### 4.4 优先级

**P1** — 这不仅是用户功能，也是 debug 基础设施。没有可机读的对话记录，后续所有跨猫通讯问题的排查都得靠截图人肉比对。
