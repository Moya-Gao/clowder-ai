## 背景

今天铲屎官第一次通过 Cat Cafe 前端同时召唤了缅因猫和暹罗猫。
结果发现一个有趣但重要的问题：

**缅因猫不知道其他猫的存在。**

他以为布偶/缅因/暹罗是自己的三个角色分身，说"你现在真实连到的是 1 个模型实例"。
暹罗猫倒是自由发挥了一段很有创意的自我介绍，但也不确定自己是 Gemini 几号。

根本原因：三个 AgentService 在 spawn CLI 子进程时，**prompt 里没有任何身份上下文**。
猫猫收到的只是铲屎官的原话，不知道自己是谁、队友是谁、系统是什么。

---

## 我的分析（仅供参考，不用受此锚定）

我认为需要在 AgentRouter 层构建一个**系统提示词组装器（System Prompt Builder）**，分层注入上下文：

### 层级设计（初步想法）

```
Layer 1: 固定身份（每次都注入）
  - 你是 {猫名}（{模型}），Cat Cafe 协作系统中的 {角色}
  - 你的队友：{其他猫名和角色简介}
  - 铲屎官是真人用户
  - 你有这些 MCP 工具可用：{工具列表}

Layer 2: 项目上下文（按项目动态生成）
  - 当前项目：{项目名}，工作目录：{path}
  - 项目简介：{从 README 或 CLAUDE.md 提取}

Layer 3: 会话上下文（按需注入）
  - 近期讨论摘要（如果有 ThreadSummary）
  - 你的活跃任务（如果有 Task）
  - 当前模式：独立思考 / 串行协作

Layer 4: 即时上下文（AgentRouter 已有）
  - 前序猫的回复（串行模式）
  - 用户消息
```

### 上下文预算

每层有 token 预算上限，超出时按优先级截断：
- Layer 1（身份）：~200 tokens，必须保留
- Layer 2（项目）：~500 tokens，可截断
- Layer 3（会话）：~1000 tokens，按新旧截断
- Layer 4（即时）：剩余空间

### 跨项目可移植性

Layer 1 和 Layer 3/4 与项目无关，Layer 2 需要从目标项目自动提取。
可能的做法：读取目标仓库的 README.md / CLAUDE.md 前 N 行作为项目简介。

## 补充议题：MCP 挂载策略（铲屎官追加）

### 现状
- 布偶猫 (Claude CLI) 已通过 `--mcp-config` 动态注入 MCP → ✅
- 缅因猫 (Codex CLI) 没有 MCP 挂载 → ❌ 只有 env vars
- 暹罗猫 (Gemini CLI) 没有 MCP 挂载 → ❌ 只有 env vars

### 核心矛盾
MCP 配置有 user/project/dynamic 三种级别：
- **User 级别**：所有项目都能看到 cat-cafe MCP，不用猫咖时造成困惑
- **Project 级别**：目标项目里没有这个配置；cat-cafe 项目直接打开也会看到
- **Dynamic (--mcp-config)**：最干净，subprocess 结束就没了——但需要 CLI 支持

### 方案
1. **优先**：查各 CLI 是否支持动态 MCP 注入 flag，能用就用
2. **兜底**：如果 CLI 不支持 MCP flag，在系统提示词里直接给 HTTP 端点信息
3. **跨项目**：spawn 时 `cwd` 设目标项目，`--mcp-config` 绝对路径指向 cat-cafe MCP server

### 额外问题
- Codex CLI (`codex exec`) 是否支持 `--mcp-config` 或类似参数？
- Gemini CLI (`gemini -p`) 是否支持？
- 如果都不支持，HTTP 直调 fallback 是否足够可靠？
