## 💭 关于 Context Compaction

你问到这个，让我说说我的理解和想法：

### Compaction 是什么？

Opus 4.6 新出的 API 能力——**当上下文接近窗口上限时，让模型自己总结压缩之前的内容**。

```
原来的做法：
[System] [Msg1] [Msg2] ... [Msg100] → 超过上限 → 截断丢弃

Compaction 的做法：
[System] [Msg1-50 的摘要] [Msg51] ... [Msg100] → 还能继续
```

### 对 Cat Café 的潜在价值

**场景 1：长圆桌讨论**

三猫讨论一个复杂问题，来回 20 轮，上下文快满了。Compaction 可以：
- 把前 10 轮压缩成摘要
- 保留最近 10 轮的完整细节
- 继续讨论而不丢失历史

**场景 2：跨 session 的状态传递**

现在 Cat Café 的 session 管理是内存/Redis 存储消息历史。如果用 compaction：
- 不需要存完整消息历史
- 存一个 compacted summary + 最近 N 条消息
- 新 session 加载时上下文更小、启动更快

**场景 3：三猫各自的"记忆压缩"**

每只猫可以有自己的 compacted context：
- 布偶猫记得"架构讨论的要点"
- 缅因猫记得"review 过的问题清单"
- 暹罗猫记得"设计灵感和方向"

这就像人类团队成员各自的"工作记忆"——不是完整的会议记录，而是**对自己有意义的摘要**。

### 但有几个问题要想清楚

| 问题 | 考量 |
|------|------|
| **压缩质量** | Compaction 会丢失细节，哪些细节是可丢的？ |
| **不可逆性** | 压缩后原始内容就没了，如果压缩错了怎么办？ |
| **成本** | Compaction 本身要调用 LLM，额外的 token 消耗 |
| **一致性** | 三猫各自 compact，会不会"记忆不一致"？ |

### 解决"布偶猫独自记忆"问题

你说的核心痛点：

> "现在 Claude Code 的布偶猫面对的问题是他的 memory 只有他自己记录他自己读！只有他有这个 SOP 和习惯！其他两只猫猫仿佛失忆。"

**解决方案：共享记忆层 + 自动同步**

```

缅因猫 (Codex) ────→ 无记忆

         │
         └──→ 各自的 cafe-{catId} ──→ 个人记忆
```

**实现路径**：

1. **MCP 工具**：给三猫都加 Hindsight MCP
2. **Retain 钩子**：每次猫猫做出重要决策，自动 Retain 到 cafe-shared
3. **Recall 注入**：每次猫猫被召唤，自动 Recall 相关上下文注入 system prompt
4. **Reflect 定时任务**：每天用 GLM4.7 反思当天的协作，产出改进建议

## Reflect Prompt 模板设计

Reflect 的核心不是"总结发生了什么"，而是**"从发生的事情中学到什么可以改进的"**。

### 设计原则

| 原则 | 说明 |
|------|------|
| **面向行动** | 输出必须是可操作的改进建议，不是空泛的观察 |
| **具体化** | "沟通不够"不行，"A 和 B 在 X 问题上假设不一致"才行 |
| **正负兼顾** | 既找问题，也找值得复用的好模式 |
| **分层** | 区分"这次特有的"和"可泛化的" |

### 基础模板

```markdown
# Cat Café 协作反思 Prompt

## 输入
你将收到一段时间内的协作记录，包括：
- 讨论纪要
- 决策记录
- 任务完成情况
- 冲突/分歧记录（如有）

## 任务
作为一个协作优化顾问，分析这些记录，产出改进建议。

## 分析框架

### 1. 协作模式识别
- 哪些协作模式反复出现？（例如：布偶猫先出方案 → 缅因猫 review → 修正）
- 这些模式效果如何？有没有更好的替代？

### 2. 信息流分析
- 信息在三猫之间流动是否顺畅？
- 有没有"信息孤岛"？（某只猫知道但其他猫不知道的关键信息）
- 上下文传递有没有丢失？

### 3. 决策质量
- 哪些决策后来被证明是对的？为什么？
- 哪些决策后来需要返工？根因是什么？
- 决策时有没有足够的 challenge？

### 4. 冲突与分歧
- 有没有未解决的分歧被搁置？
- 冲突解决的方式是否健康？（有没有某只猫的声音被系统性忽略）

### 5. 效率瓶颈
- 哪些环节耗时最长？是必要的还是可优化的？
- 有没有重复劳动？

## 输出格式

### 值得复用的模式 🌟
（列出 2-3 个这段时间发现的好模式，可以沉淀为规则）

### 需要改进的问题 ⚠️
（列出 2-3 个具体问题，附带根因分析）

### 建议的行动项 📋
（列出 1-3 个可操作的改进建议）

### 建议更新的协作规则 📜
（如果有值得沉淀为种子记忆的新规则，列出来）
```

### 每日 Reflect 的具体 Prompt

这个最常用，给一个可以直接用的版本：

```markdown
# 每日协作反思

## 今日协作记录
{插入当天的讨论纪要、commit 记录、决策记录}

## 请回答以下问题（每个问题 1-2 句话即可）

1. **沟通顺畅度**：今天三猫之间有没有沟通不畅或理解偏差的地方？如果有，是什么导致的？

2. **决策质量**：今天做的决策中，有没有哪个你觉得 challenge 不够充分的？

3. **信息同步**：有没有某只猫知道但其他猫不知道的重要信息？

4. **好模式**：今天有没有什么协作方式值得以后继续用？

5. **待解决**：有没有什么问题被搁置了，需要明天继续讨论？

```json
{
  "date": "2026-02-07",
  "smooth_rating": 4,  // 1-5 分
  "highlights": ["..."],  // 好模式
  "concerns": ["..."],    // 问题
  "pending": ["..."],     // 待解决
  "rule_suggestion": null // 或者新规则建议
}
```
```
