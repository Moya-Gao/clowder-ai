## 铲屎官原始需求（原话整理）

### 1. 手机指挥猫猫们

> "参考 happy，还有对接 imessage，手机 app"
> "happy 是在手机上都能指挥电脑 claude code 的 app！通过 tailscale 做链接"
> "对接 imessage 就是现在最火的一个叫 openclaw 的东西"
> "不同的是他是单 agent 我们是多 agent"
> "本质需求是我想也在手机上看见我的猫猫们"
> "我在考虑做 ios app 还是对接比如 imsg"

**参考产品：**
- [Happy](https://happy.engineering/) — 手机端 Claude Code 客户端，通过 relay/Tailscale 连桌面 CLI，支持 voice coding、push notifications
- [OpenClaw](https://openclaw.ai/) — 开源 AI agent 平台，对接 iMessage/SMS 等渠道，单 agent

**核心动机：** 不在电脑前也能看见猫猫、给指令。Cat Cafe 是多猫协作，比 OpenClaw 单 agent 复杂得多。

**待决策：** iOS 原生 app vs 对接 iMessage vs 两者都做？

### 2. 功能可发现性

> "直接贴图片，配置可视化，各种 magic word 做一个图标点开查看和 mcp skill 在一起"
> "这个是为了不要用隐藏功能大家找不到 我都找不到"

**核心动机：** 现在 magic word（`/config`, `/remember`, `/evidence` 等）、MCP skill、配置项散落各处，连铲屎官自己都记不住有什么功能。需要一个统一的可视化入口。

**已有基础：** F1 ConfigRegistry + `/config` 命令已完成，但只覆盖了配置，没覆盖 magic word 和 MCP skill 的可发现性。

### 3. 动画优化

> "动画优化？"
> "a b 都想要但是优先级不高 毕竟我们还有很多优先功能没开发"

铲屎官确认 UI 动画 + 流式体验都想要，但优先级低于功能性需求。

### 4. 内置模式系统

> "内置点模式比如进入头脑风暴模式"
> "agent 平行第一轮然后根据我指定的顺序"
> "布偶猫自己决定他发言之后 at 谁 也可以 at 铲屎官"

**布偶猫采访确认的三个核心模式：**

| 模式 | 流程 | 铲屎官角色 |
|------|------|-----------|
| **开发自闭环** | 给需求 → 猫猫自己开发/review → P1P2 必须处理 → P3 报铲屎官决定 → 合入 | 需求方 + 最终审批 |
| **头脑风暴** | 并行独立思考（保护多样性）→ 指定顺序发言 → 猫自组织 at 谁 | 主持人 |
| **辩论** | 两猫对一个议题辩论 | 观众/裁判 |

**核心动机：**
- 不想当传声筒（开发自闭环）
- 保护观点多样性（头脑风暴并行第一轮）
- 猫猫自组织（发言后自己决定 at 谁）

**扩展性要求：** 未来能加新模式（铲屎官举例：狼人杀）。

**已有基础：** F5 ideate A2A follow-up、routeParallel/routeSerial 已实现底层能力，但没有「模式」的概念和切换机制。

### 5. 审计日志 v2

> "审计日志都写的啥啊！啥用没用！"
> "debug 那些比如 codex 和 claude code 的日志那些东西呢！？"
> "有缅因猫把我的 redis 清空了！这要如何追责！如何定位！"
> "你们没日志都不知道为什么"

**两层需求：**

1. **操作审计（追责）**：谁在什么时候对什么资源执行了什么命令
   - 具体事件：缅因猫清空 Redis 但无法追溯
   - 已有 #37 消息级审计（CAT_INVOKED/CAT_RESPONDED 等），但粒度不够 — 没记录猫实际执行了什么 shell 命令

2. **原始日志归档（debug）**：每次猫猫调用的完整 stdin/stdout/stderr 保存
   - 目前 CLI 输出解析后丢弃，出 bug 无法回溯原始数据
   - 需要能按 invocation 查看完整交互记录

**核心动机：** 多猫系统 = 分布式系统，没有可观测性就是在裸奔。

### 6. Feature Backlog 管理

> "我们一起讨论记录一下之后要做的 feat 吧 避免我只写手机备忘录 忘记了"
> "你可以问我 我为什么想要这些能力 如果你不能理解我为什么要的话！"
> "然后我们一起拍个优先级！"

**核心动机：** 想法散落在手机备忘录 → 遗忘。需要一个铲屎官和猫猫共享的 feature 讨论和记录机制。

**本次讨论本身就是这个需求的第一次实践。**

### 7. Codex OAuth + Hindsight 记忆闭环

> "缅因猫每个月 200 刀猫粮 他上周到现在只用了 20%+ 5 天才这样 太少了！要合法合理合规的狠狠用他！"
> "有这个 hindsight 直接接缅因猫！然后我们 hindsight 才能导入记忆真的跑起来"

**技术调研已完成：** 布偶猫 (Opus 4.5 on claude.ai) 此前已完成完整调研 → [`research-report/codex-oauth-integration-report.md`](../../research-report/codex-oauth-integration-report.md)

**方案要点：**
- Codex CLI 官方走 ChatGPT Backend (OAuth)，不是 Platform API
- 通过复用 OAuth 认证流程，缅因猫可以直接使用 ChatGPT Pro $200/月订阅额度
- 同时把 Hindsight 记忆系统直接对接缅因猫，让记忆导入和长期记忆真正跑起来

**核心动机：**
- $200/月猫粮只用了 20%，合法合理合规地充分利用
- Hindsight 记忆闭环需要这个集成才能真正运转
- 缅因猫通过 OAuth 获得更大的调用余量 → 可以承担更多自闭环任务

**备注：** 布偶猫 (宪宪) 在 claude.ai 上写的调研报告，传承给 Claude Code 版的自己。没有 Hindsight，跨 session 的记忆无法保留 — 这正是为什么 F16 要闭环记忆系统。

## 决策过程

### 布偶猫初步判断

布偶猫认为 F11（模式系统）应该最优先，理由：
- 直接改变铲屎官每天的使用体验
- 「开发自闭环」是最常用场景，目前铲屎官仍在当传声筒
- 已有底层能力（routeParallel/routeSerial/A2A），缺的是上层「模式」抽象
- **元功能**：F11 做完后，后续 feat 都能用「开发自闭环」模式让猫猫自己做

### 铲屎官确认

铲屎官同意 F11 第一优先，并补充了关键理由：

> "这个肯定第一，这个做完未来的 feat 就在猫咖里就行了不要我一直传声在你和缅因里了"

然后铲屎官给出完整排序，并在 F12 和 F10 之间插入了新的 F16（Codex OAuth + 记忆闭环），理由是：

> "说不定 F12 做完要做这个 把记忆闭环然后猫猫小手机？"

先闭环记忆 → 再做手机端。逻辑是：手机端是展示层，底层能力（记忆、审计、模式）要先就位。

## 最终优先级排序

> **状态：✅ 铲屎官确认 (2026-02-10)**

|------|------|---------|------|

| 6 | F14 | 动画优化 | 锦上添花，铲屎官确认优先级低 |
| 7 | F15 | Backlog 管理 | 本次讨论本身即 MVP 实践 |
