## Why: 为什么这样做

### 根因: "没人写信"而不是"邮递员丢信"

"猫咖狼人杀"复盘发现: 三猫看不到彼此回复的根本原因是 **根本没有 context assembly 模块**。每只猫只收到 system prompt + 当前消息，历史为零。

### 方案选择: Prompt Prepend (方案 B)

- **方案 A (Multi-turn API)**: Claude 有 `--continue`, Codex 有 `--resume`, Gemini 有 `--resume` 但 index-based
  - 三家 CLI 的 session/continue 机制互不兼容
  - 无法确保跨猫可见性 (猫 A 的 session 里没有猫 B 的话)
- **方案 B (Prompt Prepend)**: 统一把历史拼进 prompt 前缀
  - 三猫统一，无 CLI 差异
  - 完全可控的截断和过滤
  - 已通过暗号测试验证

### 导出为什么复用 formatMessage()

`ContextAssembler.formatMessage()` 生成 `[HH:MM 角色名] 内容` 格式。导出路由直接复用，保持格式一致，避免维护两套格式化逻辑。

---

## Tradeoff: 放弃了什么

1. **没做 Resume 作为 context 源**: Gemini CLI `--resume` 用 index number 不用 UUID，多 session 时 index 不稳定。记录为 BACKLOG #23 (Phase 4+)
2. **history 默认 20 条**: 可能不够长对话。通过 `CONTEXT_HISTORY_LIMIT` env var 可调。
3. **导出只支持 Markdown**: JSON/HTML 等格式留后续需求驱动。
4. **没有 token 计算**: maxContentLength (500 chars) 是粗略截断，不是精确 token budget。BACKLOG #7。

## Open Questions

1. **context + system prompt + 串行前猫回复**: 三者叠加可能超 token 限制。目前无 budget 管理。
2. **默认 thread 导出**: 前端隐藏了 default thread 的导出按钮 (`id !== 'default'`)。需要 default 导出吗？
3. **AgentRouter.ts 已 344+ 行**: 加了 context history 逻辑后更长了。BACKLOG #14 提取策略函数仍待做。
4. **导出格式 locale 依赖**: `formatThreadAsMarkdown` 用 `toLocaleString('zh-CN')`，非中文环境可能格式不同。
