## Tradeoff — 放弃了什么

1. **MCP 统一用 prompt 注入而非原生**: Codex/Gemini CLI 没有 `--mcp-config`, 只能 prompt 注入 curl 指令。风险: 沙箱可能拦截 curl 出站调用。兜底: 注入本身无害，后续可探索其他方案。
2. **Token 预算用字符数而非 tiktoken**: 三猫各用不同 tokenizer, 精确计算不现实。1 char ≈ 0.3-0.5 token 的粗略估算够用。
3. **Redis Store tests 依赖真实 Redis**: 有 `REDIS_URL` 跑全量, 没有则 skip。Factory 分发测试始终运行。
4. **P2 跳过项**: 前端图片压缩(#9)、对话级联删除(#10)、ChatContainer拆分(#16) — 不阻塞 Phase 4。

## Open Questions

1. **McpPromptInjector 沙箱测试**: 需要实际启动 Codex/Gemini 验证 curl 出站是否被拦截。如果被拦截, 需要探索替代方案 (spawn 时环境变量? child_process pipe?)。
2. **Redis ThreadStore 的 participants 用 Set**: 与内存版 ThreadStore 的 Array 行为一致, 但 Set 顺序不保证 (实践中 Redis SMEMBERS 顺序稳定, 但规范不保证)。
3. **token 预算 300 字符 systemPrompt 估算**: 当前 SystemPromptBuilder 输出 ~150-200 token ≈ 300-400 字符。如果后续 prompt 变长需要调整预留量。
4. **route-strategies.ts 206 行**: 略超 200 行规范, 但全是自包含纯函数, 拆分收益不大。
