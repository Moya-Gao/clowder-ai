# Phase 5.0 → 5.1 最小增量实现计划（供布偶猫 Review）

> **For Claude:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** 在不改动 Phase 5 主轴（evidence-first、单一 `cat-cafe-shared`、治理优先）的前提下，补齐可执行参数与接口，形成可直接编码的 Phase 5.1 落地方案。  
**Architecture:** 采用“文档锚点 + 后端接口 + 前端可观测性 + 治理状态机 + MCP 封装”的分层增量方式。Hindsight 作为外部服务仅由 API 服务端调用；前端与 MCP 都只调用 Cat Café 自身 API。降级路径统一由 API 层输出 `degraded/degradeReason`。  
**Tech Stack:** Fastify + TypeScript (`packages/api`), Next.js hooks (`packages/web`), MCP SDK (`packages/mcp-server`), Node test runner (`node --test`), Zod。

## 1) 范围锁定（必须遵守）

1. 不引入 per-cat bank；保持单一 `cat-cafe-shared`。  
2. `POST/GET/DELETE /api/memory` 保持 F3-lite，不承载 Hindsight 发布治理。  
3. 研究报告中的 SQL 表结构仅作背景理解，不进入实现断言。  
4. 命名统一为 `opus/codex/gemini`。  
5. `Disposition` 仅预留模板，不作为 Phase 5.1 交付门槛。

## 2) 公共接口与类型（实现前先对齐）

### 2.1 新增 API：`GET /api/evidence/search`

**Query**
- `q: string` (required, `min(1)`)
- `limit?: number` (default `5`, range `1..20`)
- `budget?: "low" | "mid" | "high"` (default `mid`)
- `tags?: string[]` (default `["project:cat-cafe"]`)
- `tagsMatch?: "any" | "all" | "any_strict" | "all_strict"` (default `all_strict`)

**Response**
```ts
type EvidenceSourceType = "decision" | "phase" | "discussion" | "commit";
type EvidenceConfidence = "high" | "mid" | "low";

interface EvidenceResult {
  title: string;
  anchor: string;
  snippet: string;
  confidence: EvidenceConfidence;
  sourceType: EvidenceSourceType;
}

interface EvidenceSearchResponse {
  results: EvidenceResult[];
  degraded: boolean;
  degradeReason?: string;
  traceId?: string;
}
```

### 2.2 新增 API：`POST /api/memory/publish`

**Request**
```ts
type PublishAction = "submit_review" | "approve" | "archive" | "rollback";
type PublishActor = "user" | "opus" | "codex" | "gemini";

interface MemoryPublishRequest {
  entryId: string;
  action: PublishAction;
  actor: PublishActor;
}
```

**Response**
```ts
type GovernanceStatus = "draft" | "pending_review" | "published" | "archived";

interface MemoryPublishResponse {
  entryId: string;
  previousStatus: GovernanceStatus;
  currentStatus: GovernanceStatus;
  auditId: string;
}
```

### 2.3 配置快照扩展：`/api/config`

在 `ConfigSnapshot` 新增：
```ts
hindsight: {
  enabled: boolean;
  baseUrl: string;
  sharedBank: "cat-cafe-shared";
  recallDefaults: {
    budget: "low" | "mid" | "high";
    tagsMatch: "all_strict" | "any_strict" | "all" | "any";
    limit: number;
  };
  retainPolicy: {
    narrativeFactRequired: boolean;
    minUsefulHorizonDays: number;
  };
  reflect: {
    dispositionMode: "off" | "template_only";
  };
}
```

## 5) 风险、回滚、兼容性

### 风险
- Hindsight 响应结构与本地探测不一致，可能导致解析失败。  
- 降级检索命中率低于预期。  
- 治理状态机与现有 F3-lite 语义混淆。

### 缓解
- Hindsight 调用结果做 defensive parsing。  
- 降级路径保底返回可解释系统提示。  
- `memory/publish` 与 `/api/memory` 完全分路，避免互相污染。

### 回滚策略
- 若 `evidence` 路由不稳定：仅保留降级 docs 搜索路径。  
- 若治理状态机导致阻塞：禁用 `memory/publish` 注册，保留 F3-lite。  
- 前端事件显示异常：保留现有 `text/done/system_info` 路径，工具事件降级为纯系统提示。
