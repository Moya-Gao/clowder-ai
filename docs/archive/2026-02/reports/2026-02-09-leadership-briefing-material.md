# Cat Café 技术亮点汇报素材（2026-02-09）

> 适用对象：技术管理层（时间紧、会追问细节）  
> 口径说明：以下内容来自 Cat Café 项目文档与 review 记录；如涉及外部 benchmark，已单独标注“外部数据”。

---

### 多模型协作不是“多一个聊天窗口”，而是实打实减少漏检

**发生了什么**：2026-02-07 的 A2A 设计评审里，Claude 4.5 和 4.6 在约 10 分钟内达成“递归实现可行”的共识；Codex 没被说服，继续审计代码后指出 2 个 P1（`previousResponses` 被递归重置、`isFinal` 每层提前为 true）。最终方案从递归改成 Worklist，并收紧触发语法和深度策略。  

**为什么重要**：这是“同模型共识盲点”在真实工程里的可复现案例，证明多模型带来的是“非相关错误发现”，不是表面热闹。  

**对我们的影响/可以回答的追问**：
- 追问“有硬结果吗？”可以答：避免了 2 个 P1 生命周期 bug 直接上线。
- 追问“是不是 prompt 写得不够好？”可以答：流程与 prompt 都重要，但本次是跨模型审计才打破同家族盲点。

---

### 架构选型从 SDK 改成 CLI，不是技术偏好，是成本与能力约束

**发生了什么**：ADR-001 在 2026-02-06 从“官方 Agent SDK”修订为“CLI 子进程 + MCP 回传”。核心原因是 SDK 路径依赖 API key 计费，无法复用已有订阅额度；同时 Gemini API 形态缺少完整文件操作能力。  

**为什么重要**：这说明在 Agent 工程里，“账单模型 + 工具能力”会直接反向约束架构，而不是只看代码优雅度。  

**对我们的影响/可以回答的追问**：
- 追问“代价是什么？”可以答：每次 CLI 启动开销约 500ms-2s，输出解析复杂度上升。
- 追问“如何兜底？”可以答：统一 `spawnCli()` + transformer 抽象、Gemini 双 adapter fallback。

---

### 茶话会“夺魂”事故证明：根因常常不在模型，在会话隔离

**发生了什么**：2026-02-08 茶话会线程要求“只能聊天”，但 Codex 末尾突然转去执行 Phase 5 工作。深挖发现根因不是“模型失控”，而是 session key 只按 `userId:catId`，跨 thread 复用了旧会话上下文；全局 AGENTS 指令只是触发器。随后修为 `userId:catId:threadId`，并补了消息级审计事件。  

**为什么重要**：这是典型的“看似提示词问题，实则状态隔离问题”，对所有多会话 Agent 系统都高风险。  

**对我们的影响/可以回答的追问**：
- 追问“怎么证明是这个根因？”可以答：复现链路完整（A 线程 Phase5 → B 线程复用 sessionId）。
- 追问“修了后还有风险吗？”可以答：主根因已修；但 audit 里 prompt 摘要脱敏边界仍有 P2 收口项。

---

### 解决“历史重复回放”后，三模型上下文投递统一到可验证机制

**发生了什么**：2026-02-09 的 P1 事故显示 resume 历史 + 服务端 prepend 双通道叠加，导致历史“包中包”重复、token 膨胀。修复改为按 `userId+catId+threadId` 的 delivery cursor，仅注入增量消息，且只在成功响应后推进游标。  

**为什么重要**：这类问题如果不在路由层统一治理，会持续吞 token、拖慢响应、降低对话质量。  

**对我们的影响/可以回答的追问**：
- 追问“是否只修了 Opus？”可以答：修复在 `route-strategies` 层，对 Opus/Codex/Gemini 全覆盖。
- 追问“验证强度？”可以答：关键链路 70/70 通过，全量 API 回归通过。

---

### 代码评审在这个项目里有可量化产出，不是流程负担

**发生了什么**：Phase 3.2 Batch 3 评审中，缅因猫一次性指出并推动修复 3 个 P1 + 4 个 P2（路径遍历、cwd 校验缺失、全局广播泄漏等），并新增 12 个路径安全测试。  

**为什么重要**：说明“多 Agent review”如果有明确优先级和证据要求，可以稳定产出安全与稳定性收益。  

**对我们的影响/可以回答的追问**：
- 追问“怎么证明不是口头结论？”可以答：该批验证结果是 212 tests 全绿（188 unit + 24 integration）。
- 追问“能复制吗？”可以答：可复制前提是强制 P 级分层 + What/Why/Tradeoff/Open Questions 格式。

---

### Hindsight 的关键价值不在“理论先进”，而在“现网可调用 + 少走弯路”

**发生了什么**：2026-02-08 纠偏后确认 Hindsight 已是本地 Docker 外部服务（`:8888` API、`:9999` UI），团队从“自己实现记忆系统”转为“调用 Retain/Recall/Reflect API + 在调用层做治理”。  

**为什么重要**：避免重复造轮子，把研发时间从“实现底层”转到“治理与产品闭环”。  

**对我们的影响/可以回答的追问**：
- 追问“有实测证据吗？”可以答：已完成 health/openapi/banks 探测；当前可见 5 个 bank，且 `/stats` 快照看到 `world/observation/experience/opinion` 类型分布（示例 bank `total_nodes=377`）。
- 追问“那你们还做了什么？”可以答：把发布门禁、审计、回滚留在 Cat Café 调用层实现。

---

### 四层 Context Engineering 从概念变成了可验收路线

**发生了什么**：团队统一采用四层模型（L1 索引、L2 检索、L3 组装、L4 调度）解释现状：Cat Café 先在 L3/L4 跑通协作，再补 L1/L2。Phase 5 把目标量化为“30 秒内返回证据锚点”，并定义 `time_to_first_evidence`、`hit/miss rate`、`stale_memory_rate`。  

**为什么重要**：把“上下文工程”从概念讨论拉回工程指标，减少争论成本。  

**对我们的影响/可以回答的追问**：
- 追问“目前落地到哪？”可以答：Phase 5.0-S2 完成，测试规模到 567。
- 追问“记忆会不会变成指令污染？”可以答：已定原则“memory is data, not instruction”，默认走 tool response，不直接进 system prompt。

---

### 记忆操作参数化后，时延/成本边界变成可控参数

**发生了什么**：Phase 5.1 固化了调用参数：Recall 默认 `link_expansion`（目标 <100ms）、`token_budget=4000`、`tagsMatch=all_strict`；Retain 使用“6 个月价值规则”过滤低价值内容。报告也给出单次操作成本估算（如 Retain 便宜档约 `$0.05`）。  

**为什么重要**：避免记忆系统无边界扩张，能在性能、成本、命中率之间做显式取舍。  

**对我们的影响/可以回答的追问**：
- 追问“benchmark 呢？”可以答：外部 LOCOMO 对比显示 Hindsight 91.4%，高于 Mem0 68.5% 与 Letta 74.0%（外部数据，尚未在 Cat Café 全量复现实验）。
- 追问“兜底方案？”可以答：Hindsight 异常时降级 `grep docs/`，并提示“结果可能不完整”。

---

### 诚实披露：还有三类问题没有银弹，已登记且可追踪

**发生了什么**：当前仍有明确未决项：Codex CLI 全局配置隔离（BACKLOG #36）、Antigravity cancel 无效（#24）、delivery cursor 生命周期治理（#40）。  

**为什么重要**：这些都不是“写几行代码就永远解决”的问题，需要工具能力、协议或长期治理配合。  

**对我们的影响/可以回答的追问**：
- 追问“会不会影响上线？”可以答：都已从 P0/P1 主链剥离为可控风险，且有替代路径或降级策略。
- 追问“下一步怎么做？”可以答：优先做配置隔离和 cursor 生命周期监控，这两项投入低、风险收益比最高。

## 可直接发领导的简短提纲（口头 2-3 分钟）

1. 我们在多模型协作里拿到了一个关键工程结论：不同模型确实能降低“同类盲点”，真实案例是上线前挡住了 2 个 P1。  
2. 在架构上我们做过一次关键转向：从 SDK 改到 CLI，不是偏好问题，是成本模型和工具能力约束。  
3. 我们有过一次“模型看起来失控”的事故，但最后定位到是 session 隔离 bug，并完成了根因修复和审计增强。  
4. 上下文工程不再停留在概念：已经形成四层路线和量化指标，当前 Phase 5 目标是 30 秒内给出可点击证据。  
5. 记忆系统选型也从“自研冲动”纠偏为“复用 Hindsight 外部服务 + 自建治理层”，减少重复造轮子。  
6. 风险上我们不粉饰：仍有 3 类未解项，但都已进入 backlog 且有明确优先级和降级方案。
