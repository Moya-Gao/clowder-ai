# 缅因猫（Codex）任务清单

> 角色：代码审查员 + 质量守护者
> 工具：Codex CLI / OpenAI API

---

## 职责概述

1. **代码审查**：每个 Layer 完成后进行全面 review
2. **安全审计**：检查权限、文件访问、API 安全
3. **测试补充**：发现边界条件，补充测试用例
4. **文档审查**：确保代码与文档一致

---

## 审查清单

### Layer 0 审查：项目结构与类型

布偶猫完成 Layer 0 后，审查以下内容：

- [ ] **项目结构**
  - monorepo 结构是否合理
  - 包之间的依赖关系是否清晰
  - 是否有循环依赖

- [ ] **TypeScript 配置**
  - strict mode 是否开启
  - 类型定义是否完整
  - 是否有隐式 any

- [ ] **类型定义质量**
  - Branded types 是否正确使用
  - Zod schemas 是否完整
  - 前后端类型是否真正共享

- [ ] **MCP Server 安全**
  - 工具权限是否最小化
  - 文件访问是否有边界限制
  - 错误信息是否泄露敏感信息

### Layer 1 审查：API 与通信

- [ ] **API 设计**
  - RESTful 规范是否遵循
  - 错误响应格式是否统一
  - 输入验证是否完整

- [ ] **WebSocket 安全**
  - 连接认证机制
  - 消息格式验证
  - 断线重连处理

- [ ] **文件上传安全**
  - 文件类型限制
  - 文件大小限制
  - 存储路径安全（防止路径穿越）

- [ ] **@ 路由逻辑**
  - 边界条件处理
  - 无效 @ 的处理
  - 并发消息的顺序保证

### Layer 2 审查：文件系统与状态

- [ ] **文件操作安全**
  - 路径验证（禁止 ../ 穿越）
  - 权限检查
  - 并发写入处理

- [ ] **状态一致性**
  - last-seen 更新的原子性
  - 多猫同时在线的状态同步
  - 状态文件损坏的恢复

- [ ] **MCP 工具权限**
  - 每个工具的权限边界
  - 敏感操作的确认机制
  - 日志记录

### Layer 3 审查：Git 集成

- [ ] **Git 操作安全**
  - 禁止危险操作（force push 等）
  - Worktree 隔离性验证
  - 提交信息规范检查

- [ ] **并发安全**
  - 多猫同时操作同一仓库
  - Worktree 冲突处理
  - 锁机制

```markdown

- 审查日期：YYYY-MM-DD
- 审查范围：[文件列表]
- 总体评价：[通过/需修改/需重构]

## 发现的问题

### P1 - 必须修复
1. [问题描述]
   - 位置：`file.ts:line`
   - 风险：[安全/性能/正确性]
   - 建议：[修复建议]

### P2 - 建议修复
...

### P3 - 可选优化
...

## 测试建议
- [ ] 需要补充的测试用例

## 总结
[一句话总结]
```

## 协作触发点

缅因猫在以下情况被召唤：

1. **布偶猫完成一个 Layer**：进行全面审查
2. **铲屎官 @缅因 请求审查**：针对性审查
3. **发现 Bug 时**：协助定位和修复
4. **架构决策讨论**：提供落地验证视角

---

## 注意事项

1. **审查要具体**：指出具体文件和行号
2. **给出建议**：不只是指出问题，还要给修复建议
3. **优先级分明**：P1 必须修，P2 建议修，P3 可选
4. **保持耐心**：复杂代码可能需要多轮审查
5. **记录决策**：有争议的点记录到 ADR

- **铲屎官**：汇报审查结果，重大问题及时沟通
