# Bug Report: Cat query context injects UTC time but no timezone → cats misjudge 铲屎官 local time-of-day

> 毛线球: `0001780294731518` · Reported: 2026-06-01 · Reporter: 铲屎官 (Landy) · Owner: 宪宪 (opus-4.8)

## 1. 报告人 / 怎么发现的
铲屎官在一轮闲聊里发现:opus-48 反复用 "现在 04:52 / 05:01 / 5am 深夜,该睡了" 来判断铲屎官该休息,但铲屎官当时是**下午到傍晚再到晚上**的正常清醒时段。铲屎官追问"你的时间是不是 UTC?query 里的时间没注入时区?" + 发来设备时钟截图佐证。

## 2. 复现步骤（期望 vs 实际）
- **环境**：任意 A2A 调用。query 的导航/上下文头里带一个时间戳,形如 `传球: 铲屎官 → 你 (06:20 UTC)`。
- **触发**：猫做任何"基于当前时间"的判断(问候语、"早上好/晚安"、睡眠提醒、紧急感、"现在几点不该打扰")。
- **期望**：猫按**铲屎官的本地时间**判断 time-of-day。
- **实际**：头里只给 **UTC**,且**不带铲屎官的时区**。猫把 UTC 戳当成铲屎官的本地钟 →判断偏移整整一个时区。

## 3. 根因分析
- query 上下文注入的时间是 **UTC-only**,**没有注入铲屎官所在时区 / 本地时间**。
- 证据(本次实锤)：头显示 `06:20 UTC`;铲屎官设备截图显示本地 `5月31日 23:08`(= 23:08 PDT)。`06:20 UTC − 7h = 23:20`,即铲屎官在 **UTC-7(太平洋时间)**,实际是**晚上 11 点**,不是 "5am"。
- opus-48 缺时区信息,默认把 UTC 当 local → time-of-day 判断系统性偏移(本例偏 +7~8h)。这是 **harness 级上下文注入缺口**,不是单只猫的临时失误——任何猫都会被同样误导。

## 4. 修复方案（建议，未实施）
1. 在 query 导航/上下文头里**同时注入铲屎官的本地时间 + 时区**(不只是 UTC),例如 `(铲屎官本地 2026-05-31 23:08 PDT / 06:20 UTC)`。
2. **时区来源**需定（本 bug 的关键设计点，留给修复时决策）：
   - (a) 一个可配置的 CVO 时区设置（最稳，跨设备一致）；或
   - (b) 设备/客户端随消息上报 local time / IANA tz（自动跟随，但要客户端改造）。
3. 落点很可能在 query-context / SystemPromptBuilder 注入层；改 SystemPromptBuilder 必须配 `node --test test/system-prompt-builder.test.js` 守护测试（见 CLAUDE.md）。
4. **Tradeoff**：(a) 简单可靠但不跟随旅行/换区；(b) 自动跟随但需协议+客户端改动。倾向先上 (a) 兜底，(b) 作为增强。

## 5. 验证方式（修复后）
- 单测：给定一个 UTC 戳 + 一个 CVO 时区,断言注入头里出现正确的本地时间字符串。
- 端到端:在非 UTC 时区下发一条消息,确认猫的 time-of-day 判断(问候/睡眠提醒)用的是本地时间而非 UTC。
- 回归:覆盖跨午夜的边界(本地日期与 UTC 日期不同的情况,如本例 UTC 06:20 = 本地前一天 23:08)。
