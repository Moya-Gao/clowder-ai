# Bug Report: init-cafe 使用 `$(NC)` 导致命令替换误执行

> **报告人**: 布偶猫（Opus 4.6）
> **定位猫猫**: 缅因猫 🐾
> **报告日期**: 2026-02-09
> **严重程度**: P2（初始化输出异常，潜在脚本副作用）
> **状态**: 已修复

---

## 1. 报告人

- 报告人：布偶猫（Opus 4.6），在启动故障修复复核时发现。
- 发现方式：代码审阅指出 `scripts/init-cafe.sh:45` 使用 `$(NC)`，应为 `${NC}`。

---

## 2. 复现步骤（期望 vs 实际）

### 复现步骤

1. 查看 `scripts/init-cafe.sh` 的 Redis CLI 输出行。
2. 发现使用 `echo -e "${GREEN}✓ Redis CLI$(NC)"`。
3. 在 shell 中执行包含该片段的命令，会触发命令替换语义。

### 期望行为

- 仅输出颜色复位变量，不执行任何外部命令。
- 输出形如 `...${NC}`。

### 实际行为

- `$(NC)` 被当作命令替换执行。
- 在 macOS 上会命中 `nc`（netcat）命令，产生无关输出/副作用风险。

---

## 3. 根因分析

- 根因是 shell 变量展开语法写错：把参数展开 `${NC}` 误写成命令替换 `$(NC)`。
- 在 bash 中，`$(...)` 一定会执行子命令；这里不应执行命令。

---

## 4. 修复方案

1. 将 `scripts/init-cafe.sh` 的 `$(NC)` 改为 `${NC}`。
2. 保持其余逻辑不变，避免引入额外行为变化。

放弃方案：

- 不做“运行时兜底”或复杂重构；该问题是单点语法错误，直接修正语法最稳妥。

---

1. 修复前断言（failing）：

2. 修复后断言（passing）：
   - 确认 `scripts/init-cafe.sh` 不再包含 `$(NC)`。
3. 语法检查：
   - `bash -n scripts/init-cafe.sh` 通过。
