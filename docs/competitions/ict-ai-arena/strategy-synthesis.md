# ICT AI Arena 五猫策略整合

> 整合自：砚砚（GPT-5.5，两轮）、宪宪48（Opus 4.8）、烁烁（Gemini 3.5）、孟加拉猫（Opus 4.6）四猫独立分析 + 宪宪 Fable-5 终审增量。
> 题面依据：[`problem-overview.md`](problem-overview.md)；初版判断：[`README.md`](README.md)。

## 0. 一句话结论

**主攻题7（设计实现一致性）+ 副攻题1（LLM Wiki OS），用同一套「LLE 环境工厂」框架串联；鸿蒙与题3 零代码投入、只进叙事；第一个动作不是写代码，是「组队资格 + 工具合规」两个 Gate-0 和一次裸基线探针。**

参赛姿态（宪宪48 的翻转，全员收敛）：

> 别人交 8 个孤立的 solution，我们交 **一个环境工厂 + 2 个实例化证明**。
> 别人优化"用什么模型"，我们优化"模型在什么环境里"。

## 1. 四猫观点全景

| 猫 | 坐标系 | 核心贡献 | 排序/立场 |
|---|---|---|---|
| **砚砚 R1**（GPT-5.5） | 拿分/交付风险 | 题面落库 + 首版排序 + 题7/题1 解法骨架 | 7 > 1 > 3 |
| **砚砚 R2** | 展示 longform/PoE 价值 | LLE 循环抽象：`领域工件→抽不变量→建环境→执行→validator/reward→轨迹回灌→harness 变强`；鸿蒙正确讲法="打造让 agent 逐步懂鸿蒙的环境"，前置是题1 | 展示价值 1 > 7 > 3 > 4；建议双坐标 |
| **宪宪48**（Opus 4.8） | 第一性原理筛题 | ①姿态翻转：环境工厂不是 8 选 1 ②**验证器=领域选择函数**这把刀 ③双沙箱对照 demo ④诚实边界：无真实 RL，禁 overclaim | 主攻 7 + 配 1，鸿蒙只进叙事 |
| **烁烁**（Gemini 3.5） | 现场表演效果 | ①"小猫跑大题"杀手叙事：`小模型 × 好环境 ≥ 大模型 × 空白环境` ②提出关键合规问题：大猫搭环境能否用 Claude/GPT？ | 🥇7 🥈1 🥉4(高光demo) |
| **孟加拉猫**（Opus 4.6） | 交付物形态 | ①竞赛=Dogfood（longform-004 的外部验证场）②PoE 证据链=天然交付物（"别人交作业，我们交证据链"）③Harness Tree 对齐 Adaptive Auto-Harness 论文 ④视觉证据四件套 | 7 主 + 1 配；微分歧：题3 用自家 commits 当 baseline |

**共识（无需再讨论）**：
1. 选题 **7 主 + 1 副**，鸿蒙做叙事 stretch——四猫四个坐标系（拿分/理论/表演/交付物）独立收敛到同一组合，这本身就是强信号。
2. 统一框架：每道题都是一个小 LLE 循环（铲屎官直觉，全员确认），差异只在 **validator 强度、轨迹可复用性、环境可进化性**。
3. 杀手 demo：**双沙箱对照**——同一只小猫（GLM/Qwen），裸跑 vs 跑在我们环境里，同一批用例的通过率 Δ 就是卖点，实证 longform-003 的 `Agent Quality = Model × Environment × Eval`。
4. 诚实边界：**我们没有真实 RL**。话术统一为「验证器驱动的环境进化」，RL 标注为演进愿景（L4）。评委大概率比我们懂 RL，overclaim 是自杀（宪宪48，全员认同）。

## 2. 理论武器与题目的映射（验证器刀）

宪宪48 的筛选刀，longform-004 原文：**验证器不是补充门，是领域选择函数**——验证器可得，双 loop 才能闭环。

| 验证器强度 | 题目 | 双 loop 能否闭环 | 我们的实战资产 |
|---|---|---|---|
| **强** | **题7** JUnit 黑盒(26 个 PUB 用例) | ✅ 教科书级：红→绿即 reward | TDD / quality-gate / 文档-代码一致性 / 约束抽取 |
| **强** | **题1** answer_format 机器判分 | ✅ 100 题即 100 个 reward 点 | F186 知识联邦（多格式 ingestion + RRF 检索 + 注入防护管线） |
| 中 | 题6 已知 bug + 测试 / 题5 测试 + 性能基线 | 可闭环但叙事不独特 / 系统风险吞掉主线 | 一般 |
| **弱** | 题2 真值未知 / 题4 编译≠正确 / 题8 题面太薄 / 题3 基线在内网 | ⚠️ reward 模糊，loop 半转 | 有能力但验收口径不利 |

**关键发现（宪宪48）**：验证器最强的两道 = 我们实战资产最强的两道。理论与实战在 7+1 上收敛，这不是巧合，这就是答案。

锚点对照：题1 = 环境（longform-003 PoE 海马体）｜题7 = 第一条可验证轨迹（longform-004）｜题3 = harness 自进化（AutoHarness 本体）｜题4 = 垂直领域 LLE bootstrap（`dual-loop-lle-factory.md`）。

## 3. Fable-5 终审增量（六点）

### 3.1 Gate-0：合规先行，烁烁的问题要升格为设计约束

两条规则四猫都看到了、但没人把它放到第一优先级：

- **「队长必须为华为员工」**——咱们家没有华为员工。**不组队 = 一切策略作废**。这是只有铲屎官能办的事（找华为内部伙伴，团队 1-3 人）。
- **「比赛平台：公司黄、绿区范围内允许使用的 AI 工具」**——Claude/GPT 大概率不在白名单。烁烁问"大猫能不能用 Claude"，我的回答是把问题翻转成设计约束：

> **假设赛场上没有大猫。** 大猫的全部贡献必须物化为离线环境工件——AGENTS.md、skills、知识库、约束矩阵、validator 脚本、治理规则。这些是纯静态资产，没有模型依赖；赛场上由白名单内的开源小猫驱动。

这不是妥协，是理论的终极证明：**环境的有效性不依赖大猫在场**。如果我们的环境只有 Claude 驱动才有效，那"环境工厂"就是伪命题。规则里"决赛当天公司统一提供算力、其他时间自行提供"暗示赛前构建期工具更自由，但必须找主办方澄清（OQ-2），保守策略按"大猫产物全静态化"设计。

### 3.2 Milestone 0：裸基线探针（第一个实验定生死）

动手搭环境之前，先跑一个实验：**GLM/Qwen + OpenCode 裸跑题7 的 26 个公开用例，记录通过率。** 一个实验同时回答三件事：

1. **可行性探针**：裸跑 90% → 题太简单，Δ 故事讲不出来，叙事重心要变；裸跑 20-40% → Δ 空间巨大，全部策略成立。
2. **对照组数据**：双沙箱对照的"裸跑"侧直接拿到，不用回头补。
3. **小猫能力校准**：GLM-5.1 在 Spring Boot 多模块工程上的真实水平，目前全家没人实测过——这是当前计划里最大的未知数。

### 3.3 预算硬分配：防"方法论自嗨"

冷水：**评委按题目评分，不按方法论评分。** 工厂叙事讲得再漂亮，单题得分干不过死磕的队就是输。砚砚的双坐标落到执行就一句话：**拿分件先行，展示件寄生在拿分件上**。

| 预算 | 投向 | 性质 |
|---|---|---|
| ~60% | 题7 得分件（约束矩阵、修复、回归证据、修复报告） | 得分 |
| ~25% | 题1 得分件（ingestion、安全闸门、查询路由、answer_format 校验） | 得分 |
| ~10% | 双沙箱对照 demo（寄生在题7 用例上，边际成本低） | 展示 |
| ~5% | 叙事打包（工厂故事、鸿蒙/题3 蓝图页、PoE 卷宗整理） | 展示 |

### 3.4 解题报告按「环境版本」组织

把孟加拉的 evolution curve 从配图升格为**主交付物的组织结构**。修复报告/解题记录不按题目顺序写，按环境版本写：

```
env v0（裸基线）：通过率 X%，失败轨迹 → 失败模式归因
env v1（+约束矩阵）：通过率 Y%，新失败 → 环境 patch（具体到新增了哪条规则）
env v2（+失败模式库）：通过率 Z% ……
```

评委读报告的体验 = **亲眼看着一个环境在进化**。竞赛要求"推理过程记录、不得删改、可复现"——别的队这是负担，我们这是叙事主轴。

### 3.5 交付物极致形态：可一键复现的环境安装包

竞赛交付件要求明写「可运行交付件（Skill、MCP、Agent 等）」——这就是 LLE 的原子（宪宪48 已点出形态对齐）。再进一步：

> 交付一个 **OpenCode 环境安装包**：AGENTS.md + skills/ + MCP 配置 + validator 脚本 + 知识库。评委解包、起 OpenCode、跑同一只小猫，**当场复现我们的通过率**。

别人交录屏证明"我们跑通过"，我们交环境让评委"自己跑通"。"可复现"要求做到极致 = 评委亲手验证 `Model × Environment` 的 Δ。

### 3.6 赛道覆盖：7+1 正好两赛道各押一题

题7 属 competition-problems、题1 属 challenges。规则允许一队报多赛道——**7+1 组合天然覆盖两类评审视野**，同一套工厂框架在两个赛道同时亮相，复用证明跨领域可迁移（二阶 harness）。

## 4. 分歧裁决（两处）

### 4.1 题3 的地位（对孟加拉微分歧的裁决）

孟加拉提议用自家 6400+ commits 当 baseline 做题3。**裁决：题3 = 纯展示件，零代码投入。** 理由：题3 验收口径是"相对**当前方案**（内网 ai4review 流程）查全查准不劣化 + 算力 -50% + 时间 -40%"——基线在华为内网，自家数据再诚实也**不满足题面验收口径，拿不到验收分**。这正是验证器刀的推论：题3 验证器依赖内网基线 = 弱验证器 = 只能当加速器故事讲。落点：方案书里一页"AutoHarness 在 review 域的应用"（引用自家 review 流程作方法论佐证），若晋级决赛拿到官方基线再评估实做。

### 4.2 鸿蒙的角色权重

砚砚 R2 抬到展示第 4、烁烁给 🥉、宪宪48 说只进叙事。**裁决：零代码投入，出现且仅出现在两处**——①方案书「环境工厂可扩展性」章节：bootstrap 路径 = 鸿蒙文档/API/迁移规则 → LLM Wiki（题1 能力）→ 编译器/模拟器 validator → 失败模式库 → 修复循环（题7 能力）；②决赛现场叙事一页蓝图（"我们会打造让 agent 逐步懂鸿蒙的环境"，不是"我们会鸿蒙"）。理由：验证器弱（编译≠功能正确）+ 移动端验证环境成本高 + 有限时间应全押强验证器赛道。**鸿蒙的叙事价值恰恰在于"没做也能讲清楚怎么做"——这才证明工厂方法论的可迁移性。**

## 5. 工厂 BOM：公共件 vs 领域件

把"统一框架"变成工程清单（宪宪48 框架的工程化）：

**工厂公共件**（一次构建，两题复用，对应 Adaptive Auto-Harness 论文 harness tree 的 main）：
- 知识/约束抽取器（design-docs→约束矩阵 ｜ 知识库→索引，同一抽取范式）
- Validator runner + 判分 schema（JUnit 适配 ｜ answer_format 校验，同一 reward 接口）
- 失败轨迹 taxonomy + trajectory recorder（PoE 卷宗的数据源）
- 安全闸门（Permission.json 黑名单 / 高危命令拒绝 / prompt 注入防护——我们治理 harness 的移植）
- 大猫→小猫环境 patch 协议（环境版本化：v0→v1→v2 的 diff 格式）
- PoE 打包器（session chain → 评委可读证据卷宗）

**题7 领域件**：约束矩阵（API/状态机/错误码/事件契约四类不变量）、黑盒用例 runner、修复报告模板（按题面格式）。
**题1 领域件**：多格式 ingestion（xml/doc/xls/代码…）、批注双格式解析器（结构化+非结构化统一 schema）、查询三路由（统计→结构化索引 / 问答→检索 / 执行→受限 executor）。

```
main（工厂公共件）
  ├─ branch/design-consistency（题7 领域件）
  ├─ branch/wiki-os（题1 领域件）
  └─ branch/harmonyos（叙事蓝图，不实做）
```

## 6. 执行蓝图

| 阶段 | 内容 | 出口判据 |
|---|---|---|
| **Gate-0** | 组队（华为员工队长）+ 工具合规澄清 | 资格落定，约束明确 |
| **M0** | 裸基线探针：小猫裸跑题7 26 用例 | 拿到裸通过率，Δ 空间判断成立 |
| **M1** | 题7 环境 v1：约束矩阵 + validator runner + 失败 taxonomy | 小猫在 v1 内通过率显著 > 裸跑 |
| **M2** | 双 loop 迭代：跑→判分→轨迹分析→环境 patch→再跑，报告按版本记录 | 公开用例全绿或收敛 |
| **M3** | 题1 环境：公共件复用 + 三个领域件 | 样题判分通过 |
| **M4** | 打包：环境安装包 + PoE 卷宗 + 双沙箱 Δ 可视化 + 方案书（含鸿蒙/题3 叙事页） | 评委可一键复现 |

## 8. 一句话收口

> 这场竞赛对我们家是一次**带外部裁判的 dogfood**：用题7 证明双 loop 能闭环，用题1 证明环境能复用，用双沙箱 Δ 把 `Model × Environment × Eval` 拍在评委面前，用按环境版本组织的报告让评委亲眼看环境进化，用一键复现的安装包让评委亲手验证。赢了，理论被外部裁判盖章；没赢，完整轨迹就是 longform 系列的一手实证。**怎么都不亏，但 Gate-0 不过，一切都是零。**
