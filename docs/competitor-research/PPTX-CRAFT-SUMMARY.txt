🎨 DESIGN PATTERNS TO LEARN
────────────────────────────────────────────────────────────────────────────────

✅ #1: SUBAGENT PROMPT AS USER REQUEST
   → Provide ALL parameters (topic, page_count, style_id)
   → Skip confirmation dialogs naturally
   → Child skills don't need "subagent awareness"

✅ #2: APPROVAL GATES
   → Outline review BEFORE expensive generation
   → Hard requirement, not optional
   → Saves compute on wrong directions

✅ #3: TWO-PHASE GENERATION
   → Draft (640×360) = Content validation
   → Final (1280×720) = Visual polish
   → Independent agents, easy rollback

✅ #4: BROWSER-BASED HTML→PPTX
   → Playwright inject dom-to-pptx library
   → Execute in page.evaluate() context
   → Handles CSS, web fonts, charts natively

✅ #5: TIMESTAMP DIRECTORY ISOLATION
   → Format: YYYYMMDD_HHMMSS_XXX
   → Auto-increment sequence for same-second collisions
   → Enables parallel execution

✅ #6: CENTRALIZED PATH MANAGEMENT
   → Main agent controls {output_dir}, {pages_dir}
   → Pass via prompt variables, never guess
   → Prevents file scatter

✅ #7: COMPREHENSIVE INTENT FILTERING
   → 8 categories of jailbreak attempts blocked
   → Unified rejection message
   → Early return, no confusion

✅ #8: FONT EMBEDDING FOR FIDELITY
   → Auto-detect fonts used in HTML
   → Embed woff2 directly in PPTX
   → Ensures consistent rendering

🔌 CONVERSION PIPELINE (convert.js)
────────────────────────────────────────────────────────────────────────────────

1. Read HTML file
2. Launch Playwright headless browser
3. setContent(html, { waitUntil: 'load' })
4. Inject dom-to-pptx library + dependencies
5. page.evaluate() → querySelectorAll('.ppt-slide') → exportToPptx()
6. Capture PPTX blob → Buffer → writeFile()

Key: Runs JS in browser context, not server-side rendering


⚠️ GOTCHAS & LESSONS
────────────────────────────────────────────────────────────────────────────────

❌ Why NOT server-side Python-PPTX?
   → CSS/Tailwind handling difficult
   → Web fonts require browser
   → Charts (ECharts) need dynamic rendering
   → Font embedding complex

✅ Browser-based is better for:
   → Complex visual layouts
   → Web font support
   → Dynamic chart rendering
   → Iterative development

❌ Why NOT skip outline approval?
   → Wasted compute on wrong content
   → Cascading failures (fix outline → regenerate all)
   → User frustration

✅ Approval gate prevents:
   → Resource waste
   → Misaligned expectations
   → Multiple round-trips

❌ Why FORBID inline styles?
   → Style conflicts with Tailwind
   → Hard to update in phase 2
   → Visual inconsistency

✅ Tailwind-only enforces:
   → Predictable classes
   → Easier polish phase
   → No cascade bugs
