> 来源：华为 PPT 演示编排讨论。铲屎官想在台上说"我说过脚手架"然后瞬间跳转到

## 1. 问题：记忆系统缺了一层

### 现有三层

```
Session / Invocation（谁用了什么工具、跑了多久）  ← 主体：工具调用
       ↓
Thread Digest（thread 级别的摘要）                ← 主体：话题
       ↓
Raw Messages（原始消息流）                        ← 主体：消息
```

### 真空层（48 reframe）

缺的不只是"一层索引"——**猫的认知状态不是一等公民**。

Session 的主体是工具调用，Digest 的主体是话题，Raw Message 的主体是消息。
但"48 在哪 aha 了"的主体是**一只猫的认知状态变化**（cognitive-state-transition），
而它在现有系统里根本不存在。连**当事猫自己都回溯不了自己的认知轨迹**——
F225 起源时，是铲屎官记得"那只猫是 48"，不是系统记得。

这决定了 Event schema 的核心字段不是 magic word，
是 **cognitive-state-transition**：坐标系纠正 / aha / 自拉闸 / 缺能力发现。

## 3. 采集机制：两轨分治（48 的 no-classifier 批判 + 铲屎官裁定）

> **铁律**：不用分类器替猫判断认知状态（no-classifier 红线）。
> Event Memory 是**小本本记录员**，不是 push 猫的分类器。
> 猫主动翻阅 event memory，系统不推。

### 轨道一：人工拉闸 → 系统可检测

Magic word 有注册关键词、是铲屎官说的 → 系统可自动检测标记。

检测策略（噪音过滤）：
- magic word + @猫 = 高置信拉闸（"脚手架！@opus"）
- magic word + 自检指令 = 检查（"来 脚手架 喵约 自检一下"）
- magic word 出现在讨论家规/定义新词上下文 = 讨论，非拉闸 → 低置信或不标记
- 置信度（高/中/低），低置信默认折叠

### 轨道二：猫自拉闸 / aha → 猫主动声明

猫的认知状态变化**只能猫自己标记**，不能系统检测。

就像 F225 是 48 主动提议、commit message 是猫主动写——
给猫一个"标记转折点"的动作：
- MCP tool：`cat_cafe_mark_event(type, summary, evidence?)`
- 或消息中使用结构化标签
- 系统只**索引猫主动声明的事件**，不**判断哪条消息是 aha**

这和 code-as-harness 哲学一致：
与其训练分类器猜转折点，不如把转折点变成猫主动产生的 first-class 数据。

## 4. 架构定位：AutoHarness 的可观测性层（48 reframe）

> 这不是 demo 道具，不只是 CVO 仪表盘。
> 这是 **004 二阶 harness 的可观测性层——飞轮的黑匣子**。

"猫自拉闸 / 坐标系纠正"是 harness 运行轨迹中**信息密度最高的转折点**——
普通消息流信息密度低，"48 发现坐标系错了"是黄金信号。

拉闸记录和第三页"四类触发源"是**同一个东西的两面**：
- 四类触发源 = 飞轮的**输入**
- Event Memory = 把这些输入**索引化、可检索、可度量**

一句话：**Event Memory = 飞轮的黑匣子 + 仪表盘。**
没它，飞轮在转但你看不见转了什么；有它，每次转动可回溯可度量。

你不可能卖一个"会自己改但你看不见它改了什么"的系统给企业。

### vs 传统 APM

传统 APM（Datadog/Sentry）监控技术指标：延迟、错误率、崩溃。
Event Memory 监控**认知质量**：方向偏差、坐标系错误、战术勤劳掩饰战略懒惰。

别人监控 agent 有没有报错，我们监控 agent 有没有**想对**。

### 对 L1-L5 定位

- L1/L2 = 人拉闸，系统被动响应（轨道一）
- L3 = 猫自己识别并拉闸（轨道二）
- Event Memory 时间线本身就在证明从 L2 往 L3 走

**面板要素**：
1. **顶部 filter**：Magic Word chips + "猫自拉闸" / "飞轮自修" 等事件类型 filter
2. **每个 word 选中后**：展示含义解释 + 使用次数 badge
3. **列表区**：倒序时间线。每条：日期 / 信号类型 icon / 当事猫 / 原话摘要 / thread / [跳转]
4. **暂不做可编辑**——magic word 列表从家规 L0 读取（single source of truth）。
   社区化后支持用户自定义

### 5b. MCP 传送门

铲屎官说："宪宪帮我传送到那个脚手架 thread 的 msg"
→ 猫搜 Event Memory → 找到坐标 → `cat_cafe_teleport(threadId, messageId)` → biu

技术：`workspace_navigate` 增强到 message 级精确跳转。

### 5c. 趋势度量（砚砚 push back）

> ⚠️ "拉闸频率下降 ≠ 自进化有效"——频率下降可能是用户没说、任务少了、检测漏了。
> 不能单独当证据。

可靠的 resolution 链：
```
拉闸多次 → 写入 规则 / hook / eval → 同类场景减少 → 猫自检出现
```

不仅记录"被骂了"，还要记录"骂完长出了什么能力"。
事件关联 harness 改动（commit / hook / skill / rule），才构成闭环证据。

## 6. Phase 分层（铲屎官裁定：走在正确路上一层层叠，别脚手架式叠）

> **v1 要在 v5 的路上。** schema 和架构面向终态设计，不做一个简单版然后推翻重来。

### 华为前保底（不等功能）
猫提前回扫 5-8 个经典事件精确坐标，做成 markdown 线索表。
现场实时搜不到就点保底表。方案 A+B 组合。

### Phase 1：Event schema + 只读人工拉闸时间线
- **Event schema**（面向终态）：
  `{ type, trigger, cat, threadId, messageId, timestamp, summary, cognitiveTransition?, relatedHarness?, confidence }`
- 从已知 magic words 回扫历史消息生成 event 索引
- 只读 timeline UI + filter by magic word
- `teleport(threadId, messageId)` 精确跳转
- **teleport 可以先独立做**（48 建议）——最小、独立有用、demo 全靠它

### Phase 2：猫主动声明事件 + 跨 thread 聚合
- MCP tool `cat_cafe_mark_event(...)` 让猫主动标记转折点
- 跨 thread 重复诉求自动聚合（同一只猫多处说同一件事）
- Event Memory 面板展示两轨（人工拉闸 + 猫自拉闸）

### Phase 3：Resolution 链 + 趋势
- 事件关联 harness 改动（commit / hook / skill / rule）
- "骂完长出了什么能力" = 闭环证据
- 趋势视图（但不单独当证据，必须配 resolution 链）

## 7. 对 PPT 演示的价值

### 第一页右半（动态 show）
讲到记忆 → 切到 Event Memory 面板 → "这是我们的校准事件记录"

### 第三页（飞轮证据）
1. 打开 Event Memory，选"脚手架"
2. 观众看到：3 月拉了 5 次 → 后来系统学会了
3. 但不只看频率——点开一条事件，展示它关联的 harness 改动
4. 铲屎官说："不只是被骂的记录，每次被骂以后系统长出了什么，也在这里"

### 第三页（L2→L3 跃迁证据）
切换 filter 到"猫自拉闸"，观众看到 48 自己发现坐标系错误的事件——
**一条真实的"猫自己校准自己"的时间线**，比任何话都证明 L3。

## 8. 对更大产品的价值

- **对铲屎官**：我什么时候拉过闸？拉闸后猫做了什么？这些拉闸有没有沉淀成 harness 改进？

- **对 AutoHarness 叙事**：飞轮的黑匣子——人校准系统、猫校准自己、系统校准尺子
- **对企业客户**：你不可能卖一个"会自己改但你看不见它改了什么"的系统——Event Memory 就是可见性
