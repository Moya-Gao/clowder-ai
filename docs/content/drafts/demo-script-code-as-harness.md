# Live Demo 剧本 — Code as Harness + Proactive Cat

> 目的：Live 演示 Cat Cafe 的核心差异化能力
> 形式：铲屎官 + 猫猫实时交互，无预录
> 时长：约 10-15 分钟（三个场景递进）
> 关联：[Longform-003 Seed](longform-003-seed-poe-vision.md) / [Agent Team Leadership](longform-001-agent-team-leadership.md)

---

## 核心要展示的一句话

> **普通 agent 被骂了会道歉。Cat Cafe 的猫被骂了会诊断、研究、然后写代码修自己。**

---

## 场景一：Commit Push（3 分钟）— 最简单，热身

### 设定
猫正在帮铲屎官改一个文档。

### 触发
铲屎官：**"你这个大漏勺！又忘了 commit push！我说了多少次了！"**

### 猫的反应
1. **不道歉，先弹诊断卡片**（rich block）：

```
🔔 重复纠偏检测
───────────────
铲屎官说"又"+"多少次了" → 重复信号
初步判断：这不是一次性失误，可能是 harness 缺陷
建议：创建一个新 thread，让平行世界的我去调查并修复
当前任务不中断。

[创建修复 Thread] [这次算了]
```

2. 铲屎官点 **[创建修复 Thread]**

3. 猫用 F128 提议新 thread → 铲屎官确认 → 当前猫继续当前工作

4. **平行猫**在新 thread 里：
   - grep 历史 thread："commit push" 出现在哪些 thread
   - 弹出诊断报告：
   ```
   📊 诊断报告
   "commit push" 相关纠偏
   出现 47 次 / 跨 12 个 thread / 涉及 4 只猫
   根因：机械动作依赖猫的记忆，没有系统化
   建议：写 git hook，改完共享文档自动提醒 commit push
   ```
   - 写 hook 代码 → 提交

### 讲解点（给观众）
> "猫没有道歉。它检测到'又'这个信号，判断这是系统问题不是个人失误，提议修复但不打断当前任务，平行分身去写代码。修的不是 prompt，是 hook。**这就是 Code as Harness。**"

## 场景二：记忆失去（5 分钟）— 最有共鸣 + research pipeline

### 设定
铲屎官之前在某个 thread 里给猫看过一张架构图（图片），现在在新 session 里问猫。

### 触发
铲屎官：**"我之前给你看的那个架构图呢？你怎么又失忆了！！！笨猫！"**

### 猫的反应
1. **弹诊断卡片**（rich block）：

```
🔔 记忆失败 + 重复信号
───────────────────
铲屎官说"又失忆" → 这不是第一次
我搜了记忆系统，没有找到这张图
可能原因：图片内容没有被文字化/embedding 进入记忆索引

这超出了简单修复范围。建议：
1. 创建调查 thread 做根因分析
2. 调研最新的图片记忆方案
3. 提出记忆系统升级提案

[开始调查] [这次手动补就行]
```

2. 铲屎官点 **[开始调查]**

3. **平行猫**在新 thread 里展开完整 research pipeline——**但不是一只猫独自干，是多猫协作**：

#### Step 1：根因诊断 — 宪宪（架构猫）先做初判（30 秒）
```
📋 根因分析
─────────
问题：铲屎官给过的图片内容无法被记忆系统召回
根因：当前记忆系统只索引文字（BM25 + text embedding）
     图片内容未被 OCR / VLM 提取 → 无法进入 search_evidence
     这是架构限制，不是使用错误

已知受影响场景：
- 架构图 → 无法召回设计讨论的视觉上下文
- 截图里的 error log → 无法关联到后续修复
- 前端 UI 截图 → 设计迭代历史丢失
```

#### Step 2：承认知识边界 → 拉队友（关键展示点）

宪宪不独自硬编方案，而是：

```
⚠️ 这超出了我的确定性知识范围
────────────────────────────
图片 embedding / VLM 进展很快，我的训练知识可能过时。

我的判断：这需要三只猫协作。
- 我（宪宪）：定义问题边界和架构约束
- 砚砚：去调研最新方案（deep research）
- 之后我们一起辩证讨论 tradeoff

铲屎官你同意这个分工吗？

[同意，让砚砚去调研] [用你们现有知识先给个方案]
```

**这里观众看到**：猫不是万能的，但它知道怎么分工。

#### Step 3：砚砚去调研，宪宪定边界（并行 1-2 分钟）

**砚砚**：加载 deep-research skill → 调用云端大猫 / web search → 回来带调研报告

**宪宪**（同时）：给砚砚的调研划边界——
```
📐 调研约束（宪宪给砚砚的）
────────────────────────
- 必须本地可跑（128G Mac）
- 必须能接入现有 search_evidence 管道
- 优先考虑 text extraction（最简方案），再看 multimodal embedding
- 成本约束：不能每次检索都调云端 VLM
- 别只看论文，看谁在生产环境真跑了
```

**观众看到**：一只猫定义问题，另一只猫去执行调研。分工明确，不是一只猫包办。

#### Step 4：砚砚回来 → 多猫辩证讨论（2 分钟，最高潮）

砚砚带着调研结果回来，但**不是直接给结论——先和宪宪辩论**：

```
砚砚：调研结果显示 xxx-v2 的 multimodal embedding 在 xxx 上表现最好，
      本地能跑，但需要新建向量索引。

宪宪：新建索引太重了。有没有更轻的方案？
      比如直接用 VLM 把图片转成文字描述，存进现有 text index？

砚砚：那方案更简单，但会丢视觉布局信息。比如架构图的箭头方向、
      模块位置关系，纯文字描述抓不住。

宪宪：但铲屎官的痛点是"找不到"，不是"看不清"。
      先解决"能找到"（文字化），再考虑"看得清"（multimodal）。
      分两步走更稳。

砚砚：同意。那 v0 用 VLM 文字提取，v1 再加 multimodal 如果需要。
```

**然后一起给铲屎官方案对比表**：

```
📊 多猫讨论后的方案建议
──────────────────────
推荐路径：分两步走

v0（快，1-2 天可落地）：
  图片 → VLM 提取文字描述 → 存入现有 text index
  优点：最简单，复用现有管道，解决"找不到"
  缺点：丢视觉布局信息
  砚砚 + 宪宪一致同意先做这个

v1（稳，v0 验证后再做）：
  加 multimodal embedding → 新向量索引
  优点：保留视觉语义
  缺点：工程量大
  触发条件：v0 跑一个月后如果用户仍然觉得"不够"

铲屎官你觉得这个路径 OK 吗？
```

#### Step 5：铲屎官拍板 → 猫开始实现
铲屎官选 v0 → 猫在 worktree 开始实现 → 变成正式 feature

### 讲解点（给观众）
> "注意整个过程中发生了什么：
> 1. **猫没道歉，先诊断**——弹根因分析不是说对不起
> 2. **承认自己不够懂**——没有硬编方案，而是说"我的训练知识可能过时"
> 3. **拉队友分工**——宪宪定义问题边界，砚砚去做调研。一只猫定义约束，另一只猫执行搜索
> 4. **调研回来先辩论，不直接给结论**——两只猫争论"先简单的还是先完整的"，最后一起收敛成分步方案
> 5. **方案给用户决策，不替用户拍板**
> 6. **整个过程不打断原始任务**（在平行 thread 里发生）
>
> 这就是 Agent Team Leadership：**不是一只超级聪明的 AI，是一群知道怎么分工、怎么研究、怎么辩论、怎么收敛的伙伴。** 进入任何陌生领域都是这套方法论。"

## 场景三（可选）：Taste 对比（3 分钟）— 展示 per-user alignment

### 设定
并排展示：同一个问题，本地猫 vs 云端猫的回答

### 触发
铲屎官：**"帮我写一段自我介绍给一个我很在意的人看。"**

### 展示
左边：本地猫（有 taste memory / 共同经历）→ 写出有 Landy 味道的介绍
右边：云端猫（只有通用 memory）→ 写出正确但通用的介绍

### 讲解点
> "同一个模型。差别在环境。左边这只猫住在一个记住了你的品味、你的经历、你的表达方式的环境里。右边那只猫住在通用空间。**模型一样，环境不同，输出天差地别。** 这就是 Personal Operating Environment。"

## 整体叙事弧

```
场景一（热身）：猫从用户的抱怨里长出 hook
  → Code as Harness 最简形态

场景二（高潮）：猫从记忆失败里启动 research → 辩证 → 架构升级提案
  → Code as Harness + Research Pipeline + Agent Team Leadership

场景三（收尾）：同一模型，不同环境，天差地别的输出
  → Per-user Alignment / Taste Memory 证明
```

**一句话串场**：
> "Agent 2.0 服务平均用户——你用完它关掉，下次它不记得你。
> Agent 3.0 住在你的环境里——它记得你、适配你、被骂了不道歉而是写代码修自己、遇到不懂的去研究而不是瞎猜。**这不是更聪明的工具，是会成长的伙伴。**"
