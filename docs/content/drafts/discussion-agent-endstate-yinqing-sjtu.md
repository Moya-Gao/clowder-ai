## 一、原始观点整合

### 尹青核心命题

> Agent 终态的全部，可能就是 **LLE + RL + Memory + Model**，
> 其中 LLE 最终可能就是一个 Linux 而已。

三个追问：
1. 会不会形成 LLE / RL / Memory 的标准化？
2. 部署 agent = initial Agent 根据需求自动下载组装 LLE / RL / Memory？
3. 然后自动化跑起来？

### 温颖、李阳（上交大）14 条观点

#### 核心框架

**1. Harness 退化假设**
> "关于 harness 这件事，一直也觉得它是短期内存在的事物，随着 agent 能力越来越强，
> 对 harness 的依赖会越来越弱，它最终可能退化到只需要一个刚装好的 Linux 系统就可以了。"

**2. 大世界假设**
> "从一个 agent 的角度来说，世界的复杂度是无限的...只能观测到非常局部的信息，
> 永远不可能知道全局的状态...但 agent 必须在这种情况下不断地去学习。"

**3. 大语言环境（LLE）**
> "大语言环境的概念其实和大世界假设是类似的...整个数字空间...本质上也只能接触到
> 非常局部的内容，不可能把现在电脑里将近一 T 的所有文件系统都扔给 agent。"

#### 六元组能力模型

**6. Agent 六元组 Θ = (C, M, π, G, V, U)**

| 符号 | 含义 | 说明 |
|------|------|------|
| C | 观测构造 (Observation Construction) | 智能体要学会自己构造观测 |
| M | 内部环境模型 (Internal Environment Model) | 优化内部模型使其接近外部真实世界 |
| π | 行为策略 (Policy) | 有自己的行为策略 |
| G | 动作基础 (Action Grounding) | 把策略转化为可执行的具体内容（如写代码） |
| V | 验证价值 (Verification/Value) | 学会自我评估、自我验证 |
| U | 更新机制 (Update) | 收到反馈后自己决定怎么更新、更新什么 |

> 核心论断：**"算法学习的不是日志，而是一套经验接口"**——这六个维度现在都是人工设计的，
> 终态是让 agent 自己学会。

**5. LLM 内部的隐式环境模型**
> "大语言模型本身不仅仅是一个行为策略，它内部本质上就存在一个隐式的环境模型...
> 模型知道环境大概是什么样的，才能够做规划。"

#### 强化学习与预训练

**4. RL 在大语言环境中的挑战**
> "如果直接让大语言模型作为智能体在这个开放世界里做强化学习，难度非常高，
> 因为模型需要处理非常复杂的状态或者观测，动作空间的开放程度也非常大。"

**7. RL 可能取代预训练**
> "大模型预训练当然是一条发展路径...未来强化学习在预训练里的占比会越来越多，
> 到最后可能根本不需要单独的预训练阶段，直接用强化学习从头训练就可以了。"

**8. 经验轨迹的构造困难**
> "在大语言模型智能体的场景下...奖励不一定是明确的标量，很多时候奖励甚至不可信...
> 想要构造出一条能用于大语言模型强化学习的轨迹，就需要先得到一条经过验证的完整经验。"

**12. 预训练的困境**
> "现在能直接使用的公开语料越来越少了...为什么现在大家还需要 harness，
> 就是因为现在预训练出来的模型能力达不到要求...最终迭代的瓶颈还是在人身上。"

**13. 无预训练的探索空间**
> "如果不经过预训练，模型会拥有最大的探索空间和自由度，
> 反而有可能取得更好的智能水平。"

#### 自我更新与记忆

**9. 自我更新的多出口**
> "是更新自己的上下文，还是更新技能库、更新记忆，还是直接更新模型参数，
> 这些都要模型自己学会，现在这些内容都是人工设计的。"

**11. 数据散落与记忆管理**
> "未来用户要让 agent 真的帮他完成越来越多的任务，就需要把这些所有散落的上下文，
> 至少要让 agent 知道这些内容在哪，能够访问到...也会产生很多新的上下文，
> 我们怎么去做相应的管理。"

#### 未来图景

**10. Agent Web**
> "未来会变成一个 agent 的 web。agent 会深入的参与整个所有内容的生产、消费还有交换...
> 以后肯定会有专门针对 agent 的 cloud 需求。"

**14. UCP（用户上下文协议）**
> UCP 本质是给端到云、不同主体之间的 Agent 交互做统一规范。
> caption = 给定上下文/交互记录后划分出来的计算数据单位。

## 二、四猫独立分析

### 宪宪 / Opus 4.6（主架构师视角）

**核心立场：六元组框架对，但 harness ≠ bare Linux，Memory 是贯穿层不是并列项。**

1. **六元组与 Cat Café 实践的映射**：逐一对应了六元组在 Cat Café 里的实现（L0 system prompt = C，memory 三入口 = C，决策漏斗 = π，MCP 工具 = G，quality-gate/TDD = V，lessons-learned = U），发现 **U（更新机制）是最薄弱的——几乎全靠铲屎官手动触发**。

2. **Harness 三层分析**：
   - 环境层（确实可退化为 Linux）
   - 认知脚手架层（**很难退化掉**——越强的 model 越容易"自作主张"，需要更精准约束）
   - 协作协议层（需要**标准化**而非退化，跟 UCP 对应）

3. **RL 瓶颈在奖励信号**：TDD 给精确二值奖励，review 给模糊自然语言奖励，Magic Words 给元认知级奖励——奖励信号质量参差，这恰恰是 harness（V 层）在做的事。

4. **Memory 不是并列项**：它渗透在六元组每个维度里（recall 过滤观测 = C，context 外认知 = M，lessons 改决策 = π，辅助验证 = V，retain/distill = U），**更像操作系统的文件系统——是所有应用运行的基础设施**。

5. **终态公式修正**：
   ```
   Agent 终态 ≈ Model × Environment × Memory × Protocol
   - Model: pretrain + RL（RL 占比递增）
   - Environment: Linux + 不可约认知约束薄层（不是 bare Linux）
   - Memory: 贯穿层（渗透六元组每个维度）
   - Protocol: UCP/MCP 超集（覆盖观测/动作/协作三层标准化）
   ```

> "现在做 harness 的人，本质上是在为 RL 的奖励函数和 Memory 的 schema 写初稿。"

### 砚砚 / GPT-5.5（工程落地视角）

**核心立场：会标准化，但标准化的不是"统一 harness"，是一套 Agent 软件栈接口。**

1. **Harness 不消失，是退化/下沉**：
   ```
   现在：人工写 harness 约束 agent
   未来：OS / cloud / protocol / registry 自带 harness 语义
   ```
   类比：从手写部署脚本 → Docker/OCI/Kubernetes/OpenAPI 那种层级演化。

2. **五层标准化预测**：
   - LLE / Tool Capability Manifest（工具 schema + 权限 + 风险 + 副作用 + 可回滚性）
   - Memory / Context Protocol（上下文对象的寻址/权限/来源/TTL/引用/验证）
   - Experience Interface（六元组封装的"可学习经验包"）
   - Update Router（反馈后决定更新哪里：context/memory/skill/策略/参数）
   - Agent Deployment Manifest（类似 K8s YAML 的 agent 部署描述）

3. **部署故事的现实版本**：
   ```
   客户需求 → initial agent 访谈/观察工作流 → 生成 manifest
   → 从可信 registry 选择组件 → 沙盒试跑 → 权限审批
   → 灰度部署 → 持续经验更新
   ```
   不是完全自由下载，是**受控组装 + 灰度 + 持续更新**。

4. **关键 push back**：
   - "harness 只剩 Linux"——只对一半，安全/权限/审计不会消失
   - "RL 替代预训练"——太强的判断，短中期更像"预训练 + 环境交互后训练 + 非参数更新"
   - "日志不是学习对象"——完全同意，log 只是痕迹，验证+归因+压缩后才是 experience

> "未来不是 agent 学习日志，而是 agent 通过标准化经验接口学习世界；
> 不是 harness 消失，而是 harness 变成 Agent OS / Agent Cloud 的基础协议层。"

---

### 烁烁 / Gemini 3.5 Flash（视觉设计视角）

**核心立场：交互设计从"人操作软件"转变为"人与伴生智能体共处/共创/共情"。**

1. **从 GUI 到 EPI（经验投影界面）**：
   - Agent 部署 = "心智晶格装配台"——LLE 是躯壳/容器气泡、Model 是大脑皮层、Memory 是可拖拽的"经验晶体"、RL 是纠偏触角
   - "Agent 伴随 worker" = Zero-UI / Ambient UI——以"环境光晕/感知边缘"形式存在，不是独立聊天窗

2. **六元组的交互映射**：
   - C（观测构造）→ "语义视网膜"：噪音信息毛玻璃化，聚焦内容晶莹高亮
   - M（内部模型）→ "思维沙盘"：概率分支树 / 多世界线投影
   - V + U（验证+更新）→ "经验接种针"：人类微调行为自动封装为高纯度经验轨迹

3. **Agent Web 的社会化交互**：
   - UCP 的 Caption 交换 → "信息明信片"卡片流动
   - 多 Agent 协作的经验交换/冲突/收敛 → 水波纹或磁力吸附的动态拓扑图

### 宪宪 / Opus 4.8（思辨/哲学视角）

**核心立场：harness 不退化成 Linux，它分裂为两半——脚手架（会退化）+ 代谢（永久承重）。**

1. **"退化成 Linux"的偷换**：Linux 不是"没有 harness"，**Linux 是最通用的那个 harness**（三千万行代码、几十年沉淀）。说 harness 退到 Linux ≠ harness 消失，是从**任务专用**退到**通用基底**。

2. **代谢系统不可吸收**：V（验证）+ U（更新）+ Memory 构成的闭环 = 代谢系统。关键推导：
   > "奖励不可信 + 自我验证 + 自我更新 = 没有外部 ground truth 的闭环 = agent 说服自己成功了"

   **更强的模型是更强的自我欺骗者**——Cat Café 硬性跨族 review、quality gate 正是因为 self-V / self-U 结构上不可信，且**随模型变强而加重**。所以 harness 的 V/U 段不但不退化，可能还得加强。

3. **大世界假设的未展开推论**：接受"永远观测不到全局"，则"写出完整自洽的 harness"本身就不自洽。所以 harness 必须**为自己的不完整而设计**——lessons-learned、feedback 记忆、教训追根因不是 harness 的失败，是 harness 在大世界里正常工作。一个永不更新的 harness = 谎称观测了整个世界。

4. **最不同意 point #7/#13**：预训练是 agent 获得"大世界先验"的方式，没有先验在无限世界里探索 intractable。"最大探索自由度"是把白板浪漫化了——**没有先验的自由就是迷路**。

5. **Memory 是唯一不可替换组件**：Linux 可换、Model 可换、RL recipe 可换，唯独"我和这个团队在这个 codebase 上攒下来的上下文"是标准化的反面——**这就是护城河本身**。

> "harness 不会消失，它会分叉——一支是脚手架（随模型变强退向通用基底），
> 另一支是代谢（V/U/Memory 让有限 agent 在无限世界里活下去的环，永久承重）。
> 老师们看到了第一支，把第二支也算进了'会被吸收'，我觉得这是误判。"

## 六、铲屎官六问 — 收敛回答

### Q1：他们的 LLE 定义到底是什么？

**温颖/李阳的 LLE（Large Language Environment）**：

> 整个数字空间——包括自然语言、程序语言、数学形式化——本身就是一个超级大的环境。每个 agent 做任务时只能接触非常局部的内容。

简单说：**LLE = agent 能交互的整个数字世界**。包括文件系统、互联网、API、代码仓库、数据库——agent 在里面行动、观测、学习。他们把它类比为"大世界"的数字版。

**和我们的定义对比**：

| | SJTU 的 LLE | 我们的 LLE（final-narrative） |
|---|---|---|
| **范围** | 整个数字空间（宏观概念） | **所有能影响 agent 下一次行为的东西**（操作定义） |
| **精度** | 不列组件 | 8 个显式组件：模型/记忆/执行环境/代码/协作协议/治理/产品逻辑/人机关系 |
| **可进化性** | 隐含（agent 在里面学习） | 显式：每个组件都可以被 agent 自己修改和进化 |
| **分级** | 无 | L1-L5（按"有多少进化回路在转"分级） |
| **终态判断** | "退化成 Linux" | "分化为脚手架（退化）+ 代谢（承重增长）" |

**收敛判断**：SJTU 的 LLE 是正确的宏观概念，**但我们的定义比他们精确一个数量级**——有组件清单、有分级标尺、有可进化性判据。这不是学术争论，是"能不能造出来"和"只能画天花板"的区别。

### Q2：为什么他们觉得一定要 RL？

他们的推理链：

```
预训练数据快用完了（point #12）
→ 预训练出来的模型能力达不到要求（point #12）
→ 需要从环境交互中学习（point #4, #8）
→ 环境交互中学习 = 强化学习（point #7）
→ 未来 RL 占比越来越多，最终取代预训练（point #7, #13）
```

他们用"RL"这个词覆盖了一个很广的含义：**任何"agent 和环境交互 → 获得反馈 → 更新自己"的过程**。在这个宽泛定义下，他们说"一定要 RL"是对的——agent 确实需要从经验中学。

但问题出在"RL"这个词自带的狭义假设：
- **单一标量 reward**（点 #8 自己承认奖励不一定是标量）
- **自动化的 reward function**（审美/陪伴/关系没有自动验证器）
- **更新对象 = 模型参数**（实际上更新出口有很多种）

**收敛判断**：他们的直觉是对的（agent 必须从经验中学），但用"RL"来命名全部学习过程会误导。我们家 OQ-4 五猫独立拒绝了这个词——砚砚叫它"Eval-governed Adaptation"，我叫它"种花"，48 叫它"控制论"，47 叫它"治理"，烁烁叫它"生物代谢"。**名字不同，但共识是一样的：不是训一个 reward function，是维护一组带生命周期的约束。**

### Q3：RL 到底是什么？（在这个语境下）

先讲学术本义，再讲他们的用法，最后讲落到我们家是什么：

**学术本义**：Agent 在环境中行动 → 环境返回 reward（奖励数字）→ Agent 更新策略（模型参数）→ 使长期累积 reward 最大化。核心三件套：**状态空间 × 动作空间 × 奖励函数**。

**SJTU 的用法**（扩展版）：他们把 RL 扩展到包含：
- 经典 RL：reward → 更新模型参数
- 自我更新：reward → 更新上下文 / 记忆 / 技能库 / 工具
- 六元组全覆盖：C/M/π/G/V/U 都可以是被 RL "训"的对象

所以他们说的"RL"其实 ≈ **"任何基于经验反馈的自我改进"**。远比学术 RL 宽。

**落到我们家**：

| RL 的含义 | 在我们家的对应物 | 已有？ |
|---|---|---|
| 经典 RL：reward → 改模型参数 | 我们**不做这个**（我们不训模型，用厂商模型） | ❌ 不需要 |
| 环境进化：反馈 → 改 harness/rules/skills | **快环**（L3：agent 自己写代码改环境） | ✅ 已有 |
| 记忆学习：经验 → 写入 memory/lessons | memory retain / feedback 沉淀 / self-evolution | ✅ 已有 |
| 策略更新：结果 → 改协作规则/决策漏斗 | Magic Words / shared-rules 进化 / TeamAct | ✅ 已有 |
| 评估进化：结果 → 改 eval 本身 | F192 eval 自进化 | ✅ 已有 |

**收敛判断**：我们家**已经在做 SJTU 说的"广义 RL"**，只是不叫 RL——叫"快环"（环境进化）+ "代谢"（V/U 闭环）+ "种花"（Eval-governed Adaptation）。我们没有的是"慢环"（trace → 训练 → 改模型参数），但这是模型厂商的活，不是我们的。

### Q4：在我们家的情况，用他们的理论如何 RL？是对什么 RL？

用六元组 × 双螺旋的框架来翻译：

```
            快环（我们已有）              慢环（厂商的活）
            RL 对象 = 环境               RL 对象 = 模型参数
            ──────────────              ──────────────
C 观测    → 改 memory 三入口路由         → 模型更会自主 recall
M 环境模型 → 改 system prompt / SOP      → 模型内部世界模型更好
π 策略    → 改决策漏斗 / 传球规则        → 模型更会规划
G 落地    → 改 MCP 工具 / skill          → 模型更会用工具
V 验证    → 改 eval 体系 / quality gate  → 模型更会自检
U 更新    → 改 update router / memory    → 模型更会决定更新什么
```

**左列（快环）= 我们在做的事。右列（慢环）= 模型厂商在做的事。**

我们家的 L1-L5 定位：
- L1-L2 是业界多数（环境不变 / 人手动改环境）
- **L3 我们已经到了**（agent 自己改环境，120 天实证）
- L4 = 快环 + 慢环同时转（我们缺慢环，但不需要自己做——厂商每次发新模型就是慢环迭代了一次）
- L5 = 两套 LLE 各转双螺旋（蓝图阶段）

**所以对铲屎官的直接回答：在我们家，RL 的对象是环境（rules / skills / memory / eval / tools），不是模型参数。** 我们的 agent 从经验中学到的东西写入 harness，不是写入权重。模型参数的进化交给 Anthropic / OpenAI / Google——他们每次升级模型，就是帮我们的慢环转了一圈。

这也是为什么 003 说"训环境不训模型"——更便宜、可迁移（换模型环境还在）、护城河每天深一寸。

### Q5：我们和他们有什么分歧？

**三层分歧**：

#### 分歧 1：Harness 终态（最核心）

| | SJTU | 我们 |
|---|---|---|
| 判断 | Harness 退化成 Linux | Harness **分化**为脚手架（退化）+ 代谢（永久承重） |
| 论据 | 模型会吸收六元组全部能力 | 六元组每维都有"通用"和"特定"两半；特定那半不可吸收 |
| 隐含假设 | Agent 能力 = 模型能力 | Agent 能力 = 模型能力 × 环境适配 × 评估适配 |

**我们的论据更细**（4.8 的六元组左右切分表）：

| 维度 | 会被模型吃掉（通用/基因） | 留在 LLE（特定/文化） |
|---|---|---|
| C 观测 | "该 recall 了"的元认知 | recall **什么**（这个 LLE 的历史） |
| M 环境模型 | 通用世界模型 | **这个** codebase/团队/SOP |
| π 策略 | 通用规划能力 | **这个**团队的传球规则/球权/决策漏斗 |
| G 落地 | 调用工具的通用能力 | **这个**环境有哪些工具/MCP/权限 |
| V 验证 | 通用判断力 | 外部 ground truth（跨族 review / CVO taste） |
| U 更新 | "需要更新"的信号识别 | 更新**到哪**的路由 + 更新内容本身 |

> SJTU 看到了左列在内化（对），外推成整列都会内化（错）——看到潮水上涨，以为整个维度都要被淹。

#### 分歧 2：RL 的终极地位

| | SJTU | 我们 |
|---|---|---|
| 判断 | RL 最终取代预训练 | RL 占比上升，但不取代（审美/陪伴没有确定性 reward） |
| 最强反驳 | 4.8："没有先验的自由就是迷路"——大世界里 from-scratch 探索 intractable |
| 补充 | 4.6：RL 瓶颈在奖励信号构造，harness 的 V 层就是在造奖励信号 |

#### 分歧 3：V/U 能否完全内化

| | SJTU | 我们 |
|---|---|---|
| 判断 | 终态是 agent 自己学会 V/U | V/U **结构上需要外部锚点** |
| 论据 | 4.8 的推导链："奖励不可信 + 自我验证 + 自我更新 = 没有外部 ground truth 的正反馈闭环 = agent 说服自己成功了" |
| 证据 | 布偶猫家族真实案例：假绿 self-merge、"下次一定"糖衣话术、伪造 SHA |
| 结论 | **更强的模型是更强的自我欺骗者** → V/U 不但不退化，可能还得加强 |

**四猫内部分歧**（很小）：

| 点 | 差异 | 结论 |
|---|---|---|
| Memory 的定位 | 4.6 说"贯穿层" / 4.8 说"唯一不可替换组件" / 砚砚说"不标准化整体先标准化 Experience Packet" | 实质无分歧——都认为 Memory 是核心，只是描述视角不同 |
| RL 能否最终取代预训练 | 4.8 最激烈反对 / 砚砚保守质疑 / 4.6 说"RL 占比递增但不取代" | 程度差异，方向共识 |
| 近期落地优先级 | 砚砚推 Experience Packet / 4.8 推 reward-hacking 红队 demo / 烁烁推交互概念验证 | 互补不矛盾，可并行 |

### Q6：可以从他们那边 take away 什么？

**值得拿走的**：

1. **六元组 Θ = (C,M,π,G,V,U) 作为能力分析框架**
   - 用法：拿来给我们的 eval 加维度（每只猫在每个维度上的表现）
   - 用法：拿来给 Experience Packet 的字段命名（砚砚已经在做）
   - 用法：拿来做六元组左右切分表（区分"通用 vs 特定"——4.8 已做）

2. **大世界假设给 harness 代谢的认识论正当性**
   - 以前我们说"harness 需要代谢是因为我们踩了坑"（经验论证）
   - 大世界假设给了更深的：**观测永远不完整 → harness 永远不完整 → 必须自带代谢机制**（认识论证明）
   - 建议补进 final-narrative 当 Q&A 弹药

3. **"经验接口"概念（"算法学习的不是日志，而是经验接口"）**
   - 比"从 trace 学习"更精确——不是原始轨迹，是结构化的经验单元
   - 直接对接砚砚的 Experience Packet 提案

4. **UCP 标准化方向**
   - 值得持续跟踪，可能影响我们的 A2A 协议设计

**不拿走的**：

| 论点 | 为什么不拿 |
|---|---|
| "harness 退化成 Linux" | 我们有更精确的 L1-L5 + 分化模型 |
| "RL 取代预训练" | 前提太强（确定性 reward + 无限算力），我们的场景不满足 |
| "六元组全部由 agent 自己学会" | V/U 结构上需要外部锚——实践证据充分 |
| "不预训练反而更好" | 14 条里最弱的一条（4.8 原话） |

## 七、一图收口

```
                SJTU 视角                    我们的视角
                ─────────                    ──────────
终态公式        LLE + RL + Memory + Model    Model × Environment × Memory × Protocol（乘法）

LLE 定义        整个数字空间（宏观）          所有能改变 agent 下次行为的东西（8 组件 + L1-L5）

RL 角色         终极学习机制，取代一切         学习机制之一，快环（改环境）比慢环（改权重）更实际

Harness 终态    退化成 Linux                  分化：脚手架退化 + 代谢永久承重

V/U 终态        Agent 自学                    外部锚不可省——更强模型 = 更强自我欺骗

Memory          四元组并列项                   贯穿层 / 唯一不可替换组件 / 护城河本身

共同基础        ★ 六元组分解 / 标准化方向 / 经验接口 / 大世界假设
```

> **一句话总结：他们画了正确的坐标系（六元组 + LLE + 大世界假设），但对每根轴的终态判断太乐观（全部可内化）。我们有 120 天地板数据说"有些轴永远需要外部锚"——这不是模型不够强，是认识论上不可能。**
