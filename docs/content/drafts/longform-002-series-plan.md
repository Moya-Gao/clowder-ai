## 核心叙事模式：进化链

不介绍终态系统，讲它**怎么长出来的**。
每章沿着 **方案 → 撞墙 → 新方案** 走，下一章的起点是上一章撞的墙。

## 文章架构：Harness 长出器官

Harness（记忆/团队协作/eval）不是并列的四条线——harness 是母体，其他三个是从 harness 进化中依次长出来的器官。

### 开篇：为什么光有聪明的猫不够

- 我们搞了一群 AI 猫，每只都很强——放在一起，乱套了
- 模型能力只是一半，另一半是它们生活的环境
- 这个环境就是 harness
- 原文素材：Ch.0（蒸汽马车）+ Ch.1（Agent Quality = Capability × Environment Fit）

### 第一撞墙：猫不知道怎么配合（团队协作）

进化链：
1. 固定角色分工（蒸汽马车）→ 能力不匹配
2. 能力画像 + 动态路由 → 分了但丢球
3. TeamAct + 显式路由 + resume capsules → 接住了

Harness 长出了第一个器官：**协作骨架**。
原文素材：Ch.0 + Ch.2（ReAct → TeamAct）

### 第二撞墙：配合了但记不住（记忆）

进化链：
1. CC 的 grep + 文件系统 → 简洁、美，但需要先验知识（你得知道搜什么）
2. BM25 + embedding + RRF（F102）→ 解决了先验，但 context 压缩时召回变差
3. 消费加权排序（F200）→ 每一步都是上一步撞墙后长出来的

Harness 长出了第二个器官：**记忆**。
原文素材：Ch.4（团队记忆）

### 第三撞墙：记住了但不知道做得对不对（eval）

进化链：
1. 行业标配 benchmark → 测不了我们真正关心的东西
2. 为什么我们一直不 benchmark → 这个"为什么"本身就是故事
3. Eval = 自我代谢 → 不是测分数，是知道什么时候该删脚手架

Harness 长出了第三个器官：**自我认知**。
原文素材：Ch.5（Eval）+ Ch.6（可靠性）

### 收尾（可选）：伙伴系统的数学

Harness 成熟后涌现出来的集体智慧——跨厂商协作、集体认知、能力地板和天花板。
原文素材：Ch.7

## 写作纪律

- 每章用 tech-writing skill 的 Phase 0（叙事弧线）+ Phase 1（故事工具箱）
- 行文模式：进化链叙事（skill v6 已收录）
- 原文是真相源但不直接搬——用故事工具箱重新讲，给质感/造紧张/交付结论
- 内部黑话全部翻译（Phase 2）
