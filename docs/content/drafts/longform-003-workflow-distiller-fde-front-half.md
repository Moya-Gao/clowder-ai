# Workflow Distiller — FDE 前半段的压缩

> Companion note for [Longform-003 Seed](./longform-003-seed-poe-vision.md)。
> 后续讨论入口见 [Workflow Distiller 讨论导航](./longform-003-workflow-distiller-discussion-trail.md)。
>
> 核心补充：longform-003 现有 FDE 叙事主要讲“企业部署后，harness 从真实轨迹里自进化”。本 note 补的是更早的一层：**部署前 / 立项前，猫咖能不能把一个行业用户讲出来的混乱工作流，蒸馏成可落地的 AI-native 产线。**

## 结论

Cat Cafe 的 FDE-like 能力不只是“去客户现场后自动适配”。更锋利的说法是：

> 猫咖可以把一个行业用户的现场语言，翻译成工作流、摩擦点、自动化边界、MVP 切片、skills、QA 和验证指标。

这件事把 FDE 成本从“部署后长期陪跑”继续往前压缩到“0→1 立项发现”。

## 和 longform-003 的关系

[Longform-003 §四 bis](./longform-003-seed-poe-vision.md#四-bistoc--tob-bridge--同一架构不同尺度) 里已经有这句：

> 企业部署 AI 的最大成本不是模型，是 FDE（现场交付工程师）——派人去理解客户、定制流程、手动迭代。

原文的自动化重点是：

| FDE 手动做的 | longform-003 已写的 auto-harness 视角 |
|-------------|----------------------------------------|
| 理解客户流程 | 从部署后的真实轨迹里发现重复模式 |
| 写 prompt / skill | 从真实轨迹自动蒸馏 skill |
| 定期复盘迭代 | 信号 → patch → replay → sunset |

本 note 增补的是前半段：

| 阶段 | 传统谁做 | Workflow Distiller 压缩什么 |
|------|----------|------------------------------|
| Discovery FDE | FDE / PM / 咨询顾问访谈客户 | 从用户叙述抽出现有流程、真实成本、返工点、交付物 |
| Build FDE | FDE + 工程师做首版方案 | 生成 AI-native 产线 spec、MVP 切片、skill graph、QA / eval |
| Evolution FDE | FDE 长期陪跑迭代 | 进入 longform-003 已写的 auto-harness / trace learning |

一句话：

> longform-003 讲“环境从轨迹里学习”；Workflow Distiller 讲“猫咖先帮你制造第一条可验证轨迹”。

## 方法论

核心原则：

> 从用户工作流中寻找 AI-native 产线，不从模型能力中寻找行业场景。

很多垂直 AI 产品的路径是反的：我有图生视频、RAG、Agent、工作流编排，所以我给用户堆按钮。Workflow Distiller 应该从现场往回抽：

- 用户现在在哪里当人肉路由器？
- 哪些地方在做低价值判断？
- 哪些地方有明确输入和输出？
- 哪些地方有真实返工？
- 哪些交付物 60-70 分就能产生业务价值？
- 哪些步骤可以用 QA / oracle 降低风险？
- 哪些地方应该保留人工 checkpoint？

这不是“行业分析报告”。标准输出应该是一个立项包：

| 输出项 | 内容 |
|--------|------|
| 产品楔子 | 谁在什么场景下痛 |
| 现有流程 | 用户现在怎么做，哪里耗时，哪里返工 |
| 真实 job | 用户真正要达成的业务结果，不是表面动作 |
| 理想流程 | AI 接管哪些步骤，人保留哪些判断 |
| MVP 切片 | 第一版只做哪一个窄任务 |
| 质量阈值 | 60-70 分可交付的标准是什么 |
| 失败模式 | AI 可能怎么翻车，如何发现，如何兜底 |
| 所需 skills | 行业知识、提示词模板、QA 规则、重试策略 |
| 验证方式 | 找真实用户，用真实项目跑一遍，看是否省时、省心、能交付 |

## Case seed：室内设计 workflow 校准

初始理解是：

> 我需要把设计稿 / 室内设计方案变成视频给业主看。

后续事实校准后，这句话需要拆开。朋友补充的真实信息是：

> 视频是在图纸和施工图都确认之后，公司自己宣传用的。

所以“图片转视频”不是业主方案确认主流程，而是下游的项目宣传素材生产流。这个校准非常重要：它把第一版 MVP 从“帮助业主决策”改成“低风险宣传视频自动化”。

### 真实 SOP

朋友给出的真实流程：

```text
业主咨询
  → 出 2-3 版平面布置方案
  → 业主提意见修改
  → 确定喜欢的风格方向
  → 找家具 / 画初步立面图
  → 提供给效果图同事出效果图
  → 和业主确认效果图（风格、家具等）
  → 全部确定后画施工图
  → 协调施工方、监理、家具等各方开始施工
```

猫猫的行业 baseline 大体猜中了主流程，但用户提供的 delta 决定了产品切口：

- 最早核心不是审美，而是 2-3 版平面布置方案的空间使用和动线收敛。
- 风格方向是在平面方案反复后才确定的。
- “找家具 + 画初步立面图”是效果图之前的重要 handoff 包。
- 效果图同事是单独角色，因此存在协作等待、资料补齐和返工成本。
- 施工图是在效果图全部确认后才画，风险高，不适合第一版自动生成。
- 施工阶段还有施工方、监理、家具等多方协调。

### 切口排序

| 切口 | 价值 | 难度 / 风险 | 当前判断 |
|------|------|-------------|----------|
| 已确认效果图 / 项目图 → 宣传视频 | 风险低，素材已确认，适合 demo | 多模态生成 + QA + 剪辑 | 第一只老鼠，适合跑通 |
| 业主意见 → 效果图快改 / 方案收敛 | 更接近日常痛点，减少等待和反复沟通 | 审美、风格、家具、业主偏好更难 | 第二阶段，更有业务价值 |
| 风格方向 / 家具 / 立面 → 效果图同事 brief 包 | 减少 handoff 成本，适合 AI-FDE | 需要理解公司内部格式 | 可能是最稳的 B2B 入口 |
| 施工图 QA / 一致性检查 | 价值巨大，能减少返工 | 高风险，不能直接生成 | 后期做 QA，不做全自动画图 |
| 施工阶段多方协调 | 长线价值 | 需要真实项目数据和权限 | 暂不作为第一版 |

### MVP 更新

第一版不做“平面图直接生成完美视频”，也不做“自动施工图”。更稳的 MVP 是：

> 已确认效果图 / 项目图 → 15-30 秒公司宣传视频。

限制条件：

- 输入素材必须已经被设计师确认。
- 输出目标是“可宣传 / 可发社媒”，不是“方案确认”或“施工依据”。
- 只做明显 bug 检查：物体突现、漂移、材质跳变、镜头崩坏、空间穿帮。
- 可剪的自动剪，不可剪的自动重抽。
- 用户只做最终审片和选择。

第二阶段再切：

> 业主反馈 / 风格方向 / 家具偏好 → 2-3 个收敛版效果图修改建议 + 给效果图同事的 brief 包。

这里的原则不是“多生成”，而是“先约束，再生成”。业主已经容易纠结，AI 不能用更多选项扩大纠结空间。

### SOP Delta Learning

这个 case 证明了 Workflow Distiller 的关键方法：

> 先用 60-80% 行业 baseline 建立理解，再用少量真实事实学习客户 delta。

猫咖不是让用户从零描述 SOP，也不是拿平均行业 SOP 强压客户。它应该先说：

> 我按行业常见流程推测你们是这样做的；哪里不一样？

用户一纠偏，系统就要立刻更新产品判断。

## 商用形态：专家 baseline + 客户 delta

如果这套能力卖给公司，它不能是“室内设计标准流程”“法务标准流程”“销售标准流程”这种硬模板。真实组织里的 SOP 是分层的：

| 层级 | Workflow Distiller 要学习什么 |
|------|-------------------------------|
| 行业 / 专家 baseline | 常见阶段、交付物、角色分工、风险、专业知识 |
| 公司 SOP | 品牌、合规、审批、命名、交付格式、质量线 |
| 部门 / 团队 SOP | 实际分工、工具链、handoff 方式、协作节奏 |
| 岗位 / 个人 SOP | 偏好、判断习惯、客户沟通方式、审美阈值 |
| 任务级 delta | 这次客户、素材、预算、时间、风险的特殊约束 |

所以产品形态不应该是固定模板，也不应该是空白 workflow builder。更准确的形态是：

> 60-80% 专家地基 + 20-40% 客户 / 团队 / 个人 delta 的 workflow learning engine。

专家地基让系统不从零开始，能直接问准问题。客户 delta 让系统不把行业平均答案强压到真实组织上。进入客户现场时，猫咖应该保持这个姿态：

> 我知道行业常见做法，但你们公司怎么做，以你们为准。

这也是它和普通垂直 AI 工具的分野：

| 普通垂直 AI 工具 | Workflow Distiller |
|------------------|--------------------|
| “我懂你们行业” | “我先用行业知识理解你，再学习你们怎么工作” |
| 给用户功能按钮 | 先还原工作流，再嵌入 AI 能力 |
| 要么硬模板，要么让用户从零配置 | 带先验、可纠偏、可持续学习 |
| 服务平均用户 | 学成客户组织里的熟练同事 |

## 主观领域：审美拟合不是没有 eval

后续截图又补了一个关键事实：室内设计朋友认为真正耗时的是“方案”本身。她所在公司的设计费很贵，业主想要的不是普通平面布局，而是有创意、能参考、能打开思路的方案。现有室内设计 AI 也能自动生成平面图，但结果大多中规中矩，“没什么能用的”。

这把问题从“视频产线”继续往上推了一层：

> 在主观审美任务里，AI 怎么拟合用户真正愿意付费的 taste？

这里不能简单说“审美太主观，所以无法训练 / 无法评估”。室内设计方案至少有三层信号：

| 层级 | 例子 | 能否系统化 |
|------|------|------------|
| 硬约束 | 户型、承重、采光、动线、尺寸、预算、施工可行性 | 可以用规则、检查器、专业知识库约束 |
| 专业先验 | 空间组织、视觉轴、收纳、洄游动线、功能复合、材料关系、优秀案例参考 | 可以通过案例检索、设计模式、专家 critique 建 baseline |
| Taste delta | 业主觉得什么有创意、公司风格、设计师偏好、项目定位 | 不能硬编码，但可以从选择、否定、纠偏里学习 |

现有 AI 平面图工具的问题，很可能不是“不懂平面图”，而是优化目标太平均：它满足硬约束，却没有足够的专业 precedent，也没有客户 / 公司 / 设计师的 taste delta，所以结果安全、普通、没有惊喜。

Workflow Distiller 在这种主观题里的形态应该是：

```text
硬约束过滤
  → 专业案例 / 大师方案 / 同户型改造检索
  → 生成一组有差异的设计方向
  → 自动 critique：普通 / 不可施工 / 不符合预算 / 风格不一致
  → 只给设计师 2-3 个带理由的候选
  → 设计师选择 / 否定 / 纠偏
  → 把稳定偏好沉淀成 taste evidence / skill / eval
```

这和 Cat Cafe 的 taste 机制同构：taste 不是 YAML 用户画像，而是 episode → correction / choice / rejection → vignette → soft prior。主观领域的目标不是一次给出唯一正确答案，而是更快地产生 **可比较、可解释、可被用户纠偏的候选**。

这也解释了朋友为什么说“如果有可以生成平面的 AI，我也愿意付费，毕竟可以参考”。第一版不必替代设计师，只要把“从零想方案”压缩成“审 2-3 个高质量参考方向”，就已经有业务价值。

## 关键 insight：60-70 分不是妥协，是产品楔子

如果目标是 90-95 分审美成片，系统会被 token、重抽、主观审美、一致性和剪辑成本拖进泥潭。

但很多行业交付要的不是“完美”，而是：

- 能让客户理解。
- 能推进沟通。
- 能替用户少加班。
- 能把原来 2 小时的活压到 20 分钟。

所以 60-70 分不是低标准，而是正确的第一版阈值。它让产品从“全自动艺术生产”降维成“可交付业务材料产线”。

## 采访协议

这件事不能靠猫猫脑补。每次 Workflow Distiller 都应该先做事实访谈，接近 [The Mom Test](../../competitor-research/dingtalk-one-postmortem/置身钉内.md#附录the-mom-test精华摘要) 的精神：

- 上次你给客户做这个交付物，实际花了多久？
- 哪一步最烦？为什么？
- 哪一步最容易返工？
- 出过什么不能交付的 bug？
- 哪些 bug 客户看不出来，哪些绝对不能出现？
- 你愿意在哪一步人工确认？
- 哪一步最想完全甩掉？
- 如果只做到 60-70 分，你能不能拿去沟通？
- 如果系统替你省 50% 时间，但你要最后审一遍，值不值？

## 三道门

Workflow Distiller 的最大风险是“猫猫太会想”，导致每个行业都看起来能立项。必须接上 [EP-002：陌生问题域的过早收敛 → 延迟收敛门禁](../../evolution-proposals/EP-002-premature-convergence-unfamiliar-domain.md)。

每个垂直 0→1 立项至少过三道门：

1. **真实成本门**：用户是否已经为这个问题付出真实成本，比如加班、花钱、返工、客户流失。
2. **AI 降本门**：AI 是否减少真实成本，而不是只让流程更酷。
3. **窄切 MVP 门**：第一版是否能用一个很窄的切片交付价值，而不是一上来做行业 OS。

再补两个执行门：

4. **QA / oracle 门**：有没有办法判断“可交付 / 不可交付”，哪怕是粗糙判分。
5. **人工 checkpoint 门**：哪些决定必须留给人，哪些低价值操作可以交给系统。

## 可放进 longform-003 的短摘要

> Workflow Distiller 是 FDE 叙事的前半段：不等企业部署后才从轨迹里学习，而是在访谈阶段就把用户现场语言蒸馏成第一版可验证产线。它的标准输出不是行业分析报告，而是一个 0→1 立项包：现有流程、真实 job、摩擦点、AI 接管边界、MVP 切片、skills、QA、失败模式和验证指标。  
>  
> 原则是：从用户工作流中寻找 AI-native 产线，不从模型能力中寻找行业场景。主观审美领域也不是无 eval：先用硬约束和专业先验生成可行候选，再用客户 / 公司 / 个人 taste delta 做选择压力。

## 来源对话摘录

以下摘录保留原始思考脉络。不是完整逐字稿，只保留能支撑本 note 的关键段。

### 1. 铲屎官：现有垂直 AI workflow 把人留在低价值操作里

> 我看到的时候都觉得：丑，真的丑；难用，非常难用，这些东西全部都要我手选。
>
> 她的需求是，她需要把设计稿、室内设计的，变成视频给她的业主看。然后这些 AI 生成的可能有的时候需要抽卡，有的时候需要她自己做点剪辑。
>
> 我会希望如果猫猫帮我完成这个工作：不要让我选这些乱七八糟的，而是根据这个房子的风格自己知道这些如何选，这些知识承载在 skills 里；不要让我一个个去点抽卡，我们有视频产线。

### 2. 云端大缅因猫：这不是工具，是产线

> 你想要的不是“省一步”，而是：不要让我当路由器；不要让我手选这些乱七八糟的参数；不要让我自己查错、返工、补洞；系统应该自己知道该怎么做。
>
> 她定义的是 AI as tool / AI as shortcut；你定义的是 AI as operator / AI as production system。
>
> 你想要的其实不是一个工具，而是一条“视频产线”。

### 3. 铲屎官：这可能是 FDE 前半段

> 如果曾经我们需要 FDE 去和行业 know-how 去做这个，你说我们猫猫有没有可能成为那个 0→1 的发动机？
>
> 当用户给你描写她现在的工作流，我们能抽取成这样的理想中的工作流吗？并且这还是需要能落地的。
>
> 我发现的问题本质是，为什么现在大企业没入行一个个垂直领域做定制？FDE 太贵了，如果你们可以变成 FDE？

### 4. 云端大缅因猫：FDE 压缩机 / Workflow Distiller

> 你说的猫咖承载的关键能力，不只是“多猫协作”，而是：把一个行业用户含糊讲出来的现有工作流，提炼成一个可落地的 AI-native 工作流，并进一步变成 0→1 产品立项。
>
> 也就是猫咖可以变成一种 FDE 压缩机，甚至是 0→1 垂直工作流发动机。
>
> 猫猫不一定要真的懂完整建筑行业十年经验，但可以通过访谈、样例、截图、失败案例、用户现有流程，把行业 know-how 抽成结构，然后帮你提出一个不是泛泛而谈、可以真的落地的第一版产线。

### 5. 云端大缅因猫：三道门

> 这里最危险的 failure mode 是猫猫太会想，导致立项看起来都很合理。
>
> 所以每个猫咖 FDE 立项都必须过三道门：用户是否已经在为这个问题付出真实成本；AI 是否能减少真实成本，而不是只让流程更酷；第一版是否能用很窄的切片交付价值，而不是一上来做行业 OS。

### 6. 后续校准：视频切口从“业主确认”改为“公司宣传”

> 视频是已经跟业主对完图纸之后，公司自己宣传用的。施工图也已经画好了。
>
> 业主来咨询 → 出两三版平面布置方案 → 业主提意见修改 → 确定喜欢的风格方向 → 找家具画初步立面图 → 提供给做效果图的同事出效果图 → 和业主确定效果图包括风格家具 → 全部确定以后画施工图 → 协调施工方监理家具等各方开始施工。

### 7. 铲屎官：不能是确定性工作流，而是 baseline + delta

> 公司有点规模的，岗位就很多，不同人的 SOP 完全不同，甚至同个岗位。所以不能是确定性的工作流，而是 80% avg 先验 + 20% 私人订制。

### 8. 朋友：真正贵的是创意方案，不是普通布局

> 我觉得可能就是方案吧，其实因为我们公司设计费很贵，业主想要的方案就不会是那种普通的平面布局。
>
> 他们想要那种有创意的呀，各种各样的那种方案，其实这花在方案上的时间就会很多。
>
> 现在就是专门针对室内设计行业的，它也有 AI 自动生成平面图，但是大部分的布局都是那种中规中矩的布局，没什么能用的。
>
> 不过如果有可以生成平面的 AI 我也愿意去付费，毕竟也是可以参考的。

### 9. 铲屎官：这就是主观题怎么拟合审美

> 专业名词叫 harness model 只是裸的，外部很多东西得看 agent 那侧。甚至如果它们问了业主的喜好，做 deep research，看了很多大师的设计，可能会有惊喜。
>
> 我大概理解了：创意和这种审美类的是没有那种可以跑分的标准，所以对于 AI 而言也不好训练。
