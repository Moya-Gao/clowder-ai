# 华为 PPT 配图低保真稿

> **受众**：华为云内部创新汇报评委，不能假设有完整技术背景 → 少黑话、图表化、结论先行。
> **风格**：华为式（白底 70% / 深灰 20% / 品牌红 8% / 辅助 2%）；直角卡片、无渐变阴影 3D；底部红底白字结论条。配色见末尾「生成指引」。
> **原则**：每张图一眼讲清一件事；一页拆两张图（左/右），imagegen 压力小。**低保真稿必须内容保真：定义、证据、机会点不能为了好看省略。**
> **流程**：架构猫写低保真（本文）→ 铲屎官审 → imagegen 逐张出 raster PNG → 回填主 PPT。

## 为什么建这份 + 归一原则

尹青原图本是**一个坐标系**（L1-L5 阶梯 + 责任迁移轴 + 每级产品）。我们迭代时堆了三个平行视图（L1-L5 表 / 二维象限 / 候选池）→ 割裂。
**归一**：回 L1-L5 单坐标系，产品填进每级，环境真实性降成注脚，不另起轴。二维象限已撤。

## 图 5：Backup/Q&A —— 真值从哪里来？低验证场景如何防自嗨？

**一句话**：低验证场景（low verifier）不是没有真值；它不能靠单点硬判，必须把真实轨迹、双锚点、人类 checkpoint、reference/pairwise 和反例回灌组合成可审计证据链。
**版式**：华为「三栏证据管道 + 中部可信度阶梯 + 底部红条」。这张图是现场答疑备用图，不一定进入 5 张主滚动图；如果评委追问“凭什么信 eval / taste 怎么验证 / AI 会不会乱学”，就切这张。

### 内容保真要求（图内不能丢）

1. **AI 不自评**：真实轨迹先变证据，证据再分层判断能否当真值；不能画成“模型自己给自己打分”。
2. **四类传感器**：人的自然决策、世界结果、系统传感器、历史工件 / 被拒理由。
3. **四层真值闭环**：L1 规则正确性、L2 决策质量、L3 任务交付、L4 链路效率；L3 必须写“双锚点：客观事实锚 + 用户自然决策锚”。
4. **低验证补偿机制**：reference eval、pairwise 比较、rejection-driven 学习、人类 checkpoint、counterexample loop。
5. **红线**：行为频率 / 点击 / 停留这类 proxy 只能当线索，不能直接放行 harness patch；eval 自己也可能错，必须能被 review、反例和 owner pushback 校准。
