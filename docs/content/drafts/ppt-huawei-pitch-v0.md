## 第一页：创新 IDEA 产品技术方案

> 逻辑：左边画"现在行业长什么样"，右边画"我们要做成什么样"，

### 【左半：对标现状】

**维度 1：当前 Agent 平台产品（OPC）**

代表产品：Coze（字节扣子）、CodeBuddy/WorkBuddy（腾讯）、Dify、百度智能体

<!-- TODO: 铲屎官校准——具体对标哪几家？有没有漏的？ -->

共同能力：
- 可视化搭建 agent 工作流
- Plugin 市场 / 工具连接
- 快速出 demo（模板 + 拖拽）

共同短板：
- **搭完就不动了** — workflow 和 prompt 写好后不会根据使用情况自动变好
- **服务"平均用户"** — 没有从一个具体用户/团队的真实使用轨迹中学习
- **环境和模型脱节** — 换个模型，之前的调优基本作废

> 一句话：能快速搭，但搭完后要靠人维护、人迭代。

**维度 2：前沿自进化探索**

代表案例：
- OpenAI「Building self-improving tax agents with Codex」— agent 在执行过程中改进自己的策略
- Anthropic「Dynamic Workflows: A Harness for Every Task」(2026-06-02) — Claude 为每次任务现场写编排脚本

<!-- TODO: 铲屎官确认——还有哪些前沿案例值得提？ -->

已经在做的：让 agent 自己写/修编排逻辑

但仍然是**一次性的**：
- 每次任务现场生成脚本，跑完就丢
- 没有跨任务积累——上次学到的不会带到下次
- 没有退役机制——过时的策略不会自动清理

> 一句话：开始"会学"了，但学完就忘。

**创新机会点**

1. **针对"搭完不进化"**：
   让 AI 工作环境从真实协作中自主生长——agent 发现重复问题后自己写代码修复，而不是等人改 prompt

2. **针对"学完就忘"**：
   让进化成果有生命周期——产生、验证、积累、退役，跨任务持久复用

### 【右半：我们的方案】

**产品名 / 品类定位**

Cat Cafe — Agent 3.0 / 自进化 AI 工作环境（Personal Operating Environment）

<!-- TODO: 华为内部可能需要一个更正式的产品名？讨论 -->

**一句话价值**

> "让 AI 工作环境从'人工搭建一次性交付'变成'自主进化持续适配'。
> 企业定制的核心成本——现场交付工程师(FDE)理解客户、手工调优——
> 变成环境从员工轨迹中自动学习。人天变算力。"

**架构图**（六层，从上到下）

```
人 / 方向提供者
  定方向、定边界、做不可逆决策
  ↕
自进化工作环境（PoE）
  管目标、任务、记忆、工具、节奏
  ↕
多 Agent 协作层
  多模型多角色：起草、审查、设计、研究、执行
  ↕
行为约束 + 路由（Harness）
  规则 + 技能包 + 工具封装 + 安全边界
  ↕
评估闭环（Eval）
  机械正确性 → 路由决策 → 任务交付 → 整体效率
  ↕
记忆 + 偏好 + 方法沉淀
  记住事实、偏好、共同经历，把真实轨迹蒸馏成方法
```

<!-- TODO: 要不要加本地信号层？还是放到第二页技术方案里 -->

**技术挑战**

1. **安全与隐私**：
   企业场景下部分数据不能出本地/出境。需要设备端小模型做敏感信号采集和初步处理，只把脱敏后的结果上传云端大模型。
   <!-- 原来写的"128GB 消费设备"——那是我们自己的开发场景，不是华为云的卖点 -->

2. **多模型协作可靠性**：
   异构模型（不同厂商、不同规模）在同一任务链上协作，需要防止：
   - 错误在协作链中放大（一只 agent 的错被其他 agent 当真继续做）
   - 路由崩溃（小模型过于自信，该升级给大模型的不升级）
   - 协作死锁（互相等待/互相客气/无人接球）

3. **从搭建到自进化的跃迁**：
   当前行业绝大多数在"人搭建 + 人调优"的阶段。让环境自主发现问题并写代码修自己——回路主体从"人"变成"Agent"——是核心技术跃迁。

## 第二页：创新技术方案 & 目标

### 【左半：技术方案 + 目标】

**核心技术方案：自进化 AI 工作环境**

```
环境进化等级（我们提出的分级框架）：

L1 静态环境 ← 当前大多数 AI 产品
   模型 + 固定 prompt/工具，用完即走，不积累

L2 人工调优 ← 认真用 AI 的团队
   人根据经验手动调 prompt/工具/规则

L3 环境自生长 ← 我们已验证的阶段 ★
   Agent 自己写代码改进工作环境
   人提供方向和安全边界

L4 双回路进化 ← 下一步目标
   环境进化（快回路）+ 模型适配（慢回路）同时转

L5 规模化复制 ← 终局蓝图
   一套核心能力为千行百业定制自进化环境
```

**技术目标**

1. **L2→L3 跃迁**（核心突破）：
   - 当前：人发现问题 → 人写 prompt/规则 → 人验证效果
   - 目标：Agent 从重复摩擦中自主发现问题 → 自己写代码修复 → 系统自动验证
   - 关键指标：重复性问题的人工干预次数降低 X%

   <!-- TODO: 需要真实数据。我们家有一些——比如 commit push hook 消灭了手动提醒 -->

2. **自进化的完整生命周期**：
   - 不只是"能改自己"，还要"知道什么时候该删"
   - 信号发现 → 代码修复 → 效果验证 → 持久积累 → 过时退役
   - 模型升级时主动做减法（新模型自己能做对的，旧补丁就退役）

3. **安全边界内的自主性**：
   - 三道安全网：不可逆操作需要人确认 / 跨 agent 交叉审查 / 关键变更自动回滚
   - 安全不是限制 agent 做事，是让 agent 在安全范围内大胆做事

### 【右半：产品计划】

**已验证的证据**

- 120+ 天连续运转的真实飞轮
- 6400+ 次代码提交
- 240+ 个功能迭代
- 40+ 个失败模式被命名、被追踪、被修复
- 3 个不同厂商的 AI 模型在同一环境中协作

**路线图**

| 阶段 | 目标 | 用户 |
|------|------|------|
| Phase 1（已验证） | 个人自进化环境 | 单人 + AI 伙伴 |
| Phase 2 | 小团队协作环境 | 2-10 人团队 |
| Phase 3 | 企业级部署 | 组织级（替代 FDE） |

同一套架构在三个尺度上的投影——不是三个产品，是一个产品的三种规模：

| | 个人 | 小团队 | 企业 |
|---|---|---|---|
| 谁在用 | 一个人 | 2-10 人 | 整个部门/公司 |
| 偏好是什么 | 个人审美和节奏 | 团队协作规范 | 组织文化和合规标准 |
| 学什么 | 个人踩坑长出的方法 | 团队沉淀的工作流 | 千人轨迹抽出的最佳实践 |

**FDE 替代——对企业客户最直接的价值**

| 现在 FDE 手动做的 | 自进化环境怎么自动化 |
|---|---|
| 去客户现场理解业务 | 从员工日常使用轨迹中自动发现重复模式 |
| 手写 prompt / 规则 | Agent 从真实问题中自己写修复代码 |
| 适配不同员工 | 每个人的上下文和偏好自动注入 |
| 定期复盘迭代 | 自动发现→修复→验证→退役，持续进化 |

## 第三页：典型应用场景

### 【左半：场景 1 — 自动修复重复问题】

**场景名**：Code as Harness — 被骂了不道歉，写代码修自己

**场景描述**：

用户在日常使用中反复遇到同一个问题（比如 AI 助手总忘记某个操作步骤）。
传统方案：用户反馈 → 运维团队收集 → 产品经理排需求 → 开发修复 → 发版 → 用户更新。
我们的方案：AI 自己检测到用户的重复不满 → 自动定位根因 → 自己写代码修复 → 当前工作不中断。

**客户可感知的创新点**：

1. **零人工介入的问题发现和修复** — 不需要提工单、不需要等排期。AI 从用户行为模式中自主发现重复问题
2. **修的是运行时机制，不是静态配置** — 写的是真实代码（hook / 检查器 / 自动化脚本），不是改一行 prompt
3. **当前工作不中断** — 发现问题和修复问题在"后台线程"进行，用户正在做的事不受影响

### 【右半：场景 2 — 面对陌生任务自主建能力】

**场景名**：Build Mode — 没做过的事，组织调研然后建出新能力

**场景描述**：

用户给 AI 一个它从没做过的任务类型。
传统方案：AI 说"我不会" → 用户去找其他工具 → 或者人工写 prompt template → 下次才能做。
我们的方案：AI 识别"这是新类型" → 自动组织多个专长不同的 AI 协作调研 → 从调研中提炼方法 → 沉淀为持久能力 → 下次直接能做。

**客户可感知的创新点**：

1. **从"不会做"到"学会做"** — 不是一次性完成任务，是把"怎么做这类事"沉淀下来
2. **多 AI 自组织协作** — 不是人分配谁做什么。擅长深度分析的、擅长工程落地的、擅长审美判断的各自认领
3. **能力持续积累** — 今天学会的方法明天还在。而且如果后续有更好的方法，旧方法会被自动替换
