设计说明 D — ReconciliationFindingCard 交互
1. Finding card 出现在有 drift/SLA finding 的 issue row 下方（和 DirectionCard / ClosureChecklistCard 同位置）
2. INV-D6.3: Evidence Source 区域展示完整信息链—GitHub 状态、内部状态、finding ID、首次发现时间、appended event ID
3. 三个操作按钮对应 finding lifecycle: Acknowledge(标记已知) / Resolve(问题已解决) / Waive(忽略+记录原因)
4. Waive 按钮点击后展开 waiver 审计表单（同 Mockup 2 模式），不是一键完成
5. Card 左 border 颜色根据 severity: needs-owner=critical(red), needs-human=warning(yellow), informational=info(blue)
6. kind badge 颜色: drift=critical, sla=warning, stale=info

Design Constraints Checklist

INV-D6.1 Close action disabled until checklist ready or waiver exists

INV-D6.2 Waive action always opens audit form; no one-click waive

INV-D6.3 UI must show evidence source (comment URL, waiver, finding details) rather than only a green/red badge

INV-D6.4 Frontend uses SVG icons only, no emoji

KD-5 Community is a Workspace tab, not a standalone page

KD-8 Give data, not conclusions — findings show evidence, owner decides action

KD-9 All icons SVG, zero emoji

OKLCH All colors from theme-tokens.css, dark mode auto-switch

Responsive Cards follow Workspace panel width (min 320px ~ max 480px)

SO-D6 Checklist card replaces DirectionCard position when case has resolved past intake

Finding lifecycle open → acknowledged → resolved | waived — all transitions visible in UI
