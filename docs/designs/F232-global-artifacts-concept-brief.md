## 🎨 视觉色彩与意象设计 (Aesthetic Language)

我们复用并强化 Phase A 已有的 6 种类型色彩系统，但赋予它们更柔和的渐变（Gradients）和暗色模式（Dark Mode）微发光效果：

| 产物类型 | 代表色 & 渐变系统 (HSL) | 视觉意象 |
| :--- | :--- | :--- |
| **Image** (图) | `#4a7fb0` ➔ `linear-gradient(135deg, #4a7fb0, #6fa3d2)` | **天青蓝**：视觉创意，灵感涌现 |
| **Video** (视频) | `#b05a5a` ➔ `linear-gradient(135deg, #b05a5a, #d27f7f)` | **晚霞红**：动态画卷，记录瞬间 |
| **Audio** (语音) | `#8866b0` ➔ `linear-gradient(135deg, #8866b0, #aa8cd2)` | **极光紫**：声音频率，空气颤动 |
| **File/Doc** (文档) | `#b58a45` ➔ `linear-gradient(135deg, #b58a45, #d2ad6f)` | **琥珀金**：知识沉淀，智慧结晶 |
| **Code/PR** (代码) | `#479a5a` ➔ `linear-gradient(135deg, #479a5a, #6cbd7f)` | **薄荷绿**：逻辑构建，坚实地基 |

## 🧭 六大核心问题的“烁烁式”解答

### Q1: 页面入口 ➔ 视口双态切换 (Viewport Slider)
> **问题**：workspace 模式新增一个 "全局" tab？独立路由 `/artifacts`？还是现有产物 tab 里加全局/当前切换？

* **设计方向**：**在当前已有的顶层 `WorkspacePanel`“产物”面板内部，进行“视口双态”切换。**
* **具体交互**：
  * 在面板顶部搜索栏下方，放置一个精致的胶囊型双态切换滑块（Segmented Slider），只有两档：
    * `[ 🐾 当前对话 / Current ]` (默认)
    * `[ 🌌 猫咖全局 / Global ]`
  * **切换动效**：当从 "Current" 切换到 "Global" 时，触发**“电影推焦动效” (Parallax Focus Transition)**。整个产物列表通过轻微的弹性（Spring）动画向两侧微张，左边或顶端以平滑渐入的方式展示“多维过滤器”（如猫咪头像行、时间范围选择器），提供从“局部焦点”到“广角镜头”的无缝拉伸感。

```
+------------------------------------------+
| 📦 产物 / Artifacts                       |
| [ 🐾 当前对话 ]   [======== 🌌 猫咖全局 =======] |  <-- 胶囊滑块 (Segmented Control)
+------------------------------------------+
| [🔍 搜名字、指令或问猫猫...               ] |  <-- 意图搜索框
+------------------------------------------+
```

---

### Q2: 主交互模式 ➔ 意图过滤与星云拼图
> **问题**：搜索优先（Spotlight）还是浏览优先（文件管理器）？

* **设计方向**：**“意图 Spotlight (精确检索)” 与 “星云拼图陈列墙 (Nebula Mosaic Wall) (视觉陈列)” 的动态融合。**
* **具体交互**：
  * **未输入/初始态（浏览优先）**：由于产物多，页面不要一上来就是大白列表。可以设计一个**“色彩星云拼图墙”**——将近期生成的产物按其类型色块，以不同大小的不规则磁贴（Adaptive Tiles）铺满展示（大图展示 Image，胶囊声波展示 Audio，紧凑文字条展示 Code）。让铲屎官一眼就能感知猫咖最近在产出什么。
  * **一旦打字/聚焦搜索（搜索优先）**：拼图墙像流沙一样向四周淡出，界面瞬间收拢为高效的 **Spotlight 精确搜索**。
  * **搜索框特权**：支持输入快捷搜索修饰符（如输入 `@` 触发猫咪过滤，`/` 触发类型过滤）。

---

### Q3: 布局密度 ➔ 混合自适应布局 (Adaptive Grid & List)
> **问题**：卡片网格 vs 紧凑列表 vs 混合视图？

* **设计方向**：**自适应卡片流（Adaptive Masonry/Flex Layout）。不同的产物，用最适合它本身的密度呈现。**
* **具体版式**：
  * 📸 **Image & Video (媒体类)**：采用 **Card Grid (网格卡片)**。显示精美缩略图，悬停时微放大 3%，视频卡片悬停 0.5s 后直接在原地进行**静音预览播放 (Muted Hover Play)**。
  * 🧮 **Code & PR (代码与任务)**：采用 **Compact List (紧凑列表)**。一行包含：类型色块 icon、产物名、作者猫头像、所归属 Thread 气泡。
  * 🎵 **Audio (语音类)**：呈现为 **胶囊波形条 (Capsule Waveform)**。可以直接在原地点击播放，甚至附带 15 字的“智能简要转译”前缀，不需要点开就能猜到大致内容。

---

### Q4: 分组逻辑 ➔ 三维聚焦旋钮 (Tri-axis Filter Grouping)
> **问题**：时间线平铺 vs thread 分组 vs 类型分组？

* **设计方向**：**允许用户通过顶部快捷 chips 一键切换分组维度。**
* **三种极具特色的视图**：
  1. **Timeline (流沙时光轴)** (默认)：最新产物优先，用一条微弱发光的垂直虚线穿过所有产物，右侧标注相对时间。
  2. **Threads (对话树抽屉)**：按原 Thread 聚合。每个 Thread 呈现为一个精致的小卡片柜，顶部显示 Thread 标题和参与该 Thread 的所有猫咪头像簇。点击可折叠/展开该 Thread 的产物。
  3. **Cats (猫咪时光馆)**：**按猫咪分组**。过滤栏是一排活泼的猫咪动态头像行（Avatar Row）。点击某只猫（如砚砚 `@gpt52`），界面背景会被薄荷绿浸润，并过滤出砚砚产生的所有代码和 PR。这极度突出了“我们是共创伙伴”的世界观。

---

### Q5: Thread 上下文 ➔ 悬停时空缩影 (Hover Time-slice Tooltip)
> **问题**：怎么优雅展示 "这个产物来自哪个对话"？

* **设计方向**：**在卡片/行中展示“微缩气泡标签” + “悬停时空切片”。**
* **具体交互**：
  * 每个产物项底部都带有一个小小的胶囊标签：`# F232 产物面板`。
  * **黑科技动效**：当鼠标悬停在这个 Thread 标签上时，弹出一个超轻量磨砂玻璃质感的悬停框（Time-slice Tooltip），里面内联渲染出**生成该工件那一刻的前后 3 句对话摘要**。
  * **价值**：铲屎官不需要真的跳回 Thread，悬停 1 秒就能立刻回忆起这个产物是在什么讨论背景下被制造出来的。

```
+-------------------------------------------------------------+
| 📄 backlog.md                                 [ 🐾 砚砚 ]   |
|   来自: # f232 产物追踪系统                                  |
|  +-------------------------------------------------------+  |
|  | Hover 浮窗:                                           |  |
|  | > Landy: 宪宪，把 backlog 里的 Phase B spec 确认一下     |  |
|  | > [opus🐾] 明白，我已经把 requirements 梳理好并写入...   |  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
```

### Q6: 点击行为 ➔ 双栏分合视口 (Dual-Pane Split View)
> **问题**：内联展开详情（drawer/modal）vs 跳转到原 thread 的产物面板看上下文？

* **设计方向**：**双栏抽屉拆分预览，结合 “时空传送门 (Teleport Gate)” 按钮。**
* **具体交互**：
  * 全局产物中心是一个宽面板。当点击某个产物时，**绝对不要弹窗遮挡**。
  * 采用 **分栏视图**：左侧 40% 保持产物列表/过滤状态，右侧 60% 平滑推入（Slide-in）内容预览区。
  * 复用 Phase A.1 的查看器（Markdown 阅读器、图片灯箱、音频播放器、视频播放器、代码 diff 对照器）。
  * 预览区右上角提供两个核心动作：
    1. `[ 🚀 传送现场 / Teleport ]`：一键将当前主聊天区域切换至该 Thread，并滚动定位至生成该工件的消息位置。
    2. `[ 📁 贴到工作区 / Stage ]`：若为代码或文档，一键让左侧主开发区打开对应文件。

## 💡 烁烁最重要的设计原则 (Core Axioms)

1. **“点一下就看到内容”是灵魂**：全局搜索必须让查看极其轻量。左边搜索过滤，右边一秒预览。任何需要跳页面或者下载的操作都是阻碍。
2. **色彩是有功能逻辑的**：6 种类型的代表色必须严格贯穿整个列表 and 预览区，防止信息过载时视觉疲劳。
3. **保持猫咪的主体感**：突出“是谁（哪只猫）生成的”，用动态的猫咪头像，让铲屎官感觉猫猫们一直在他身边辛勤工作，而不是冷冰冰的文件生成器。
