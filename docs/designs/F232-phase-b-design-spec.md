## 1. Approach: 视口双态切换（非独立页面）

Spec 写"独立页面"，但实际落地推荐**在现有产物面板内做 scope toggle**，理由：

1. **一致性**：recall 面板已有 `[记忆流] [拉闸记录]` 双态切换先例，UI pattern 复用
2. **可发现性**：用户已知产物在 workspace 面板，不需学新入口
3. **工程量小**：复用 ArtifactsPanel 基础设施，增量改动
4. **可逆**：后续如需独立路由，抽离成本低

如 CVO 偏好独立页面，可调整。

## 3. Key UX 决策

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| 1 | 入口 | workspace 产物面板内 scope toggle | 复用现有入口，一致性好 |
| 2 | 交互模式 | 浏览优先 + 实时搜索过滤 | Phase A 已有此 pattern，用户熟悉 |
| 3 | 布局 | 统一紧凑列表 | 面板宽度有限，列表密度最高；图片靠详情区预览 |
| 4 | 分组 | 三种可切换（时间/对话/猫），默认时间 | 覆盖 spec 要求的所有检索维度 |
| 5 | Thread 上下文 | 每行末尾 thread 标签（小胶囊） | 简洁、不占行高 |
| 6 | 点击行为 | 面板内分栏（列表+详情），复用 ArtifactDetailView | 不跳页，"点一下看内容"灵魂 |
| 7 | 详情操作 | 传送现场（teleport）+ 在编辑器打开 | 复用 Phase A teleport 机制 |

### 与 gemini35 概念的差异说明

| gemini35 概念 | 落地调整 | 原因 |
|--------------|---------|------|
| 星云拼图陈列墙 | 统一列表 | 面板宽度不足以做 masonry；列表信息密度更高 |
| 流沙/推焦动效 | 简单 fade/slide | 动效复杂度与价值不成比例 |
| 悬停时空切片（3句对话） | Phase B 不做，预留 | 需要后端额外查询，可作为后续增强 |
| 猫咪头像行+背景浸润 | 分组标题显示猫名 | 简化视觉，头像行占空间 |
| 混合 card/list 布局 | 统一 list | 面板内混合布局不实际 |

保留的核心精神：
- "点一下就看到内容"
- 类型色彩系统贯穿
- 猫的主体感（分组显示、每行标注作者）

## 4. 技术方案（概要）

### API

新增 `GET /api/artifacts`：
- Query: `?type=image&cat=opus&q=keyword&group=time&page=1&limit=50`
- 遍历用户所有 thread，每个调 `aggregateThreadArtifacts()`（AC-B2）
- 并行 Promise.all 加速
- 返回 `{ artifacts: GlobalArtifactDTO[], total, page, limit }`

```typescript
interface GlobalArtifactDTO extends ThreadArtifactDTO {
  threadId: string;
  threadTitle: string;
}
```

### 组件架构

| 层 | 新增 | 复用 |
|----|------|------|
| API 路由 | `GET /api/artifacts` | `aggregateThreadArtifacts()` |
| Hook | `useGlobalArtifacts()` | — |
| 面板 | ArtifactsPanel 增加 scope state | ArtifactDetailView, artifact-view.ts |
| UI 控件 | ScopeToggle, GroupingChips, ThreadBadge | type filter chips, 搜索框, detail viewer |

### 性能策略

MVP：遍历全部 thread 并行聚合，前端分页。
预留 OQ：Redis 反向索引（Phase A OQ-2）——如果 thread 数量过多导致首次加载慢。
