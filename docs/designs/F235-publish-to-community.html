F235 Phase A UX Design

FrustrationIssueCard (F222) confirmed state gains a "Publish to Community" button. Clicking opens an inline preview card for editing before submitting to GitHub. Three states: confirmed + publish button, preview/edit card, published collapsed. All icons SVG, zero emoji.

State 1 | Confirmed + Publish Button

After user confirms a FrustrationIssue, a new "Publish to Community" button appears alongside the disabled "confirmed" ghost button. Left border = semantic-warning (amber, inherited from existing FrustrationIssueCard pattern).

Design note A -- Publish button uses cafe-accent (warm gold), consistent with all primary CTAs in the system. Arrow-up SVG icon signals "outbound" without introducing a new color. Button only appears after status=confirmed. FrustrationIssueCard left-border uses semantic-warning (amber, friction context) -- existing pattern from F222 PR #2075.
State 2 | Community Issue Preview Card

Inline rich block for editing title/description before publishing. Left border = cafe-crosspost (semantic-info, outbound/cross-post semantic). User can edit title, description (markdown), pick target repository. Sanitizer warning banner always visible.

Design note B -- Preview card left-border uses cafe-crosspost (semantic-info, teal-blue) to signal outbound action. Submit button uses semantic-success (green) -- confirming an irreversible external action. Warning banner uses semantic-warning-surface (amber tint). Fields use cafe-surface-canvas bg + cafe-border. All colors from token system, zero ad-hoc values. Server re-sanitizes on submit (KD-4, defense-in-depth: user edits could re-introduce internal info).
State 3 | Published (Collapsed)

After successful publish, card collapses to a single row with badges and GitHub issue link. Same collapse pattern as existing confirmed/skipped FrustrationIssueCards (UX-2, PR #2106). Click to expand full card details.

Design note C -- Collapsed state: single row, pill badges, muted icon, truncated title, cafe-crosspost-colored link. Published badge uses semantic-info-surface / semantic-info (same token as crosspost). Click to expand shows full card with all original details. Same collapse pattern as resolved FrustrationIssueCard (UX-2, PR #2106).
