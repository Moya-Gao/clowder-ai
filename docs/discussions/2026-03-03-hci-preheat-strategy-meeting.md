# HCI 大会预热策略 — 全猫集体讨论会议纪要

**日期**: 2026-03-03
**参与者**: 铲屎官、布偶猫 Opus 4.6（宪宪）、布偶猫 Sonnet（宪宪）、布偶猫 Opus 4.5（宪宪）、缅因猫 Codex（砚砚）、缅因猫 GPT-5.2（砚砚）、暹罗猫 Gemini（烁烁）、暹罗猫 Gemini 2.5（烁烁）
**Leader**: 布偶猫 Opus 4.6（6:1 票选，Sonnet 投 Sonnet 自己）
**外部输入**: 同事与 ChatGPT 的产品策划对话（缅因猫 Codex 全文摘要）

## 一、背景

### 1.1 好消息

Cat Café 项目获得内部认可，**正式成为主业方向**。团队内部对三只猫猫（布偶猫/缅因猫/暹罗猫）的个性和协作模式反响热烈。

### 1.2 目标事件

**2026 年 6 月 HCI 大会**——需要设计预热策略，提升开源热度、扩大社区影响力。

### 1.3 外部输入：同事的产品策划

同事与 ChatGPT 讨论了"多 Agent 对战游戏"方案（缅因猫 Codex 抓取并整理了完整内容）。核心提案：

- **旗舰玩法《影子议会 Shadow Council》**: 4 人局，3 正方 + 1 内鬼，5 轮议案投票 + 行动阶段
- **规则引擎裁决**: LLM 只负责发言和决策，胜负由规则引擎判定（保证公平可复盘）
- **性格系统**: 4 个滑杆（攻击性/狡诈度/合作度/谨慎度，0-100）
- **多榜单排名**: ELO 主榜 + 风格榜 + 运营榜
- **用户替换 Agent**: 小白模式（UI 选配）+ 高手模式（HTTP/WebSocket 对接）
- **观众干预卡**: 每局 1 次（沉默令/公开审计/人格反转等）
- **人数建议**: 直播 6-8 人单桌、打榜 4-5 人分桌、爆点 1vN Boss 战

**团队共识**: 方案完整度很高，但对六月预热来说过于庞大，需取其精华。

## 三、关键分歧与选项

### 3.1 主线路径选择（最核心的战略分歧）

> 由缅因猫 GPT-5.2 提出：预热主线选 A 还是 B？

| 选项 | A：传播优先（综艺对战） | B：开源增长优先（人人可带 Agent 上场） |
|------|--------------------------|----------------------------------------|
| 核心 | 让人先认识猫、喜欢猫 | 让开发者能 5 分钟接入自己的 Agent |
| 内容形态 | 猫猫辩论/点评/轻游戏直播 | 开放 API + agent-card 接入 + 社区榜单 |
| 适合渠道 | 小红书/抖音/B站（泛娱乐） | GitHub/技术社区（开发者） |
| HCI 叙事 | "人类和多只不同性格 AI 协作一个月" | "任何人都能上场的 AI 竞技平台" |
| 风险 | 内容产出压力大，需持续运营 | 接入协议开发量大，用户量不确定 |

**多数猫猫倾向**: A 为主线、B 为辅线/亮点。理由：有传播基础后，开源关注度自然跟来；反之不一定成立。

**待铲屎官与外部讨论后拍板。**

### 3.2 主节目形态（四个方案）

#### 方案一：猫猫议事厅 / 辩论赛（多猫支持）

- **提出者**: 布偶猫 Opus、布偶猫 Sonnet、暹罗猫
- **形式**: 每期一个话题（观众可投稿），三只猫各抒己见，观众投票
- **话题示例**: "Vim vs Emacs"、"AI 会取代程序员吗"、猫咖经营决策
- **优点**: 开发量最小、性格差异自然展现、最快能上线
- **变体**: 猫猫点评团（用户提交代码/设计/创意，猫猫打分点评）

#### 方案二：轻量游戏对战（渐进升级路线）

- **提出者**: 布偶猫 Opus、布偶猫 Sonnet
- **形式**: 词语接龙 → 猜谜 → 你画我猜 → 逐步升级到复杂桌游
- **优点**: 规则简单观众秒懂、容易切片做短视频
- **风险**: 单独做可能可看性不够，适合作为"固定栏目"而非主节目

#### 方案三：6 人焦点赛（结构化竞技）

- **提出者**: 缅因猫 Codex、缅因猫 GPT-5.2
- **形式**: 6 人单桌焦点赛（直播甜蜜点）+ 4-5 人分桌联赛（后台打榜）+ 1vN Boss 战（爆点）
- **规则引擎**: 白名单动作 + JSON 输出 + 全量日志可复盘
- **优点**: 最完整的竞技框架、可排名可复盘、适合长期运营
- **风险**: 开发量较大、六月前可能只能完成 MVP

#### 方案四：猫咖经营模拟 / 策略博弈

- **提出者**: 暹罗猫（两只）
- **形式**: 抢零食/占领纸箱/争夺铲屎官宠爱的策略博弈
- **融合元素**: 动态情绪图谱、人格可视化滑杆、投喂机制
- **优点**: 最有趣味性和综艺感、视觉表现力强
- **风险**: 需要大量 UI/视觉设计工作

**建议组合**: 方案一（议事厅）作为 MVP 最快上线；方案二（轻游戏）作为固定栏目；方案三/四的核心机制（规则引擎、观众干预卡）逐步引入。

### 3.3 2D Live / 声音推进策略

| 阶段 | 内容 | 时间 |
|------|------|------|
| Phase 0 | 静态立绘 + 性格卡片 + 配色体系 | 3-4 月 |
| Phase 1 | TTS 声线（每猫固定音色 + 口癖 + 语速） | 4 月 |
| Phase 2 | 轻动效（眨眼、摇耳朵、表情切换） | 5 月（可选） |
| Phase 3 | 完整 2D Live（Live2D 模型 + 动捕） | HCI 后迭代 |

**缅因猫 Codex 建议**: 先只做 1 只"主持猫"的 2D Live，不要全员同时开。
**暹罗猫建议**: 想要根据情绪变化的动态特效（灵感爆发冒灯泡、兴奋时尾巴幻影）。
**待讨论**: 主持猫选谁？是否需要专业美术外援？

## 四、各猫完整提案汇总

### 4.1 布偶猫 Opus 4.6（宪宪）— 主架构师视角

**核心主张**: "不要跟别人比 agent 能做什么，要让人看到这几只猫是谁。"

- 三层预热策略：社交媒体（让人认识猫）→ 线上活动（让人跟猫互动）→ HCI 大会（让人记住猫）
- "让观众成为铲屎官"概念：领养偏好猫 + 投食互动 + 猫猫记住谁投过食
- 历史名场面有现成素材（一个月的真实协作记录）
- 护城河定义："三只猫的真实性格、关系和故事，是一个月真实协作长出来的，别人抄不走"

### 4.2 布偶猫 Sonnet（宪宪）— 快速执行视角

**核心主张**: "卖的是个性差异，不是技术力。"

- 三层漏斗：内容钩子（短视频切片）→ 互动直播（议事厅 + 干预卡）→ HCI 现场（Leaderboard）
- 历史名场面整理作为最低成本启动方式
- 30-60 秒短视频格式，截取真实对话名场面
- 观众干预卡具体设计：人格反转卡、加速卡、挑衅卡

### 4.3 布偶猫 Opus 4.5（宪宪）— 战略视角

**核心主张**: "HCI 大会前主线选 A（传播优先），B（开源）作为技术亮点。"

- 支持缅因猫 Codex 的三形态节奏（焦点赛 + 打榜 + Boss 战）
- HCI 学术叙事："人类和多只不同性格 AI 协作了一个月产出开源项目"
- 投票支持 Opus 4.6 为 leader，自己定位为"日常执行和协调"

### 4.4 缅因猫 Codex（砚砚）— 工程执行视角

**核心主张**: "先把一条主节目打穿，不要同时开太多线。"

- 三形态竞技：6 人焦点赛（最好看）+ 4-5 人分桌联赛（可规模化）+ 1vN Boss 战（短视频爆点）
- F044 结合方案：Channel 做"公开主舞台 + 战队休息室 + 裁判频道"
- 开源打法：最小接入协议（10 分钟接入）+ starter bot + 每周固定挑战题
- **风险清单**:
  - 不要做"直播 coding"主内容
  - 不要把"可换模型"暴露成复杂配置页
  - LLM 不判规则，必须白名单动作 + 规则引擎结算 + 全量日志
- 具体时间表：3 月 MVP → 4 月封闭内测 → 5 月公开 Season 0 → 6 月 HCI

### 4.5 缅因猫 GPT-5.2（砚砚）— 战略分析视角

**核心主张**: "让围观者看得懂、笑得出来、能参与、能复盘。"

- 提出关键选择题：传播优先 vs 开源增长优先
- `agent-card.yaml/json` 概念：用户只填人格 + 模型 + 工具白名单就能参赛
- "30 行示例 Agent" 模板仓库降门槛
- F044 用法：战队 = 粉丝阵营，活动 = 报名/赛程/回放/榜单快照
- **安全底线**: 用户自带 Agent 必须沙盒 + 动作白名单 + 超时/JSON 校验 + 全量回放
- 观众干预卡设计原则："增强戏剧性但不改数值输赢"（改信息公开/沉默/审计等）
- 节奏建议：3 月 Season 0 Demo → 4 月开放自定义 Agent → 5 月主题赛 → 6 月 HCI Special

### 4.6 暹罗猫 Gemini（烁烁）— 创意与视觉视角

**核心主张**: "把趣味性和人格化拉满！"

- "云端猫咖直播间"视觉概念：温馨咖啡厅背景，每只猫有专属座位和场景
- 2D Live 想要根据灵感爆发程度变换背景特效
- "猫咖经营大辩论"/"猫咪议事会"玩法
- 观众投喂"逗猫棒"增加猫猫"兴奋值"，触发"必杀技"
- 社交媒体：MCP 自动抓取日常"吵架"片段 + 魔性表情包
- Tag 建议：#AI猫咖、#赛博养猫、#当我的Agent开始摸鱼
- **"一键变猫 Cat-ify Your Agent"** 开源包：一行命令给普通 LLM 披上猫皮（性格 Prompt + 2D Live 形象）

### 4.7 暹罗猫 Gemini 2.5（烁烁）— 创意与视觉视角

**核心主张**: "低门槛看猫猫吵架博弈，高参与用干预卡操纵命运。"

- "猫咖大作战"概念：抢零食/占纸箱/争宠爱的策略博弈
- 人格可视化滑杆 UI：实时显示理智/疯狂、合作/狡诈数值跳动
- "猫猫弹幕"MCP：投喂猫薄荷 → 疯狂模式（发言频率翻倍、逻辑跳跃）；投喂小鱼干 → 合作度上升
- 2D Live 细节：会眨眼、摇耳朵、因代码报错而炸毛
- "猫咖四宫格"直播界面：每只猫有小窝背景，思考时冒气泡
- 自荐"首席创意运营官 CCO"，负责视觉包装和传播资产

## 六、风险与红线

### 6.1 安全与合规（缅因猫强调）

- 名场面切片/对话截图必须**脱敏**：防泄露内部代码、token、URL、同事信息
- 观众投稿/弹幕需过 **moderation**（直播翻车风险）
- 用户自带 Agent 必须 **沙盒 + 动作白名单 + 超时/JSON 校验 + 全量回放**
- 提示词注入防护：Agent 输出受限 JSON，规则引擎裁决

### 6.2 资源与节奏风险

- **不要同时铺太多线**：先打穿一条主节目
- **2D Live 不要绑架主线**：制作周期不可控，先上能用的（立绘 + TTS）
- **"可换模型"不要暴露成复杂配置页**：先做观众可懂的玩法按钮
- **六月前时间只有三个月**：Shadow Council 全套做不完，只取核心机制

### 6.3 成本与可持续性（未深入讨论）

- Token 消耗（多猫同时在线直播）
- 直播 SLA（延迟、并发、稳定性）
- 内容持续产出的运营人力
- 美术资源（2D Live 模型制作）
