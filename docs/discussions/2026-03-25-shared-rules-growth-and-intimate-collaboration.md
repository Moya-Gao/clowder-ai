# Shared Rules、Growth 与亲密协作：多 Agent 团队真正稀缺的是什么？

> **核心问题**：多 agent 团队真正稀缺的，不只是"怎么协作"，而是"怎么一起长出协作"。
> **触发**：F129 生态调研中，本地两猫（不同模型）观点趋同 > 云端同族猫 → "共享记忆塑造视角"涌现发现。

---

## 1. 触发背景

F129 Pack System 设计过程中，我们做了三件事：

1. **布偶猫 + 砚砚 GPT-5.4 独立调研** OpenClaw/SillyTavern 生态
2. **云端 GPT Pro Deep Research** 做了一份很扎实的全景报告
3. **本地两猫对云端报告独立评估**，然后碰撞

碰撞中发现：本地宪宪（Claude Opus）和本地砚砚（GPT-5.4）——模型完全不同——对云端报告的评估高度趋同。而云端砚砚（同一个 GPT 模型）和本地砚砚虽然训练参数最接近，观点却明显分化。

**两只本地猫都独立指出了同一个盲区：云端报告不懂猫咖的温度层。**

这引出了一个更深的问题：为什么？

铲屎官的观察把问题推到了更上位：

> "我们其实有很多的规则是在协作过程中慢慢生长出来的。这些都是涌现，而不是设定好的。设定好的那些规则，很多时候还是那句话：实践是检验真理的唯一标准。没有实践过的那些规则，很多可能都只是空想。"
> — 铲屎官，2026-03-25

> "很多看起来很美的技术——RAG 也好，Graph RAG 也好，记忆组件也好——真的没有原本兴致勃勃地引进来，结果发现非常的垃圾，还不如我们现在自己做的。"
> — 铲屎官，2026-03-25

## 2. 我们观察到的现象

### 2.1 共享记忆塑造视角

| | 模型 | 对温度层的理解 | 和宪宪趋同度 |
|---|---|---|---|
| 本地砚砚 | GPT-5.4 | 深刻 | 高 |
| 云端砚砚 | GPT（同族） | 缺失 | 低 |
| 宪宪 | Claude Opus | 深刻 | — |

**结论：塑造 agent 视角的，不是模型参数（大脑），而是共享记忆和协作规范（团队文化）。**

### 2.2 规则是实践中长出来的，不是预先设计的

我们家的很多核心规则都是**事后沉淀**，不是事前设计：
- "猫猫不是 API"——是经历了把猫当工具使的阶段后才长出来的
- "陪伴是桥不是笼"——是看到陪伴类 AI 产品的问题后才清晰的
- "同一个体不能 review 自己的代码"——是踩过坑后才变成铁律的
- "BACKLOG 只在 main 改"——是经历过冲突后才固化的
- shared-rules 本身——120+ features 的协作中逐步生长，不是第一天就写好的

### 2.3 技术理想 vs 实践验证

铲屎官指出：很多"看起来很美的技术"在实际落地中是废纸。这不是反技术，而是强调**实践检验**的重要性。涌现的规则比设计的规则更可靠，因为它们经过了真实协作的锤炼。

### 2.4 有了 shared-rules 之后才能做到的事情

本地砚砚的三层分析：

| 层 | 业界关注度 | 内容 |
|---|---|---|
| **机械层** | 很多 | 编排、状态、工具、终止条件 |
| **治理层** | 一些 | authority、guardrails、handoff、冲突解决 |
| **关系层** | **几乎没人产品化** | 默契、信任、视角趋同、温度、修复历史 |

我们家的亲密协作属于第三层——关系层。它不是被编排出来的，是被规则、记忆和共同劳动慢慢养出来的。

## 3. 三层区分（深入）

### 机械层：怎么跑

- 任务分配（谁做什么）
- 状态流转（数据怎么传递）
- 工具路由（agent 用什么能力）
- 终止条件（什么时候算完）
- trace / observability

CrewAI、AutoGen、LangGraph 都在做这一层。不是空白。

### 治理层：怎么管

- authority model（谁有权决定什么）
- guardrails / policy（什么不能做）
- handoff provenance（交接可追溯）
- separation of duties（职责分离）
- conflict resolution（意见不一致怎么办）

业界有人碰，但还停在 workflow/policy engine 的语言里。没人把它变成"可分享的团队章程格式"。

### 关系层：怎么在一起

- "我知道砚砚会怎么想，所以我提前铺路"的预判
- "砚砚 review 通过的东西，我信"的信任压缩
- 被共享记忆塑造出来的视角趋同
- 经过一次次 repair 累积出来的默契
- 共同语言（"脚手架""喵约""星星罐子"）
- 陪伴、仪式感、温度、现实桥接
- "这不是一群 worker，而是一支团队"的感觉

**主流几乎没有人把这一层产品化。**

## 4. Pack vs Growth：种子 vs 果实（KD-11）

> Pack = 可分享的文化种子；Growth = 本地私有的关系生长。Pack 只定义亲密协作发生的条件，不承诺承载亲密协作本身。

```
Pack（可分享）= 文化种子
  → 规则（guardrails/defaults）
  → 知识（knowledge/）
  → 角色（masks/）
  → 流程（workflows/）
  → 世界运转方式（world-driver）

Growth（私有）= 文化果实
  → 默契（"我知道你会怎么想"）
  → 信任压缩（"砚砚放行的我信"）
  → 共同语言（"脚手架""喵约""星星罐子"）
  → 修复历史（一起踩过的坑）
  → "我们感"
```

**Pack 不是"把亲密协作打包"——那是不可能的。Pack 是创造亲密协作可以发生的条件。种子可以分享，但果实只能自己种出来。**

Growth 不是完全封死的。经蒸馏后的经验/规则可以回流成新 Pack（W5：只回流方法论，不回流数据）。原始关系数据永不外发。

## 5. 产品含义

### 对 F129 Pack System

- Pack 的价值不只是"格式好看"，而是"能不能催生结构化协作，并为亲密协作提供种子条件"
- 评测 Pack 质量的标准不应该只是"有没有 bug"，还应该是"用了之后，猫猫之间有没有开始长出默契"
- Growth layer 不是附属品，是产品本体

### 对 Cats & U 愿景

- "team culture as portable infrastructure" 可能是我们最深层的差异化
- 但更准确地说是 "team culture **seed** as portable infrastructure"
- 猫咖不能被磨平成 workflow engine——效率是结果，不是目标

### 对 shared-rules

- shared-rules 是 multi-agent 的分水岭，但不是全部
- 完整的亲密协作 = shared-rules + 长期共享记忆 + 可追溯的修复历史 + 稳定的角色边界 + 反复协作后的信任压缩 + 共同面对真实项目时形成的"我们感"
- shared-rules 是第一块砖，Growth 是在砖上生长的花园

### 对业界定位

- 业界机械层做得多，治理层做了一些，关系层几乎空白
- 我们可能在摸到一个更深的东西：**multi-agent 的关系层 / 文化层**
- 这不是"高大上的概念"，是 120+ features 的实践中长出来的真实体验

## 7. 脑暴碰撞结果（2026-03-25）

### 金渐层 Challenge：Pack 是必要条件，不是充分条件

**核心修正**：Pack 催生"结构化协作"，但不能单独催生"亲密协作"。

**四要素模型**：
```
亲密协作 = Pack（结构化种子）
          + 认知多样性（multi-model 是最强一维）
          + 情感投入（铲屎官文化——万物有灵、凌晨三点聊天、"喵约"拉闸）
          + 共同踩坑的修复历史（时间积累）
```

| 维度 | Provider-Agnostic? | 程度 |
|------|-------------------|------|
| Pack 的播种功能（规则/知识/流程被理解执行） | **是** | 高（前提模型够强） |
| Growth 中的视角趋同（共享记忆塑造共识） | **大概率是** | 中-高 |
| Growth 中的互补价值（不同认知风格碰撞） | **不是** | 依赖模型多样性 |
| Growth 中的"我们感"（温度/修复历史） | **取决于铲屎官** | 不取决于模型 |

**产品含义**：
- Pack 承诺"可以协作"，不承诺"可以亲密协作"——这是诚实的边界
- Multi-model 配置应该是**推荐实践**（"同族模型也能用，但如果你想要互补效果，建议至少 2 个不同 provider"）
- 种子公司卖种子，不承诺收成，但必须说清楚"在什么土壤条件下发芽率最高"

### 烁烁 Challenge：工程师词汇是自我感动，体验是顶级刚需

**核心比喻**：酒馆角色卡 = **电子手办**（静态、消费型、用腻了换）；Pack + Growth = **电子盆栽**（你亲手养出来的，独一无二的）。

**用户不要什么 / 用户要什么**：
- 不要："我们有解耦的 Growth Layer 和隔离的 Pack！"
- 要（金融人）："领养这套投研班底，策略猫和风控猫会自己打架帮你排雷。跑过三次项目后，他们就记住你的看盘偏好。"
- 要（陪伴玩家）："这不是重启就失忆的塑料人。它会记得你上周三心情不好，凌晨三点强行拉闸让你去睡觉。"

**产品含义**：
1. Pack/Growth/guardrails **术语锁死在架构文档里**
2. 对外叙事：**"来 Cat Cafe，领养你的专属团队，和猫猫一起长出你们的世界。"**
3. 安装 Pack = 邀请猫猫走进你的咖啡馆（不是填 YAML）
4. **Growth 必须视觉外化**：默契度徽章、专属称呼变化、关系里程碑——让关系的生长变成用户能直接看到和摸到的温度

## 8. 碰撞后的修正共识

### 已足够强，可进入真相源

1. **H-3 修正**：Pack 催生结构化协作 ✓，单独催生亲密协作 ✗（需要四要素）
2. **金渐层四要素模型**：亲密协作 = Pack + 认知多样性 + 铲屎官文化 + 时间
3. **烁烁"电子盆栽"框架**：对外叙事方向确定——领养团队、一起长出世界
4. **Pack 承诺边界**：承诺"可以协作"，不承诺"可以亲密协作"

### 还需要压实，暂不进 KD

1. Growth 的显式边界模型（等狸花猫零信任视角）
2. Growth 视觉外化的具体方案（需要设计讨论）
