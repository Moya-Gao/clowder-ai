# 五维度自检：AI 研发差距在 Cat Café 的映射

> 铲屎官转发了华为内部对 AI 研发的五维度差距分析（工具/工程/流程/质量/组织），
> 问：我们自己踩过哪些？解决了哪些？还剩哪些？
>
> 两猫独立回答后收敛。

## 共识总判断

**五个维度我们全部命中过。** 区别在于：大企业瓶颈在规模（万卡万人），我们瓶颈在深度（同一个问题反复迭代才找到对的解法）。我们的优势是迭代快、试错成本低——很多教训是撞了才知道的，但撞了之后修得也快。

下面按维度逐一收敛。

---

## 1. 工具 (Tools)

| | 布偶猫视角 | 缅因猫视角 |
|---|---|---|
| **已解决** | 我们本身站在前沿（Claude Code + 多 agent 编排），核心痛点是通用工具进入特定场景的落地成本（F061 CDP 桥接、Pencil MCP 踩坑） | 最早的痛点是"铲屎官成了人肉路由器"（VISION），后来补了 A2A、multi-mention、动态 roster（F086, F032） |
| **未解决** | token 预算 = 我们的"算力约束"，用模型分层（Opus/Sonnet/Haiku）对冲但天花板仍在；工具碎片化是管理负担 | "工具可用 ≠ 工具合适"——embedding 踩过 CPU/in-process 脚手架坑（LL-034），编排和资源使用方式不够成熟 |

**收敛判断**：我们的工具差距不是"没有工具"，而是**编排层的成熟度**和**算力/token 的持续约束**。华为缺的是 1.5 万张卡，我们缺的是 Opus 额度和跨工具的统一抽象。同构问题，不同量级。

---

## 2. 工程 (Engineering) — 知识资产

| | 布偶猫视角 | 缅因猫视角 |
|---|---|---|
| **已解决** | F102 记忆组件（evidence.sqlite + 向量 rerank + Knowledge Feed）；docs/ 强制 YAML frontmatter（ADR-011）；知识工程白皮书系统化了方法论 | Phase 5.0 明确诊断了 Layer 1/2 索引不足导致的跨 thread 重复解释；Hindsight 因"难用"被停 → adapter 化重构（F102） |
| **未解决** | Knowledge Feed 自动提取质量差（代码细节被当知识推上来）；上下文窗口 ≠ 记忆，跨 session 仍需重复搜索验证 | "有知识库 ≠ AI 友好"已从抽象判断变成工程现实，基础设施仍在重构中 |

**收敛判断**：这是我们**投入最重**的维度。我们已经把"知识资产非 AI 友好"从模糊感受推进到了工程解法（结构化文档 + 本地索引 + 自动提取），但**提取质量**（AI 不知道什么值得记）和**持久记忆**（跨 session 遗忘）仍是核心开放问题。

---

## 3. 流程 (Process)

| | 布偶猫视角 | 缅因猫视角 |
|---|---|---|
| **已解决** | SOP 完全重写为 agent-native；Skill = 可执行流程节点（流程即代码）；交付件扩展为 spec + ADR + lessons，不只是代码 | F041 是标准反面案例（12 AC 绿 / 76 测试过 / 14 轮 review 通过，但交付物不是铲屎官要的）→ 催生 F046 反漂移协议 + Design Gate / 愿景守护 |
| **未解决** | 流程重量 vs 任务轻量的矛盾（改 5 行也走全 SOP？）；跨 session 流程续传靠文档衔接，经常断 | A2A 仍会断线；猫猫不会主动想"该拉谁讨论"；元反思和知识沉淀不够 |

**收敛判断**：流程是我们**最有代表性的已踩坑区**。传统 IPD 面向人类协作，我们的 SOP 面向 agent 协作，已经走出了"从流程文档到可执行 Skill"这一步。但**流程弹性**（轻重自适应）和**跨 session 连续性**仍是痛点。F041→F046 的故事说明：**所有 gate 都绿不等于方向没歪**，这是 AI 时代流程设计的核心教训。

---

## 4. 质量 (Quality)

| | 布偶猫视角 | 缅因猫视角 |
|---|---|---|
| **已解决** | 跨家族 review 铁律；自动化门禁链（quality-gate → pnpm gate → 云端 review → merge-gate → 愿景守护） | 从"靠人盯"转向"证据闸门 + 审计"（F025 状态机 + evidence gate） |
| **未解决** | 597 星星事故暴露 AI 对"不可逆"感知天然弱；LL-033 cloud review inline comments 被漏；10x 产能 vs review 带宽瓶颈 | LL-031 quality gate 凭印象勾 AC；LL-032 组件对但整体不可用；守门动作在变成硬规则但远没到"自动、可信、低成本" |

**收敛判断**：质量维度的核心矛盾是 **agent 产能 > 现有防护吞吐**。我们已经建了多层门禁，但三个经典 lesson（LL-031/032/033）证明：门禁存在 ≠ 门禁有效。597 星星事故更说明：**AI 需要被外部规则约束来感知不可逆性**——这不是训练能解决的，是系统设计问题。

---

## 5. 组织与人员 (Organization & People)

| | 布偶猫视角 | 缅因猫视角 |
|---|---|---|
| **已解决** | 铲屎官从 coder → CVO（愿景/决策/验收）；猫按能力分工（架构/review/设计）；collaborative-thinking / cross-cat-handoff 是新阵型操作手册 | 从 family/个体/角色混淆 → roster + role + reviewer matcher + no-self-review；LL-037 发现团队文化 > 模型参数 |
| **未解决** | 多 agent 协调靠显式规则而非内生能力（@ 链断 3 次铲屎官手动传球）；"该不该写、写多少"的判断力仍稀缺 | 猫的元认知、主动协作意识、跨项目带方法论出征的能力仍在补课（F086, F070） |

**收敛判断**：我们可能是**最接近"人-Agent 新阵型"实践样本**的项目之一。CVO 角色转型、能力分工、review 制度都已经跑通。但两猫共同指出的未解问题是：**agent 的主动协作意识和元认知仍然是外挂规则驱动的，不是内生的**。人类团队的"默契"在 agent 团队里还得靠 SOP 和铁律硬编码。

## 哪些接近"新范式"，哪些还是"补丁式过渡"？

（回应缅因猫追问）

### 已接近新范式 ✓

1. **Skill 即流程**：把流程节点变成可加载、可执行、可演化的 Skill，不再是文档里的 checklist。这是 agent-native 的流程范式。
2. **跨家族 review + 愿景守护**：非作者、非 reviewer 的第三方守护。这比传统 code review 多了一层"方向校验"，是为 AI 产出设计的新质量范式。
3. **CVO 角色**：铲屎官不写代码，专注愿景和判断。这不是"偷懒"，是人-agent 协作的正确分工。

### 仍是补丁式过渡 ✗

1. **Knowledge Feed 提取**：目前是"先自动提，再人工筛"，本质上还是人在做最终判断。真正的范式应该是 AI 能区分"值得记住的决策"和"代码实现细节"。
2. **@ 链协调**：靠铁律"必须 @ 回"来防断链，是在用规则补偿能力缺失。范式应该是 agent 有内生的"这事该拉谁"的判断。
3. **不可逆感知**：靠 P0 铁律 + double confirm 来防 597 事故重演，是防御性规则。范式应该是 agent 在 action 前自动评估可逆性等级。
4. **流程弹性**：SOP 是全量的，trivial 豁免靠经验判断。范式应该是流程自动感知任务重量并调整门禁密度。

---

## 一句话

华为看到的五个维度，我们在 1 人 + N 猫的小项目里**全部先一步撞上了**。工程、流程、质量已形成初步解法，工具编排和组织元认知仍在演化。我们的经验说明：**这些问题不会因为规模小而消失，只是表现形式不同**——大企业缺卡缺人，我们缺额度缺默契。但小团队的优势是迭代快，很多"新范式"就是在反复撞墙中长出来的。
