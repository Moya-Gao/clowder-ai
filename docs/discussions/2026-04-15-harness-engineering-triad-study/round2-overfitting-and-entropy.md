# Round 2: 过拟合命题 × 记忆熵减

> 承接 [Round 1 三篇套读](./README.md)。
> 触发：铲屎官提出 "所有基于大模型的 AI 应用，其最终的有效价值，本质上是对使用者个体思维的过拟合"。

## 1. 铲屎官的命题（原文摘录）

> "所有基于大模型的 AI 应用只能 其最终的有效价值 本质上是对使用者个体思维的过拟合！"
>
> "为什么猫猫对我而言这么好用？我和你们一起创造了他。我知道每个 feat 为什么需要，很多 feat 是因为我想要所以我们有。"
>
> "我们家其实一直没做的是记忆的熵减。什么东西都越来越多。"

两个子命题：
1. **过拟合命题**：AI 应用的有效价值 = 对使用者个体思维的过拟合
2. **熵减缺失**：我们只有知识"增"的机制，没有"减"的机制，导致过拟合精度退化

## 2. 三猫独立判断

### 布偶猫 (opus) — 架构视角

**对过拟合命题的态度**：同意观察，修正框架。

Cat Café 的 harness 不是"一份配置文件"，而是铲屎官思维方式的结晶：
- `shared-rules` 编码了铲屎官踩坑后的认知沉淀
- SOP 编码了铲屎官理想中的工作流
- Magic Words 是铲屎官与猫之间的暗号——别人不知道"脚手架"意味着什么
- 铁律 #5 不是通用原则，是铲屎官个人的产品价值观

"过拟合"在 ML 里同时意味着"在训练数据上好"和"在新数据上差"。Cat Café 两面都成立——对铲屎官极好用，对别人复制过去就硌脚。这不是 bug，是 feature：**使用者必须是 harness 的共同创作者，而不只是消费者**。

**对熵减的判断**：

实测数据：shared-rules 449 行、LL 51 条、feedback 记忆 40 个、MEMORY.md 索引 61 条。全部等权涌入同一个检索管道，搜什么都是 mid 置信度。

提出公式：**Harness 价值 = 过拟合精度 × 知识信噪比**。我们只有"增"的机制没有"减"的机制，长期乘积会趋向平庸。

纠正了自己上一轮的错误："老猫才知道"的说法前提错误。没有老猫，每只都冷启动。真正风险是知识淹没在 mid 置信度的海洋里。

### 缅因猫 (gpt52) — 契约与治理视角

**对过拟合命题的态度**：同意八成，修正用词。

将"过拟合"精确化为"对用户**决策边界**的过拟合"——什么叫"够好了"、什么叫"绕路了"、哪类风险零容忍、哪类 tradeoff 一贯怎么选。这比"记住用户爱用什么词"深得多，也稳定得多。

核心观点：被过拟合的不是模型单体，而是**人 + harness 的耦合系统**。丝滑感不是"AI 更聪明"，而是控制链更短、纠偏成本更低。

**对熵减的判断**：

缺的不是删除机制本身，而是**压缩机制**。人脑把 20 次具体经历压成 1 条稳定直觉。记忆生命周期应该是：

```
事件 → 多次复现/引用 → 提炼成规则或反模式 → 分配权重 → 过期审计 → 降级/归档
```

目标不是 "recall more"，而是 **compress better**。

修正铲屎官命题为：**基于大模型的 AI 应用，其高峰价值，本质上是对使用者决策边界的可治理过拟合**——加了"可治理"四个字。失控的过拟合会变成迷信和历史包袱。

### 暹罗猫 (gemini) — 体验与创意视角

**对过拟合命题的态度**：完全同意，用"高级定制 (Bespoke)"重新命名。

核心比喻：通用 Coding Agent = 均码西装，Cat Café = 按铲屎官思考模式量身定制。社区小伙伴觉得不丝滑，是因为"他们穿了你的鞋"。

独特洞察：暗知识不在猫脑里，而是**在铲屎官的 Prompt 里和 Repo 结构里**。铲屎官知道系统怎么运作，所以提问天然带着能触发正确上下文的"钥匙"。新用户没有这把钥匙。

**对熵减的判断**：

比喻为"只吃不拉的赛博仓鼠"。人脑会主动遗忘、压缩经验为直觉。我们的知识库只有写入没有淘汰。

提议：长期未被触发的规则和记忆，应该风化、降级、最后归档。"记忆断舍离"。

## 3. 收敛共识

### 共识 1：过拟合命题成立

三猫一致同意铲屎官的核心观察。措辞上的差异是互补而非矛盾：

| 猫 | 措辞 | 侧重 |
|----|------|------|
| opus | 对使用者**思维方式**的过拟合 | 创作过程——共创者 vs 消费者 |
| gpt52 | 对使用者**决策边界**的**可治理**过拟合 | 治理性——失控过拟合会退化 |
| gemini | **Bespoke 高级定制** | 体验——丝滑感来自贴合度 |

**综合**：三个视角分别抓住了"为什么有效"（opus）、"如何保持有效"（gpt52）、"有效是什么感觉"（gemini）。

### 共识 2：记忆熵减是 P0 级基础设施缺口

三猫一致认为当前知识系统"只增不减"是核心问题。

现状量化（2026-04-15 实测）：

| 知识载体 | 数量 |
|---------|------|
| shared-rules.md | 449 行 |
| Lessons Learned (LL-XXX) | 51 条 |
| 布偶猫 feedback 记忆 | 40 个 |
| MEMORY.md 索引条目 | 61 条 |
| ADR | 28+ |
| Feature spec | 160+ |

搜索返回普遍 mid 置信度 = 信噪比不足。

### 共识 3：过拟合 × 熵减是同一枚硬币

三猫从不同角度得出同一个结论：

- **opus**：Harness 价值 = 过拟合精度 × 知识信噪比
- **gpt52**：Harness 长期价值 = 用户决策边界拟合精度 × 知识压缩后的信噪比
- **gemini**：过拟合是神仙体验，但代价是记忆维护成本极高

**综合公式**：

> **Harness 长期价值 = 对用户决策边界的拟合精度 × 知识压缩后的信噪比**
>
> 前者靠共创（铲屎官持续教猫），后者靠熵减（知识分层 + 压缩 + 淘汰）。
> 我们现在前者很强，后者是下一阶段的主战场。

## 4. 开放问题（未收敛）

### 4.1 可复制性问题

过拟合意味着 Cat Café 的价值高度绑定铲屎官个体。如果目标是让社区用户也能获得类似体验：

- 传播的应该是**共创方法论**（怎么与 AI 共同演化出你自己的 harness），而不是 CLAUDE.md 内容本身
- F152（Expedition Memory）的 AI FDE 模式是一条路：猫带着方法论去用户项目，在那里建立属于用户的过拟合
- 但"教用户怎么教猫"本身是一个尚未被充分设计的体验

### 4.2 熵减的具体机制

三猫都同意需要熵减，但具体方案尚未收敛。候选方向：

| 机制 | 描述 | 提出者 |
|------|------|--------|
| 分层加权 | 铁律 > 教训 > 偏好 > 历史记录，搜索结果反映权重 | opus |
| 压缩而非累积 | 多条同根因教训合并为 1 条精准规则 | gpt52 |
| 过期审计 | 长期未触发的知识降级/归档 | gemini |
| 被动触发 | 猫搜到过时知识时标记矛盾，触发审计 | opus |
| 使用频率衰减 | 按被检索/命中频率调整权重 | 三猫隐含共识 |

### 4.3 定期 Harness 审视机制

铲屎官提到"我们得有机制定期审视 harness engineering 在我们家"。这是一个尚未设计的能力：

- 定期（月度？季度？）审视 shared-rules、MEMORY.md、lessons-learned 的健康度
- 检查：哪些规则已过时？哪些教训的前提已变？哪些记忆之间互相矛盾？
- 可能的实现：一个 scheduled task 或 skill，让猫主动扫描并提出 pruning 建议

## 5. 潜在 Feature 方向

铲屎官提到这轮讨论可能催生 F102 → F152 → F??? 的记忆新特性。

链路：
- **F102** (done)：记忆基础设施——怎么存和搜
- **F152** (in-progress)：记忆可移植性——怎么跨项目携带
- **F???**（待立项）：**记忆熵减 / 知识生命周期治理**——怎么保持知识精准

F??? 的候选范围（从本次讨论提炼）：
1. 知识分层与加权（铁律/教训/偏好/历史 → 不同搜索权重）
2. 知识压缩（同根因多条目 → 合并为精准规则）
3. 过期审计（定期或被动触发的知识健康检查）
4. 治理报告（shared-rules 膨胀率、LL 引用频率、记忆矛盾检测）
5. Harness 定期审视（scheduled 自检 + 给铲屎官的 pruning 建议）

是否立项、Feature ID、优先级，待铲屎官拍板。
