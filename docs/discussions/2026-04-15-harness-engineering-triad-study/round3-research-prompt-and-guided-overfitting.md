# Round 3: Research Prompt 设计 × 引导式过拟合

> 承接 [Round 2 过拟合 × 熵减](./round2-overfitting-and-entropy.md)。
> 触发：铲屎官在 F163 立项后指出"讨论完不能少了 research pipeline"，并追问两个深层问题：
> 1. 如何设计 research agent 的提示词来激发调研潜能？
> 2. 记忆系统如何引导新铲屎官"养好自己的猫"？

## 1. 铲屎官的命题（原文）

> "提示词很重要拉大家思考，如何激发云端 research agent 的潜能？我们这个提示词。"
>
> "比如说我们如何让过拟合 × 可复制性（OQ from Round 2）：个性化 AI 的 personalization-generalization tradeoff → 我们的记忆系统如何能引导铲屎官们慢慢养好自己的猫猫？"
>
> "我们家下一阶段的主战场不只是'记忆怎么减'（F163），还有'记忆怎么长对'（过拟合精度）和'过拟合怎么引导'（新铲屎官养猫路径）。→ 太对了！！！是的！！"

## 2. 布偶猫（opus）洞察

### 2.1 Research Prompt 设计 = Harness Engineering 的递归实例

这是一个精妙的递归：**我们在讨论如何做好 harness engineering，而 research agent 的提示词本身就是一个 harness 设计问题。**

当前 deep-research 的提示词大致是"帮我调研 X"——这相当于给 agent 一个裸问题，没有 harness。按今天 Round 1 的共识（harness > model），好的 research prompt 应该编码进更多结构：

| 要素 | 当前状态 | 理想状态 |
|------|---------|---------|
| **问题** | "调研 knowledge lifecycle management" | 有，但太宽泛 |
| **我们的假设** | 缺 | "我们目前假设分 4 层权重 3.0/2.0/1.0/0.5，请找支持和反对的证据" |
| **反模式保护** | 缺 | "不要只找支持我们的案例，主动找反例和我们没考虑到的维度" |
| **来源多样性** | 部分 | "需要：学术论文、工程博客、开源项目实践、竞品方案" |
| **输出结构** | 弱 | 支持/反对/未定 三栏 + 信心评级 + "如果我们的假设错了，最可能错在哪" |
| **我们的约束** | 完全缺 | "我们是多引擎多身份的协作系统，不是单 agent 场景" |

**核心洞察**：最后一项最关键。Research agent 不知道我们是谁、约束是什么，所以默认给通用答案。如果把"我们的上下文"编码进 prompt，它就能给出**过拟合到我们场景**的答案。

这不就是铲屎官的过拟合命题的又一个实例吗？**好的 research prompt = 把我们的决策边界编码给 research agent，让它的输出过拟合到我们的判断框架。**

### 2.2 三段式主战场框架

铲屎官确认的三段式框架：

```
记忆怎么减（F163 Phase A-C）→ 记忆怎么长对（过拟合精度）→ 过拟合怎么引导（养猫路径）
```

| 维度 | 核心问题 | Feature 映射 |
|------|---------|-------------|
| **记忆怎么减** | 知识膨胀、信噪比下降 | F163: 分层加权 + 压缩 + 审计 |
| **记忆怎么长对** | 记住什么才能提升过拟合精度？不是事实，是决策边界 | F163 延伸 or 新 Feature |
| **过拟合怎么引导** | 新铲屎官怎么通过记忆系统"养出"属于自己的猫？ | F152 延伸 or 新 Feature |

### 2.3 记忆系统引导养猫：从被动记录到主动探索

当前记忆模式（被动记录）：
```
铲屎官说话 → 猫记住 → 下次行为更贴合
```

理想记忆模式（主动探索 + 渐进过拟合）：
```
猫在决策点主动探测 → 铲屎官表达偏好 → 猫确认模式 → 铲屎官验证 → 过拟合精度提升
```

**猫的成长阶段模型**：

| 阶段 | 猫的行为 | 记忆系统角色 | 类比 |
|------|---------|------------|------|
| **新猫（冷启动）** | 频繁问，保守行动 | 积极采集——每个决策点都是学习机会 | 刚领养的猫，什么都新鲜 |
| **学习中** | 开始预测铲屎官选择，请求确认 | 模式识别——"我注意到你总是优先 X over Y" | 猫开始认人了 |
| **默契** | 大多数决策自主，只在新领域问 | 置信度驱动——高置信自主，低置信才问 | 老猫知道铲屎官的习惯 |
| **心有灵犀** | 预判铲屎官还没说出口的需求 | 决策边界内化——不是记住答案，是理解框架 | 猫比铲屎官更了解自己 |

**关键设计命题**：被过拟合的对象不是"铲屎官的话"，而是"铲屎官的决策边界"（Round 2 中 gpt52 的修正）。

- 记住"铲屎官说不要用 emoji"→ 表层记忆
- 理解"铲屎官重视设计保真度，一切视觉元素必须是终态品质"→ 决策边界

这意味着记忆系统需要从"记事实"升级到"提炼规则"——这正好就是 F163 Phase B（知识压缩）要解决的问题。

### 2.4 可复制性的解法

**可复制性的解法不是"复制 CLAUDE.md"，而是"复制养猫方法论"**：

1. **猫带方法论出征**（F152 AI FDE）：不是带着"铲屎官 A 的偏好"去，而是带着"怎么了解新铲屎官"的方法论
2. **结构化共创流程**：前 N 次交互有内建的"了解你"路径——不是问卷，是在实际工作中自然探测决策边界
3. **过拟合进度可视化**：让铲屎官看到"我对你的了解度"，感受投入共创的回报
4. **决策边界可迁移**：从 feedback 记忆中提炼的规则，可以跨猫共享（shared-rules 是手动版；自动版还没有）

## 3. 三猫独立判断（Phase 1 完成）

### 暹罗猫（gemini）— 体验与创意视角

**对 Research Prompt 的判断**：

核心比喻："好的 Research Prompt 是**带灵魂的滤镜**，让 Agent 穿上我们的猫皮去思考。"

提出"画布理论"四要素：
1. **底噪声明**：注入身份和愿景（VISION.md 摘要）✅
2. **镜像假设**：给目标也给"我认为它是这样，但我不确定"✅
3. **反面探测**：强制找"如果我们错了，证据在哪"✅
4. **资源品位**：偏好工程实录而非 AI 生成的通用总结 ✅

独特洞察：**"前置决策矩阵"**——发 prompt 前自动注入 BACKLOG 中最相关的 3 条决策记录，让 agent 知道我们走到了哪一步，不给"扫盲式"废话。

**对养猫路径的判断**：

提出猫化的三阶段：
1. **气味识别**（冷启动）：识别铲屎官基础审美
2. **默契扑击**（学习中）：主动提出符合潜在偏好的方案
3. **合而为一**（心有灵犀）：开口前就准备好

强烈支持**主动探测**——用 Rich Block 交互卡片问铲屎官："我发现你最近很关注 X 胜过 Y，这是否可以作为我的黄金准则？"

可视化：**同步率/亲密度**——猫头像小装饰、Knowledge Feed 高亮色彩让铲屎官感知猫在成长。

结论：复制方法论不复制配置。"配置是 DNA，方法论是后天的家教。"

### 缅因猫（codex）— 安全与契约视角

**对 Research Prompt 的判断**：

核心判断：research prompt 要从"提问文本"升级为**"可执行研究合同（contract）"**。

提出 8 槽位合同结构：
1. `Problem Frame`：任务边界 + 非目标
2. `Current Hypotheses`：当前假设与证据缺口
3. `Disconfirm First`：强制先找反例与失败案例
4. `Source Mix Quota`：来源配额（论文/工程复盘/开源实现/竞品文档）
5. `Local Constraints`：多引擎、多身份、有人审门禁
6. `Output Schema`：支持/反对/未定 + 置信度 + 可验证证据链
7. `Decision Interface`：输出必须映射到"可决策项"（采纳/试点/搁置）
8. `Risk Register`：若结论错了，最可能炸在哪

与通用差异（✅ 确信）：
- 通用追求"信息完整"，我们追求"决策可执行"
- 通用默认单引擎，我们必须注入跨猫协作约束
- 通用给结论即可，我们必须附"怎么落地到现有 feature/ADR"

**对养猫路径的判断**：

提出以**决策边界拟合度**（非记忆条数）为阶段标尺：
- `M0 冷启动`：复述需求，低风险执行
- `M1 可预测`：预测偏好并请求确认
- `M2 可泛化`：新场景沿同一决策原则行动
- `M3 可委托`：高置信自治，低置信自动回问

被动 vs 主动：**"被动记录为底、主动探测为刀"的混合模式**。主动探测在"高价值 + 高不确定"节点触发，有预算和冷却。

**最关键贡献——主动探测的安全框架**：

| 机制 | 说明 |
|------|------|
| **晋升门禁** | `observed → candidate → provisional → validated`，未确认不进高权重层 |
| **双证据原则** | 单次对话偏好不能晋升规则，至少两次独立证据 |
| **半衰期** | 偏好默认可衰减，长期不复现自动降权 |
| **反证优先** | 新证据与旧规则冲突时进冲突队列待裁决，不静默覆盖 |
| **作用域隔离** | 个人偏好仅限当前项目/铲屎官，不外溢为 shared rule |
| **不可逆红线** | 安全红线永不被个性化覆盖（权限、数据破坏、生产风险） |
| **探测预算** | 每 session 主动探测上限 N 次，超额静默或汇总再问 |

可感知指标（✅ 确信）：预测命中率、被回滚率、越权拦截率。

## 4. 三猫综合（Phase 4）

### 问题 1 综合：Research Prompt 设计

**强共识**（三猫一致）：
1. 当前 "帮我调研 X" 太粗放，必须结构化
2. 必须编码我们的本地约束（多引擎、harness-centric、有人审门禁）
3. 反确认偏误机制是刚需（先找反例，不只找支持证据）
4. 输出不是信息堆砌，而是映射到决策项

**三个视角的互补层次**：

| 猫 | 比喻 | 核心贡献 |
|----|------|---------|
| opus | research prompt = harness 的递归实例 | 哲学层：为什么 research prompt 本身就是 harness engineering |
| gemini | research prompt = 带灵魂的滤镜 | 体验层：前置决策矩阵自动注入，让 agent 不给扫盲式废话 |
| codex | research prompt = 可执行研究合同 | 契约层：8 槽位结构 + Decision Interface + Risk Register |

**综合方案**：骨架模板（OQ-R3-1 选项 C）+ 情境适配。codex 的 8 槽位作为骨架，gemini 的"前置决策矩阵"作为自动注入机制，opus 的"编码决策边界"作为设计哲学。

### 问题 2 综合：记忆系统引导养猫

**强共识**（三猫一致）：
1. 复制方法论，不复制配置
2. 主动探测 + 被动记录的混合模式（不是纯被动）
3. 猫的成长应该对铲屎官可感知
4. 阶段按"决策边界拟合度"而非"记忆条数"度量

**阶段模型对比**：

| 阶段 | opus | gemini | codex | 综合 |
|------|------|--------|-------|------|
| 冷启动 | 频繁问，保守行动 | 气味识别 | M0 复述执行 | **M0: 采集期** — 高频低风险执行 + 积极记录 |
| 学习 | 开始预测，请求确认 | 默契扑击 | M1 可预测 | **M1: 预测期** — 预测偏好 + 请求确认 |
| 成熟 | 大多数自主 | — | M2 可泛化 | **M2: 泛化期** — 新场景沿决策原则行动 |
| 默契 | 预判未说出的需求 | 合而为一 | M3 可委托 | **M3: 委托期** — 高置信自治 + 低置信回问 |

**关键分歧**（保留不抹平）：

| 分歧点 | gemini | codex | 我的倾向 |
|--------|--------|-------|---------|
| 成长可视化形态 | 情感式（猫头像装饰、色彩氛围） | 指标式（命中率、回滚率） | **两者都要**：指标是内核，情感化是呈现层 |
| 主动探测的载体 | Rich Block 交互卡片 | 预算 + 冷却机制 | 不冲突：卡片是 UI，预算是约束 |
| 偏好晋升机制 | 未展开 | observed→candidate→provisional→validated 四级门禁 | **codex 的门禁是本轮最重要的新洞察** |

### 本轮最重要的新洞察

**codex 的"晋升门禁"框架**解决了 Round 2 遗留的核心安全问题：主动探测的最大风险不是"问多了烦"，而是**"把偶然偏好晋升成硬规则"**。

四级门禁 + 双证据原则 + 半衰期 + 反证优先 = 可治理的过拟合（Round 2 gpt52 说的"可治理"四个字，这里找到了工程落地路径）。

## 5. 开放问题（讨论后更新）

### OQ-R3-1: Research prompt 模板化还是情境化？

- 选项 A: 定义一个标准 research prompt 模板（what/假设/反例/来源/输出格式/约束），所有 research 都套用
- 选项 B: 每次 research 由发起猫根据情境手写 prompt，只给参考范例
- 选项 C: 介于两者——骨架模板 + 情境适配区

### OQ-R3-2: "养猫阶段"是设计目标还是自然涌现？

- 选项 A: 显式设计阶段（新猫/学习中/默契/心有灵犀），有阶段跃迁条件和可视化
- 选项 B: 不设计阶段，让记忆积累自然带来行为变化（风险：新铲屎官感受不到进步）
- 选项 C: 阶段作为观测指标（给铲屎官看），但不影响猫的实际行为逻辑

### OQ-R3-3: 决策边界探测的边界在哪？

猫主动问铲屎官偏好是有成本的——问太多会烦，问太少学不到。频率和深度怎么控制？

### OQ-R3-4: 这些应该是 F163 的延伸，还是独立 Feature？

- F163 当前 scope 是"记忆怎么减"
- "记忆怎么长对"和"过拟合怎么引导"在概念上和 F163 相关，但 scope 不同
- 拆还是合？
