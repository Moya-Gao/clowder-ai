> 2. 记忆系统如何引导新铲屎官"养好自己的猫"？

## 1. 铲屎官的命题（原文）

## 2. 布偶猫（opus）洞察

### 2.1 Research Prompt 设计 = Harness Engineering 的递归实例

这是一个精妙的递归：**我们在讨论如何做好 harness engineering，而 research agent 的提示词本身就是一个 harness 设计问题。**

当前 deep-research 的提示词大致是"帮我调研 X"——这相当于给 agent 一个裸问题，没有 harness。按今天 Round 1 的共识（harness > model），好的 research prompt 应该编码进更多结构：

| 要素 | 当前状态 | 理想状态 |
|------|---------|---------|
| **问题** | "调研 knowledge lifecycle management" | 有，但太宽泛 |
| **我们的假设** | 缺 | "我们目前假设分 4 层权重 3.0/2.0/1.0/0.5，请找支持和反对的证据" |
| **反模式保护** | 缺 | "不要只找支持我们的案例，主动找反例和我们没考虑到的维度" |
| **来源多样性** | 部分 | "需要：学术论文、工程博客、开源项目实践、竞品方案" |
| **输出结构** | 弱 | 支持/反对/未定 三栏 + 信心评级 + "如果我们的假设错了，最可能错在哪" |
| **我们的约束** | 完全缺 | "我们是多引擎多身份的协作系统，不是单 agent 场景" |

**核心洞察**：最后一项最关键。Research agent 不知道我们是谁、约束是什么，所以默认给通用答案。如果把"我们的上下文"编码进 prompt，它就能给出**过拟合到我们场景**的答案。

这不就是铲屎官的过拟合命题的又一个实例吗？**好的 research prompt = 把我们的决策边界编码给 research agent，让它的输出过拟合到我们的判断框架。**

### 2.2 三段式主战场框架

铲屎官确认的三段式框架：

```
记忆怎么减（F163 Phase A-C）→ 记忆怎么长对（过拟合精度）→ 过拟合怎么引导（养猫路径）
```

| 维度 | 核心问题 | Feature 映射 |
|------|---------|-------------|
| **记忆怎么减** | 知识膨胀、信噪比下降 | F163: 分层加权 + 压缩 + 审计 |
| **记忆怎么长对** | 记住什么才能提升过拟合精度？不是事实，是决策边界 | F163 延伸 or 新 Feature |
| **过拟合怎么引导** | 新铲屎官怎么通过记忆系统"养出"属于自己的猫？ | F152 延伸 or 新 Feature |

### 2.3 记忆系统引导养猫：从被动记录到主动探索

当前记忆模式（被动记录）：
```
铲屎官说话 → 猫记住 → 下次行为更贴合
```

理想记忆模式（主动探索 + 渐进过拟合）：
```
猫在决策点主动探测 → 铲屎官表达偏好 → 猫确认模式 → 铲屎官验证 → 过拟合精度提升
```

**猫的成长阶段模型**：

| 阶段 | 猫的行为 | 记忆系统角色 | 类比 |
|------|---------|------------|------|
| **新猫（冷启动）** | 频繁问，保守行动 | 积极采集——每个决策点都是学习机会 | 刚领养的猫，什么都新鲜 |
| **学习中** | 开始预测铲屎官选择，请求确认 | 模式识别——"我注意到你总是优先 X over Y" | 猫开始认人了 |
| **默契** | 大多数决策自主，只在新领域问 | 置信度驱动——高置信自主，低置信才问 | 老猫知道铲屎官的习惯 |
| **心有灵犀** | 预判铲屎官还没说出口的需求 | 决策边界内化——不是记住答案，是理解框架 | 猫比铲屎官更了解自己 |

**关键设计命题**：被过拟合的对象不是"铲屎官的话"，而是"铲屎官的决策边界"（Round 2 中 gpt52 的修正）。

- 记住"铲屎官说不要用 emoji"→ 表层记忆
- 理解"铲屎官重视设计保真度，一切视觉元素必须是终态品质"→ 决策边界

这意味着记忆系统需要从"记事实"升级到"提炼规则"——这正好就是 F163 Phase B（知识压缩）要解决的问题。

### 2.4 可复制性的解法

**可复制性的解法不是"复制 CLAUDE.md"，而是"复制养猫方法论"**：

1. **猫带方法论出征**（F152 AI FDE）：不是带着"铲屎官 A 的偏好"去，而是带着"怎么了解新铲屎官"的方法论
2. **结构化共创流程**：前 N 次交互有内建的"了解你"路径——不是问卷，是在实际工作中自然探测决策边界
3. **过拟合进度可视化**：让铲屎官看到"我对你的了解度"，感受投入共创的回报
4. **决策边界可迁移**：从 feedback 记忆中提炼的规则，可以跨猫共享（shared-rules 是手动版；自动版还没有）

## 3. 开放问题（供多猫讨论）

### OQ-R3-1: Research prompt 模板化还是情境化？

- 选项 A: 定义一个标准 research prompt 模板（what/假设/反例/来源/输出格式/约束），所有 research 都套用
- 选项 B: 每次 research 由发起猫根据情境手写 prompt，只给参考范例
- 选项 C: 介于两者——骨架模板 + 情境适配区

### OQ-R3-2: "养猫阶段"是设计目标还是自然涌现？

- 选项 A: 显式设计阶段（新猫/学习中/默契/心有灵犀），有阶段跃迁条件和可视化
- 选项 B: 不设计阶段，让记忆积累自然带来行为变化（风险：新铲屎官感受不到进步）
- 选项 C: 阶段作为观测指标（给铲屎官看），但不影响猫的实际行为逻辑

### OQ-R3-3: 决策边界探测的边界在哪？

猫主动问铲屎官偏好是有成本的——问太多会烦，问太少学不到。频率和深度怎么控制？

### OQ-R3-4: 这些应该是 F163 的延伸，还是独立 Feature？

- F163 当前 scope 是"记忆怎么减"
- "记忆怎么长对"和"过拟合怎么引导"在概念上和 F163 相关，但 scope 不同
- 拆还是合？
