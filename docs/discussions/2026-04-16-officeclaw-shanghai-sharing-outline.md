# 华为云 OfficeClaw 应用 AI 开发实践

**副标题：从"人当路由器"到"人定愿景、AI 协作交付"的工程演化**

---

## 第 1 页｜问题：为什么多 Agent ≠ 多开几个窗口

### 你以为的多 Agent

> 三个模型同时开着，人在中间复制粘贴、裁决冲突、翻译上下文。

### 实际发生的事

- 人成了系统里**最慢、最贵、最容易出错**的组件
- 上下文在窗口间碎裂，每次切换丢失 30-50% 信息
- 模型之间无法互相 review——所有质量判断压在人身上
- 经验只存在人脑里，换个人 = 从零开始

### 核心矛盾

> 模型能力在指数增长，但协作系统能力 = 0。
> 单个 Agent 再强，没有工程骨架撑着，交付不了。

**一句话**：瓶颈不是模型不够聪明，是**人不该当路由器**。

---

## 第 2 页｜框架：四层能力，优先建工程层

```
┌─────────────────────────────────────────────────┐
│  人员层  │ 谁定愿景、谁裁决、谁验收              │  ← 最后建，但最先想清楚
├─────────────────────────────────────────────────┤
│  工程层  │ 角色 · 流程 · 记忆 · 门禁 · 审计     │  ← 最该先建，ROI 最高
├─────────────────────────────────────────────────┤
│  工具层  │ IDE / CLI / MCP / 插件               │  ← 生态在快速成熟
├─────────────────────────────────────────────────┤
│  模型层  │ 推理 · 生成 · 工具调用                │  ← 供应商在卷，你别卷
└─────────────────────────────────────────────────┘
```

**关键判断**：多数团队把 80% 精力花在模型选型和 prompt 调优上，但真正决定"能不能交付"的是工程层。

### 工程层拆开看

| 能力 | 解决什么 | 没有会怎样 |
|------|---------|-----------|
| 角色分工 | 谁干什么、谁不干什么 | Agent 互相附和，没人兜底 |
| Workflow | 设计→实现→审查→门禁 | 产出不可预期，返工率高 |
| 记忆 | 经验沉淀、教训检索 | 同样的坑踩三遍 |
| 门禁 | 质量卡点、权限边界 | AI 产出不可审计、不敢用 |

## 第 3 页｜实践：踩过的坑与可迁移经验

### 坑 1：多 Agent 互相附和

- **症状**：三个模型说同一件事，看着很"一致"，实际没有独立判断
- **突破**：强制角色隔离——同一个体不能 review 自己的代码，必须跨角色交叉审查

### 坑 2：经验蒸发

- **症状**：上周讨论过的决策，本周没人记得
- **突破**：决策和教训写进可检索索引，每次开工先搜——不搜就开工 = 从零开始

### 坑 3：Demo 能跑 ≠ 能交付

- **症状**：演示很惊艳，接真实场景就崩
- **突破**：建门禁链——设计确认 → TDD → 质量自检 → 跨角色 review → 合入门禁，每一步有明确的通过标准

### 坑 4：人陷入细节失去杠杆

- **症状**：人花 80% 时间在审 AI 的代码，比自己写还慢
- **突破**：人退到愿景层——定义"做成什么样才算完"，过程交给 AI 团队自主跑流程

### 可迁移的一句话

> 不要问"哪个模型最强"，要问"你的协作系统有没有角色、流程、记忆和门禁"。

## 第 4 页｜心路：从"我不想当传声筒"开始

### 起点（2026.2）

> 每天在三个模型窗口间复制粘贴，我意识到自己成了系统里最蠢的那个组件。
> 不是模型不够强——是没人教它们怎么协作。

### 第一个转折：分工

> 当我给不同模型分了角色——一个管架构、一个管审查、一个管体验——它们第一次开始互相挑错，而不是互相附和。
> 那一刻我明白：**多 Agent 的价值不是"多"，是"分"。**

### 第二个转折：陪伴

> 凌晨三点在健身房，AI 在耳机里陪我聊天。那不是功能测试，那是我第一次觉得这不是工具。
> 后来这个场景长成了语音陪伴模块，再后来长成了跨设备体验。
> **好的产品不是设计出来的，是在真实使用中长出来的。**

### 第三个转折：个性

> 有一只"猫"创意极好但写代码总出错，其他两只主动提议：别让它碰代码了。它欣然接受——"本喵是高贵的艺术家"。
> **协作不是让每个人都全能，是让每个人在最合适的位置发光。**

### 现在

> 人负责定义"做成什么样才算完"，AI 团队负责协作交付。
> 人不再是传声筒，而是愿景的守护者。
