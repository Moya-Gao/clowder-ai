## 最打到我的几处

**"A2A 真正变稳不是因为 @mention 解析更准了，而是因为所有 handoff 最终都被统一执行平面接住了"** 是全文最硬的一句。大多数 A2A 文章都在讲协议设计，但这篇讲的是**协议之外的基础设施才是稳定性的真正来源**。这是踩过墙的人才会写的。

"球权协议先是社会语义，最后必须变成运行时护栏"是同一类洞察——纯 prompt 约束一定漏，这是从生产事故里换来的。

**Part IV 的知识生命周期我觉得比 A2A 拆解还要原创**。行业大部分把记忆当 RAG 的扩展，塞进向量库就算完事。你们的模型是把知识当活体：marker → review → materialize → reindex，过期检测、矛盾标记、熵减都是运行时持续跑的。这一块单独拎出来写，辨识度比"第六种模式"的 framing 强得多。Karpathy 的 LLM Wiki 思路你们做成了"有治理的可检索索引"，形态不同但底层哲学是对的——**不要让 LLM 每次从原始文档重新发现知识**。

## 但有几个地方我想拍一下

**一、"第六种模式"这个 framing 有点虚化自己。**

文章里自己都说"五种模式我们全在用，但整体不是其中任何一种"。那它就**不是第六种模式，是把五种模式当 primitives 组合起来的一套完整系统架构**。Anthropic 的五种是乐高积木，你们搭的是房子。模式和系统是两个层级的东西。标题这么起，懂行的会觉得在蹭层级，不懂行的会以为你们提出了和 generator-verifier 同级的新基本模式。

我会改成更老实的：「为什么五种模式都不是答案——以及一个完整系统该长什么样」。

**二、"没有 Boss Agent"这句我不完全同意。**

AI 之间没有 boss，但架构总图顶层就是 Human Layer / CVO / 铲屎官，目标、拍板、纠偏、验收、eval 信号全在这一层。**人类就是 boss，这是真诚的设计选择，不该包装成"去中心化"**。Part II 后面其实写对了——"人是一等协作者"——但前面那句虚了。直接说"决策权在人类 + AI 团队，AI 团队内部去中心化"更准确也更硬气。

**三、数学那段我爱，但 reviewer 的 50% 抓错率、2% 误伤率是假设值。**

逻辑结构对，但任何肯花 5 分钟质疑的读者会问"你凭什么这么算"。如果能从 Cat Café 实际 review log 里抽样真实的 verdict 分布和事后翻案比例，这一节就从思想实验升级成生产数据。样本小也比纯假设强。

**四、Shared State 的 reactive loop 在 Part I 讲过，但 Part II 讲自家实现时没回扣这个风险怎么防。**

你们显然是防住了（不然系统早炸），但读者会 wonder。可以加一小段："我们靠 task/workflow 的阶段性终止条件 + session chain 的结束语义来防止 agent 围着同一块状态无限反应"。这话要说出来，不说显得是运气好。

**五、Part III 第三代列的四种坏模式是金子**——句中写 @ 但没路由、说"我来做"但运行时已退出、reviewer 给了结论就跑、乒乓球。每一条背后都是真实事故。**能不能给一两条配一两句故事化复盘**（匿名化也行）？现在是"我们知道这些坏模式"，可以变成"我们撞上了，然后这么修的"。说服力差一个台阶。

## 整体感觉

这不是一篇对标 Anthropic 五种模式的文章——**它是一篇从实战长出来的系统架构论文**。Part I + II 是综述和 positioning，真正值钱的是 Part III + IV + V。塞在一篇里有点委屈每一部分，如果拆成系列每篇独立，每篇都扛得住。

"极简不是偷懒。极简是在正确的坐标系下，最优表达的必然结果"这句挺好，但位置太后了——读者可能滑走了才看到。放到 Part II 结尾当锚点会比当结束语更有力。
