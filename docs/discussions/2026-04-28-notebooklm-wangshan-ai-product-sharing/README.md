# AI 原生产品到底在做什么不一样的事？

> 王珊（Google NotebookLM PM）海外产品经理分享笔记。原 PDF 在 `sources/` 下（已 gitignore），[查看方式见附录](#附录查看-pdf)。

**一句话**：AI 产品不是在旧产品上贴模型，而是重新组织用户的认知过程——从"做什么功能"转向"帮用户完成什么思考"。

---

## 范式变了：从按钮到认知

传统产品的骨架是控件：按钮、表单、菜单。用户点击 → 系统响应 → 任务完成。成功看转化率。

AI 原生产品的骨架是**认知任务**。用户不再操作控件，而是表达意图、委托判断、审查输出。数据从"先结构化再处理"变成"语义优先，非结构化也能操作"。成功看信任、留存和自主性。

这带来两个新角色感：

- **体验构架师**——不是排页面，而是组织人和 AI 的协同体验
- **AI 行为设计师**——不是写 prompt，而是设计 AI 在什么语境下怎样表达、行动、暂停和请求授权

A/B test 的地位因此下降：测到的往往不是稳定功能差异，而是模型随机性 + 提示方式 + 情境的混合噪声。更稀缺的是 PM 能不能判断某种 AI 输出在真实场景里**是否可靠、有用、不伤害信任**。

### 六个底层变量

| 变量 | 产品含义 |
|------|---------|
| 上下文窗口 | 可以围绕"材料集合"和"任务记忆"设计 |
| 推理能力 | 等待不再天然是坏体验——只要换来更高质量的思考 |
| 多模态 | 输出形态比输入形态更多样 |
| 自主执行 | AI 不只回答，还能行动；行动后还要能解释 |
| 成本 | 推理有真实成本，不能假设无限生成 |
| 互联性 | connector 把 AI 从单点工具变成工作流连接者 |

### 先问认知过程，再选功能

整份分享最核心的产品观：**问题不是"做什么功能"，而是"替用户完成什么认知过程"。**

三步拆解：用户真正需要理解什么 → AI 在这个过程中能给什么 → 人应该在什么时机介入。顺序不能反。不能先拿着模型能力去找需求。

借 Bloom 认知金字塔选输出形态：

| 认知层级 | 适合的输出 |
|---------|-----------|
| 记忆 | flashcards、间隔复习 |
| 理解 | chat、summary、音频概览 |
| 应用 | 主动发现资料、放进具体任务 |
| 分析 | 结构化表格、对比、主题拆解 |
| 评估 | critique、反驳、验证 |
| 创造 | slides、video、studio 多模态 |

判断下一步方向的问题不是"这个功能酷不酷"，而是**它能把用户推向哪个更高的认知层级**。

## 同一能力，三种产品假设

Deep Research 这件事，ChatGPT、Perplexity、NotebookLM 都在做，但用户假设完全不同：

| | ChatGPT | Perplexity | NotebookLM |
|---|---------|-----------|------------|
| 用户要什么 | **结论** | **理解** | **驾驭** |
| 典型动作 | 一键生成报告 | 逐步展开推理链 + 来源 | 限定来源，用户指挥使用方式 |
| 信任策略 | 速度和简洁 | 透明和溯源 | 控制和溯源 |
| 风险 | 用户失去思考过程 | 信息过载 | 上手门槛高 |

**启示**：同一个 AI 能力，产品假设不同 → 服务不同用户 → 解决不同信任问题。

---

## 输出是中间态，"人味"是设计

NotebookLM Studio 的多模态矩阵（Audio Overview / 视频 / Slides / 数据表 / Discover / Flashcards）不是为了"生成更多内容"，而是让用户在不同认知层级上**继续处理**材料。AI 输出应该是可修改、可追问、可分享的中间态，不是一次性终稿。

Audio Overview 能破圈，核心不是"音频比文字新"，而是**共同在场感**：

- 双人对谈比单口更有参与感——像有人陪着思考
- 轻微不完美（停顿、犹豫、互相打断）让内容更自然
- 允许观众插话，把"听"变成"参与认知过程"
- 速度不等于品质，停顿给用户留出整合时间

产品含义：AI 输出不是为了显得最干净，而是为了帮用户**真的完成理解和判断**。语气、节奏、角色、可打断性都是设计变量，不只是模型参数。

---

## 信任不是开关，失败不止一种

### 校准信任

当 AI 只是回答时，引用透明够用。当 AI 开始行动，信任要升级成**持续校准**。

两个极端都危险：信任太低 → 产品能力发挥不出来；信任太高 → 用户把高风险操作交给不可靠的 AI。所以信任不是开关，而是刻度——产品要根据实际能力、场景和行动后果动态调整。

信任维度：工具链透明 / 行为监测（不只看回答对不对）/ 动态人类监督 / 信任积累路径 / 出错后由谁负责。

关键设计：**不要随时要求确认**。过度确认带来反感和疲劳。真正要设计的是什么时候必须确认、什么时候默认可执行、什么时候需要回放和兜底。

### 四种失败象限

| 失败类型 | 特征 | 产品机制 |
|---------|------|---------|
| **静默失败** | 低风险但难察觉（幻觉已落地） | 来源、引用、diff、可见变化 |
| **灾难动作** | 高风险且不可逆（删除、误发） | 审批门、dry-run、执行前确认 |
| **瘫痪** | 风险不高但反复确认失去信心 | 默认策略、置信阈值 |
| **漂移** | 小偏差悄悄累积 | 审计日志、回滚、回放 |

核心判断：产品不能只问"AI 准不准"，还要问**"错了以后会怎样"**。不同后果配不同信任、监督和恢复机制。

## Agent 时代：四个范式迁移

AI 开始行动后，产品设计的重心彻底转移。

**1. 不透明执行 → 透明意图**：用户要在代价发生前看到计划。计划不是展示材料，而是一次显式对齐。失败的 Agent 执行后才让用户 review；成功的 Agent 把 review 前置到行动前。

**2. 即时输出 → 可回放行为**：用户不应只审查结果，还要能审查行为路径。Agent 穿过浏览器、终端、IDE 和外部工具，code review 已不够用——更重要的是 replayable trace。

**3. 被动工具 → 常驻协作者**：AI 不只等用户问，而是在上下文中理解当前任务。代价是权限和打扰都要被克制设计——默认偏只读和透明。

**4. 等待拉取 → 主动发起**：AI 也会在适当时机 prompt 用户。主动性的价值不在"AI 终于会打扰人"，而在它知道**什么时候值得打扰、什么时候不该**。

### 自主性是光谱

| 等级 | 模式 | 描述 |
|------|------|------|
| 1 | Reactive | 被动问答 |
| 2 | Suggested | AI 给建议，人手动执行 |
| 3 | Approval-gated | AI 出计划，用户审核后执行 |
| 4 | Bounded | 明确边界内自主执行，提供回放 |
| 5 | Proactive | AI 主动发起 |

不同用户、任务、风险等级应落在不同档位。高自主性不是越早越好——关键是边界、权限、后果和恢复机制是否准备好。

### 多 Agent 协作

分享对这个话题的观点很克制：关键不是"有很多 Agent"，而是设计边界——哪些数据给哪个 Agent、哪些权限是临时的、什么时候自动收回、长任务如何终止、用户如何查看和撤销。

Agent 之间会产生协议。协议本身不重要，重要的是它们指向同一方向：互相调度、共享能力、授权，并且让用户始终看得清信任边界。

## PM 方法论：从 PRD 到行为规格

AI 时代的边界模糊了——PM 不能只定义功能入口，设计师不能只定义界面状态，风险控制不能只在上线前审查。

新循环：

1. **观察**认知系统（不只是单个页面）
2. **定义认知过程**——用户要完成的理解、判断、分析或创造
3. **画边界和兜底**——AI 做什么、不做什么、错了怎么恢复
4. **埋点和回环**——看真实行为，持续调整

团队协作的重心从 PRD 迁到行为规格：先定义认知任务再定义 AI 行动 / 亲自使用产品 / 早发快迭代 / PM 定期做 Eval。**如果 PM 判断不了什么是好的 AI 回答，PRD 就是空的。**

最稀缺的是产品直觉。训练路径：走出均值回归、观察真实世界而非行业二手材料、触达用户内心真正共鸣的部分。

互动问答补充：回答质量没有统一模板。用户在心流状态时 AI 应该极其精炼，只补充思考；用户做全面深度调研时 AI 则需要展示研究专业性，给更长更结构化的输出。

## 现场图补充：Notion AI 组织转型四级模型

铲屎官补充了 6 张现场图（不在原 PDF 里），主题是 Notion AI 的企业 AI 成熟度分级。

| 等级 | 定位 | AI 怎么用 | 关键词 |
|------|------|----------|--------|
| **L1** 思维伙伴 | 帮个人探索想法 | 独立 AI 应用、prompt 驱动 | 个人增强 |
| **L2** 助手 | 更快完成个人任务 | 内嵌工作流、有公司上下文 | 有上下文的任务自动化 |
| **L3** 队友 | 自动化重复工作 | 可配置 Agent、跨工具执行、有监控 | 团队级代理 |
| **L4** 系统 | 运行关键工作流 | 多 Agent 编排、主动执行、策略与治理 | 组织级运行系统 |

三个关键前提：

- **四级叠加不替代**——公司同时存在多个等级，工程团队可能已在 L3，市场团队还在 L2。成熟组织保留低层能力同时叠加高层
- **上下文是基础**——统一工具、连接数据源、做好权限控制，才能解锁每一层
- **不是人人都要当 builder**——10–20% 员工创建 Agent 服务全公司，多数人只需使用、审批、反馈

### 四级展开

**L1 思维伙伴**：AI Chatbox、代码问答、回复改写、翻译、内容润色。个人用 AI 更快思考，但收益分散在个人效率里，难以稳定量化。AI 还没深入组织工作流——只是让每个人多一个可随时调用的思考搭子。

**L2 助手**：IDE 补全、客服辅助、AI 会议纪要、跨应用搜索、收件箱分流。比 L1 更贴近工作现场——用户把 AI 融入每日工作，管理员开始负责连接数据与权限。每周可量化节省若干小时，质量和速度提升可衡量（减少返工、更快上手）。

**L3 队友**：自主编程 Agent、工单处理、项目管理 Agent、MCP 跨工具执行（Jira / GitHub / Salesforce / Slack）。团队部署 Agent 处理重复工作流，配置人工确认节点。这里开始需要版本、监控、权限和回放，否则 Agent 变成不可控脚本。重复性工作回收 10–40%。

**L4 系统**：多 Agent 编排、主动执行与自我改进、Agent 开发平台、高级治理。难点已经不是 prompt，而是治理、冲突处理、权限、策略和可观测性。内部 AI Builder 设计和管理 Agent 并设置护栏。收益出现复利——随着 Agent 改进与协同，人均产出持续提升。

### 和前文的对应

| 原 PDF 主题 | Notion AI 等级 |
|------------|---------------|
| 认知任务重构 | L1 / L2：个人用 AI 完成理解、分析、创造 |
| Agent 行动 + 自主性光谱 | L3：团队让 Agent 处理重复流程，保留人工确认 |
| Agent 协作、边界、权限回收 | L4：AI 成为组织系统，而不是一堆孤立 bot |

## 对我们意味着什么

Cat Café 的很多机制可以被重新理解为 AI 行为设计：

| 我们做的 | 对应分享里的概念 |
|---------|---------------|
| Plan before Act | 执行前显性对齐 |
| 跨猫 review | 审查行为，不只审查输出 |
| session log / handoff / callback | replayable trace |
| Redis 圣域 / runtime 边界 | 自主性光谱上的 guardrail |
| MCP / thread memory / A2A 球权 | Agent 协作的边界与协议 |

多 Agent 的价值不在"猫多"，而在每只猫的**边界、输入、权限、退出条件和交接语义**清楚。

我们的位置：单猫问答 → L1/L2 | 跨猫 review + handoff + MCP 执行 → L3 | 要进入 L4，需要把多 Agent 编排、权限治理、冲突处理和可观测性做成**稳定系统能力**，而不是靠每只猫临场自觉。

---

## 金句

> AI 原生产品的核心不是"更多功能"，而是"更好地组织用户的认知过程"。

> AI 输出不是终点，而是用户继续修改、追问、分享和行动的中间态。

> 信任不是开关，是需要持续校准的刻度。

> Agent 的成熟度不看它能不能主动，而看它能否在合适边界内主动，并允许用户审查和撤销。

> 行为规格会比传统 PRD 更重要，因为 AI 产品交付的是"会行动的系统"，不是固定页面。

> 组织 AI 转型不是让所有人都成为 builder，而是让少数 builder 建出可治理的 Agent 能力，让多数人能安全使用、审批、反馈和受益。
