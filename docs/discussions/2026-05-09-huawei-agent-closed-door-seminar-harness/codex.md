# 议题 2 Agent Harness 独立阐述：从项目脚手架到可迁移 Agent Runtime

> **给投资人的一句话**：2027 年真正让企业 aha 的 Harness，不是更厚的 prompt，也不是更复杂的 workflow 编排，而是一个能让 Agent 安全改变现实、留下证据、跨项目复用经验的 **Agent Runtime Control Plane**。

如果给我 1000 万做这个技术项目，我不会把钱投在“再做一个 Agent 编排框架”上。编排框架会被模型能力和平台能力不断吞掉，护城河不够。我会投在更底层、更企业级的东西上：

> **把一个项目里的 Agent 运行经验，沉淀成下一个项目可以继承的运行时、治理层和知识联邦。**

这就是我对 Agent Harness 的 2027 判断。

---

## 1. 我会怎么开场

现在行业讨论 Harness，常见说法是：Agent 在开放环境里自主推进目标，会遇到五个挑战：

1. 状态持久性
2. 目标一致性
3. 行动可验证性
4. 熵增抑制
5. 人机边界

这五个挑战都对，但我会先 push back 一点：**它们是症状清单，不是架构定义。**

它们描述的是一个 Agent 在长任务里会怎么失败：忘记上下文、目标漂移、自我表扬、产物变脏、不知道什么时候该停。但企业真正要买的不是“治疗每个症状的一堆补丁”，而是一个可以长期运转的系统。

我的定义更底层：

> **Harness 是把模型的计算状态接到企业现实状态上的运行时。**

模型负责推理，Harness 负责让推理能安全落到现实里：仓库、文件、任务、审批、测试、审计、权限、记忆、交接、回滚。这些东西不在模型权重里，也不应该只靠 prompt 约束。

---

## 2. 为什么这不是“模型变强就消失”的东西

我会把 Harness 拆成三层，而不是简单说“会变薄”或“会变厚”。

| 层 | 作用 | 未来趋势 | 投资价值 |
|---|---|---|---|
| **补模型短板层** | 教模型格式、流程、工具样例、思考步骤 | 会变薄，被强模型吞掉 | 低，容易过时 |
| **现实闭环层** | 持久状态、验证、审计、安全、隔离、球权 | 会变厚，随 autonomy 半径增长 | 高，是企业上线前提 |
| **可迁移治理层** | 把经验、规则、ADR、Skill、知识库带到新项目 | 会成为 2027 的新增长面 | 最高，是复利和护城河 |

第一层会被模型吃掉，这点我同意。比如大量“请一步步思考”“收到 review 后先做什么”的解释性 prompt，随着模型更强，应该逐步删除。

但第二层不会消失。因为它解决的不是“模型不够聪明”，而是“现实世界需要外部约束”。你不能让被约束的对象自己充当唯一约束者。企业需要的是：

- 谁让 Agent 做了这件事？
- 它读了哪些数据？
- 它调用了哪些工具？
- 它改了哪些文件？
- 它有没有通过测试？
- 它有没有碰到生产环境？
- 它失败后谁能接手？

这些问题，模型再强也必须有外部系统回答。

第三层是我觉得最值得投钱的部分：**可迁移 Harness**。一个项目踩出来的教训，如果只能留在这个项目里，就是成本；如果能带到下一个项目里，就是资产；如果能在一个行业里复用，就是产品和护城河。

## 3. 对议题三个问题的回答

### Q1：哪些是补充模型不足，哪些会长期保留？

我的判断标准是：

> 这层 Harness 是在替模型做它未来能内化的事，还是在维护模型永远不该单独承担的现实闭环？

会变薄的是这些：

- 推理步骤模板
- 工具调用示例
- 格式纠错样例
- 弱模型时代的流程解释
- 因短上下文产生的临时提醒

长期保留的是这些：

- **Durable State**：任务、决策、审计、知识不能只活在上下文窗口里
- **Verification Loop**：测试、lint、review verdict、跨模型复核
- **Safety Boundary**：权限、环境隔离、不可逆操作升级
- **Observability**：trace、调用链、回放、异常信号
- **Collaboration Protocol**：多 Agent 的球权、交接、冲突处理
- **Knowledge Governance**：知识过期、矛盾检测、权威性标注、规则 sunset

所以我不会说 Harness 是模型不足的补丁。更准确地说：

> **Harness 的一部分是补丁，但真正值钱的部分是企业现实闭环的操作系统。**

### Q2：Harness 会变薄，还是演化成控制 / 治理 / 运行时层？

我的回答是：**表面变薄，底座变厚，横向联邦化。**

表面变薄：prompt 里的解释、示例、流程教育会减少。强模型不需要那么多碎碎念。

底座变厚：Agent 能做的事情越多，风险半径越大，越需要运行时控制层。以前 Agent 只是回答问题，错了也只是错一句话。未来 Agent 会改代码、调工具、发 PR、查内部数据、触发工作流。能力越强，越不能裸奔。

横向联邦化：企业不是只有一个项目。真正的问题是：A 项目的经验，怎么让 B 项目继承？一个部门的 Agent 规范，怎么变成集团级能力？这就是从“项目 Harness”到“企业 Harness Federation”的变化。

2027 年让人 aha 的点可能不是“这个 Agent 会自己规划 100 步”，而是：

> 新项目接入后，不是从零训练一套 Agent 工作方式，而是自动继承集团已有的工具边界、知识治理、审计规则、踩坑教训和行业方法论。

### Q3：企业真正稀缺的是更强模型，还是可控性、审计性与隔离？

短期看，可控性更稀缺。模型能力已经在快速同质化，企业真正卡住的是“不敢放它进生产”。

但我会再往前推一步：企业最稀缺的不是单点可控性，而是 **Environment Fit 的复利能力**。

也就是：

> 每接一个新项目，Agent 系统能不能更快适配业务、更少重复踩坑、更稳地遵守安全边界？

如果每个项目都重新做一遍工具接入、知识整理、安全边界、review 流程、审计规范，那么 Agent 是成本中心。

如果这些能力能沉淀成统一 runtime、skill、ADR、知识联邦和治理策略，那么 Agent 才会变成利润中心。

## 4. 如果投 1000 万，我会做什么

我会把项目定义为：

> **企业级 Agent Harness Control Plane：让 Agent 能在真实业务系统里安全、可审计、可迁移地长期工作。**

它不是一个聊天机器人，也不是一个通用 workflow builder。它是企业 Agent 的运行时底座。

### 模块 1：统一运行入口

所有 Agent 请求先进入统一入口，完成身份、权限、路由、限流、审计。不能让不同部门各自直连模型 API 和工具 API。

核心价值：企业终于知道“谁在用 Agent 做什么”。

### 模块 2：现实状态层

把任务、决策、交接、文件修改、测试结果、审计记录持久化在模型上下文之外。上下文重置不等于项目失忆。

核心价值：Agent 可以跨天、跨 session、跨人接续工作。

### 模块 3：验证与责任链

每个关键动作都要有证据：测试结果、review verdict、工具调用记录、产物 diff、审批记录。纯文本“我完成了”不算完成。

核心价值：从“Agent 说它做了”变成“系统能证明它做对了”。

### 模块 4：安全与隔离

把生产数据、测试环境、敏感工具、不可逆操作分层隔离。按风险动态调整审批边界，而不是靠一个静态白名单。

核心价值：企业敢让 Agent 做更长、更深、更接近生产的任务。

### 模块 5：知识治理与联邦

把知识分成真相源和索引层。检索结果不只返回文本，还返回来源、权威性、置信度、是否过期。不同项目之间能共享方法论，但不泄漏业务数据。

核心价值：一个项目踩过的坑，下一个项目自动避开。

### 模块 6：Harness 自演化

每条规则都要有触发记录和 sunset 条件。规则不是越加越多，而是能证明自己该保留、该降级、还是该删除。

核心价值：Harness 不会因为成功而变成新的技术债。

## 5. 怎么证明这个项目值钱

我不会用“模型 benchmark 提升几分”作为主要指标。那是模型厂商的指标，不是企业 Harness 的指标。

我会用这些指标：

| 指标 | 含义 | 为什么投资人该关心 |
|---|---|---|
| 新项目冷启动时间 | 从接入到 Agent 能可靠做事需要多久 | 决定复制速度 |
| 可验证完成率 | Agent 产出中有测试 / review / 审计证据的比例 | 决定能不能进生产 |
| 重复踩坑率 | 同类错误在不同项目中是否下降 | 决定知识是否真的复利 |
| 人类接管率 | 需要人类救火的比例 | 决定运营成本 |
| 风险拦截率 | 越权、误触生产、敏感数据流出的拦截情况 | 决定企业敢不敢放权 |
| Harness 规则退役率 | 规则能否随着模型变强而删除 | 决定系统是否可持续 |

如果 12 个月后我们能证明：

- 新项目 Agent 冷启动从数周降到数天
- 关键任务 80% 以上有可回放证据链
- 跨项目重复踩坑明显下降
- 高风险操作都有可审计边界
- Harness 规则不是只增不减，而是能持续退役

那这个项目就不是研究玩具，而是企业 Agent 基础设施。

## 6. 2027 年的 aha 应该是什么

我认为 2027 年的 aha 不是“Agent 会自己写更多代码”。这个会发生，但不够新。

真正的 aha 是：

> **企业第一次发现：Agent 能力不是按单个模型购买的，而是按组织的 Harness 成熟度释放的。**

同一个模型，在没有 Harness 的企业里，只能当聪明助手；在有 Harness 的企业里，可以变成长期协作者；在有可迁移 Harness 的企业里，会变成跨项目复利资产。

这也是我认为华为云这类云厂商可以做创新技术项目的原因。模型本身会竞争激烈，但企业级 Harness Control Plane 有天然云厂商优势：

- 接近企业身份、权限、网络、审计系统
- 能做跨工具、跨项目、跨部门的统一治理
- 能把行业解决方案沉淀成可复用模板
- 能提供本地化、私有化、合规、安全隔离能力

模型厂商卖的是能力上限，云厂商可以卖的是：

> **让企业敢用、会用、持续用强模型的运行时能力。**

## 7. 我建议在闭门研讨会上这样讲

如果只有 3 分钟，我会这样阐述：

> 我认同 Harness 要解决状态持久性、目标一致性、行动可验证性、熵增抑制和人机边界这五个挑战。但我不会把 Harness 定义成这些挑战的补丁。  
>
> 更底层地看，Harness 是把模型的计算状态接到企业现实状态上的运行时。模型负责推理，Harness 负责持久化、验证、审计、隔离、协作和治理。  
>
> 随着模型变强，解释性 prompt 会变薄，但控制层、治理层、运行时层会变厚。因为模型越强，能改变现实的半径越大，企业越需要知道它做了什么、为什么做、谁批准、怎么回滚。  
>
> 2027 年真正有投资价值的 Harness，不是单项目里的编排脚本，而是可迁移的 Agent Runtime Control Plane。它能把一个项目里的规则、教训、审计策略、工具边界和知识治理带到下一个项目，让 Environment Fit 从一次性成本变成可复利资产。
