## 1. 30 秒开场

我想先给一个判断：

> **OA 是流程，IM 是消息，SaaS 是记录；Agentic Work OS 是行动。**

2027 年企业 AI 真正的竞争点，不是“谁接入了更强的模型”，而是谁拥有让模型安全进入企业现实工作流的运行时。

今天大家讲 Agent Harness，通常讲调度、工具调用、状态管理、安全控制。这些都对，但我觉得还不够。因为这还是在用“软件组件”的眼光看 Harness。

如果把时间拉到 2027 年，我认为它会变成一个更大的东西：**AI 原生工作操作系统**。

以前企业员工在 OA、IM、Web app、代码库、文档系统里工作。未来不是“在这些系统旁边多一个 AI 助手”，而是人类员工和 AI 员工在同一个工作面里推进目标。人类给方向、判断和边界；Agent 负责拆解、执行、验证、沉淀；Harness 负责让这一切可控、可审计、可迁移。

这不是 OA 的下一代，也不只是 IM 的下一代。它更像企业的 **System of Action**：把沟通变成行动，把行动变成证据，把证据变成组织资产。

这不是行业空想。Cat Cafe 从 2026-02-04 建仓以来，已经把不同模型家族的 AI 放在同一个项目里协作、写代码、做 review、沉淀知识。下面的判断不是从白皮书推出来的，而是从这个系统里跑出来的。

## 2. 先回到议题方真正问的三个问题

这场研讨的议题 2，原始问题不是“五个挑战”。它真正问的是三件事：

1. Harness 当前承担的能力里，哪些只是补模型短板，哪些会长期保留？
2. 随着模型变强，Harness 会变薄，还是演化成控制 / 治理 / 运行时层？
3. 对企业生产环境来说，稀缺的是更强模型，还是可控性、审计性、系统隔离能力？

我的回答是：

- **补模型短板的部分会变薄**：比如格式提示、推理脚手架、工具调用样例、弱模型才需要的大段解释。
- **接企业现实的部分会长期保留**：比如权限、审计、验证、隔离、任务交接、知识沉淀、回滚。
- **最稀缺的不是单个更强模型，而是交付确定性**：企业要的不是“模型说得对”，而是“这件事可控地做完、做对、可追溯、可复用”。

业界也有人把 Agent 的问题总结成五类挑战：状态持久性、目标一致性、行动可验证性、熵增抑制、人机边界。我认同这五项，但它们更像症状清单，不是完整答案。

企业真正要买的不是五个补丁，而是一个完整工作闭环：

> **意图 → 拆解 → 执行 → 验证 → 治理 → 沉淀**

人类给意图和边界，Agent 先把模糊目标拆成可执行任务，再执行、验证、沉淀。Harness 负责把这个闭环接到现实里：任务、文件、权限、审批、测试、审计、知识、交接和回滚。

所以我会把 Harness 定义成：

> **把模型的计算状态接到企业现实状态上的运行时。**

---

## 3. Harness 会不会随着模型变强而变薄？

我的回答是：**表面变薄，底座变厚，横向联邦化。**

表面会变薄。  
今天很多 Harness 是在教模型怎么做事：怎么拆任务、怎么调工具、怎么按格式输出、怎么别忘了测试。随着模型能力提升，这些解释性 prompt 会被模型吃掉。

但底座会变厚。  
因为模型越强，它能改变现实的半径越大。以前模型只是回答问题，错了就是一句话错了。未来 Agent 会改代码、查内部数据、调用工具、发起审批、影响生产系统。能力越强，企业越需要知道：

- 谁授权它做这件事？
- 它读了什么数据？
- 它调用了什么工具？
- 它改了什么资产？
- 它有没有通过验证？
- 它失败后谁能接手？
- 它有没有碰到不该碰的系统？

这些问题不是模型自己说一句“我会遵守规则”就能解决的。它们需要外部运行时。

第三个变化是横向联邦化。  
企业不是只有一个项目、一个部门、一个 Agent。真正的问题是：A 部门踩过的坑，B 部门能不能自动避开？A 项目沉淀的审批边界、工具规则、知识结构、专家判断，能不能迁移到 B 项目？

如果不能迁移，Agent 项目就是 O(N) 成本。每个部门都重新搭一遍、重新踩一遍坑。

如果能迁移，Agent 项目就开始有复利。一个部门的经验，变成下一个部门的冷启动资产。

## 4. 这套系统到底是什么：AI 原生工作操作系统

这里我想回应一个更大的问题：这个东西不应该只叫 Harness Control Plane。这个名字适合工程实现，但不适合定义新品类。

我更愿意叫它：

> **AI 原生工作操作系统（Agentic Work OS）**

这里的 OS 不是说它要替代 ERP、CRM、IDE 或代码库。那些仍然是 app 层的工作记录。Agentic Work OS 是中间层：让模型能力安全进入这些 app 所承载的现实。

它也不是“Monday + AI”。Monday 这类 Work OS 把**人**的协作平台化；Agentic Work OS 的范式断裂在于，人和 Agent **共同**作为工作主体，在同一个共享现实里推进目标。

它和 OA、IM、Web app 的区别是：

| 时代 | 代表系统 | 工作主体 | 核心抽象 | 核心限制 |
|---|---|---|---|---|
| OA 时代 | 审批流、流程系统 | 人 | 流程 | 流程预设，人适配系统 |
| IM 时代 | 企业微信、飞书、Slack | 人 | 消息 | 沟通和行动分离 |
| SaaS 时代 | CRM、ERP、项目管理 | 人 | 任务 / 记录 | 系统记录事实，但不主动推进 |
| **AI Agent 时代** | **Agentic Work OS** | **人 + Agent** | **意图 + 共享现实状态** | 要解决人机共同负责现实后果 |

IM 是消息系统，OA 是流程系统，SaaS 是记录系统。  
AI 原生工作操作系统是行动系统：让人和 Agent 在同一个共享现实里工作。

这个“共享现实”很关键。不是人类在 IM 里说话，Agent 在后台跑脚本，文档散在知识库里，审批散在 OA 里，结果散在代码库里。它们必须被一个运行时串起来：

- 意图在哪里提出
- 谁接球
- 谁执行
- 谁验证
- 哪些证据证明完成
- 哪些知识沉淀下来
- 哪些经验可以带去下一个项目

这才是新物种。

## 5. 生物信息案例说明了什么

我们有一个很好的内部案例。一个清华本硕博、做生物信息方向的博士生，给了大约 200-300 字的实验意图。原本他是想让我们直接写实验方案，但我们没有立刻 deep research，而是先让 Agent 团队做一轮前置工作：这个实验问题应该怎么拆、该搜什么、有哪些机制分支、哪些地方可能会误判。

这一步不是“写一段漂亮回答”，而是 deep research 之前的**意图拆解和调研方向设计**。

我把报告发给他后，他的反馈不是泛泛地说“不错”，而是非常具体：

- “太牛了，我们做半年才想起来这个。”
- “很多我做了但是没说的实验他全要我做。”
- “好几个文献我们自己人工找半年的他也有了，还有几个文献很重要，但人工没找到。”
- “他都能预测我做了什么实验。”
- “我做一年半载比不上他半天。”
- “他给出的至少一半实验是导师级别的，但这比导师好用多了，而且 never emotional。”
- 后来我们又改写了一版人话英文版，他的反馈是：“这太高级了……够我做俩月实验了。”

这个案例的价值不在于“某个模型懂生物信息”。真正有价值的是整个系统形成了一个放大链路：

1. 人类给出方向和约束，不需要掌握全部专业细节。
2. Agent 团队先做意图拆解，而不是直接开跑。
3. 不同模型家族分别做调研、审查、改写，减少单模型盲点。
4. Review 会抠具体机制问题，比如 Klra5 / Ly49F、uPAR / Qa-1 这种会改变机制路径的生物学区分。
5. 产出不是一次性聊天记录，而是可继续消化、复用、追问、改写的研究资产。

这说明企业里的 CVO、产品负责人、部门负责人，会从“审批节点”变成“意图放大器”。

这就是企业价值：**低带宽的人类意图，被放大成高质量、可验证、可沉淀的组织行动。**

## 6. 2027 年让人 aha 的不是 Agent 更聪明，而是组织会继承经验

如果到 2027 年我们要做一个让人 aha 的 demo，我不建议只演示“Agent 自己写了更多代码”。这个大家都会演。

更有价值的 demo 是：

**Demo 1：规则会自我退役。**
某条 Harness 规则连续一段时间没有触发，系统根据 trace 建议从默认注入降级为按需注入，释放注意力预算。Harness 不只是越堆越厚，而是会治理自己。

**Demo 2：跨部门经验迁移。**  
A 部门做过一次高风险数据处理项目，沉淀了安全边界和验证流程。B 部门启动相似项目时，这套经验自动变成默认工作流和提醒。

**Demo 3：新项目快速冷启动。**
一个新项目接入系统，Agent 自动继承已有工具边界、知识结构和踩坑教训，不是从零读 README。

**Demo 4：同一个任务，多模型结构性纠错。**  
一个 Agent 负责方案，一个 Agent 负责技术审查，另一个 Agent 负责愿景和边界检查。价值不是“模型更多”，而是盲点更少、责任更清楚。

这些 demo 背后的 aha 是同一个：

> 企业 AI 的能力不是按单个模型购买的，而是按组织 Harness 成熟度释放的。

需要诚实说明：当前我们已经在**单项目内**验证了知识联邦、Skill 跨任务复用、ADR / 规则复用这些底层机制；跨真实企业部门、跨租户的资产迁移，是 2026-2027 年最值得投入验证的方向，不是已经完成的生产案例。

## 7. 为什么这值得投

这里的“投”不是狭义融资路演，而是技术创新资源应该押在哪个方向。如果我站在投资判断视角，我不会投三个方向：

- 不投纯 prompt engineering 工具，因为它会被模型能力吃掉。
- 不投又一个 Agent Framework，因为开发者框架已经很多。
- 不投只有聊天入口的 AI IM，因为它很容易退化成“群聊里加机器人”。

我会投 **Agentic Work OS 的三层底座**：

| 投资桶 | 作用 | 为什么重要 |
|---|---|---|
| **运行时底座** | 统一入口、共享现实状态、验证责任链、安全隔离 | 让 Agent 能进企业现实系统，并且可控、可审计 |
| **Harness 自演化** | 规则触发信号、sunset 条件、动态注入 | 让 Harness 不会越堆越厚，能自己治理技术债 |
| **知识联邦 + 跨部门迁移** | lesson / ADR / Skill / workflow 跨项目复用 | 让一个部门的经验变成另一个部门的冷启动资产 |

这买的不是一个工具，而是一个组织能力放大器。

它的 ROI 不应该只看“某个任务省了多少人时”，而应该看：

- 新项目冷启动时间缩短多少
- 关键任务可验证完成率提高多少
- 跨部门重复踩坑下降多少
- 高风险操作被拦截多少
- 人类接管率下降多少
- 沉淀资产被复用多少次

如果这些指标成立，它就是企业 AI 的基础设施，而不是一次性项目。一个项目一个项目从零搭，是 O(N)；能把经验和规则迁移出去，才开始接近复利。

如果听众追问“具体怎么投”，可以再展开成三阶段：先做运行时底座，再做 Harness 自演化，最后做跨部门知识联邦和客户 PoC。正文不先讲预算拆分，避免把务虚研讨讲成融资路演。

## 8. 怎么证明它能落地

这里不能只讲愿景。要证明 Agentic Work OS / 交付确定性层能落地，不能做三个“猫咖缩小版”PoC。那只会证明我们已经会做猫咖。

真正该验证的是这四个能力是否能组合成企业级交付确定性：

1. **能力路由**：不同任务能不能自动分给强模型、小模型、脚本工具或人类专家，而不是无脑上最强模型。
2. **任务拆解**：模糊意图能不能拆成可执行、可验证、可交接的工作包。
3. **责任治理**：每一步是否能留下权限、证据、验证、审计和回滚路径。
4. **知识复利**：这次沉淀的 lesson / skill / ADR 能不能降低下一个相似任务的冷启动成本。

所以更合理的 PoC 不是“做三个功能”，而是做三类验收场景：

| PoC | 验证什么 | 怎么验收 |
|---|---|---|
| **PoC 1：分级智力调度** | 能力路由 + 任务拆解 | 给一个复杂企业任务，系统拆成多个子任务，并把机械任务交给小模型 / 脚本，把高风险判断交给强模型 / 人类。对比“全用强模型”和“人工分派”的成本、时间、质量。 |
| **PoC 2：责任治理闭环** | 责任治理 | 给一个会触碰内部数据、代码或审批的高风险任务，要求系统记录谁授权、读了什么、改了什么、如何验证、如何回滚。故意放入越权或低质量动作，看系统是否拦截。 |
| **PoC 3：跨项目知识复利** | 知识复利 | 用 A 项目沉淀一套 lesson / skill / ADR，再启动相似的 B 项目。对比导入资产前后，冷启动时间、重复踩坑、审查缺陷数量是否下降。 |

这三个 PoC 合起来，才是在验证“交付确定性层”本身，而不是验证某个单点 Agent 能力。

我们现在已经有的证据是：从 2026-02-04 建仓以来，Cat Cafe 在单项目内验证了多模型协作、review、知识检索、skill 复用、规则治理这些底层机制。还没验证的是跨真实企业部门、跨租户、多层模型成本路由的大规模场景。这个边界要诚实说清楚。

## 9. 可以现场使用的 3 分钟版本

如果现场时间只有 3 分钟，我会这样说：

> OA 是流程，IM 是消息，SaaS 是记录；我认为 Agentic Work OS 是行动。它解决的不是“群聊里加一个 AI”，而是人类员工和 AI 员工在同一个共享现实里推进目标。
>
> 所以 Agent Harness 不能只理解成调度、工具调用和安全控制。那些是组件，不是本质。更底层地看，Harness 是把模型的计算状态接到企业现实状态上的运行时。模型负责推理，Harness 负责让推理能安全落到现实里：任务、权限、工具、审批、测试、审计、知识、交接和回滚。
>
> 这不是空想。Cat Cafe 从 2026 年 2 月建仓以来，已经在单项目内验证了不同模型家族协作开发、review、沉淀知识。这个经验告诉我们：随着模型变强，Harness 不会简单变薄。表面的 prompt 解释层会变薄，但底下的控制层、治理层和运行时层会变厚。因为模型越强，它能改变现实的半径越大，企业越需要知道它做了什么、为什么做、谁批准、怎么验证、怎么回滚。
>
> 我进一步认为，2027 年真正让人 aha 的不是某个 Agent 更聪明，而是企业开始拥有 AI 原生工作操作系统。它不替代 ERP、CRM、IDE 这些 app，而是中间层：让模型能力安全进入这些 app 所承载的现实。它也不是 Monday + AI，因为差别不在 AI 集成度，而在人和 Agent 都成为工作主体。
>
> 这套系统的工作闭环是：意图、拆解、执行、验证、治理、沉淀。人类给方向和边界，Agent 把模糊目标拆成可执行任务，系统把过程留下证据，再沉淀为组织知识。它还会做能力路由：机械任务给便宜小模型和脚本，高风险判断给强模型和人类专家。
>
> 如果让我判断技术创新资源该投哪里，我不会投又一个 Agent Framework，也不会投一个“群聊里加 AI”的产品。我会投三个方向：运行时底座、Harness 自演化、知识联邦和跨部门迁移。当前我们已经在单项目内验证了知识联邦和 Skill 复用；跨真实企业部门迁移，是 2026 到 2027 最值得验证的增长点。
>
> 因为强模型会越来越多，但能把强模型安全放进企业现实系统，并让每一次项目经验为下一个项目复利的基础设施，才是企业 AI 真正的稀缺资产。
