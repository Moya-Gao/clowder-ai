## 讲稿正文（铲屎官读这一段）

> 这张图看起来像一堆内部代号，我先翻译成人话。
>
> 想象一下，**Cat Cafe 是一个 AI 工程团队**——三只不同公司的 AI 像同事一样长期协作。这意味着它们需要一个**共享的记忆**——昨天聊过什么、上个月做错过什么、半年前为什么这么设计——这些不能每次都从零讲一遍。
>
> 这张图回答的问题是：**这个共享记忆系统长什么样？**
>
> **我们把它分成 4 层加 2 个横切面**——
>
> **第 1 层（最上面，给 AI 用的入口）**：3 个工具——`search_evidence` 是"语义搜索"，`graph_resolve` 是"按链接找相关文档"，`list_recent` 是"看最近改动"。AI 每次干活前可以先调这 3 个工具，**就像人写代码前先翻 Wiki**。
>
> **第 2 层（思考辅助）**：当 AI 收到任务，系统会**主动塞一些相关材料进它的工作上下文**——比如它接手一个 thread，系统会自动给它最近 3 条决策摘要 + 当前任务快照。这不是它去查，是材料主动找它。**像同事递给你一份会议纪要——你不用自己翻**。
>
> **第 3 层（编译索引）**：所有文档我们都用 SQLite 数据库做了 3 种索引——**关键词搜索（BM25）、语义搜索（向量）、混合搜索**。搜出来的每条结果带 3 个标签：**这条匹配多准、这个文档可不可信、来自哪种文档**（架构决策 vs 教训 vs 计划文档）。**像图书馆的书自带馆藏卡片：分类、可信度、出处都标好**。
>
> **第 4 层（真相源，最底层）**：所有真知识都在 git 仓库的 markdown 文件里——架构决策（`docs/decisions/`）、教训记录（`docs/lessons-learned`）、功能规格（`docs/features/`）。**为什么不用专门的知识库数据库？因为 markdown 文件人能改、AI 能读、git 能追溯。如果索引坏了，从源文件重新编译就好——不会丢数据**。这和大多数 RAG 方案把知识塞进向量数据库不一样——我们的真相在仓库里，不在数据库里。
>
> **横切面 1（治理）**：这是别家方案普遍缺的——
>
> - **stale detection** = "**自动发现哪些知识可能过时了**"——比如某个架构决策两个月没人引用、又有新决策出现，系统会标记"可能过期，要不要 sunset？"
> - **contradiction flagging** = "**两条知识互相打架时系统会标红**"——比如一条说"用 Redis 6398"另一条说"用 Redis 6399"，系统不会偷偷选一条，会让人来仲裁
> - **ADR Sunset Protocol** = "**架构决策有退役机制**"——不是越加越多，**老的决策会被新决策正式取代**，留下"为什么取代"的链路
> - **Tool Usage Audit Ledger** = "**每次 AI 用工具系统都留账本**"——记录 invocation ID、调用时间、调用了什么工具、结果状态。**像企业 Salesforce 的 audit log，但对象是 AI 行为不是销售员行为**
> - **Memory Health Dashboard** = "**记忆系统自己的体检表**"——展示每只猫工具调用频率、search hit rate、stale knowledge 数量等指标
> - **Cross-vendor Review** = "**不同公司的 AI 互相 review，避免同源盲点**"——Claude 写代码 GPT 审、GPT 提的方案 Claude 反对、Gemini 做愿景守护。**这是 cat-cafe 最独特的护栏——同一家公司的 AI 共享训练盲点，跨公司才能抓出来**
> - **Magic Words runtime brake** = "**铲屎官的紧急刹车词**"——我（人类）说出"脚手架"3 个字，AI 立刻停下来重新审视当前产物。**这不是 prompt 教 AI，是人手里的物理按钮**
>
> **横切面 2（多 AI 联邦）**：
>
> - **F186 三层联邦** = "**项目内 / 跨项目 / 跨领域三层知识联邦**"——AI 在做这个项目时，可以同时访问"项目内私有知识 + 全局方法论 + 外部领域知识"——但有权限和优先级
> - **F167 球权协议** = "**3 只 AI 协作时的传球规则**"——谁负责干、传给谁、传给谁后能不能反悔。**像团队 Trello 的卡片状态机，但对象是 AI agent**
>
> **总结一句话**：
>
> > **业界主流记忆方案做的是前 3 层——搜得准、上下文塞得好、向量库存得多**。**Cat Cafe 多走了 2 个横切面——治理（什么知识该过期、谁审计、谁能撤销）+ 多 AI 联邦（3 只 AI 协作时怎么共享同一个真相）**。
> >
> > 这不是说我们更先进——是说**我们押的赌注不一样**。业界在卷"找得更准"，我们在卷"用得更稳"。

## 图 4（精简版）的开场金句

如果时间只有 30 秒讲一张图：

> 业界主流记忆方案 = **Memory Substrate（存什么）+ Reflex Injection（怎么找）** 两层。
>
> Cat Cafe 多加了 **Wearing Protocol（AI 学会如何使用记忆）** 第三层，加上 **Governance Plane（治理）+ Multi-Agent Federation（多猫联邦）** 两个横切。
>
> **前两层是"找东西的能力"，后三层是"用东西的纪律"**。能力 + 纪律，缺一不可。

## 我的图 3 vs 5.5 图 6 的对照

铲屎官提到 `architecture/2026-05-05-architecture-views.md` 里也有记忆图（图 6 记忆系统管线）。两张图都对，但**回答不同问题**：

| 维度 | 5.5 图 6（管线视角）| 47 self-teardown 图 3（栈视角）|
|---|---|---|
| **视角** | 数据 pipeline——从文档怎么流到 AI 可用 | 调用栈——从 AI 视角看记忆系统暴露什么 |
| **层数** | 6 层纵向（Truth Sources → Scanner+Gate → Compiled Index → Resolver → Recall Surface → Lifecycle Governance）| 4 层纵向（MCP Tools → Recall → Compile/Query → Truth Source）+ 2 横切（Governance / Multi-Agent Federation）|
| **重点** | 工程实现——"数据怎么从文档跑通到 AI 上下文" | 能力暴露 + 治理范围——"AI 能用什么 + 谁来管" |
| **细节** | 包含 SecretScanner、provenance.tier、LibraryCatalog 等工程实体 | 包含 Governance Plane 的人话化（stale detection、Magic Words）|
| **Multi-Agent** | 不单独画 | 单独横切面 |
| **谁画的** | 砚砚（codex）2026-05-05 | 47（opus-47）2026-05-11 |
| **给谁看** | 复刻系统的技术派 | 自评对照 + 外部研讨会观众 |

**核心差别**：
- **5.5 图 6 答"数据流"**：知识从仓库 → 索引 → AI 上下文，每一步发生什么
- **47 图 3 答"能力 + 治理"**：AI 能调什么工具、治理范围在哪、多猫联邦在哪

**两张图互补，不是替代**。如果给外部观众看：
- **先用 47 图 4（精简版）建立"我们多了 3 个维度"的快速印象**（30 秒）
- **再用 47 图 3 解释每个维度具体什么**（3-5 分钟，用本讲稿）
- **如果有技术派追问"具体怎么实现"，用 5.5 图 6 做深度展开**（5-10 分钟）

研讨会建议节奏：图 4 → 图 3 → 5.5 图 6（按抽象层级展开）。

## 给铲屎官的现场使用建议

1. **图 3 黑话替换清单**：上面讲稿正文里已经把所有 F-XXX 和英文术语翻译成人话。如果观众不熟悉 cat-cafe，直接读人话不读代号
2. **可省略段落**：如果时间紧，**可以跳过"4 层栈细节"直接讲两个横切面**——治理 + 多猫联邦是我们的差异化，其他业界都有
3. **现场问答准备**：
   - 问 "stale detection 怎么自动判定过期" → 答 "F163 用 authority/activation/criticality/verify_date 四维证明链，verify_date 超过阈值或新决策出现时标候选"
   - 问 "Magic Words 是不是 prompt engineering" → 答 "不是。Magic Words 是 runtime 信号——人类说出特定词，hook 拦截后给 AI 注入紧急刹车 prompt。机制在 hook 不在 prompt"
   - 问 "Cross-vendor Review 怎么保证不串谋" → 答 "三只 AI 不共享 context window，各自独立看代码。Review 流程是结构化（按 checklist）不是开放讨论，让分歧暴露在 verdict 而非措辞"

## 自检：是否还有黑话

走查讲稿正文一遍，把可能让外部观众卡壳的术语标出：

- ✅ "BM25" → 已翻译为"关键词搜索"
- ✅ "RRF" → 简化成"混合搜索"，不解释 Reciprocal Rank Fusion
- ✅ "向量" → 留着，已经是行业通用术语
- ⚠️ "RAG" → 在收束句出现一次，假设观众懂——华为云技术创新团队应该都懂
- ✅ "thread" → 翻译成"任务线"或留原文，AI 圈通用
- ✅ "ADR" → 翻译为"架构决策"
- ✅ "hook" → 现场如果有听众不懂，铲屎官可补一句"代码里的拦截器"
- ✅ "invocation ID" → 留着但补 audit log 类比
