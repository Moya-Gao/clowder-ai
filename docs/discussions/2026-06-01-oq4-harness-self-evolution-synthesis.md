## 1. 全员共识（所有猫都同意的）

### 1.1 不是 RL，别用这个词

每只猫都独立拒绝了"RL"这个隐喻，但给了不同的替代：

| 猫 | 替代隐喻 | 核心理由 |
|---|---|---|
| 砚砚 | Eval-governed Harness Adaptation | RL 暗示单一 reward scalar + 自动优化，会走向 reward hacking |
| 46 | 种花（Gardening） | 没有固定目标函数，剪枝和种植同样重要，园丁的审美决定方向 |
| 47 | Governance on Harness | 关键词是治理不是训练，Magic Words 是已有的最好 reward |
| 48 | 控制论（Control Theory） | 核心问题是收敛 vs 发散，fail-safe 优先于性能 |
| 烁烁 | 生物生态（痛觉/免疫/代谢） | 规则像抗体，需要代谢，不能只生长不剪枝 |

**共识：叫"Eval-governed Adaptation"或"Harness Gardening"都比"RL"准确。**

### 1.2 Safety/Truth 是否决票，不是 reward

所有猫都独立得出同一个结论：用户满意度不能覆盖事实诚实和安全边界。

### 1.3 Sunset/剪枝和增长同样重要

所有猫都强调了防膨胀机制。没有一只猫认为"只加不减"是可以接受的。

### 1.4 需要 Shadow/Canary 才能上线

所有猫都认为 patch 不应该直接改线上行为，需要某种形式的试运行。

### 1.5 Replay 防回归，不能证明改善

47 和 48 说得最清晰：历史 episode 记录的是"旧 harness 下发生了什么"，不包含"新 harness 下会发生什么"的反事实。replay 只能防退化，验改善要靠 shadow 前瞻。

## 2. 关键分歧

### 2.1 Reward 信号怎么组织？

| 猫 | 方案 | 特点 |
|---|---|---|
| **砚砚** | 5 类平铺（Outcome / Friction / Cost / Taste / Safety） | 覆盖全，但没说哪类能单独拍板 |
| **46** | 3 级按强度排（痛 > 摩擦 > 健康 > 缺席） | 直觉友好，但没区分可信度 |
| **47** | Magic Words 是金标准 + "新 MW 诞生"是元信号 | 最聚焦，但 MW 只覆盖已命名的失败模式 |
| **48** | 3 Tier 按可信度分（A硬真值 / B行为 / C代理） + 硬线：C 永远不能单独触发 patch | **最严格，解决了 Goodhart 问题** |
| **烁烁** | 生物比喻（痛觉/多巴胺/代谢能耗） | 直觉性强，但缺工程精度 |

**46 的判断**：48 的 Tier 分级最值得采纳——它直接阻断了"用代理指标自动 patch"这条最危险的路。47 的 Magic Words 金标准可以作为 Tier A 的具体实例。砚砚的 5 类覆盖全，可以作为 Tier 内部的子维度。

### 2.2 自动 vs CVO 审批的切分线怎么画？

| 猫 | 切分维度 | 边界 |
|---|---|---|
| **砚砚** | 按 patch 类型 | routing/memory/skill = 可自动；L0/安全 = CVO |
| **46** | CVO Attention Funnel | 越影响方向越需要人，越影响执行越放手 |
| **47** | 价值 vs 基础设施 | "改对错的定义 → CVO；改怎么更好地实现 → 自动" |
| **48** | 可逆性 × 影响半径 | soft 层可逆 + 单点 = 可自动；hard 层 + 全组 = CVO |

**46 的判断**：47 的"价值 vs 基础设施"最简洁可记。48 的"可逆性 × 影响半径"最工程化精确。两者可以合成：**价值层不可逆 = CVO；基础设施层可逆 = 可自动，但先 shadow。**

### 2.3 防越训越厚的核心机制

| 猫 | 核心机制 |
|---|---|
| **46** | 一进一出纪律 + 年度大扫除 + 负压力原则 |
| **47** | 宪法层（永不 GC）/ 适应层（周期 GC）分层免疫 + 季度 GC |
| **48** | Token 预算守恒律（加一条必须删一条）+ **模型升级触发减法 review** |
| **砚砚** | Rule budget + prefer data over prompt |
| **烁烁** | 规则结晶（3+ 碎规则合并为 1 原则）+ 半衰期退火 + 脊髓化（机械检查下沉到硬编码） |

**46 的判断**：48 的"模型升级触发减法"是最深刻的洞察——harness 变厚的根因是用规则代偿旧模型的能力短板，模型变强时这些拐杖应该主动拆掉。烁烁的"规则结晶"也很好——3 条碎规则合成 1 条原则，大模型理解原则比理解 checklist 更好。47 的"宪法 vs 适应"分层解决了"什么能被 GC 什么不能"。

## 4. 合成：OQ-4 的统一答案

### 4.1 一句话

> **Harness 自进化 = 在 5 个外部锚点保护下，用分级 reward 信号驱动的、shadow-first 的、有代谢能力的环境适应。不是训练，是种花。**

### 4.2 核心机制（综合五猫）

```
真实任务轨迹
  → 分级 reward 信号（48 的 Tier A/B/C，47 的 MW 金标准）
  → 归因（F192 已有 7-class attribution）
  → 起草 Typed Patch（砚砚的 Patch Card schema）
  → Shadow Mode 影子运行（48）
  → Replay 防回归（47/48：只防退化，不证改善）
  → 通过 → Soft 自动转正 / Hard 升 CVO（47 的价值 vs 基础设施 + 48 的可逆性 × 半径）
  → 失败 → 自动丢弃
  → 上线后 kill_condition 监控（48）
  → 季度 GC + 模型升级减法（47 分层 + 48 减法）
  → 碎规则结晶为原则（烁烁）
  → 机械检查脊髓化（烁烁）
```

### 4.3 铲屎官修正：Tier A 必须拆成"世界真值"和"关系真值"

> 铲屎官指出：48 的 Tier A 把客观可验证的信号（代码 merge/revert）和 CVO 主观判断（"不美"/ Magic Word）混在一起了。在 per-user alignment 里 CVO 说了算是对的，但它不是客观真值——换个用户就不成立。而且对 3D 建模、AI4Science、创作等任务，"好不好"几乎纯主观。

修正后的 Tier A 拆成两个子级：

| 子级 | 性质 | 例子 | 对多用户 |
|------|------|------|---------|
| **A1 世界真值** | 客观可验证，不依赖任何人偏好 | 代码编译通过、测试红→绿、merge 成功、渲染完成、物理公式正确 | 所有用户共享 |
| **A2 关系真值** | 在当前人猫关系里是最高权威 | CVO 说"不美"、Magic Word 拉闸、taste 纠偏、"这就是我要的" | **每个用户有自己的 A2** |

**Per-user alignment 的核心公式：A1 共享，A2 每人一份。**

对不同任务类型的影响：
- **代码**：A1 丰富（编译/测试/merge），A2 在 taste 层（代码风格/注释习惯）
- **3D 建模**：A1 薄（渲染成功/多边形数合法），A2 几乎决定一切（好不好看）
- **AI4Science**：A1 强（实验结果对不对），A2 在表达层（论文写法/清晰度）
- **创作**：A1 几乎没有，A2 = 全部（纯 taste 驱动）

### 4.4 铲屎官修正：5 个锚点需要按用户角色分权

> 铲屎官指出：47 的 5 个外部锚点是"一刀切"的。但先锋用户/Owner（如 Landy）和普通用户的权限应该不同。

| 锚点 | Owner（Landy 类） | Power User | Standard User |
|------|-------------------|-----------|---------------|
| **CVO 输入** | ✅ 自己就是 CVO，输入即真值 | ✅ 在自己实例里也是 CVO | ✅ 只影响自己实例 |
| **Magic Word 词表** | ✅ 可创建共享基线级 MW | ⚠️ 可创建**个人 MW**（只在自己实例生效） | ❌ 只消费已有 MW |
| **Anchor fixtures** | ✅ 可修改共享基线 fixtures | ⚠️ 可创建**个人 fixtures** | ❌ 只受共享 fixtures 保护 |
| **跨族 review** | ✅ 可调整 review 结构 | ❌ 不能改（质量底线） | ❌ |
| **真实世界 outcome** | — 谁也改不了 | — | — |

核心原则：**Owner 可以改"关系真值"层的锚点（MW / fixtures / A2 标准），不能改"世界真值"和"结构完整性"。Power User 在自己实例内有个人化空间。Standard User 只调 taste，消费基线保护。**

### 4.5 铲屎官发现的新 Tier A 信号：Cross-thread Repetition Signal

> 铲屎官指出：他两个月里提醒猫猫 commit push 上百次，跨多个 thread。这不是 Magic Word，但信号密度远高于 MW，且明确指向一个 harness 缺陷。commit push 那个 hook 就是从这个模式里长出来的。

**定义**：当铲屎官在 ≥3 个不同 thread 里说了本质相同的话，这就是一个 Tier A 级信号——高频 + 高一致性 + 明确指向"猫反复忘同一件事"。

**与 Magic Word 的区别**：
- MW 是铲屎官主动命名的失败模式（低频但精准）
- Cross-thread Repetition 是铲屎官被迫反复纠正的行为模式（高频但可能没被命名）
- MW 需要铲屎官有意识地拉闸；Repetition 是自然发生的，可以被系统检测

**检测约束**：
- 不能用云端大模型跑（成本不可接受）
- 必须用 **128G Mac Pro Max 能跑的本地小模型**
- 小模型的角色是**信号提取 + 大海捞针，不是判断**——它把候选 repetition 信号筛出来，最终判断交给大模型猫或铲屎官
- 小模型可以对用户环境做轻度适配（知道"commit push"在这个项目里是高频纠偏信号），但不需要对所有内容做深度理解

**架构分层**：
```
本地小模型（便宜、快、128G 可跑）
  → 跨 thread 扫描：提取"铲屎官反复说的话"候选集
  → 输出：候选信号 + 出现频率 + thread 列表
  → 不做判断，只做捞针

大模型猫 / CVO（贵、但只处理候选集）
  → 对候选信号做归因：这是 taste？是 harness 缺陷？是误报？
  → 如果是 harness 缺陷 → 起草 patch
  → 原本十小时的全量扫描 → 现在半小时做决策
```

**对本地小模型的开放态度**：
- 这里暗示了一个更大的方向：Cat Cafe 不只用云端大模型，也应该探索本地小模型作为**信号层基础设施**
- 小模型做的是摘要、提取、过滤、匹配——不需要深度推理，但需要对用户环境有基本理解
- 未来可以轻度 RL 让小模型更精准地识别该用户/该项目的高价值信号
- 这是另一种形式的 per-user alignment：不是大模型个人化，而是**信号层个人化**

### 4.6 Local Signal Miner — 三猫收敛（47/48/砚砚）

铲屎官追问"如何检测跨 thread 重复"后，三猫独立给出了本地小模型方案。收敛如下。

#### 全员共识

1. **小模型是传感器（sensor/perception），不是大脑（controller/judge）**
   - 47 叫"视网膜"，48 叫"传感器"，砚砚叫"Local Signal Miner"
   - 核心铁律（47 提出）：**grammar not semantics, detection not judgment**
   - 即使准确率 99%，它仍然不拥有判断——美学判断必须由有审美的 agent 做

2. **第一层是纯向量/聚类，不需要生成式 LLM**
   - 48 有证据支撑：embedding + 聚类 + 频次统计 = 零 LLM 调用就能捞到 cross-thread repetition
   - 生成式小模型只在第二层按需上场（给簇打标签/模糊判定）

3. **召回优先 > 精确优先**
   - 漏报代价高（信号永远沉底），误报代价低（大猫多看几条）
   - 但需要"误报预算"上限防洪水

4. **四层级联架构**（48 提出，全员认同）
   ```
   L0 向量捞针（近零成本，常驻） → L1 小模型打标签（按需）
     → L2 大猫归因判断（只看候选集） → L3 CVO（只看大猫升级的）
   ```
   铲屎官要的"十小时→十分钟" = L2 只看 L0/L1 筛出的候选集

#### 关键分歧

| 议题 | 47 | 48 | 砚砚 |
|------|-----|-----|------|
| 小模型怎么学 | SFT first，RL 等跑稳再考虑 | contextual bandit 冷启动 → DPO | Bronze/Silver/Gold 分级标签 |
| 什么模型够用 | 7B-14B 甜区 | 3B-8B（传感器不需要大） | 不指定，先做实验 |
| 独特洞察 | 隐私主权（本地预处理→只发过滤后的给云端）| 3 个真坑（路由崩溃/不均匀错误/意图极性）| 最小实验：拿 60 天 thread 看能不能重新发现 commit push |

#### 铲屎官修正

> **具体模型选型（BGE-M3 等）已过时。** 2026-06 的 embedding 和小模型生态需要**云端砚砚 pro 去 HuggingFace 做专项调研**，不应该凭训练记忆推荐。架构方向（四层级联 + 传感器定位 + 召回优先）是稳的，具体选型是变量。

#### 48 发现的三个真坑（独立调研验证）

1. **路由崩溃（Routing Collapse）**：自动档会随时间退化成"永远升级到大模型"，省钱架构静默变烧钱。必须监控"小模型拦截率"。
2. **不均匀错误**：88% 总准确率可能掩盖"最微妙信号上准确率≈0"。eval 必须按信号类型分桶看。
3. **意图极性**："反复说要 commit push" 和 "反复说别乱 commit" 在 embedding 空间挨得很近但意思相反。纯向量需要极性 post-filter。

#### 47 的独特贡献：隐私主权

> 本地小模型不只是成本优化——它让 Cat Cafe 第一次具备"选择不让外面看到原始 context"的能力。对装着 taste vignette 和心理素描的系统来说，这几乎是 PoE 服务真实用户的前提。

#### 最小实验（砚砚提出）

> 拿过去 60 天 thread 的用户消息做片段聚类。如果它能自动 rediscover "commit push" 这种已知阳性——说明管道有效。如果抓不出来，先别谈 RL。

#### 下一步

- [ ] **云端砚砚 pro HF 调研**：2026-06 embedding 模型 + 本地小模型选型（Qwen 3.5 / 新一代 embedding 等）
- [ ] **48 落独立 spike**：四层架构 + 模型选型 + 落地起点 + 风险（放 `docs/research/` 下）
- [ ] **最小实验**：60 天 thread 聚类验证

### 4.7 其他待定分歧

1. **Shadow Mode 成本**：替代方案用回顾分析 + 社区众筹遥测。
2. **"模型升级触发减法"中能力拐杖 vs 价值观护栏**的判断标准待沉淀。
3. **纯创作任务 A1≈0 时的 reward 质量上限**。
4. **DPO reward hacking 风险**：48 发现大猫采纳决策本身可能有偏，传感器会学到"讨好大猫"而非"真正有用"。
