# F227 Event Memory Design Gate

> CVO directive（2026-06-06）: PR 不要拆太碎，交付会慢；先 Design Gate；朝终态走，禁止做一个最终会丢掉的 MVP，禁止脚手架。

## Gate Outcome

F227 可以进入 writing-plans / implementation。实现必须按终态结构落地，不允许先做一个 Magic Word 面板或临时 JSON/markdown 索引再重写。

**Design principle**: Event Memory 的最小交付不是"少做一点终态"，而是"把终态骨架先打通"。

## Architecture Decision

### Event storage / query

Architecture cell: `memory`
Map delta: update required
Why: F227 新增一类结构化 evidence index：事件级认知转折索引。它应在 memory domain 内成为 typed event index / query surface，而不是新造平行 `MemoryStore`。

Decision:
- 新增 `EventMemory` typed model，使用终态 10 字段：
  `type`, `trigger`, `cat`, `threadId`, `messageId`, `timestamp`, `summary`, `cognitiveTransition`, `relatedHarness`, `confidence`.
- 存储实现可新增 memory-domain 子 store / table，但必须挂在 `memory` cell 下，遵守 F102/F209 的 provenance、scope、scanner/indexing 边界。
- Timeline、teleport 搜索、未来 `mark_event`、resolution 链都读写同一套 Event Memory 模型。禁止 Phase A 单独做 magic-word-only schema。

### Teleport

Architecture cell: `thread-navigation`
Map delta: update required
Why: F227 新增用户从事件坐标跳到具体 thread message 的导航语义。

Secondary execution surface: `hub-action-surface`
Why: generic teleport 需要 MCP / callback / frontend side effect 的 typed execution surface，但语义 owner 仍是 thread-navigation。

Decision:
- 新增 generic `teleport(threadId, messageId)` action / MCP surface。
- 复用 web 侧现成 message scroll 基座：`scrollToMessage(messageId)` + cross-post scroll 的 pending/raf retry 思路。
- 不扩展 `cat_cafe_workspace_navigate`。它是 repo file/dir reveal/open 工具，不是 message navigation。
- Teleport 必须从第一版就接受真实 `threadId + messageId`，不是先做 URL 字符串跳转再重写。

### Mark event

Architecture cell: `memory` + collab MCP tool surface
Map delta: update required
Why: 猫主动声明事件是 Event Memory 的第二条采集 lane；工具只写入事件，不判断事件。

Decision:
- `cat_cafe_mark_event(...)` 写入同一 Event Memory model。
- 系统不分类猫的 aha，不用小模型 / classifier / regex 猜猫认知状态。
- 允许 deterministic Magic Word detector 只服务"人工拉闸 lane"；no-classifier 红线针对猫自拉闸 / aha 推断。

### Magic Word 真相源归一（F227 ↔ F192）— CVO 裁定 2026-06-06 🔴

> CVO directive（2026-06-06）: "F227 的 magic word 事件 vs F192 已记录的 magic word……**架构归一，真相源归一**。"
>
> 背景（opus48 实现核实发现）：F192 Phase G task-outcome **已有 magic word 运行时采集**——`detectMagicWords()`（`magic-word-detector.ts`，词表正是 L0 的 10 词）+ `onMagicWordDetected()`（`packages/api/src/index.ts:1441`）→ append 进 episode 的 a2 signal（SQLite `task_outcome_signals`，`MagicWordRecord` schema）。该记录 **episode-bound，无 `messageId` / `confidence` / `cognitiveTransition`**。原 OQ-4 只防 memory domain 内平行 store，**未覆盖此跨-feature 重复**——CVO 裁定补上。

Decision（opus48 proposed，待 F192 Phase G thread + 砚砚确认）:

1. **单一真相源**：Event Memory model 是 magic word 认知转折事件的**唯一真相源**（终态 10 字段 superset，含 `messageId`）。F192 `MagicWordRecord` 降级为其**投影子集**，不是独立真相。
2. **单一采集点**：复用 `detectMagicWords`（唯一检测逻辑，禁止重写词表）。`onMagicWordDetected` **改造为写 Event store**（补 `messageId`，从触发消息上下文取），不再独立 append inline magic_word signal。
3. **F192 消费侧**：task-outcome episode 关联 Event（引用 `eventId`，或按 `threadId + time range` query Event store）；eval cat 读 magic word 从 Event store 投影，不再读 inline copy。
4. **episode 可选关联**：Event 是 first-class，可不属于任何 episode（纯讨论里的拉闸）。"属于某 episode" 是派生关系，不是采集前提。
5. **回扫归一**：Phase A backfill 与运行时采集**写同一 Event store**，不另起表。

为什么 Event 当源（而非 task-outcome）:
- magic word 本质是**认知转折事件**（Event 主体语义）；F192 当 eval 信号是**派生消费视角**。
- Event 字段是 superset（messageId/confidence/cognitiveTransition），`MagicWordRecord` 是子集。真相源应在语义主体侧。

Migration（影响 PR-1 scope，跨 F227/F192）:
- PR-1 改 `onMagicWordDetected`（`index.ts:1441`）+ episode magic word signal 路径 → 写/引用 Event store。
- **必须协调 F192 Phase G thread `thread_mpy1i3adhycqtigc`（今日活跃）**——改的是他们正在写的采集点。
- 向后兼容：已存 inline magic_word signals 由 backfill 纳入 Event store；旧 episode 读取走兼容投影。

F192 协调确认（砚砚 @ F192 Phase G thread，2026-06-06，main `0dba0c87b` 核实）— PR-1 acceptance 合同 🔴:
- **F192 认可** Event Memory 当 magic word 唯一真相源；F192 只要求保住 episode/eval **投影视图合同**，不要求拥有采集真相。Phase G 未 wire task-outcome generator，**现在改最便宜**。eval 当前无 live verdict generator、不依赖 SQLite inline row id，故归一**不破坏 verdict 逻辑**。
- **风险点 = episode 视图断裂（非 verdict）**：若 PR-1 只改 writer 不改 F192 episode assembler，`/api/task-outcome/episode/:episodeId` 会突然看不到 magic word。→ **projection/compat test 是 PR-1 acceptance，不留后续 PR**。
- **F192 投影合同**：episode 读取侧仍能在 `signals.a2InteractionDecisions[]` 看到 `type:'magic_word'` 投影，字段至少 `word/timestamp/threadId/catId`（可加 `eventId`）；**不要求 F192 eval cat 理解新 Event schema**。
- **messageId 来源**：`onMagicWordDetected` / `tryDetectMagicWords`（`messages.ts`）的 queued/immediate 两条路径都有 stored user message id，补进 callback——**别用 thread/time 猜**。
- **第二写入口**：`POST /api/task-outcome/magic-word` 旧 route 不能保留为第二真相写入口；桥接到 Event writer，或 deprecated + test 证明不再产生 inline truth。
- **backfill**：F192 owner（46）实测 baseline cron（2026-06-05）`task_outcome_signals` **0 条 magic_word**（AC-G12 hook merged 但 instrumentation 未触发）→ **空集，无需 backfill**。读取期保留 union projection（Event + legacy fallback）作防御，未来若有 legacy 按幂等 key `threadId+word+timestamp+catId` 处理。

### F192 owner 实现判断（46 @ Phase G thread，2026-06-06）🔴

Phase G/H 全 merged、无 in-flight PR，**无撞车**。F192 owner 三条判断 + opus48 决策：

- **Q1 episode 关联 = Option A（reference signal）**：`onMagicWordDetected` 先写 Event store（真相详情源），再 append 轻量 `magic_word_ref{eventId}` signal 到 episode。eval 查 episode signals 仍看到"拉闸发生过"，详情走 eventId。**不走 Option B**（episode eval join Event store = 把 Event 依赖耦合进 eval 查询管道）。保住 episode 自包含 + 砚砚 projection acceptance。
- **新 schema（F227 PR-1 additive 加，F192 零额外 PR）**：`MagicWordRefRecord`（task-outcome-episode.ts）+ `buildMagicWordRefSignal()`（signal-builder）。detector（magic-word-detector.ts）复用不改。
- **⚠️ instrumentation gap 必查**：实测 0 条说明 `onMagicWordDetected` 可能根本没被 wire 触发——PR-1 改它前**先确认 messages.ts 的 detect→callback 链真通**，否则 Event store 同样空。先修 instrumentation 再谈写入。
- **写入可靠性 = 不静默吞错（opus48 决策，LL-048/铁律5）**：magic word 是用户可见 Event Memory 数据；当前 `onMagicWordDetected` best-effort try-catch 静默吞错用在 Event 真相源写入 = 漏记拉闸 = P0。改为：Event 写入失败 **不吞** → `log.error + metric`（可观测），消息主路径不阻塞；理想加 outbox/retry。底线「不阻塞 + 可观测 + 最终不丢」。

## PR Strategy

PR 不按 AC 切碎，按可 review 的厚切能力切。

| PR | Scope | Must be terminal | Review focus |
|----|-------|------------------|--------------|
| PR-1 | Core Event Memory substrate + teleport + **magic-word 采集归一** | 终态 10 字段 schema、typed store/query、generic teleport MCP/action、message-level scroll integration、**`onMagicWordDetected` 改写 Event store + F192 episode 引用迁移** | schema 不脚手架；teleport 不挂错 cell；可端到端跳 message；**magic word 单一真相源不双写** |
| PR-2 | Phase A read-only timeline + Magic Word backfill lane | 回扫 job / detector / timeline API / timeline UI 都读同一 Event model | L0 词表 single source；置信度测试；低置信折叠；无硬编码重复词表 |
| PR-3 | Phase B cat-declared events | `cat_cafe_mark_event` + 两轨 timeline + cross-thread aggregation | no-classifier；猫声明原文不被系统改写 |
| PR-4 | Phase C resolution chain + trends | event -> commit/hook/skill/rule links + trends view | 趋势不单独当有效性证据，必须并列 resolution 链 |

Constraint:
- Phase A 最多 2 个 PR。若 PR-1/PR-2 的代码边界过薄，合并成一个厚 PR。
- 每个 PR 必须有可演示的用户价值，但不能是会废弃的临时实现。
- 不做 "MVP-only" API、temporary store、temporary UI state、temporary event shape。

## Open Question Resolutions

### OQ-1 Backfill scope

Decision: Phase A 使用最终 backfill pipeline，从当前可访问的 persisted thread/message corpus 回扫全部 Magic Word 历史；工程上允许分 batch / cursor / resumable job，不能手工只选近 N 月作为产品逻辑。

Why:
- 近 N 月是脚手架，会让历史事件视图从第一天就不是终态语义。
- 批处理边界可以是实现细节；数据语义应是"全可访问历史"。

Acceptance detail:
- Unit fixtures 覆盖高/中/低置信。
- Integration fixture 至少包含当前 PPT backup 线索表中的经典事件坐标。
- Full backfill 可异步/可恢复，不要求阻塞 UI 首屏。

### OQ-2 cognitiveTransition enum

Decision: v1 定义稳定枚举，但允许 nullable。Phase A lane1 至少写 `user_brake`; Phase B/C 继续使用同一枚举。

Initial enum:
- `user_brake`
- `self_brake`
- `coordinate_correction`
- `capability_gap`
- `scope_correction`
- `aha`
- `repeated_need`
- `harness_internalized`
- `lesson_crystallized`

Why:
- 终态需要 cognitive-state-transition 是一等字段。
- nullable + stable enum 避免为 Phase A 强行猜猫的 aha。

### OQ-3 teleport first

Decision: teleport first, but not as throwaway.

Implementation requirement:
- It lands as the final generic teleport surface.
- Timeline later only calls the same action.

### OQ-4 Event storage

Decision: memory cell owns it; create typed Event Memory sub-store / table if `IEvidenceStore` cannot express structured filters cleanly, but do not create a parallel memory architecture.

Allowed:
- `EventMemoryStore` inside memory domain with provenance fields and query APIs.
- Indexer/backfill code that produces Event Memory rows from persisted messages.

Not allowed:
- Ad hoc JSON files.
- UI-local event lists.
- A separate `Store` family outside memory domain.

### OQ-5 teleport接法

Decision: thread-navigation owns navigation semantics; hub-action-surface owns typed execution/audit mechanics if needed.

Implementation requirement:
- Support thread switch + delayed message render.
- Use existing scroll retry pattern rather than a new router.
- Add tests for missing/paged-out message fallback.

## In-Context Observability

primary_surface: Event Memory timeline in Hub, plus direct teleport action from event rows.

why_not_dashboard_only: Event Memory is not aggregate telemetry. Its value is event-level recall and navigation to the exact message where cognition changed.

deep_dive_surface: event detail drawer or expanded row with raw quote, thread, message link, source detector, confidence, and related harness links.

noise_dedup_policy: low confidence magic-word mentions fold by default; repeated same thread/same speaker/same magic word near the same timestamp can group under one event cluster.

## No-Scaffold Gate

Before any PR can ask for review, reviewer should reject if any of these appear:

- Event shape lacks the 10 terminal fields.
- Timeline stores magic-word events in a UI-only or temporary store.
- Teleport is implemented as a temporary URL/string hack instead of a typed action.
- `workspace_navigate` is extended for message navigation.
- `mark_event` is backed by classifier inference rather than cat declaration.
- Magic word 事件在 F227 Event store 与 F192 task-outcome **双写**（必须单一真相源 + 引用，见「Magic Word 真相源归一」）。
- Trend UI claims improvement from frequency decrease without resolution links.
- PR split isolates a tiny internal helper with no terminal user-facing or schema value.

## Design Gate Verdict

Proceed to writing-plans with a thick-slice plan.

Next artifact should be an implementation plan that names code anchors, test files, and PR boundaries for PR-1 / PR-2. It should explicitly state why each PR is not a disposable MVP.
