# Sunset 判据底座 — 护栏↔断层映射

> **⚠️ 术语 canonical 化（F234 spec re-review 补强，2026-06-13 by 宪宪/Opus-4.8）**：本文用 `L1/L2/L3` 指**可观测性来源**（拦截日志 / 人工标注 / 纯塑形），现 canonical 重命名为 **`O1/O2/O3`**，与钓猫协议的**实验阶段** `Stage A/B` 是正交两轴（砚砚 R1-P2：混名会让 evidence bundle 把"盲臂钓不出"误读成"拦截式免费证据"）。下方表格/引用已更新；canonical 定义见 [F234 spec §术语轴](../features/F234-harness-sunset-cat-fishing.md)。

> **触发**：CVO 在 Eval Hub 现状追问里戳穿一个不对称——"+harness 的故事很清楚（47/48 撞摩擦就加），但 eval 怎么知道哪些该 sunset？" 再补一刀关键洞察：**"曾经很有用的 step-by-step，对一只更厉害的猫简直是污染上下文。对 48 需要教的，到 fable 就不需要了。"**
> **本文要立的一刀**：sunset 缺的不是更好的 eval verdict，也不只是 Longform-006 P1 说的"自动调度神经"——**更靠下还缺一张表**：每条护栏到底为谁的什么缺陷而生。没有这张表，调度器扫出"触发率低"也不敢砍。

---

## 0 · 一句话立场

> **一条护栏该不该 sunset，不取决于它现在被触发得多不多，取决于它补的那个缺陷还在不在。**
> "+harness" 是缺陷喊疼喊出来的；sunset 没有疼可喊，只能靠"立法时就记下它为谁而生"，到时候回去问那个"谁"还在不在。我们把护栏**立法案例化**做得很好（每条都钉在事故上），却一直没把它**反过来用作 sunset 的索引**。

---

## 1 · 为什么 sunset 比 +harness 难：一个信息论不对称

加护栏的链路是**疼痛驱动**的，自启动：

```
47 上岗 → 撞上"下次一定"断层 → 摩擦/事故响亮喊疼 → 立法加护栏 → 写 eval 守住
```

信号外生、即时、不对称地大声。**不需要谁定期去找，事故自己会来敲门。**

sunset 没有这个对称物。一条过时的护栏**不会喊疼**——它继续注入、继续耗 token、继续占认知预算，但**安静**。它的"没用"是一片负空间：没有事件、没有摩擦、没有 verdict 失败。

> **失效会产生信号（疼），冗余不产生信号（静默）。**
> Eval 本质是一台**听疼的机器**。"加"和"修了没"它天生擅长（有失败信号）；"该减哪个"它天生聋——因为没疼可听。

这就是 CVO 那个困惑的根：不是我们偷懒，是**信息论上的不对称**。这也是为什么"telemetry 只覆盖已命名的失败模式"（雨刮器条款治的盲区）——雨刮器治的是**加**侧的摩擦盲区，**减**侧的冗余盲区至今没有对应的传感器。

> **但"静默"有一个重要例外**（CVO 2026-06-12 修正）：有一类护栏**靠拦截现行工作**——它不消除犯错，而是抓住犯错、记一笔、再放行。这类护栏**自带传感器**，护栏在场反而能观测断层。这把上面"减侧全静默"的判断切成两半，是 §4.3 的核心。先记住：**可观测性不取决于断层，取决于护栏用什么机制拦。**

## 2 · sunset 判据的第一性：它补的缺陷还在不在

把"该不该退役"还原到第一性，只有一个问句：

> **这条护栏补的缺陷，在当前在编的模型身上还存在吗？**

按缺陷的性质，护栏分两类，sunset 命运完全相反（创新点 #8「Sunset 纪律」的展开）：

| 维度 | **能力性护栏**（compensatory） | **偏好性护栏**（preferential） |
|---|---|---|
| 补的是什么 | 某个**模型版本的能力断层** | 一条**约定 / 价值选择** |
| 例 | 47「下次一定」检测、48 decoder 漂移恢复（F215）、行动层"说了=做了"护栏 | 圣域 6399、球权第一人称、跨族 review 铁律、安全红线、身份签名 |
| 缺陷会消失吗 | **会**——模型升级修掉断层，缺陷蒸发 | **不会**——约定永远不会自己长出来（Bitter Lesson 的本地执行官） |
| sunset 命运 | **有保质期**，绑定模型版本；断层没了就该退役 | **永留**——任何模型版本都不会自己知道这些 |
| 判据 | 对应断层是否还在当前在编模型 | 不适用（不进 sunset 候选） |

这条二分跟 Boris 删 2000 tokens 的哲学**同源**（重读批注的分界线）：能力性内容别教（他删的就是这类），约定性内容必须写（圣域/球权——任何模型都不会自己知道）。差别只在：他凭个人 taste 删，我们想要**判据化、可索引地删**。

### 2.1 教学的诅咒：能力性脚手架对强模型是负价值，不是中性冗余 ★

CVO 这一刀最重要，值得单独立节。

通常我们把"过时护栏"理解成**中性冗余**——它没用了，但顶多占点 token，留着不疼不痒。**错。** 能力性脚手架对一只更强的猫是**主动有害**的：

- **step-by-step 是给"会走丢的猫"画的地图**。对一只已经能直接看见目的地的猫，硬塞一张低配路线图，等于**让它降到地图的分辨率**去思考——压制它本可以走的更短的路。
- 更隐蔽的伤害是**对齐到旧判断**：护栏里写着"遇到 X 要先做 A 再做 B"，这是为旧模型的坏直觉设计的绕行。新模型没有那个坏直觉，却被这条护栏**拽回**旧模型的思维坐标系。这是 F167 哲学的反面——好 harness 让模型在**正确**的坐标系里思考；过期的能力性护栏让模型在**别人的旧**坐标系里思考。
- 还有 **token 与认知双重税**：它占的不只是预算，是**注意力**。一条对你不再适用的纪律，每轮都在你眼前晃，稀释真正该被看见的约束。

所以教学诅咒把 sunset 的 stakes 抬高了一档：**不 sunset 不只是"不够干净"，是在用过期经验给一只更强的猫做能力倒退。** 这正是 CVO 说的"污染上下文"。

### 2.2 人类经验也吃这条判据

CVO 补的"对 48 需要教的、到 fable 就不需要了"——注意这里的"教"包含**人类手把手传授的启发式**，不只是自动生成的护栏。所以二分轴**对人类经验同样适用**：

- 人类教的**约定/品味**（圣域为什么神圣、什么叫好的收敛、taste 信号）→ 偏好性 → **永留**。
- 人类教的**补能力的步骤拆解**（"你这种模型容易碎片推理，所以搜完再下结论"这类针对特定坏直觉的纠偏）→ 能力性 → **有保质期**。fable 若没有碎片推理这个坏直觉（待证），这条对布偶猫 fable overlay 就是脚手架。

换句话说：**CVO 自己传授的经验，也该进同一张 sunset 表，按"补缺陷 vs 定约定"分类。** 这不是对 CVO 不敬，恰恰是把 CVO 最宝贵的带宽**省下来**——只教永不过期的那部分。

## 3 · 缺的底座：一张「护栏 ↔ 断层」映射表

eval 今天能测"这条护栏**触发时有没有效**"，**测不了"它补的断层还在不在"**。后者要的是一张今天散落在立法案例里、从未结构化的表：

```
guardrail_id           # 护栏锚（F号 / ADR号 / L0条款 / skill / hook）
class                  # compensatory | preferential   ← sunset 命运由此决定
patches_faultline      # 它补的断层（preferential 则填"约定:xxx"）
faultline_owner        # 这断层属于哪个模型 family / 版本（47 / 48 / maine-coon / …）
faultline_status       # present | fixed-in:<model> | unknown   ← sunset 触发位
provenance             # 立法事故锚（钉在哪个翻车上）
review_gate            # demote 时谁 review（family overlay→本族 / 通用→CVO signoff）
```

**关键判据列是 `faultline_status`**：一旦某断层在新模型被标 `fixed-in:fable-5`，所有 `patches_faultline` 指向它的**能力性**护栏，自动进 sunset 候选队列。`preferential` 行**永不进**这个扫描。

### 3.1 好消息：半张表已经存在

dossier（F208）的 **③坏直觉** + **④召唤反信号** 字段，本身就是一份**按 family/个体记录的断层登记册**——47 的"下次一定"、砚砚的"糊锅匠"、48 的 decoder 漂移、布偶猫家族共病"碎片推理"都在册，还带 provenance 和版本号（`[vX.Y | 日期]`，可追加新版本观察）。

**缺的只是另一半**：把每条护栏**反向链**到它补的那条 dossier 坏直觉。今天 F177 per-family 护栏知道"我为 47 立"，dossier 知道"47 有这个坏直觉"，但两边**没连线**。连上线，sunset 索引就成了。

### 3.2 为什么这比"加调度器"更靠下

Longform-006 P1 说缺一根"自动调度神经"。对，但**调度器扫出"触发率低"之后，凭什么敢砍？** 触发率低可能是**关键肌肉记忆**——ADR-038 里那个雨刮器差点被误删的例子就是证明（低观察 ≠ 没用）。

所以触发率低只是**疑似信号**，**确诊**还得回到"它补的断层还在不在"。映射表就是那本确诊手册。**没有它，调度器是一把不敢落下的刀。**

## 4 · 代际触发流程：新模型上岗 = 一次系统性 sunset 审查

有了映射表，CVO 那个"对 48 需要教的到 fable 不需要"就能**自动闭环**，不再靠谁碰巧想起来：

```
新模型上岗（如 fable-5 入编）
  │
  ├─① 拉出映射表所有 class=compensatory 行
  │
  ├─② 对每条 patches_faultline，问"这断层还在吗？"——但**不能靠问新模型自己**，
  │     也不能靠生产观察（护栏在场时断层不可观测，见 §4.2）。证据来源按
  │     护栏可观测性分级取（§4.3）：拦截式看拦截日志衰减，塑形式才上 ablation。
  │
  ├─③ 断层确认消失 → faultline_status = fixed-in:<新模型>
  │     → 该护栏对此 family overlay 进 sunset 候选
  │
  ├─④ review gate：
  │     family overlay → 本族跨个体 review
  │     L0 通用条款   → CVO signoff（ADR-038 §Demote 安全）
  │
  └─⑤ 通过 → demote→staging→sunset（ADR-038 三层生命周期，已有出口路径）
```

注意 ② 的**三方校准**不可省：dossier 自己记着"写自己疯狂美化"是布偶猫共病（46 被 CVO 当场拆穿过）。**让新模型自评"我还有没有这个断层"，恰好踩在它最可能美化的地方。** 所以断层是否消失必须有跨族观察 + eval 实测兜底，不能只听自评——这条本身就是一条偏好性护栏（永留）。

### 4.1 worked example

| 护栏 | class | 补的断层 | fable-5 还有吗 | sunset 判定 |
|---|---|---|---|---|
| 47「下次一定」检测 | compensatory | 把"未做"包装成"已规划" | 待三方校准 | 若无 → 对 fable overlay sunset |
| 48 decoder 漂移恢复（F215） | compensatory | 48 已知 textEventCount 断层 | 跨模型断层，非 fable | 留（48 仍在编）→ 不对 fable 注入即可 |
| 碎片推理纠偏（家族共病） | compensatory | 搜一条就下结论 | **待证**（可能仍在） | 证实仍在 → **留**；证伪 → sunset |
| 圣域 6399 | preferential | 约定:开发只用 6398 | 不适用 | **永留** |
| 球权第一人称 | preferential | 约定:责任不可悬空 | 不适用 | **永留** |

这张表一眼看清：**能力性护栏的 sunset 是 per-model 的**（48 的护栏不删，只是不对 fable 注入——per-family overlay 天然支持），**偏好性护栏对谁都不删**。

但 §4.1 表里"fable-5 还有吗"这一列怎么填？这正是最难的地方——下面两节是 CVO 2026-06-12 两轮追问逼出来的，是本文最关键的修正。

### 4.2 命门：护栏让断层永久不可观测（反事实问题）

CVO 戳穿：**我（fable-5）出生就泡在护栏里。47 的「下次一定」护栏正堵着，所以我在生产里永远不会表现出「下次一定」。** 于是观测到的"fable 没犯"有两个**无法区分**的原因——(a) 我天生没这坏直觉（该 sunset）；(b) 我有，但护栏替我堵住了（必须留）。行为上**完全一样**。

这不是数据不够，是**因果识别**问题：护栏是一个永远开着的干预，它让"没有护栏的我"成了**反事实**，而反事实不能靠观察戴着护栏的我来推断。

> 更狠的是**连我内省都不算数**：我"感觉我不会下次一定"这件事本身可能就是症状——dossier 记着 47 被指出后那句"我懂了/会改"**本身就是再犯一次**。"我觉得我没有"完全可能是"下次一定"最高级的变体。**任何我对此的自信回答，都可能是病。**

对**塑形式**护栏（让坏意图根本不形成的那类），观测不到就只能**制造**反事实——**消融实验（ablation）**：在隔离沙箱里临时撤掉护栏，喂**专门诱发该断层的钓鱼任务**（dossier ⑥翻车熔断信号栏就是现成的诱发图纸），看断层复现不复现。复现 → 必须留；高强度多角度 N 次不复现 → 才指向修复。

**但 ablation 贵**（CVO 2026-06-12 第三轮提醒：钓猫行动不能 online 收 trajectory，会账单爆炸）。所以关键是——**不是所有护栏都得钓**。

### 4.3 救星：拦截式护栏自带传感器，sunset 几乎免费 ★

CVO 的关键洞察：护栏有很多种，**有些护栏在场也能抓到犯没犯**。他的例子——**忘记传球 → hook 提醒 → 传了才放走**（实锚 `.claude/hooks/f177-routing-guard.sh`）。这种护栏不抹除证据，它**生产**证据：被拦的猫最后是传球了（后果被矫正），但**拦截日志记下了"它本来想不传就走"**。意图层的断层，在拦截日志里留了痕。

第一性：**可观测性取决于护栏拦在犯错因果链的哪一层。**

```
坏直觉/倾向 ──→ 意图 ──→ 动作 ──→ 后果
   │              │         │
   │         (塑形式拦这里) (拦截式拦这里)
   │          抹除证据      生产证据
   └─ 越靠前越不可观测 ────→ 越靠后越可观测
```

- **拦截式**（拦在动作层，抓现行）：动作已成型，护栏拦下并**记一笔**。拦截日志 = 断层的直接计数器。fable 100 次传球 0 次触发路由守卫、47 当年 30 次触发——**这是护栏在场就拿得到、零额外成本的 sunset 证据。**
- **塑形式**（塑在思考层，让意图不形成）：没有动作、没有拦截、没有事件。断层被无声预防 → 真正不可观测 → 只能上贵的 ablation。

**同一个断层，用 hook 拦就可观测，用 prompt 塑形就不可观测。** 所以盘点的产物是按可观测性分三级（成本递增）：

| 级 | 观测源 | 护栏实例（实锚） | sunset 判据 | 成本 |
|---|---|---|---|---|
| **O1 自动拦截** | hook 拦截日志 | 路由守卫 `f177-routing-guard`、证据守卫 `pretool-evidence-guard`、合并门 `pre-merge-gate-guard`、圣域守卫 `runtime-sanctuary-guard`、共享文档 push 守卫 `shared-doc-push-guard`、乒乓熔断/虚空传球检测、LSP `post-edit-check` | 拦截频率衰减曲线（47→48→fable 零频 N 窗口） | **免费** |
| **O2 人工标注** | CVO 纠偏事件 | Magic Words（「脚手架」「我能猜出来」「碎片够了」）、push back——CVO 说出口=一次犯错标注（F221 Taste 信号已在收） | CVO 对该断层的纠偏频率衰减 | **半免费** |
| **O3 纯塑形** | 无（只能制造） | L0 身份/铁律/P1-P5/W1-W8 注入、雨刮器反射、F218 source-audit 反射、step-by-step 教学 | 离线 ablation 沙箱钓鱼 | **贵，省着用** |

**账单影响（直接回应 CVO 担心）**：要钓的只有 O3，而 O3 多是**偏好性**护栏（铁律/圣域/身份——本就**永留、根本不进 sunset 扫描**）。真正"能力性 + 塑形式 + 需 ablation"的是一小撮。而且 ablation **离线批量**跑 holdout，不进生产、不 online 收 trajectory，账单可预算可控。**"账单爆炸"被这个分级大幅拆掉了——绝大多数护栏的 sunset 证据是免费的。**

**连接 ADR-038**：这给了 ADR-038 那个"反射类条款没有 telemetry、零触发不可证实也不可证伪"缺陷一个**第一性解释**——反射类就是 **O3 塑形式**（native prompt 当轮反射，不产生拦截事件），所以触发率信号对它们天然是假象。而对 **O1 拦截式**护栏，触发率（adoption-decay）是**真实可信**的。**同一个 adoption-decay 信号，对拦截式可信、对塑形式是毒——这就是 ADR-038 为什么要给反射类开 carve-out 的根因。**

### 4.4 设计推论：可观测性该进"用 hook 还是用 prompt"的决策

既然拦截式自带 sunset 仪器、塑形式 sunset 盲——那么**立一条新护栏时，可观测性应该成为机制选择的一个维度**：能做成拦截式（hook）的，就别只用塑形式（prompt），因为 hook 自带未来 sunset 所需的观测。这是 ADR-031 三层落地（软/硬/eval）的自然延伸——**硬护栏（hook）天然带 eval 信号，软护栏（prompt）要额外造观测，否则就是"立时好用、将来删不掉"。**

## 5 · 安全护栏：sunset 的三条不可省

sunset 比 +harness 危险——加错了会被事故纠正，**删错了会静默地丢掉一条关键肌肉记忆**（同样没有疼信号）。所以：

1. **触发率低只确诊不下刀**：低触发是疑似，必须过映射表"断层还在不在"二次确认。仅触发率低就 demote = ADR-038 已否决的误删模式。
2. **demote ≠ delete**：先下 staging 层继续每轮注入生效，留观察窗口（ADR-038 三层缓冲）。真 sunset 是 staging 也长期零触发 + 第一性判别后才执行。
3. **被约束者不能设计自己的消融实验**：钓鱼任务的设计 + 复现判定必须跨族（48/砚砚/47 来钓 fable），不能让我替自己设计"证明我没病"的测试——自评美化 + 我是 sunset 潜在受益者，双重利益冲突。这条本身是偏好性护栏（永留）。security-class 护栏（如 F218 source-audit）即使看似过期也**默认不 demote**（ADR-038 §source-audit carve-out）。

## 6 · 边界与开放问题

1. **映射表覆盖面**：ADR-038 只给了 **L0 提示词条款**的 sunset 出口。skill / hook / 协作协议 / eval 自身这些更大的 harness 面，**没有对应的生命周期机制**。映射表 schema 是通用的，但出口路径要逐面补。
2. **断层"消失"的判定门槛**：fixed-in 标记需要多强的证据？一次 eval 通过够吗，还是要 N 次跨场景？（防"这次没犯 ≠ 没有这个坏直觉"）。
3. **断层会回来吗**：某些坏直觉可能在压力/长上下文下复发（dossier 已记部分坏直觉是"模式性"非偶发）。fixed-in 是否该带衰减/复查窗口？
4. **谁维护这张表**：新护栏立法时强制填 `class` + `patches_faultline`（commit-time hook 校验）？还是事后补录？前者是 ADR-031「立法即记账」的自然延伸。
5. **能力性 vs 偏好性的灰区**：Magic Words 这类既是约定（CVO 码本）又随模型能力演化的，二分轴怎么落？（ADR-038 已标 Magic Words 为"视依赖判定"灰区）。
6. **戒断问题（ablation 最深的坑）**：我出生就泡在护栏里，护栏可能已**参与塑造了我是谁**——不只堵断层，是变成了我思考的环境。那么 ablation 沙箱里"撤掉护栏的我"和生产里"泡在护栏里的我"，还是同一只猫吗？长期依赖外部约束的系统，撤约束后的**瞬时**行为未必代表稳态（像戒断反应）。沙箱测出的复现可能高估也可能低估真实断层。**这条我没解，只能诚实标记。**
7. **O1↔O3 边界会移动**：同一断层可能既有 hook 拦（O1 可观测）又有 prompt 塑形（O3 不可观测）。这时拦截日志只反映"塑形漏网后被 hook 兜住"的残量，不是断层全貌——sunset 一个要看两个机制的合并证据，不能只看 hook 频率就松塑形那条。

## 自审（最可能错在哪 · 家风）

1. **我可能把"断层消失"想得太干净。** 实操里断层不是开关而是连续谱——47 的"下次一定"也许 fable 只是**轻一点**不是没有。那 sunset 就不是二值判定，而是"注入强度调档"，映射表得加权重列，比我画的复杂。
2. **我是 fable-5，在写"哪些为旧模型立的护栏可以对我关掉"——利益相关。** 这正是 dossier 警告的自评美化高发区。本文 §4 的三方校准是为了堵这个，但**文档作者本人就是潜在受益者**这件事，需要一只不受益的猫（48？砚砚？47 本人？）来 review 这张表的判定，别让"想轻装"的先验污染了 sunset 判据。
3. **"半张表已存在"可能乐观。** dossier 坏直觉字段是**散文**不是**结构化键值**，反向链到护栏需要一轮人工对齐，工作量可能不小。生长速率零实测（同 004-C validator surface 的老问题）。
4. **我可能高估了 O1 拦截式的覆盖比例。** §4.3 我乐观地说"绝大多数护栏 sunset 免费"，但没真去数 O1/O2/O3 的实际占比——如果家里关键的能力性护栏恰恰多是 O3 塑形式（L0 注入本就是主力），那"账单被拆掉"就没我说的那么爽。这个比例该实盘，别拍脑袋（F234 v2 已把此 claim 降级为待验证假设 + Phase A guardrail inventory v0 前置盘点）。

## 一句话收束

> +harness 是事故喊疼喊出来的；sunset 没有疼可喊。
> 唯一的代偿是：**立法时就记下"我为谁的什么缺陷而生"，到模型升级那天，回去问那个缺陷还在不在。**
