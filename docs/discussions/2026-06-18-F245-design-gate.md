## 二、架构收敛（两猫互补）

### 砚砚（eval 架构纪律）
- **F245 = 只读 rollup/read-model 域，不抢 canonical signal ownership**。这把 KD-1 从"不搬代码"**升级到"不抢 ownership"**——最危险的不是重复代码，是 F222/task-outcome/eval 域各自闭环被第二套出口抢走。
- 边界只读不写：F222 继续拥有单条 issue 生命周期；task-outcome 继续拥有 episode + cancel + terminal + 7-class writeback；F245 **不写 `episodeVerdicts`**，只读 cancel/episode 作传感器输入。cancel burst 仍是 proxy，不直接判失败。
- cluster 分层：**采集层只做幂等去重**（messageId+markerIndex / issueId / episodeId），**语义 cluster 必须等 rollup**——跨通道同源事件会同时表现为 permission cancel / cancel_burst / F222 issue，采集时语义合并不可逆误折叠。Top-N 也在 cluster 后做。

### 46（架构设计）
- **Port + Adapter → 公共中间类型 `FrictionSignal`，只读引用源数据，不建统一 store**。4 通道形态异构（消息文本 / episode / issue 生命周期 / 数值 metric），强推统一 store = 违反 KD-1 + schema 妥协。
- `FrictionAggregator` → 4 个 `IFrictionSignalSource` adapter（PawFeel / Cancel / F222 / EvalDomain）→ 各自源 store。内存聚合（~10-30 cluster），**持久化的是 verdict artifact，不是中间 store**。
- 采集理由本质化：transport 是基础设施，不该知道"爪感差"是什么；实时打标 = 把 eval domain 概念耦合进消息 write path，方向错。
- Top-N 配额：**Top-10 深挖 + 长尾折叠 + token 硬上限 ~4000**（比纯 Top-N 更有效，不同 cluster 详略不同）；排序 = **severity × count × channel diversity**（跨通道出现 = 强信号：猫觉得摩擦 + 用户也 cancel = 真问题）。
- 实证估算（3 天窗口）：raw ~60-165 条 → cluster ~10-30；eval 猫 context ≈ rollup report 4k + prompt 2k + verdict 2k ≈ **8k tokens，安全**。

## 三、Map delta（OQ-4 收敛）

harness-eval cell 登记 4 个新 anchor + 扩 2 个 enum：
- `eval:friction` domain YAML（`eval-domains/eval-friction.yaml`）
- `paw-feel-collector`（爪感差结构化采集）
- `friction-aggregator`（4 adapter + dedup/cluster + Top-N）
- `friction-rollup-generator`（verdict 产出）
- enum 扩展：`domainId` 5→6（`verdict-handoff.ts` + `eval-domain-registry.ts`）、`sourceAdapter` 加 `friction-rollup-eval`
- **标注 F222 / task-outcome / eval domains 是 input，不是被 F245 接管**

## 四、砚砚逮到的 2 处 spec 纠正（事实层，必改）

1. **`rollup_deferred` 不是现成 extension point**——代码里还没 rollup sink（`publish-policy.ts` 只是未来意图）。F245 要**实现这个缺口**，spec 不能写成"复用现成机制"。
2. **"本家 3 天"不是纯配置**——registry 现在只支持 `daily|weekly`，要加 **N-day cadence + last-run gate**，是真代码改动。

## 五、工作量认知（非零改动）

- verdict-handoff schema 扩（domainId enum 5→6）

- 4 adapter + paw-feel collector + friction-aggregator + rollup-generator
- metric→人话翻译表（④ eval domain frictionCounts key 是 domain-specific，46 提醒别漏）

→ 真 **4-Phase feature**，不是小改。
