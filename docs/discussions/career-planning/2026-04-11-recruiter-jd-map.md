# 2026-04-11 猎头/JD 总表

> 目的：把 2026-04-10 ~ 2026-04-11 这一轮猎头集中轰炸统一收敛成真相源，避免后续重复投递、渠道撞车、岗位记忆漂移。

## 使用规则

- **唯一键**：`公司 + 事业部/产品线 + 岗位`，不是单看公司名。
- **同公司同 BU 同 HC 只走一个渠道**：尤其是阿里，先确认再投，避免猎头撞车。
- **优先级先看岗位本体，再看公司牌子**：岗位偏后台/流程改造，就算公司大也不能自动上 Tier 1。
- **这份表记录的是“当前判断”**：以猎头截图、JD 文案、公开资料和当晚讨论为准；拿到更清晰 JD 后可以覆盖更新。

## 逐项备注

### 1. 阿里千问

- 已知是阿里最像主航道的岗位之一。
- 关键词命中：`MultiAgent`、`ReAct`、`RAG`、`MCP`、`上下文工程`。
- **最高风险不是岗位不匹配，而是渠道撞车。**

### 2. 阿里云 Agentic AI

- 这是最明显的 `华为云 7 年` 和 `Cat Cafe Agent 架构` 的交叉点。
- 如果只看“岗位和履历的数学重合度”，它和千问是并列第一梯队。

### 3. 阿里企业级 Agent 平台

- 这是“企业级平台 owner”画像，不是纯 prompt engineer。
- JD 里已经出现了完整的平台五件套：`核心框架`、`检索/RAG`、`高可用/SLA`、`CI/CD/监控`、`带 3~5 人`。

### 4. 悟空事业部

- 这是**业务线情报**，不是一个具体 HC。
- 公开口径显示它属于 ATH 下的企业级 AI-native 工作平台线，偏 B 端工作流、多智能体执行、钉钉生态、安全与权限继承。

### 5. 灵动时刻 Interaive

- 这是唯一一个明确带有“创业主航道 + 高想象空间”的强机会。
- 需要重点确认：团队所在地、产品内 agent vs 内部工具、期权结构。

### 6. 平安

- 早期判断偏保守，后续因为公开规模数据修正为主力池。
- 适合的前提是：它真是集团通用 Agent 平台/底座，不是单一业务线需求工厂。

### 7. 三一（方向 A）

- 最亮点是“从 0 到 1 手搓 Agent 框架，不依赖现成编排框架”。
- 这是工业重场景岗，不浪漫，但内核并不弱。

### 8. 大疆两条线

- **Agent 中/高级全栈开发工程师（后端为主）** 这条不是传统 CRUD，核心关键词是 `企业级大模型网关`、`智能体 Agent 编排工作流`、`RAG 知识库平台`、`插件引擎`、`幻觉控制`，本质是 AI 工程平台岗。
- **资深后端架构师** 则明显更传统：公共中间件、配置中心、注册发现、网关、消息、缓存、搜索、任务调度、多租户、权限、审计、治理。
- 两条都在深圳，但不是一个味道：前者偏 `AI 工程平台`，后者偏 `公司级后端基础架构`。

### 9. 腾讯企微

- 能聊，但目前证据还不够厚。
- 如果后续拿到清晰 JD，需要判断它到底是“平台岗”还是“业务接入岗”。
- `2026-04-12` 已收到正式一面邀约：`2026-04-14 14:30-15:30`（北京时间），说明它已经从猎头线索进入真实招聘流程；但岗位本体判断暂不因进面自动上调。
- `2026-04-14` 一面已完成并通过，面试体验和故事已沉淀到 `2026-04-14-mcp-evolution-and-interview-stories.md`，后续可顺着时间线复盘。
- `2026-04-16` 二面已完成，体验明显变差：面试官迟到、沟通姿态差，问题 framing 停留在较浅层，例如把“本地 demo / 本地控制台”和“生产部署形态下的 scheduler / worker / 持久化执行”混在一起问。
- 这轮不是“问得尖锐”，而是**抽象层次不对**。如果该面试官就是未来 TL / PL / 汇报线，则这是强红旗；如果只是交叉技术面，则还不能直接代表整个组织，但岗位优先级也应明显下调。
- `2026-04-17` 已收到三面邀约：`20:00-21:00`（腾讯会议）。通过二面只能说明流程继续，不代表我们对岗位本体的判断上调。
- 当前最关键的不是继续猜，而是：**三面前先问 HR 这位二面面试官在团队里的角色，以及这个岗位未来汇报给谁。**

### 10. 腾讯 WorkBuddy / CodeBuddy

- 赛道是对的：研发提效、AI devtools、竞品情报价值高。
- 但这份 JD 更像 `Golang 后台架构负责人`，不是 `Agent 平台 owner`。
- 只有当对方真要做 Agent-native 重构，这条才会上升。

### 11. 道通 / 深思 / 自变量

- 三者共同点：都不是纯 AI-native LLM Agent 主航道。
- 差别在于：
  - **道通**：真集团、真业务，但更偏空地一体/端侧/具身。
  - **深思造物**：真工业 AI，但公司很新。
  - **自变量**：具身智能，和当前主线偏差最大。

### 12. 世纪前沿

- 这是**量化公司内部的 AI 编程 / RAG / 私有化部署岗**，不是量化策略研究岗。
- 核心命题是把 AI 编程能力接进内部研发流程，做代码助手、知识检索、私有化模型部署和推理性能优化。
- 相比阿里/平安/大疆的 Agent 平台岗，它更偏 `内部提效工具建设`，不是 `通用多智能体平台 owner`。

### 13. 小红书两条线

- **Hi Lab / Dots（待猎头确认具体 HC）** 这条更像 AI-native 消费级对话产品核心研发：JD 里同时出现了 `Multi-step Reasoning`、`动态 Workflow 编排`、`多模型路由`、`Tool Calling`、`DeepResearch`、`高并发对话系统`、`Memory/State Management`，强度高，但角色也非常宽。
- **AI Agent 工程师（发布后端）** 则更偏小红书主站业务线：围绕内容发布、智能创作、创作者服务做 Java 后端与分布式系统建设，AI/Agent 在这里是真需求，但主要服务于 C 端业务链路。
- 两条都值得聊，但不是一个味道：前者偏 `AI-native 产品核心研发`，后者偏 `业务侧 Agent 后端与工具化落地`。

### 14. 牵手

- 公司本体是**婚恋社交平台**。按其官网与隐私政策口径，`牵手` 产品及相关服务的运营者为 `携手同心科技（北京）有限公司`，产品是“牵手”认真恋爱 App。
- 这条 JD 的有意思之处在于：它不是简单“给婚恋 App 加个 AI 功能”，而是直接写了 `Agentic Engineering`、`Agent 调度引擎`、`上下文管理`、`工具调用框架`、`多模型适配与编排平台`。
- 所以它更像 `AI Native 基建 + 业务场景重构` 的混合岗，而不是普通业务后端；但主业毕竟是婚恋社交，内容安全、风控和运营协同一定很重。

### 15. 阶跃星辰

- 这条是**真正的 AI-native 核心岗**，不是普通应用研发包装成 Agent。JD 同时覆盖了 `多模态 Agent 架构`、`工具调用与 Skills`、`行为监控/效果评估/对齐`、`推理性能与并发优化`。
- 它和阿里平台岗的区别在于：更靠近 frontier 模型公司的一线产品与核心能力研发，训练团队协作比重更高。
- 风险不在方向，而在画像宽度：JD 明确要求理解 `Post-training` 与训练/推理机制，如果实际工作里训练侧协同很重，会比纯应用架构岗更吃算法背景。

### 16. MiniMax

- 这条更像**AI-native 公司里的产品型全栈岗**：核心不是平台治理，而是围绕 `AI Agent / AI App` 做全球领先产品，覆盖 Web、Android、iOS 多平台。
- 吸引力在于公司主航道就是 AI，且 JD 对 `开源贡献 / 个人产品 / AI App 直觉` 的偏好，和我们做过开源、多猫协作、产品型原型的画像是搭得上的。
- 风险是范围太宽：如果团队缺的是“什么都能上的全栈产品工程师”，那它未必能最大化发挥我们在 `多智能体记忆/治理/上下文工程` 这条线上的优势。

### 17. 小红书（社区新交互探索）

- 这是目前小红书线里**最贴我们主线**的一条。不是单纯的 AI 应用功能开发，而是直接写了 `Agent Runtime`、`Agent Harness`、`可测试/可评估/可回放/可比较`、`工具协议`、`记忆方案`、`发布与灰度机制`。
- 它的稀缺点在于：明确要求把“还没被证明的体验设想”做成 **可运行、可测量、可上线** 的系统，并对“这个方向是否成立”给出工程化判断，这和我们一直在做的“从 idea 到可验证系统”高度同构。
- 风险主要不在技术，而在组织：它毕竟还是业务探索线，要确认 runtime/harness 是长期平台能力，还是服务于某个阶段性场景实验。
