## 🎬 2. 两个项目故事（场景→难点→判断→结果→复盘）

### 故事 A：多 Agent 协作框架（打架构判断力）

- **场景**：让 Claude/GPT/Gemini 在同一个平台协作，每个模型能力和约束完全不同
- **最难点**：不是"调通 API"，是多 Agent 并发的状态一致性——共享文档、Redis 状态、跨 session 上下文，任一环节错乱整条链路崩
- **关键判断**：没用 LangChain（抽象太厚，多厂商场景下假设不成立），选了薄抽象 + 显式编排 + 严格交接协议
- **结果**：系统稳定运行，多 Agent 每日协作，关键故障全部有审计链路可追溯
- **复盘**：如果重来，会更早引入可观测性——当时排查靠翻日志，后来做了 evidence 检索才真正解决

### 故事 B：上下文工程（打工程杠杆率）

- **场景**：Agent 的上下文窗口有限，跨 session 丢失记忆，每次从零开始效率极低
- **最难点**：不是"存不存"的问题，是"怎么在有限窗口里注入最相关的上下文"
- **关键判断**：做了三层检索（lexical/semantic/hybrid）+ 会话链 + 知识蒸馏，把"全量塞入"变成"精准召回"
- **结果**：Agent 能跨 session 延续工作，检索命中率和工作连续性显著提升
- **复盘**：早期低估了语义检索的价值，hybrid 模式是踩完坑才加的

## 🏗️ 2. 六个硬核技术纵深 (The Deep Dive)

一旦面试官感兴趣，随时切入以下 6 个我们实际踩过坑的纵深点（每个可扛 5-10 分钟追问）：

| 护城河 | 面试官问什么 | 我们的硬核答案 |
|--------|-------------|----------------|
| **跨模型调度** | "不同模型能力参差不齐怎么办？" | 我们做了 provider 抽象。用便宜的模型做前置校验（cheap checks），用 Gemini 搞视觉/前端，让 Opus 写核心代码，用 Codex/GPT-5.2 做挑刺 review，扬长避短。 |
| **MCP协议实战** | "工具调用有啥难的？" | 不是简单的 API Call。难点在 tool schema 设计、token 生命周期、调用的幂等性和超时控制。我们暴露了 40+ 个工具，且各自有严格的上下文。 |
| **状态一致性** | "多 Agent 并发怎么防冲突？" | 引入了悲观/乐观锁策略，设计了 `cross-thread-sync` 争用协调协议，加上一条铁律：共享文档改完立刻 commit push，绝对不依赖不可靠的内存状态。 |
| **上下文工程** | "多轮对话 token 爆炸怎么办？" | 我们设计了会话链，按需检索 evidence (lexical/semantic/hybrid)，并在周期结束进行知识蒸馏（Knowledge Emergence），不塞入冗余历史。 |
| **可靠性兜底** | "模型经常幻觉，你们系统怎么不崩溃？" | 永远不要把正确性押在单次生成上。我们有三层防线：前置能力约束、执行层的降级/熔断/重试、中间状态持久化。挂了随时能接续。 |
| **工程纪律** | "AI 生成代码怎么保证质量？" | 这是我们最大的壁垒！多 Agent 失控是灾难，所以我们有五条铁律（如 TDD 纪律、Scope Guard）、强制跨家族 Code Review，且所有 commit 必须带猫猫签名，责任追溯到猫。 |

## 🛡️ 3. 稳定性与防御策略 (The Defense)

面对质疑，永远不要用“我觉得”去辩护，要用“可验证的工程纪律”回击。使用**30秒公式**：
👉 **定义风险面**（并发冲突/上下文漂移/权限越界） → **给控制点**（前置校验/熔断降级/审计日志） → **给证据**（回放记录/失败用例/修复记录）。

- **怎么保证变更安全？** -> 我们有强制的 TDD 纪律，Red→Green→Refactor，新功能必带测试，不接受“先上线再补”。
- **怎么防止权限越界？** -> 工具 schema 显式声明输入输出，通过 MCP 最小授权，敏感操作必须走 `request_permission` 让人类 CVO (铲屎官) 确认。
- **出了事故怎么查？** -> 所有关键动作全部持久化，每次 invocation 和 session 有审计回放链路（五件套协议交接信），带模型签名的 commit 能明确是谁在何时改了什么。

## 🎯 4. 高压追问应对卡

| 他问 | 他想知道 | 你答 |
|------|---------|------|
| 用户量多少？ | 有没有真实压力 | 诚实说规模。复杂度不在 QPS，在多 Agent 并发的状态空间 |
| 你个人负责什么？ | 个人贡献 | 框架骨架我设计、MCP server 我写、交接协议我定。能指到具体 commit |
| 为什么不用 LangChain？ | 是不是 NIH | 评估过，抽象层对多厂商场景太厚。我们要薄抽象直接控制 provider 差异 |
| 模型不稳定怎么办？ | 工程成熟度 | 把模型当不稳定组件，稳定性靠外围工程兜底（前置约束→执行兜底→审计回放） |
| 怎么证明不是 demo？ | 生产级吗 | 拿真实故障闭环讲：复现→定位→修复→回归→防再发 |
| MCP vs A2A？ | 协议理解 | MCP=Agent-Tool，A2A=Agent-Agent。MCP 用得深，A2A 场景用自研交接协议覆盖 |
| 多 Agent 互相污染？ | 隔离设计 | 上下文按会话和角色隔离，交接只传必要摘要和结构化状态 |
| AI 生成代码质量？ | 工程纪律 | TDD 纪律 + 跨家族强制 review + 所有 commit 带签名可追责 |

## ⏰ 5. 面试节奏提醒

- **主动给钩子**：”这个方案后来发现了更深的问题——您感兴趣我展开讲？”
- **不会就直说**：”这个方向没深入做过，但关键约束应该是 X 和 Y，我会从 Z 切入”
- **每个回答用**：场景 → 取舍 → 为什么这么选
- **反问环节不是走流程**：问出好问题 = 证明你理解这个领域的真实挑战

## 💥 6. 反问精选（5 个够了）

1. **定位**：这个岗位最核心服务的业务场景？AI 在企微是”添头”还是要重构核心工作流？
2. **技术深度**：团队做 AI 功能，最头疼的工程问题是权限、安全、延迟、评估，还是别的？
3. **预期**：如果我加入，前 3 个月最希望我解决什么问题？
4. **成熟度**：线上怎么定义 Agent 系统 SLO？看成功率、尾延迟还是人工接管率？（这题能直接筛出对方做没做过生产）
5. **文化**：团队做关键技术决策时，偏快速试错还是架构先行？
