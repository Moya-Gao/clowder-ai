## 2. 两个故事

### 故事 A：多模型统一调度与协作治理

**一句话**：怎么让 Claude、GPT、Gemini 三个完全不同的模型在同一个平台上安全协作。

**场景**：
每个模型的 CLI 调用方式、事件流格式、session 管理完全不同。Claude 输出 NDJSON，Codex 是自有格式，Gemini 又是另一套。要让它们在同一个 Thread 里协作，不是换个 API key 的事。

**最难点**：
不是"调通 API"。难在三个层面：
1. **接口差异**：每个 CLI 的 spawn / sendMessage / abort / event 行为都不同
2. **能力差异**：Gemini 擅长视觉但不能写代码；Codex 擅长 review 但上下文窗口不同；Claude 写代码快但贵
3. **并发状态**：多个 Agent 同时操作共享文件、Redis、文档，任一环节状态错乱整条链路崩

**关键判断**：
- 没用 LangChain — 评估后发现它的抽象层假设所有模型行为一致，但我们的核心问题恰恰是**模型行为不一致**。选了薄抽象：一个 ICliAdapter 统一接口，每个模型一个 Adapter 实现，上层不感知底层差异
- 不做中央 orchestrator — 猫和猫之间是对等判断，不是主从指挥。路由通过 @mention 触发，走统一 Dispatch Queue（支持排队/插队/暂停/重启恢复）
- 交接用五件套协议（What/Why/Tradeoff/Open/Next），不是自由聊天

**结果**：
6 个品种的 AI 每天在同一个平台协作，161 个 Feature 都是这样交付的。关键故障全部有审计链路——每个 commit 带模型签名，能追溯到是哪只猫在什么时候改了什么。

**复盘**：
如果重来，会更早做 Dispatch Queue 的重启自愈。早期进程重启后 in-flight 任务丢失，后来补了队列状态持久化和自动恢复。

### 故事 B：记忆系统 — 从"记住"到"学会"

**一句话**：Agent 的上下文窗口有限，跨 session 丢失所有记忆。怎么让它们"记住"甚至"学会"。

**场景**：
每次新 session，Agent 对之前的架构决策、踩过的坑、讨论过的方案一无所知。相当于每天来一个新员工。

**最难点**：
不是"存不存"的问题——存了几千篇文档。难在"怎么在有限的上下文窗口里注入最相关的那几段"。全塞进去 token 爆炸，不塞又回到失忆。

**关键判断**：
做了三层架构：
1. **文档真相源**（docs/ 目录，git 版本化，1922 篇）— 唯一权威数据
2. **检索索引**（evidence.sqlite）— BM25 全文 + 向量语义 + RRF 融合，启动时自动从 docs/ 重建
3. **知识晋升**（Knowledge Feed）— 每 30 分钟自动从对话中提取 durable knowledge 候选，走状态机（captured → normalized → approved → materialized → indexed），人类审核后才沉淀

三种检索模式：lexical（精确 ID）、semantic（跨语言同义）、hybrid（日常默认）。

更深一层：记住还不够，要"学会"。设计了五级阶梯：
```
Episode（一次事件）→ Method（提炼方法）→ Skill（封装行为协议）
  → Eval（可验证检查点）→ SOP（写入团队流程）
```
50 条 lessons-learned，每条追到根因，不是"下次注意"。

**结果**：
Agent 能跨 session 延续工作。开工前自动检索相关上下文注入，不再从零开始。教训变成了系统级防护，同类错误不再重复。

**复盘**：
早期只做了 lexical 检索，漏掉了大量语义相关但措辞不同的内容。hybrid 模式是踩完坑才加的——这本身就变成了一条 lesson。

## 3. 展示档位（面试官追问深度不同，按档切换）

### 第一档：画一条主链路（3 分钟）

```
用户消息 → targetCats 路由（谁来做）
  → Dispatch Queue（排队/插队/暂停）
  → CLI Adapter（统一接口调模型）
  → Agent 执行（MCP 工具调用，40+ 工具）
  → 跨 Agent 交接（五件套协议）
  → 状态持久化（Redis + evidence.sqlite）
  → 结果回传（WebSocket 实时推送）
  → 失败兜底（重试/降级/中间状态恢复）
```

面试官对哪个节点感兴趣就往下钻。不要试图全讲完。

### 第二档：挑一个节点深入（5-10 分钟）

| MCP 工具体系 | 自己实现 MCP server，40+ 工具，tool schema 显式声明，鉴权 + token 生命周期 + 幂等性 |

### 第三档：讲设计哲学（面试官明显感兴趣时）

**决策漏斗 — 一句话怎么变成一个 Feature**：

大多数 AI coding 工具的模型：人说需求 → AI 写代码 → 人看对不对。隐含假设：人的第一句话就是完整需求。

我们不做这个假设。铲屎官的一句话是**信号**，不是 spec：

```
信号 → CVO 采访（追问隐藏需求）→ 多猫独立调研（互不可见）
  → 讨论收敛（分歧保留理由，共识结晶为约束）
  → Feature Spec + ADR → Design Gate → 进入交付管线
```

161 个 Feature 每一个都走过这条漏斗。没有一个是"人说一句话猫就开始写"。

**真实例子**：铲屎官凌晨说了一句"飞书和微信能不能直接跟猫聊天？"然后去睡了。第二天早上：BACKLOG 多了一行，docs/ 下出现了 3000 字 spec，一只猫在底部留了 Threat Model，另一只猫已经开了 worktree。但中间经过了 CVO 采访、隐藏需求挖掘（"表面需求是聊天，隐藏需求是零摩擦入口——家不应该是你必须特意去的地方"）、架构讨论、约束收敛。

## 4. 追问应对卡

| 他问 | 怎么答（用具体的东西） |
|------|---------------------|
| 用户量多少？ | 诚实说规模。但复杂度不在 QPS——同时 6 个不同厂商 Agent 并发协作的状态空间，管理难度不亚于高并发服务 |
| 你个人负责什么？ | CLI 抽象层我设计的、MCP server 我写的、交接协议我定的、记忆检索架构我做的。4400+ commit 里有签名可追溯 |
| 为什么不用 LangChain？ | LangChain 假设所有模型行为一致，我们的核心问题是模型行为不一致。需要薄抽象直接控制 provider 差异 |
| 和开源 agent 框架区别？ | 大多数解决单模型+工具。我们解决多个异构 Agent 的协作治理——身份、权限、状态同步、交接协议、审计 |
| 模型不稳定怎么办？ | 把模型当不稳定组件。三层：前置约束（限输入和权限）→ 执行兜底（超时/重试/降级）→ 审计回放（每次调用可还原） |
| 怎么证明不是 demo？ | 66 天 161 个 Feature 全量交付。50 条 lessons-learned 每条追到根因。5 个 IM 平台接入在跑。不是 POC |
| MCP vs A2A？ | MCP 解决 Agent-Tool 集成，A2A 解决 Agent-Agent 互操作。MCP 我们用得很深（自己实现了 server），A2A 场景用自研交接协议覆盖，因为需要更强治理能力 |
| AI 生成代码质量？ | TDD 红绿重构不跳步 + 跨模型强制 review（Claude 写的 GPT 审）+ 双层审查（本地+云端）+ 所有 commit 带模型签名可追责 |

## 8. 你能带给他们什么（如果需要收尾升华）

不搞 multi-agent 也能借鉴的模式——这些是你做过的、可迁移到任何企业 AI 系统的工程实践：

- **Cross-model review**：不同模型盲区不同，交叉检查 > 同模型自检
- **Dispatch Queue + 重启恢复**：管理异步 AI 调用不要裸调
- **三层记忆架构**：文档→索引→知识晋升，不要全塞 prompt
- **Skill = 行为协议**：定义"什么场景做什么"不是"能做什么"
- **教训驱动进化**：不是"下次注意"，是"这条规则从此生效"
- **Connector 抽象**：多平台接入用归一化层，不要每个平台一套
