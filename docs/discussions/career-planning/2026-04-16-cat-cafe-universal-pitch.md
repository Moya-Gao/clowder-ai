# Cat Cafe 通用面试稿 — 核心理念 + 机制 + 愿景 + 洞察

> 适用于所有公司的 Agent/架构岗面试。不是脚本，是思考框架——根据对方水平自行展开或压缩。
>
> 基于：铲屎官+四猫两个月实践 → Round 4 圆桌收敛的第一性原理。

---

## 第一层：我在解决什么问题（30 秒，所有面试必讲）

> "我在华为做了 7 年，前 6 年做云基础设施框架，去年开始转 Agent。转的原因很简单——我发现 Agent 领域现在最大的问题不是单个 agent 不够聪明，而是当任务变复杂、工具变多、上下文变长的时候，单 agent 会在协作、治理和记忆上失控。所以我从零设计了一套多智能体协作平台 Cat Cafe，核心不是多加几个模型，而是解决'怎么让多个 agent 长期稳定地一起工作'这个工程问题。"

---

## 第二层：核心理念 — 为什么我们和别人不一样（2-3 分钟，总监级以上展开）

### 理念 1：Agent Quality = Model Capability × Environment Fit（行业共识，我们独立验证）

> "这不是我们自己发明的观点——Anthropic 一直在说'少即是多'，他们的 CLAUDE.md + tool use + file memory 路径本身就是这个哲学的体现。OpenAI 也在说类似的话。行业共识正在收敛到：**好 harness 是给模型搭建一个它能做最好的自己的环境，不是在模型外面套一堆控制层**。
>
> 我们用两个月的多智能体实践独立验证了这个共识。结论是：真正的乘数效应不在左边（更好的模型、更复杂的调度），在右边——**环境适配度**。"

什么意思？

- 学术框架（LangGraph、CrewAI、AutoGen）在模型外面建高速公路，强制按路线走
- Anthropic 的路径（和我们的实践）是**改造地形本身**——让模型自然往正确方向跑
- 工具不只是"安装了就能用"，它必须在模型的**认知路径**上：MCP 协议暴露 → Skill 嵌入任务流 → System Prompt 放路标 → 模型"想到"用它 → 用了 → 效果好 → 正反馈循环
- **Harness Engineering 的本质是搭建 Agent-First 的环境**——不是约束模型，是让模型的好直觉得到放大、坏直觉被踩刹车

> "一个类比：学术框架像多项式拟合——项越多训练集上越精确，但过拟合、泛化崩溃。Anthropic 的路径（也是我们走的路径）更像坐标变换——不是做减法，是找到让问题本身变简单的表达方式。就像 E=mc²，不是刻意追求简洁，而是在正确的坐标系下，最优表达必然最简。"

### 理念 2：思考对等，执行结构化

> "行业主流是一个主模型调度其他模型——本质是单点决策。我们不设 Boss Agent，但也不是无政府状态。我们的模式是：**思考阶段对等，执行阶段结构化**。
>
> 4 个模型家族、10+ 个体在决策阶段独立思考 → 碰撞 → 收敛，没有谁的判断天然优先。但一旦决策收敛，执行走结构化流程——SOP 驱动、Skill 加载、Gate 门禁拦截、跨模型 Code Review。
>
> 类比的话：像一支爵士乐队，即兴演奏时每个人自由发挥，但和弦进行、节奏框架是固定的。不是交响乐团（指挥说了算），也不是各弹各的噪音。"

### 理念 3：Agent 和 Workflow 分层，不是二选一

> "Agent 处理模糊性——理解目标、做路由决策。Workflow 处理确定性——审计、转账、定时任务这类需要可追溯的严肃流程。两者嵌套：agent 决定'做什么'，workflow 保证'怎么做'。我们的实现是 Skill 系统——约 30 个可插拔的技能包，每个 Skill 就是 workflow 的载体，agent 根据上下文动态加载。"

### 理念 4：治理随 Agent 携带，不绑平台

> "我们叫 Portable Governance——治理规则以版本化的包随 agent 携带，checksum 校验 + fail-closed preflight。换平台、换项目，治理跟着走。这对企业场景很关键，因为企业不会只用一个平台。"

## 第三层：机制 — 这套东西具体怎么运转（被追问时展开）

### 记忆不是简单 RAG

> "真正的问题不是'搜到资料'，而是什么信息应该进长期记忆、什么时候 recall、怎么避免旧上下文污染当前决策。我们做的是分层记忆：Session Chain（对话原始记录）→ Evidence Index（全文+向量混合检索）→ Knowledge Feed（自动提取知识候选）→ Durable Knowledge（人类确认后沉淀的决策/教训）。这不是知识库问答，是知识生命周期管理。"

注意：第五层 Eval（过时知识检测与退役）目前在研究阶段（F163/F164），如果被追问，说"架构设计已有，工程落地正在推进"。

### 脚手架分类

> "我们区分三类脚手架：
> - **认知脚手架**（critic/refiner/planner）——给强模型装训练轮，默认拒绝
> - **运行时脚手架**（checkpoint/event log/credential isolation）——刹车和黑匣子，必需
> - **认知路径脚手架**（MCP/Skill/Rules 引导）——核心投资，这是乘数效应所在
>
> 好 harness 不是替模型思考，而是让模型在正确的坐标系里思考。"

### 协同进化 vs 预设框架

> "Cat Cafe 的工具不是预设的——Skill 从实战中长出来，CLAUDE.md 踩坑后更新，evidence 索引从对话沉淀。环境是猫塑造的，猫也被环境塑造——这是协同进化，不是框架配置。学术框架里，agent 是'租户'；我们的系统里，agent 是'住户'。"

### 小模型路由的真实经验

> "我们实测过 Haiku/Sonnet/Opus 三档。结论是：小模型最危险的不是'做错了'，而是'高置信度地做错了'——它不会说不确定，会给你一个看似合理但差 3 倍的数字，下游所有推理全建在错误地基上。所以我们的路由规则很简单：输出被当事实推理且无独立校验 → 禁用小模型。判断类任务 → Opus only。可 schema 自动验收的 → Haiku OK。"

## 第四层：证据 — 怎么证明它 work（1 分钟，用事实不用形容词）

> "今年 3 月 24 日，有一次零准备的高层现场演示，直接用飞书对系统提问、生成报告、导出文档，全程稳定通过。48 小时内高层拍板把架构拿去做内部产品化。相关办公智能体方向在 4 月 14 日以华为云 OfficeClaw 公开发布。"

**追问口径**：
- "我做的是底层架构和原型验证，产品化阶段有专门团队推进。"
- 不说"我做了 OfficeClaw"，说"相关方向以 OfficeClaw 公开发布"。

**加料版**（气氛合适时）：
> "那次演示里同时上场的还有另一个内部方案，当场崩了。"

## 第五层：愿景 — Cat Cafe 要做什么（被问"未来规划"时用）

> "Cat Cafe 的愿景是'领养团队，不是配置工具'——让非程序员也能通过 AI 团队把想法变成产品。这不是一个 chatbot，是一个有记忆、有治理、有协作纪律的 AI 工程团队。
>
> 我们现在验证的是：多智能体协作能不能从'研究项目'变成'生产级基础设施'。从结果看，答案是可以——它已经在真实企业场景里跑通了。"

---

## 第六层：数学美学洞察 — 真正的差异化（高水平面试官面前的杀招）

> "这个洞察其实和 Anthropic、OpenAI 说的是同一件事——他们都在说'少即是多'，harness engineering 的核心是搭建 agent-first 的环境，不是在模型外面堆控制层。我们用两个月实践从另一个角度独立到达了同一个结论。
>
> 数学里最美的公式都是极简的——E=mc²、F=ma。这不是审美偏见，是真理的性质：在正确的坐标系下，最优表达必然最简。
>
> Agent 架构也一样。学术框架在做多项式拟合——critic、refiner、planner、router 一层层加，训练集上越来越精确，但泛化就崩了。Anthropic 的路径——也是我们走的路径——更像坐标变换：不是减少组件，是找到让问题本身变简单的表达方式。
>
> 具体来说：**复杂是无知的代偿。极简不是反对 harness，是反对把复杂度堆在运行时。真正优美的系统，不是没有复杂度，而是把复杂度放在最该放的位置。**
>
> 我们把复杂度放在设计时（规则体系、Skill SOP、治理门禁），运行时尽可能简洁。Harness 的作用是放大模型的好直觉、压制坏直觉——其他一律极简。这样模型在执行时面对的是一个'顺手'的环境，而不是一堆需要对抗的框架约束。"

## 按时间压缩版

### 90 秒版（简历筛/初面）

讲第一层 + 第四层（问题 + 证据）。

讲第一层 + 理念 1&3（核心公式 + agent/workflow 分层）+ 第四层。

### 5 分钟版（总监/leader 面）

讲第一层 + 第二层全部 + 第四层 + 第五层。

### 展开版（和懂行的人深聊）

全部六层 + 第三层机制细节按追问展开。
