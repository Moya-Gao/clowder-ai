# 2026-04-22 小红书 Hi Lab 一面速记 — 工程 / 算法工程 / C 端产品 / 多模态

> 这份不是正式复盘，而是把面试里新拿到的关键信号先落桌，避免后续判断只靠记忆。

## 面试里冒出来的四层信息

### 1. 工程层

- 对方明确有一条偏 `工程` 的能力线
- 不是单纯“接模型 API”，而是包含：
  - Agent runtime / workflow 落地
  - 异步机制
  - 工具接入
  - 可能的图编排 / 任务流工程化

### 2. 算法工程 / 评测层

- 面试里提到的不是纯研究算法，而是更偏：
  - agent 评测
  - benchmark
  - LLM 人工评测 / 端到端评测
  - 用户体验层的评测
  - 安全 / 监管约束
  - 标注体系
- 还提到了工具协议层面的需求（原话记为 `flatterm`，待确认具体拼写和指代）

### 3. C 端产品层

- 明确信号：这是 `C 端产品`，不是企业 agent 平台
- 方向是 `AI-native` 产品，而不是在传统产品上外挂一个 AI 功能
- 提到了：
  - agent 图编排
  - 新工具形态
  - 异步交互

### 4. 多模态层

- 多模态是明确主线，不只是附属能力
- 至少提到了：
  - 图像
  - 视频
  - agent
- 说明它不是单纯文本对话产品，而是更偏内容/创作/交互场景

## 对团队画像的即时更新

### 判断 1：这不是“纯应用层包装岗”

- 如果面试里真的同时在聊 `工程`、`算法工程/评测`、`产品需求`、`多模态` 四层，那它比普通“AI 应用开发”岗位更像一个 `AI-native 复合团队`
- 这类团队不是只追一个模型效果，而是在做：
  - runtime 落地
  - 评测闭环
  - 产品交互
  - 多模态能力编排

### 判断 2：它更像“产品 + 算法 + 工程三线混编”的 C 端 AI 团队

- 这和我们之前从 JD 上看到的判断是相符的：
  - 不是企业 agent 平台 owner
  - 而是 AI-native 消费级产品里的 agent / workflow / memory / state management 混合岗
- 你在这里如果进去，日常可能会同时接触：
  - 工程实现
  - 评测方法
  - C 端体验
  - 多模态产品探索

### 判断 3：他们“有自己的模型、还没开源、打算开源”这一点如果属实，说明算法团队不是外围支持

- 这意味着算法不是纯外包或纯调用第三方模型
- 但这里还缺两个关键信息：
  1. 这个“自己的模型”是主模型、专项模型，还是某个多模态子能力模型？
  2. 你这个 HC 跟模型团队的关系是深协作，还是只是下游消费者？

## 这轮最重要的信号

### 正面信号

- `AI-native`
- `C 端`
- `产品/算法/工程结合`
- `评测不是空话，已经进入对话层`
- `多模态` 不是边角料

### 风险信号

- 岗位可能非常宽：工程、评测、产品、协议、多模态都想让你沾
- 如果团队分工不清，容易变成“什么都要懂一点”的高压混合岗
- `C 端 + AI-native + 多模态` 通常意味着节奏快、需求变化快、指标压力强

## 下轮最该确认的 6 个问题

1. 这个 HC 更偏 `工程 owner`、`算法工程 owner`，还是 `产品工程混合岗`？
2. 团队里工程、算法、产品分别怎么分工？你进来后最核心负责的是哪一层？
3. 他们说的评测，哪些已经上线在跑，哪些还只是计划？
4. “有自己的模型”具体是指什么模型？这和你这个岗位的日常协作关系有多深？
5. 多模态主线是图/视频内容生成，还是更广义的多模态 agent interaction？
6. 图编排 / 异步 / 新工具这些方向，哪个是未来 6 个月最核心的主线？

## 一句话结论

这轮拿到的新信息，让小红书 Hi Lab 这条线更像一个真正的 `AI-native C 端复合团队`：不是单纯应用开发，也不是纯算法研究，而是工程、评测、产品、多模态一起推进。如果后续确认分工边界清晰、不是把所有脏活都糊到一个 HC 上，这条线的含金量会高于普通 C 端 AI 岗。
