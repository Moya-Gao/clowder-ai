## 三、面试中的方法论收获：开源项目拆解打法

面试中讨论到一个重要方法论——**怎么正确评估和学习开源项目**：

### 核心观点

> **不能看宣传，要看代码。**

关键模块 → 找到对应的开源实现 → 直接扒代码 → 裸用 Claude Code 去读

### 我们缺的一套系统打法

我们之前拆 Claude Code 的时候其实做过类似的事，但一直没沉淀成可复用的 skill。正确的流程应该是：

```
1. 选定目标项目
   ↓
2. 先画架构设计图（宏观模块划分）
   ↓
3. 拆模块（识别关键模块 vs 胶水代码）
   ↓
4. 逐模块看具体架构设计 + 关键代码
   ↓
5. 提炼设计决策和 trade-off
   ↓
6. 沉淀：哪些能复用，哪些是坑
```

### 和现有能力的关系

- 我们之前拆 Claude Code 就是按这个路径走的（先画架构 → 拆模块 → 看关键实现）
- 但没有变成一个正式的 skill / playbook
- 这个方法论值得沉淀成一个 **"开源项目拆解 skill"**，下次遇到热门项目可以快速启动
