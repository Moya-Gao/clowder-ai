# 2026-04-29 淘天二面复盘 — 信息不对等与方案收集风险

## 基本信息

- 公司/线：阿里淘天集团-业务技术
- 岗位：AI Agent 开发专家（急招）
- 轮次：二面
- 时间：`2026-04-29 19:30`
- 铲屎官主观反馈：感觉不好，怀疑对方在“偷方案”

## 面试现象

本轮与 `2026-04-17` 一面的正向信号形成反差。

铲屎官反馈：

- 对方把 Cat Cafe / 多 Agent 协作 / 架构设计问得很细。
- 但当铲屎官反问对方团队在做什么、要解决什么问题、岗位具体负责什么时，对方回答很敷衍。
- 整体体验像“单向索取架构方案”，而不是双向评估匹配度。
- 铲屎官追补：问对方任何问题，基本都是两句话敷衍结束。
- 铲屎官判断：以对方对 agent 的理解深度看，甚至不像充分理解 Anthropic 的五种 multi-agent coordination patterns。

## 判断

不直接下结论说对方“偷方案”，但这轮暴露了明确红旗：

| 风险 | 判断 |
|---|---|
| 信息交换不对等 | 对方深挖候选人架构，但不愿披露自身团队/项目/目标 |
| 岗位透明度不足 | 二面仍回答不清“做什么、为什么做、做到哪层” |
| 技术成熟度存疑 | 对 multi-agent 基础分类和工程模式的理解可能不足 |
| 方案收集风险 | 候选人输出高密度实践细节，对方未给等价信息回馈 |
| 优先级下降 | 一面“懂 agent infra”的正向判断需要回调 |

## 和一面判断的修正

一面结论曾判断：淘天像“同行”，不是浅层 AI 应用岗。

二面后修正为：

> 淘天确实可能在做 agent infra 相关问题，但候选人侧可见的信息透明度不足。它能识别 Cat Cafe 的价值，不等于它愿意给出对等岗位授权、资源和职业回报。

进一步修正：

> 不排除对方对候选人不满意，但从行为模式看，更强的信号是“团队透明度不足 + interviewer 对 agent-native 架构理解不够深”。如果二面面试官代表未来汇报线或核心技术判断层，则该岗位应继续降权。

## 后续策略

如果淘天继续推进，不再继续展开 Cat Cafe 的底层架构细节。后续统一改成“原则层 + 结果层”回答：

- 可以讲：问题定义、取舍原则、可验证结果、为什么这样设计。
- 不继续讲：完整模块拆解、具体状态机、球权协议细节、治理规则实现、内部 prompt/skill 组织方式、落盘结构。

反问优先级：

1. 这个岗位入职后前三个月具体 deliverable 是什么？
2. 团队现在在做通用 Agent runtime，还是某条淘天业务线的定制平台？
3. 你们现在已有的 agent runtime / model gateway / eval / observability 做到哪一层？
4. 这个岗位是否有架构 owner 权限，还是只负责实现指定方案？
5. 如果你们希望我继续展开方案细节，能否先说明当前团队边界、已有系统形态和我的角色授权？

## 当前优先级

从 `Tier 1 / 强匹配` 下调为 `降权观察`。

不是因为技术方向不对，而是因为二面暴露了：

- 透明度不足
- 授权不清
- 候选人价值被单向提取的风险

后续除非对方明确给出团队/岗位/授权信息，否则不继续作为主攻机会。
