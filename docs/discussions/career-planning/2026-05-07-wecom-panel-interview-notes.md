# 2026-05-07 腾讯企微面委会面经 — 系统分层 / 记忆设计 / vibe coding

> 这轮记录的重点不是“面得好不好”，而是**对方到底在问什么**。相比之前偏浅层的企微轮次，这次问题更集中在 agent engineering 的系统设计、协作治理和工程落地。

## 基本信息

- 公司 / 线：腾讯企微（WXG）
- 岗位：AI Agent 开发工程师
- 轮次：面委会一面
- 时间：2026-05-07 19:00-20:00（北京时间）

## 面试问题原始清单

### 一、架构与系统设计

1. 架构图为什么要这样分层？
2. 记忆系统为什么这样设计？
3. 在存量项目里，要如何用猫猫开发？
4. 你们在团队多人开发过程中，出现很多冲突之后如何解决？
5. 如何保证新的功能加入进去后，老功能不漂移？
6. 如果我们的云服务用这个开发，依赖了其他服务，他们要如何开发和做测试？
7. 你的项目如何迭代到现在这样的？
8. 你在你们团队内的职位是干嘛的？如何和他们分工？
9. 你有做 `session` 隔离吗？或者记忆隔离？提起别的项目记忆会不会搞乱当前项目？
10. 他们在长流程开发中如何做到上下文一致？比如一个功能开发五天，过程中如何目标不偏移？
11. 如果要把你这个做成云端版本，你有设计吗？如果做成逻辑多租要怎么做？

### 二、工程治理与质量

1. 猫猫开发过程中遇到需求变更怎么办？特别是 `SDD` 场景中的需求变更
2. 有测试 agent 吗？
3. 你的用户在使用过程中出现问题，如何反馈给你？

### 三、使用方式与产品化

1. 你能讲一下，如果用你的猫猫进行 `vibe coding`，他的流程是什么样的吗？
2. 你这个项目为什么公司会允许你开源？
3. 你现在的级别？为什么走？

### 四、现场题 / 设计题

1. `vibe coding` 题
2. 用你的猫猫实现一个 `Claude Code` 简易版 / 实现一个断路器

## 这轮问题透露出的信号

### 1. 这次终于开始问“怎么长期做系统”

和此前企微线一些更偏浅层或更偏八股的轮次不同，这轮问题明显更聚焦：

- 架构分层
- 记忆设计
- 冲突治理
- 需求变更
- 回归稳定性
- 测试策略
- 用户反馈闭环
- session / memory 隔离
- 长流程上下文一致性
- 云端化与多租户设计
- 开源边界与组织许可

这说明至少这位面委关注的不是“会不会调 API”，而是：

> 这套 agent 系统能不能进入真实团队、真实项目、真实工程流程。

### 2. 对方在尝试判断：这是“玩具 demo”还是“工程系统”

像下面这些问题，本质上都不是在问功能，而是在问**工程可信度**：

- 为什么这样分层？
- 老功能怎么不漂移？
- 依赖其他服务怎么测？
- 需求变更怎么办？
- 有没有测试 agent？

这类问题说明，对方在判断的是：

> 你的系统能不能从“展示能力”升级到“组织可采纳能力”。

### 3. `vibe coding` / Claude Code 简化版题，说明他们在试探可迁移性

这类题不是要你再讲一遍 Cat Cafe，而是要你证明：

- 你不是只会讲自己的项目
- 你能把抽象方法迁移到一个新系统
- 你能把复杂协作系统收缩成最小可落地骨架

换句话说，他们在试你：

> 你是“做过一个项目的人”，还是“掌握了一套可迁移方法的人”。

## 这轮真正想考什么

如果把这些问题压缩成 4 个核心维度：

1. **系统抽象能力**
   - 分层
   - 记忆
   - 角色分工

2. **工程治理能力**
   - 冲突处理
   - 需求变更
   - 回归稳定性
   - 依赖服务测试
   - 长流程一致性
   - session / 记忆隔离

3. **质量保证能力**
   - 测试 agent
   - 用户反馈回路

4. **平台化 / SaaS 化能力**
   - 云端版本
   - 逻辑多租户
   - 服务依赖下的开发与测试

5. **方法迁移能力**
   - vibe coding 流程
   - Claude Code 简化版
   - 断路器设计

6. **组织与可信度判断**
   - 为什么公司允许开源
   - 候选人的级别与离职动机

## 目前的即时判断

### 正面

- 这次问题集比之前企微线的很多轮次都更像真正的 agent engineering 面
- 对方至少在试图判断“真实工程系统”而不是“演示项目”
- 问到了长期演进、需求变化、依赖服务测试这些真实问题，说明不是只看 prompt 层

### 待观察

- 是否真正理解多智能体 / 记忆 / 协作治理背后的设计取舍，还要看追问质量
- 是否会把这些问题最后收敛回岗位真实职责，而不是“想全考一遍”
- 是否会在后续给出足够清晰的团队边界和授权范围

## 一句话结论

这轮面委会的问题，第一次比较系统地把企微这条线拉到了“真实 agent engineering”层面：它不是在问你会不会做 demo，而是在问你这套东西能不能进团队、进流程、进生产。
