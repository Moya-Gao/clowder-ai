# 深信服 AI Coding 机会复盘

## 一、事实摘要

这次沟通把深信服从“薪资/职级校准样本”上调为“需要认真评估的 AI Agent 工程化机会”。

已知信息：

- 薪酬结构：基本月薪 + 年终奖（0-6 个月，常态约 4 个月）+ 股票（真实股票）。
- 组织位置：AI Coding 部门，服务深信服内部研发，同时做开源 + 商业化。
- 组织升级：2025 年是二级部门，2026 年升级成一级部门；编制由创始人团队批准，投入力度上升。
- 业务目标：2026 年营收目标千万级。
- 产品方向：企业 AI Coding / coding agent 解决方案，类似 Claude Code / Cursor，但面向企业研发场景。
- 已有商业信号：央企/招商局方向有 200w+ 级别成交，与腾讯、中兴等竞品竞争。
- 团队定位：中台能力团队，研究院/部门内有 infra 和 harness 方向。

## 二、技术方向拆解

### 1. 企业级 AI Coding

核心不是普通“写代码助手”，而是面向企业大代码仓和组织研发流程：

- 大代码仓开发
- 上下游依赖分析
- 多仓协同
- 代码迁移与生成
- coding agent 与企业研发流程结合

关键问题：

> 企业内部代码规模、权限、依赖、流程复杂度远高于个人项目，AI Coding 的核心难点会从“能不能生成代码”转向“能不能理解组织级上下文并安全落地”。

### 2. 代码图谱与多仓依赖

明确提到：

- 大代码仓如何开发
- 图谱怎么做
- 上下游依赖怎么做
- 多仓问题怎么处理

这与 Cat Café / Agent 工程经验的连接点：

- 共享状态不应只来自单个 repo，而要能跨 repo / 项目 / 组织建索引。
- 代码理解不只是 RAG，要结合依赖图、调用图、变更影响面和项目规范。
- 任务执行前需要把“当前开发者/项目/语言/平台”的上下文注入给 Agent。

### 3. ToB 开放性与规范性平衡

深信服场景的核心矛盾：

- ToC 类产品可以开放 Skills，让用户自由扩展。
- ToB 场景必须保证规范性、安全性、质量和可审计。

需要平衡：

- 开放扩展能力
- 标准化流程
- 权限与安全边界
- 质量门禁
- 企业知识沉淀

这与 Cat Café 的经验高度相关：Skill 渐进披露、工具白名单、质量门禁、review、eval、trace 都可以映射过去。

### 4. 质量体系与测试闭环

对方提到的质量方向：

- TDD
- check 代码逻辑是否真正修复
- Web 程序多模态测试结果
- 安全相关 coding review

判断：

> 这不是单纯模型效果问题，而是 Agent 产出的可验证性问题。优势点在于我们已经长期做“代码生成 → 测试 → review → merge gate → 证据留痕”的闭环。

### 5. 组织级 Memory / 自进化

最有价值的新信息是“组织能力增强”这条线：

- 不是单个开发者的 memory，而是组织维度的知识和技能流转。
- 通过分析 1000 人级别的研发轨迹，抽取最佳实践。
- 按语言、模型、项目、人、组织等维度整理。
- 整理后形成知识库，上传云端。
- 根据组织/开发者画像注入上下文：例如 Windows + Java 开发者自动获得相关项目规范与最佳实践。
- 目标是组织能力获得 10% 级别提升。

这条线与我们长期讨论的 memory / eval / self-evolution 完全对齐，但 scale 更大：

| 我们的概念 | 深信服场景 |
|---|---|
| Agent memory | 组织研发知识库 |
| Recall eval | 轨迹消费与最佳实践抽取 |
| Self-evolution | 组织研发流程持续增强 |
| Capability profile | 人 / Agent / 项目画像 |
| Harness | 企业级 AI Coding 工作流底座 |

### 6. 模型与长程任务

对方提到：

- RL / SWT
- 长程任务微调
- model + memory + self-evolution

判断：

> 他们不只是做 IDE 插件层产品，也在思考模型能力、长程任务、组织轨迹数据和记忆系统的结合。这里如果是真的投入，会比普通 AI Coding 工具更有技术纵深。

### 7. 多人 / 多 Agent 协作

对方提到：

- 两三个人接到需求后如何分工协作
- Agent board
- 根据人 / Agent 画像分配任务
- 接口契约固定，能够联调

这与我们提出的“能力画像 × 任务画像”高度贴合。

关键判断：

> 深信服这条线最像 Cat Café 的企业版落地：把多 Agent 协作、能力画像、任务拆分、接口契约、质量门禁、组织 memory 放到真实企业研发流程里。

## 三、机会价值判断

### 上调项

1. **技术匹配显著上调**
   - 不只是 AI Coding 插件，而是企业级 coding agent + infra + harness + memory + eval。
   - 关键词与我们能力重合度很高：memory、eval、自进化、harness、能力画像、多 Agent 分工、组织知识流转。

2. **组织重视度上调**
   - 2026 年从二级部门升一级部门。
   - 编制由创始人团队批。
   - 有明确营收目标和商业化方向。

3. **商业信号上调**
   - 已有 200w+ 级别订单信号。
   - 与腾讯、中兴等竞品竞争，说明不是纯内部玩具项目。

4. **职业训练价值上调**
   - 能训练“把 Agent 工程能力放进企业组织”的能力。
   - 能训练 ToB 产品、组织流程、安全合规、商业化交付。
   - 对“未来想做组织级 AI Agent 基建”的方向有复利。

### 风险项

1. **营收目标千万级，说明仍在早期商业验证**
   - 有真实订单，但还不是成熟规模化业务。
   - 2026 是关键验证年，压力可能较大。

2. **AI Coding 赛道竞争极强**
   - Claude Code / Cursor / 阿里 / 腾讯 / 字节 / 中兴等都会竞争。
   - 深信服必须靠 ToB 私有化、安全、组织知识和企业流程差异化。

3. **开放性与规范性矛盾很难**
   - ToB 客户要可控、安全、合规。
   - 开源和商业化路线如何切分，需要问清楚。

4. **股票价值需要细查**
   - “真实股票”比期权确定性高，但仍要看授予价、归属周期、锁定期、离职处理、税务和总包折算。

5. **个人授权与岗位边界仍待确认**
   - 是做核心 harness / memory / eval / agent runtime，还是变成项目交付救火。
   - 是否有架构决策权，是否能 owner 一条关键技术线。

## 四、相对华为 / 大厂 / 创业公司的位置

深信服不是传统意义上的“创业公司”，也不是大厂成熟螺丝钉岗位。它更像：

> 中型上市公司内部一级新业务部门，做企业级 AI Coding 商业化。

它的训练价值在于：

- 比华为更靠近商业化验证和 ToB 产品闭环。
- 比纯创业公司更稳定，股票与组织资源更确定。
- 比大厂成熟团队更可能给到 owner 空间。
- 技术方向比一般 AI 应用岗更贴近 Agent 工程底层。

但它的前提是：

> 你要进入的是核心 harness / memory / eval / enterprise coding agent infra，而不是普通项目交付。

## 五、后续必须问清的问题

### 1. 个人职责

> 如果我加入，前三个月最希望我负责哪条技术线？是 agent runtime / harness / memory / eval / 代码图谱 / 多仓依赖 / 企业交付，还是模型侧？

### 2. 部门结构

> 这个一级部门目前大概多少人？infra、模型、产品、交付分别怎么分工？

### 3. 商业化阶段

> 2026 年千万营收目标主要来自哪些类型客户和交付形态？是私有化部署、SaaS、咨询项目，还是平台授权？

### 4. 产品定位

> 你们更想做企业版 Cursor / Claude Code，还是做企业研发流程中的 AI Coding 中台？

### 5. 开源策略

> 开源部分会开到什么层级？核心 runtime、插件生态、协议，还是只开放外围工具？商业闭源边界怎么划？

### 6. 数据与安全

> 企业客户代码和研发轨迹数据如何处理？最佳实践抽取是在客户私域内完成，还是会上云沉淀为通用知识？

### 7. 模型策略

> 你们在 RL / SWT / 长程任务微调上是已有团队和数据，还是未来规划？和 coding agent 产品如何闭环？

### 8. 个人成长与授权

> 这个岗位一年后理想状态是什么？是某个技术模块 owner、团队技术负责人，还是偏客户交付专家？

### 9. 薪酬与股票

> 股票授予方式、归属周期、锁定期、离职处理和总包折算方式是什么？年终奖 0-6 个月的实际分布大概如何？

## 六、当前结论

深信服这条线需要上调。

旧判断是：

> offer 概率高，但薪资/职级匹配风险大，可作为市场校准样本。

新判断是：

> 技术方向与 Cat Café / Agent 工程化高度贴合，组织投入和商业化信号比预期强。若岗位能落在核心 harness / memory / eval / enterprise coding agent infra，而薪资与股票结构能匹配华为 17 的机会成本，则值得进入认真比较。

一句话：

> 深信服不是“因为对方喜欢我所以可以考虑”，而是“它可能真在做企业版 Agent 工程化主战场的一部分”。
