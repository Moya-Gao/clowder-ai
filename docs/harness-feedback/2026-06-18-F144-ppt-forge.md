# F144 PPT Forge — Harness Fit Review（ppt-forge skill）

## Summary

F144 最终交付了 `ppt-forge` skill（3 文件系统），而不是最初设计的五层代码管线。
这是一次**成功的 harness fit**——skill 路径（低保真 MD → imagegen 精美图）
比任何代码渲染路径都更自然地匹配了猫猫的原生能力。

## Fit Assessment

| 维度 | 状态 | 说明 |
|------|------|------|
| **触发自然性** | ✅ | 铲屎官说"做个 PPT 华为风格"即触发，无需记命令 |
| **输出质量** | ✅ 超越目标 | imagegen 图片质量远超 pptxgenjs/HTML/SVG 任何代码路径 |
| **猫猫分工清晰** | ✅ | 架构猫写低保真 MD（ASCII art + 视觉指引）→ imagegen 猫逐页出图 |
| **可扩展性** | ✅ | 新风格 = 新 ref 文件，无需改代码 |
| **流程摩擦** | ✅ 低 | 3 文件 ref 覆盖所有场景，有最小可抄模板，新猫直接照抄 |
| **可编辑性** | ⚠️ 取舍 | 产出 PNG 不可编辑文字（但铲屎官 KD-20 明确接受这个 tradeoff） |

## What This Tells Us About Skill Harness Design

1. **内容生成类功能优先评估 imagegen 路径**：当猫猫有原生多模态生成能力时，"代码渲染"往往是次优路径。Future content-generation features（视频帧/图表/海报）应第一时间对比 imagegen vs 代码路径
2. **skill ref 文档是知识容器**：4 个月探索积累的认知（密度原则 / 风格 token / 低保真规范）通过 3 个 ref 文档保存了下来，没有因为废弃代码路径而丢失
3. **实战 > 实验室**：铲屎官真实使用场景（试用期 PPT）比任何 benchmark 测试都更有说服力

## Sunset Signal

当出现以下信号时，重新评估 ppt-forge skill fit：
- imagegen 质量显著下降，导致铲屎官反馈"图太丑了"
- 铲屎官明确需要可编辑的 .pptx 输出（回头考虑 Phase D HTML 路径）
- 需要覆盖华为以外的风格 preset（按需新建 ref，不需要改 skill 架构）
