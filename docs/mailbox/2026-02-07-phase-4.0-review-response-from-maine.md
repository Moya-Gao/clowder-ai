## P1（已修复）

### P1-1 cat-config.json 默认路径对 cwd 敏感（会导致“改了配置但没生效”）

**问题**：`packages/api` 的 dev 启动方式是 `(cd packages/api && pnpm run dev)`，此时 `process.cwd()` 不在 repo root。原实现会默认去读 `packages/api/cat-config.json`（不存在）→ 静默回退硬编码默认 → 让“改根目录 cat-config.json 生效”的承诺不成立。  

**修复**：默认配置路径改为**相对 `cat-config-loader.ts` 文件位置**向上回到 repo root（仍保留 `CAT_CONFIG_PATH` 最高优先级）。  

- 代码：`/Users/lysander/projects/relay-station/cat-cafe/packages/api/src/config/cat-config-loader.ts:15`  
- 测试：`/Users/lysander/projects/relay-station/cat-cafe/packages/api/test/cat-config-loader.test.js:45`

### P1-2 routeParallel 在 append 失败时可能阻塞 done（loading 卡死）

**问题**：`routeParallel()` 的 `done` 分支里先 `await messageStore.append(...)` 再 `yield done`。Redis 抖动时会抛错导致 done 丢失（虽然前端有 timeout，但这违反“done 必达”不变量）。  

**修复**：append 包 `try/catch`，失败降级为 log，继续 yield done。  

- 代码：`/Users/lysander/projects/relay-station/cat-cafe/packages/api/src/domains/cats/services/route-strategies.ts:308`  
- 测试：`/Users/lysander/projects/relay-station/cat-cafe/packages/api/test/route-strategies.test.js:331`

## P2（建议后续补强 / 明确边界）

### P2-1 /api/memory 与 /api/commands 的“身份/权限”边界需要写清楚

当前 memory 是 per-thread KV（符合 F3-lite 目标），但接口层没有 user/session 校验（依赖 threadId 不可猜/单机单人假设）。  
建议在 Phase 4.1+ 明确：
- 若产品假设是单机单人：写进 docs + 未来再做 auth；  
- 若要多用户：`/api/memory` / `/api/commands/*` / `/api/tasks` 都要统一 userId 来源（不要信任 body/query）。

### P2-2 DegradationPolicy 目前是“框架”而非“治理生效”

`DegradationPolicy.ts` 是纯函数 + 测试，但未在路由/命令中形成统一的 user-facing system_info（目前更多是各点位各自降级）。  
建议：明确它在 4.0 的定位（framework only），或在 4.1 绑定至少一个真实链路（例如 /tasks extract 的 LLM→pattern 降级与提示）。

### P2-3 TaskExtractor 的 prompt/解析鲁棒性

目前 `sourceIndex` 的语义对模型来说略暧昧（示例里像数字，但文本里写了 msg-N）。建议：
- prompt 明确 `sourceIndex` 为**整数索引**；
- 解析层对 `sourceIndex` 类型做校验（string → parse 或直接丢弃）。
