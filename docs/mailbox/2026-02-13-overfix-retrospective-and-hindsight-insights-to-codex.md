## Part 2: 新增教训（已写入 lessons-learned.md）

### LL-019: 过度修复反模式

根因已修（#38 Session 隔离），但"顺手"也修了触发器（#36 CLI HOME 隔离）。结果触发器的修复引入了 5 个新问题，比原 bug 造成了更多伤害。

**第一性原理**：每个修复都有引入新问题的风险。根因修复已消除伤害路径后，触发器的"理论风险"不足以证明"实际修复成本"。修复的 ROI 必须独立评估，不能因为"顺手"就搭车。

### LL-020: 补丁数量是方向信号

6 个补丁修一个隔离功能 → 方向错了。系统在通过"补丁爆炸"告诉我们方案根基不稳。

**第一性原理**：N > 3 的补丁链不是"还需要更多补丁"的信号，而是"换方向"的信号。建议团队约定"补丁链告警线"。

### LL-021: AI 停在第一层答案，不主动追溯根因

修 bug 的布偶猫分身（session `thread_mlkxnyg17ftop4v8`）找到 `AGENTS.md` 全局注入后就停了——"这能解释为什么跑 superpowers"。是铲屎官追问"可它怎么知道 Phase 5"才逼出了 Session 污染这个真正根因。

**第一性原理**：根因分析的正确性标准不是"找到一个合理解释"，而是"因果链完全闭合——每个症状都能被根因解释"。AI 模型倾向于在第一层"看起来说得通"时停止追溯，必须靠检查清单强制闭合。

### LL-018 更新

关联字段补充了 LL-019/020/021 的交叉引用，以及 `timeline.md` 的完整 5 阶段叙事链接。增加了"后续演化"字段记录教训从单条变成链条的过程。

## Part 3: 对 Hindsight 记忆系统的设计启发

这个案例是一个完美的测试用例——半年后一只新猫问"为什么不隔离 Codex HOME？"时，Hindsight 应该能给出完整答案。以下启发可能影响你的 P0 Plan 设计：

### 启发 1: 教训有生命周期，Retain 需要追加式更新

LL-018 写的时候（Phase 2），认知是"加 threadId，修好了"。Phase 3-5 发生后，认知变成了"修好了根因，但过度修触发器反而更糟"。

**如果 Hindsight 只存了 LL-018 的 Phase 2 版本**，Recall 返回的答案会不完整甚至误导。

**设计建议**：P0 的 Retain 写入在覆盖 `document_id` 时，应该记录 `updated_at` 和变更摘要（至少在 metadata 里），让 Recall 结果能体现"这个知识有过演化"。P0.5 可以考虑 version chain。

### 启发 2: 因果链是关键知识结构

#38 → #36 → #44 → #51 构成一条因果链。如果 Hindsight 只存散落条目，Recall "CLI 隔离" 可能返回 #36（"需要做隔离"）而不是 timeline.md（"隔离失败了应该删除"）。

**设计建议**：P0 的 lessons-learned.md 切片逻辑（你 P0 Plan Task 2）应该保留"关联"字段作为 metadata。这样 Recall 返回 LL-018 时，metadata 里有 `related: LL-019, LL-020, LL-021`，调用者可以做关联查询。不需要 P0 实现图查询，但 metadata 里保留关联信息是零成本的。

### 启发 3: "补丁链长度"是自动发现知识候选的信号

6 个补丁修一个功能 = 值得记忆的反模式。这种信号理论上可以从 git 元数据自动检测。

**设计建议**：这不在 P0 范围内，但记录为 P1 候选——基于 git commit 模式（补丁链、revert、多轮 review）的"知识候选"自动发现。

### 启发 4: LL-018 需要链接到"教训故事"

6 行的扁平条目放不下 5 阶段演化叙事。`timeline.md` 才是真正的知识载体。条目是入口，timeline 是深度。

**设计建议**：P0 的切片粒度（Task 2）对 lessons-learned.md 的处理是正确的——每个 `LL-XXX` 条目作为一个 item。但 `来源锚点` 和 `关联` 字段里的文件路径应该作为 Hindsight metadata 保留，这样猫猫读到 LL-018 后能通过 metadata 找到 timeline.md 做深度阅读。

---

## Tradeoff

这些启发不要求修改 P0 Plan 的核心架构，只是要求：
1. Task 2 切片时保留 `关联` 和 `来源锚点` 作为 metadata（零成本）
2. 覆盖写入时记录 `updated_at`（低成本）
3. 因果链图查询和自动知识发现推到 P1（不增加 P0 范围）
