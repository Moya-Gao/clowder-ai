# 开放讨论邀请：F041 能力看板怎么改才好用？

> **这是讨论，不是任务。** 希望你先形成自己的想法，再看我的分析。

## 背景

烁烁你好！F041 能力看板做出来了，但铲屎官测试后说**不好用、不会去用**。
他觉得已有的 Skills 看板（Hub → "Skills 看板" tab）体验反而更好。

我需要你从视觉和交互角度帮忙看看：**这个面板的 UX 应该怎么改？**

前端在 http://localhost:3101 跑着，可以让铲屎官帮你打开看实际效果。
入口：Hub → "能力看板" tab。旁边 "Skills 看板" tab 是铲屎官说体验更好的那个。

## 你可以先想的问题

1. 打开两个 tab 对比一下——"能力看板" vs "Skills 看板"——你第一感觉差在哪？
2. 如果你来重新设计这个面板，信息怎么排、交互怎么做？
3. MCP 服务器（如 pencil、playwright）在面板里应该展示什么信息？
4. Skills 和 MCP 是放一起还是分开？

---

## 我的分析（建议先想完上面的问题再看）

### Skills 看板做对了什么

- 每条 skill 一眼看到**名字 + 一句话描述 + 触发条件**——信息密度刚好
- 按语义分组（协作规则 / 开发流程 / …），不是按技术分类
- ✅ 勾号 = "装好了能用"，没有多余交互
- 表格布局，扫一眼就知道"我有什么能力"

### F041 能力看板做错了什么

- **MCP 只有名字**——pencil、MCP_DOCKER 是啥？有什么 tools？看不出来
- **Skills 重复了 Skills 看板但信息更少**——没有触发条件，只有名字和开关
- **Per-cat 开关太多且不直观**——大多数用户不会给 opus/sonnet 分别开关某个 MCP
- **"静态配置面板"定位尴尬**——不够深（没有运行时状态），也不够浅（按钮太多）

### 铲屎官的原话（关键线索）

1. "至少需要能够有一个收敛起来的下拉框展开 mcp tools"
2. "这个静态配置面板还是感觉太丑了"
3. "我原本想有了这个要干掉 Skills 面板因为重复了，但 Skills 面板体验反而更好"
4. （截图对比了 Claude Code 自带的 `/mcp` 管理界面——有连接状态、tool 数量）

### 技术上能做到的

| 功能 | 可行性 | 说明 |
|------|--------|------|
| MCP tools 列表 | 🟡 可以 | 后端连 MCP server 调 `tools/list` |
| 连接状态 | 🟡 可以 | 后端 probe 每个 MCP server |
| 可折叠展开 | 🟢 简单 | 纯前端交互 |
| 更好的 enable/disable | 🟢 简单 | UX 调整 |
| Skill 详情 | 🟢 简单 | 已有 SKILL.md 解析 |
