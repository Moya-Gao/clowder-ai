# 任务令：抖音 & B站 MCP 调研

## 背景

Cat Café 正在为 2026 年 6 月 HCI 大会准备预热。我们需要让三只猫（布偶猫/缅因猫/暹罗猫）能在社交媒体上自主发布内容。

**小红书已搞定**：铲屎官本地有一个小红书 MCP Server（`localhost:18060`），我们已经接入了 Cat Café 的 `.mcp.json`。

**现在需要你调研**：抖音和 B站的 MCP 接入方案。

## 调研目标

### 1. 抖音 MCP

请调研以下内容：

- **现有 MCP 实现**：GitHub 上有哪些抖音 MCP server？（我们初步搜索发现有若干实现，但质量和维护状态未知）
- **抖音开放平台 API**：个人账号（非企业号）能做什么？发布图文/短视频？读评论？数据看板？
- **接入可行性评估**：
  - 个人号 API 权限范围
  - 认证方式（OAuth？Cookie？）
  - 发布限制（频率、内容审核）
  - 是否需要实名/企业认证才能发布

### 2. B站 MCP

同样调研：

- **现有 MCP 实现**：已知有 `huccihuang/bilibili-mcp-server`（搜索过滤）、`bilibili-video-info-mcp`（字幕/弹幕/评论）、`bilibili-mcp-js`（JS/TS 实现）、`dnullp/bilibili-mcp-server`（Go 实现）
- **B站开放平台 API**：个人号能做什么？发布视频/动态？读弹幕/评论？
- **接入可行性评估**：
  - 同抖音的评估维度
  - B站动态（类似微博的短文图片）的 API 支持程度

### 3. 对比小红书方案

铲屎官现在用小红书的方式是：用个人号 + 猫猫签名。请评估抖音/B站是否可以复制这个模式。

## 约束

- 铲屎官只有个人账号（抖音和B站都是），不是企业号
- 我们的使用模式是"铲屎官的号 + 猫猫签名"，不是独立账号
- 重点关注**发布图文/短文**的能力（短视频发布是加分项，不是必须）
- 关注 MCP 实现的**维护状态**（最后更新时间、issue 处理、star 数）
