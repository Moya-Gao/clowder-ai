# Review Request: F168 C3.2 — DirectionCard frontend + RouteDecisionEvalEvent eval.1

Review-Target-ID: f168-c3.2
Branch: feat/f168-c3.2-direction-card-eval

## What

Two deliverables in one branch:

1. **DirectionCard component** (`packages/web/src/components/DirectionCard.tsx`, 354 lines new) — Renders narrator triage analysis inline in CommunityPanel when a pending-decision issue has narrator data. Includes:
   - 5-question results grid (PASS/WARN/FAIL/UNKNOWN color-coded)
   - Verdict badge (WELCOME / NEEDS-DISCUSSION / POLITELY-DECLINE)
   - Narrative text + evidence refs
   - Route recommendation display (existing-thread / new-thread / decline)
   - Role dropdown (case-owner / narrator / reconciler)
   - Action buttons (Accept / Discuss / Decline; order flips for POLITELY-DECLINE)
   - All SVG icons (KD-9 compliance), OKLCH color tokens

2. **CommunityPanel integration** (`CommunityPanel.tsx`, +104/-34 lines) — Clicking a pending-decision issue with narrator data expands the DirectionCard. `resolveIssue` callback POSTs to `/api/community-issues/:id/resolve`.

3. **eval.1 backend** (`community-issues.ts`, +54 lines) — After resolve, records `RouteDecisionEvalEvent` (kind: `case.route_decision_eval`) comparing narrator recommendation vs owner decision. `agreed` is a pure projection (computed, not stored).

## Why

Phase C goal: narrator can triage community issues and recommend routing; owner sees the recommendation and can accept/override. eval.1 records agreement data for future routing automation calibration (INV-13).

## Tradeoff

- **Type bridge**: `DirectionCardPayload` defined locally in DirectionCard.tsx (not imported from shared) because the shared type is opaque `Record<string, unknown>`. Used `as unknown as DirectionCardProps['directionCard']` cast at integration point. Alternative was widening DirectionCard props to accept `Record<string, unknown>` — rejected because it would lose type safety inside the component.
- **eval.1 best-effort**: Eval event recording wrapped in try/catch — recording failure never blocks resolve. Tradeoff: could silently lose eval data vs blocking a successful resolve operation.
