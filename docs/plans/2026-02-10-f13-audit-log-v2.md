# F13 审计日志 v2 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** 在现有消息级审计基础上，补齐“可追责 + 可调试”的调用级证据链，尤其覆盖 CLI 实际执行轨迹。  
**Architecture:** 保留 `EventAuditLog` 作为结构化事件账本；新增“调用关联上下文 + 原始事件归档”双轨。结构化事件用于检索与告警，原始归档用于故障复盘。两者通过 `threadId/userId/invocationId/catId` 关联。  
**Tech Stack:** Fastify + TypeScript (`packages/api`), Node test runner (`node --test`), NDJSON append-only 日志。

## 1) 范围与边界

1. 本轮只做 F13 的最小可交付切片，不一次性覆盖全部审计需求。  
2. 不记录完整 prompt 原文，不扩大敏感信息面；继续使用 digest/摘要策略。  
3. 不把审计写失败升级为主流程失败（保持 best-effort），但必须有错误可观测。  
4. 输出必须能回答三个问题：  
   - 谁在什么线程触发了哪只猫？  
   - 猫执行了哪些工具/命令，结果如何？  
   - 出错时能否还原关键原始轨迹？

## 3) 验收标准（M1）

1. 单次调用至少有：`CAT_INVOKED` + `CLI_TOOL_*`（若发生 command_execution）+ `CAT_RESPONDED/CAT_ERROR`。  
2. 通过 `threadId + invocationId` 能从结构化日志定位到对应原始归档文件。  
3. API 主链路不因审计写失败而中断；失败会有可检索错误日志。  
4. 新增测试全部通过，且不降低现有测试通过率。

## 4) 后续扩展（M2+）

1. 将 `CLI_TOOL_*` 覆盖到 Claude/Gemini 的 tool_use 事件。  
2. 增加 `/api/audit/invocation/:id` 聚合查询接口。  
3. 引入日志轮转/清理策略与归档压缩。  
4. 按风险级别提供脱敏模板（命令参数、路径、token 模式）。
