# F047 Queue Steer Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a “Steer” action for `queued` queue entries so the user can (1) execute a queued entry immediately by canceling the current invocation, or (2) promote it to the front to run next—without supporting “processing” steer.

**Architecture:** We keep message immutability and avoid editing stored messages. Steer operates on queue ordering/execution only. Backend exposes one steer endpoint with two modes (`immediate` and `promote`). Frontend adds a Steer button per queued entry + modal to choose mode. State updates come from existing `queue_updated` WS events (and route responses as fallback).

**Tech Stack:** Fastify routes (`packages/api`), in-memory `InvocationQueue` + `QueueProcessor`, Web (Next.js + Zustand), WebSocket events.

---

## Definitions

- **Steer target**: a queue entry with `status === 'queued'`.
- **Steer mode**:
  - `immediate`: cancel the current invocation (if any) for this thread and execute the selected queued entry now.
  - `promote`: move the selected queued entry to the front (index 0 of queued entries) without canceling; it runs next.
- **Out of scope**: “processing steer” (no steer UI/action for `status === 'processing'`).
