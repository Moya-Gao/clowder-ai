# F056 Phase A-2.5: High-Confidence Neutral Codemod

**Feature:** F056 — `docs/features/F056-cat-cafe-design-language.md`
**Goal:** Auto-replace high-confidence Tailwind neutral colors with `cafe-*` semantic tokens, eliminating ~40% of hardcoded colors
**Acceptance Criteria:** AC-A2.5: 高置信 codemod 完成（~40% 硬编码颜色消除）
**Architecture:** Regex-based codemod script replaces Tailwind neutral class names with semantic `cafe-*` equivalents across `packages/web/src/`. Operates on word boundaries within string contexts — safe for className strings, cn() calls, and template literals.
**Tech Stack:** Node.js script, regex word-boundary replacement
**前端验证:** Yes — visual regression check needed after codemod (colors should look identical since tokens map to same values in light mode)

### Task 4: Handle Tailwind opacity suffix edge case

Tailwind supports `text-gray-400/50` (opacity modifier). The codemod regex `\btext-gray-400\b` won't match this because `/` is not a word boundary character... actually `\b` matches between `0` and `/`, so it WILL match. Need to ensure the replacement preserves the `/50` suffix.

**Step 1:** Check if opacity suffixes exist in codebase

```bash
grep -rn 'gray-[0-9]\+/[0-9]' packages/web/src/ | head
```

**Step 2:** If found, update regex to capture and preserve opacity: `\b{source}(/\d+)?\b` → `{target}$1`

**Step 3:** Update test, re-run
