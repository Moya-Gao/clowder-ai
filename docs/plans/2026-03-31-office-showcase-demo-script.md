## 前提：Backup 版 vs 他们的版本

### 话题选择指南

话题由铲屎官根据受众和热点现场决定。好话题的标准：

| 标准 | 为什么 |
|------|--------|
| **真实** | 大领导看过太多假 demo，真实感是唯一武器 |
| **有争议空间** | 多猫辩论需要分歧，一边倒的话题出不了好效果 |
| **受众能感知价值** | 分析完的结论对在座的人有实际参考价值 |
| **48 小时内热点优先** | 时效性强的话题更有冲击力 |

> **⚠️ 不预设固定话题。** Demo 前一天确定即可。如果当周没有热点事件，选一个受众关心的战略判断问题（如行业准入、技术选型、竞争策略）。

## 整体流程（Expert Panel 多猫辩论团）

```
铲屎官在飞书发一句话（真实问题，触发 expert-panel）
  │
  ├─ Dispatch：收敛猫（默认宪宪）分发独立调研任务，不注入自己的判断
  │
  ▼
各猫独立调研 + 独立分析（互不可见，大屏投屏 Hub thread 看过程）
  │  每只猫按 WHY 链四格输出：Evidence / Reasoning / So what / Confidence
  │  默认 Light 调研（WebSearch + search_evidence）
  │
  ▼
Synthesis 收敛（各猫分析汇总后讨论，共识 + 分歧各方理由保留）
  │
  ▼
Contributor Check（各猫确认收敛报告没有误读自己的观点）
  │
  ▼
一次性交付：洞察卡片 + 语音总结 + 正式报告（DOCX）
  （全程没打开任何专门的 AI 界面）
```

### 猫猫分工

| 猫猫 | 模型 | Expert Panel 角色 | 预期贡献 |
|------|------|-------------------|---------|
| 宪宪 | Claude Opus 4.6 | Analyst + Convergence Lead | 技术深度、架构对比 + 收敛报告 |
| 砚砚 | GPT-5.4 | Assessor | 成本结构、风险预警、踩坑 premortem |
| 金金 | opencode (Opus 4.6) | Strategist | 行业生态定位、趋势判断、用户/人才视角 |
| (烁烁) | Gemini 2.5 | 备选（UX/创意视角） | 如果 3 分钟内响应就加入，否则不等 |

### 语音总结由谁来发

**默认宪宪**（Convergence Lead，收敛后总结）。语音内容结构：
1. “我们刚才讨论了 XXX，核心结论是……”（30 秒）
2. “还有几个 open questions 需要你拍板……”（15 秒）
3. “完整报告已经发到飞书了，你可以看一下。”（5 秒）

### 交付件（收敛后一次性发出）

**a) 洞察卡片**（rich block，收敛消息里同步发）：
- 核心结论（每条附一句 Evidence + Reasoning 摘要）
- 共识区 + 分歧区（各方理由保留）
- Tradeoffs / 适用边界
- Open Questions（待铲屎官拍板）
- Premortem（最可能翻车在哪）

**b) 语音总结**（~50 秒）：核心结论 + 最大风险 + 需要拍板的事

**c) 正式报告**（`generate_document`，优先 DOCX）：
- 命题与范围
- 核心判断（每条 WHY 链四格）
- 证据矩阵（各猫调研发现 + 来源可靠度）
- Tradeoffs / 适用边界
- Premortem + 护栏
- 行动建议（分层：决策者 / 执行者）
- Open Questions
- 独立贡献记录

> **已验证经验（2026-03-31）**：`generate_document` 发送 `docx` 到飞书群已实测成功。
> 建议现场按”先 `docx` 验链路，再按需要补 `pdf`”执行。
> **⚠️ 交付时机铁律**：富块和文档必须在新鲜 invocation 里发，不能拖到 multi_mention 链末尾（凭证会过期）。

## 正式剧本：8 分钟

> **核心原则**：不编场景，不写死台词。用猫猫真实在做的事来演。
> 大领导看过太多假 demo，唯一能打动他的是：**这不是表演，这是真的在工作。**
>
> **⚠️ 话题留白。** 下面的 `[话题]` 占位符在 demo 前一天填入。

### 开场 [0:00-0:30]「它已经在替你干活了」

**动作**：打开飞书，展示今早 8 点猫猫自动发的卡片。

**画面**：飞书群里有一张 rich block 卡片——Signal Hunter 当天真实抓取的行业动态。

> **⚠️ 注意**：此处必须使用 Signal Hunter 前一天真实抓取的内容。
> 不要写死具体新闻——大领导追问来源时必须经得起查证。
> Demo 前一天检查 morning briefing 是否正常投递，如有问题手动触发一次。

**台词**：
> "这是今天早上八点，我还没到公司，猫猫团队已经帮我扫完了全网跟 AI 相关的动态。每天自动跑，我什么都不用做。"

**展示重点**：被动触发 + 持续存在（不是你想起来才用的工具）

---

### 第一幕 [0:30-4:00]「Expert Panel · 多猫辩论团」

> **这是最核心的一幕——展示多猫独立调研 + 多视角辩论 + WHY 链论证，不是写文案。**

**铲屎官在飞书发一句话**（demo 前一天确定的真实问题）：

```
[话题——demo 前一天填入]

帮我分析一下。
```

> **触发词"帮我分析一下"会让猫猫自动进入 expert-panel 模式。**

**大屏同时投 Hub thread**，让观众看到整个过程：

**Phase 1 — Dispatch**（~30 秒）：
宪宪（Convergence Lead）把任务分发给各猫，每只猫拿到：原始问题 + 角色 + 视角 + 调研范围。
**关键：Lead 不注入自己的判断——各猫从零开始独立思考。**

**Phase 2 — Independent**（~90 秒）：
各猫独立调研，互不可见。每只猫的分析用 WHY 链四格：
- **Evidence**：具体案例/数据/事件 + 来源
- **Reasoning**：从证据到结论的逻辑链
- **So what**：对我们意味着什么
- **Confidence**：确信 / 中等 / 猜测

> **⚠️ 这是和普通 AI 问答最大的区别——不是给你一个答案，是给你论证过程。**
> 让观众看到证据和推理，不是看到"AI 觉得……"。

**Phase 3 — Synthesis**（~60 秒）：
各猫分析出来后，宪宪汇总收敛，保留分歧和各方理由。

> **⚠️ 以下是预期节奏，不是死台词。**
> Live 时让 thread 自己长出来——允许乱、允许打断、允许偏离脚本。
> 真实感 > 排练感。如果每句都和稿子一模一样，反而像表演。

**台词**（在猫猫讨论时对观众说）：
> "注意看——每只猫在独立做调研，互相看不到对方的分析。
>  这不是一问一答，是三个视角同时在跑：技术深度、风险成本、行业趋势。
>  等一下你会看到它们互相挑战——敢说'我不同意'，不是附和。"

**最后收敛成一张洞察卡片**（rich block）：

```
🔍 Expert Panel 洞察 | [话题] | [日期]

📊 核心判断（每条附证据+推理摘要）：
• [判断 1]
• [判断 2]
• [判断 3]

✅ 共识区：[猫猫达成一致的判断]

⚠️ 分歧区：[争议点 + 各猫立场和理由]

📐 Tradeoffs / 适用边界：[结论在什么场景成立、什么场景不适用]

❓ Open Questions：[待铲屎官拍板]

🔮 Premortem：[最可能翻车在哪 + 护栏]
```

**台词**：
> "这不是在写文案。猫猫真的去搜了、真的在互相挑战。
>  更重要的是——你看到的不只是结论，每个结论后面跟着证据和推理。
>  你可以判断这个结论靠不靠谱，不需要'信 AI'。"

---

### 第二幕 [4:00-5:00]「语音总结 · 猫猫汇报」

> **讨论完了，猫猫主动用语音总结给你听。**

**触发**：讨论自然收敛后（或铲屎官在飞书打一句"总结一下"），宪宪发一条语音消息到飞书。

**语音内容**（~50 秒，宪宪发出）：

> "铲屎官，我们刚讨论完，给你汇报一下。
>
> 核心结论：[话题] 我们的判断是——[关键发现 1-3]。
>
> 有几个 open questions 需要你拍板：
> [决策点 1-2]。
>
> 完整报告已经发到飞书了，你可以看一下。"

**台词**（对观众）：
> "讨论完了，猫猫不等你问——主动用语音把结论告诉你。
>  你在开车听语音，回到工位看卡片，两种场景都覆盖了。"

---

### 第三幕 [5:00-5:45]「正式报告 · 文档交付」

> **洞察卡片是速览，报告是完整版——可以直接转发给决策层。**

**猫猫自动生成正式报告**（通过 `generate_document`），投递到飞书群。

> **现场执行建议**：先用 `generate_document` 发 `docx` 确认文档已送达，再按需补 PDF。

**台词**：
> "从一句话到一份可分发的正式报告，全自动闭环。
>  里面有证据矩阵、推理链、分歧记录、行动建议——
>  你可以直接转发，不用再人工整理。"

---

### 第四幕 [5:45-6:30]「记忆 · 它认识你」

**铲屎官在飞书里追问一句**（关联团队近期真实讨论，demo 前一天确定具体措辞）：

```
[回忆问题——引用一个团队近期真实做过的讨论/决策，
 让猫猫展示记忆连续性。demo 前一天填入。]
```

**猫猫回复**（直接续上历史上下文，不问"哪个讨论"）。

**台词**：
> "我没有告诉它'上次聊了什么'。它自己记得。
>  不只记得结论，还记得是谁说的、为什么那么判断。
>  这不是搜索历史记录——这是一个团队的共同记忆在持续生长。"

## 应急预案

| 风险 | 降级方案 |
|------|---------|
| 飞书 bot 响应慢（>30s）| 切到 Hub 网页版直接打字，Hub 里猫猫响应更快 |
| 某猫超时（>3min）| 不等，剩余猫继续。最少 2 猫即可完成 expert panel |
| 语音总结发不出 | 改为宪宪在飞书里打一段文字总结 |
| DOCX 生成失败 | 降级发 rich block 洞察卡片（共识+分歧+Tradeoffs+行动项）|
| 凭证过期（stale_ignored）| 铲屎官发一条新消息触发新 invocation，在新鲜凭证里重发交付件 |
| 记忆没续上 | 手动补一句上下文提示，猫猫会接住 |
| 所有 IM 都挂了 | 直接在 Hub 网页版演，用大屏投 thread —— Hub 不依赖任何外部 IM |
| 讨论跑偏 / 太慢 | 铲屎官在飞书里打"总结一下"打断，强制进入语音总结 |
| 争论不起来 | 那就是共识，不演。共识也有价值 |

## 和「他们的版本」的区别

他们可能演：写 PPT、做周报、单轮问答。

我们演的是完全不同的东西：
1. **Expert Panel 多猫辩论团**（独立调研 → 多视角辩论 → WHY 链论证 → 收敛交付）— 他们最多写总结
2. **多猫可见协作**（投屏 Hub thread，实时争论）— 他们只有单 agent
3. **WHY 链标准**（每个结论有证据+推理+适用边界，不是"AI 觉得"）— 他们只给结论
4. **Premortem 风险预演 + Tradeoffs**— 没有任何 AI demo 演过
5. **语音主动汇报**（讨论完猫猫语音总结给你）— 他们的猫不会主动汇报
6. **正式报告自动生成**（证据矩阵+推理链+独立贡献记录）— 他们最多贴段文字
7. **记忆连续性**（记得历史讨论和判断）— 他们 sessionChain=false
8. **被动触发**（morning briefing）— 他们没有
9. **端到端闭环**（飞书一句话→独立调研→辩论→语音→报告→行动项）— 他们做到第一步就停了

**一句话：他们演的是"AI 办公小秘书写文案"，我们演的是"AI 技术参谋团——结论不值钱，论证过程才值钱"。**
