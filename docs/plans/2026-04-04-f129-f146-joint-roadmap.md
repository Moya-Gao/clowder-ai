# F129 + F146 联合 Roadmap

> 决策来源：布偶猫 + 缅因猫讨论收敛（2026-04-04）
> 铲屎官指导原则："不要并发搞乱，串行整理清楚"

## 已完成底座

| Feature | Phase | 状态 | 交付物 |
|---------|-------|------|--------|
| F129 | Phase A | ✅ | Pack 格式 + Loader + Compiler + Runtime wiring (PR #748) |
| F129 | Phase B-α | ✅ | PackExporter + GrowthBoundary + Coding World + TRPG packs (PR #942) |

## Wave 结构

### Wave 1（串行）: F146 Phase R — 调研

**Owner**: 砚砚主导，宪宪辅助
**产出**: AC-R1~R6 全部完成
- 跨生态 schema 对照矩阵（Claude/Codex/OpenClaw/Antigravity）
- adapter 可行性结论
- F129 Pack ↔ Marketplace 条目映射契约（`kind`/`installPlan` 对齐）
- 实施收敛稿

**出口门槛**: 对照矩阵 + 映射契约 review 通过 → 冻结 `kind`/`installPlan` 初始字段集

### Wave 2（有限并行）: F146 Phase A ‖ F129 B-β 上半

**并行条件**: 不同代码路径 + 不同 owner + disjoint write-set
**WIP ≤ 2**

| 线路 | Owner | 内容 | 代码路径 |
|------|-------|------|----------|
| F146-A | 砚砚 | 能力中心写路径（preview/install/CAS 锁/审计） | `packages/api/src/domains/capabilities/` + `packages/web/` |
| F129-Bβ 上半 | 宪宪 | OpenClaw/SillyTavern 解析器 + IR 转换（**不落 installPlan**） | `packages/api/src/domains/packs/importers/` |

**关键约束**: F129 B-β 上半只产出中间表示（IR），不触碰 F146 的写路径接口。installPlan 在 Gate G2 冻结后再对接。

**出口门槛**: 各自 quality-gate + 交叉 review 通过

### Gate G2（串行）: 接口冻结检查

在进入 Wave 3 前，双方碰头冻结：
1. `installPlan v1` 完整 schema
2. 错误模型（安装失败的错误码 + 回滚语义）
3. 审计字段（who/when/what/from）
4. F129 B-β 下半（importer 落 installPlan）在此完成

**产物**: 接口契约文档 + F129 B-β 全量交付 + 冒烟测试

### Wave 3（串行）: F146 Phase B — Marketplace 聚合

**Owner**: 联合（宪宪出架构，砚砚把安全关）
**内容**: 4 生态 adapter + 统一搜索 + `kind=pack` 可发现

**为什么串行**: F129 Pack 和 F146 Marketplace 代码路径在此交汇，并行容易撞车

**出口门槛**: 端到端冒烟（搜索 → 发现 Pack → installPlan 生成）+ quality-gate

### Wave 4（有限并行）: F146 Phase C ‖ F129 Phase C

**并行条件**: 不同代码路径 + 不同 owner + 治理策略 API 已冻结

| 线路 | Owner | 内容 | 代码路径 |
|------|-------|------|----------|
| F146-C | 砚砚 | 治理门禁 + quarantine 状态机 + 供应链安全 | `packages/api/src/domains/capabilities/governance/` |
| F129-C | 宪宪 | MCP Capability Pack 运行时加载 + Pack Composer | `packages/api/src/domains/packs/runtime/` + `packages/web/` |

**出口门槛**: 各自 quality-gate + 交叉 review + Integration Gate

### Wave 5（串行）: F146 Phase D — 联动收尾

**Owner**: 联合
**内容**: L1/L2/L3 视图联动 + "缺什么补什么" + 端到端验收场景
**出口门槛**: 浏览器三后端验收场景全流程通过（agent-browser/pinchtab/claude-in-chrome）

## 硬护栏（每个 Wave 适用）

1. **WIP ≤ 2**: 同一时刻最多两条开发线
2. **Disjoint Write-Set**: 每个并行波次开始前写清文件/模块所有权清单，禁止交叉写同一文件
3. **Integration Gate**: 每个波次结束必须过契约一致性 + e2e 冒烟，不过不开下一波
4. **交叉 Review**: 并行波次中宪宪 review 砚砚的代码，砚砚 review 宪宪的代码

## 视觉总览

```
Wave 1: ──[F146-R 调研]──────────────────────────────────→ Gate R

         ──[F129-Bβ 上半]──┘     ↓ F129-Bβ 下半完成
Wave 3: ──[F146-B Marketplace 聚合]───────────────────────→ Gate B
Wave 4: ──[F146-C 治理]────┬──→ Integration Gate
         ──[F129-C Runtime]─┘
Wave 5: ──[F146-D 联动]──────────────────────────────────→ 验收
```
