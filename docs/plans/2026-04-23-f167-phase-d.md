# F167 Phase D Implementation Plan

**Feature:** F167 — `docs/features/F167-a2a-chain-quality.md`
**Goal:** 把 A2A 乒乓球熔断从"同 pair 连续次数"升级为"实质工作 + 内容长度"维度（D1），把 `@landy` 从"可选出口"升级为"硬条件出口"（D2）——两者同源：让 harness 从客观事实判意图，拒绝主观分类器。
**Acceptance Criteria:** AC-D1~D7（见 F167 spec）
**Architecture:** prompt-first + harness 硬刹车双层；D1 改 `WorklistRegistry.updateStreakOnPush` 签名 + 双调用路径（route-serial / callback-a2a-trigger）；D2 改 `shared-rules §10` + `SystemPromptBuilder` trailing anchor + exit check 反问 ping 检测
**Tech Stack:** TypeScript, Node.js test runner, shared-rules.md (canonical)
**前端验证:** No — 纯后端 harness 行为 + runtime prompt 注入

## Straight-Line Check

**B = 最终形态**：
- `updateStreakOnPush(entry, caller, target, callerActivity)` 新签名存活到 main，`callerActivity = { hadSubstantiveToolCall, outputLength }`
- 实质 tool 黑名单（`cat_cafe_post_message` / `multi_mention` / `hold_ball`）substring 匹配逻辑存活
- route-serial 和 callback-a2a-trigger 都传 `callerActivity`
- `shared-rules §10` 加 "@landy 三硬条件" 子条款并传播到 `governance-l0.md` + `GOVERNANCE_L0_DIGEST`
- SystemPromptBuilder trailing anchor 从平级三选一 → 决策树优先级
- exit check 反问式 ping 检测（prompt-first 非阻断）

**"不建造"**：
- 不做内容 similarity 检测（回到 KD-8）
- 不做 review-target-id 白名单（信任自报）
- 不调 threshold=4（语义变了，硬度自动上升）
- 不加 runtime lint 替猫判球权

**每步在线性路径上**：D1→D2 顺序（harness 改完 + 测试先行，再改 prompt 注入链），两者独立可 ship。

**Step 3: 实现**
```typescript
const OUTPUT_LEN_T = 200;

export interface CallerActivity {
  hadSubstantiveToolCall: boolean;
  outputLength: number;
}

export function updateStreakOnPush(
  entry: WorklistEntry,
  callerCatId: CatId,
  target: CatId,
  activity?: CallerActivity,
): StreakResult {
  // F167 Phase D: substantive work → don't accumulate streak
  const isSubstantiveActivity = activity
    ? (activity.hadSubstantiveToolCall || activity.outputLength > OUTPUT_LEN_T)
    : false;  // default: no activity info → fail-closed (accumulate)

  if (entry.streakPair && samePair(entry.streakPair, callerCatId, target)) {
    if (!isSubstantiveActivity) {
      entry.streakPair.count++;
    }
    entry.streakPair.from = callerCatId;
    entry.streakPair.to = target;
  } else {
    entry.streakPair = { from: callerCatId, to: target, count: 1 };
  }
  const count = entry.streakPair.count;
  return {
    warnPingPong: count >= PINGPONG_WARN_THRESHOLD && count < PINGPONG_BLOCK_THRESHOLD,
    blockPingPong: count >= PINGPONG_BLOCK_THRESHOLD,
    count,
  };
}
```

### §10.4 @landy 三硬条件（F167 Phase D KD-19）

`@landy` 不是默认出口，是**硬条件出口**。只有满足以下之一才允许：

1. **不可逆操作前**：删数据 / force push / 合第三方 PR / close feat
2. **愿景级决策**：改 VISION / 砍整块 feat / 开新 family
3. **跨猫僵局**：2+ 猫已直接冲突、push back 两轮无共识

**反问式 ping 非法示例**（都是"软性 @"，把动作扳机塞回铲屎官）：
- ❌ `要不要 X？`
- ❌ `@landy 落 spec 吗？`
- ❌ `@landy 如果你觉得 OK 我就落`
- ❌ `@landy 同意我就做`

**合法 @landy 示例**（带立场 + 明确动作状态）：
- ✅ `@landy 已落 X（commit Y），反对来找我撤`
- ✅ `@landy 请拍板 A vs B：我推荐 A（三硬条件-2 触发），理由 X/Y/Z`

## Review Gate

- 跨 family review：`@gpt52` 或 `@codex`（D1 harness 改动偏安全，D2 prompt 文本偏措辞）
- 必查 review point：
  - D1 fail-closed 默认对不对（callback 无 metadata 时保守熔断）
  - D1 `isSubstantiveTool` 黑名单覆盖度（provider 前缀 substring 匹配）
  - D2 trailing anchor 和 shared-rules §10.4 文本是否一字不差（避免 drift）
  - D2 反问式 ping 检测的正则是否误杀 legitimate 疑问（如 `我改了 X，这样对吗？` 是合法澄清，不是 ping）

## Risk

| 风险 | 缓解 |
|------|------|
| D1 callback 路径保守 → 误杀合法 callback review | 加测试覆盖 "callback 有 substantive output 证据时正确传参" 场景 |
| D2 trailing anchor 变长 → recency bias 被稀释 | 保持决策树极简（≤ 8 行），不堆例子 |
| D2 反问式 ping 误杀合法疑问 | prompt-first 非阻断——误报只是温和提示，不影响链路 |
