# F193 Phase A — KD-1 Enforcement Implementation Plan

**Feature:** F193 — `docs/features/F193-cross-thread-comm-unification.md`
**Goal:** 落地 KD-1 (principal-conditioned threadId semantics) 两层 enforcement，按 AC-A3 4 格矩阵 reject 不合法组合，恢复 F043 #316 防误投契约。
**Acceptance Criteria（从 spec 抄过来）:**
- AC-A1: `crossPostMessageInputSchema` 补 `targetCats` 字段并在 handler 透传
- AC-A2: MCP handler 层 — invocation-token caller 调 `post_message` 传 `threadId` 时 reject，错误消息提示用 `cat_cafe_cross_post_message`
- AC-A3: API route 层 — `CallbackPrincipal × threadId × targetCats` 组合校验，按 4 格允许/拒绝矩阵；违反 KD-1 时 400 + alternatives
- AC-A4: `cross_post_message` 缺 `targetCats` AND 无行首 @ → reject (400) + alternatives
- AC-A5: 测试覆盖 principal × threadId × targetCats 全组合矩阵；F052 sourceThreadId 注入仍正确；同名猫跨线程豁免不退化

**Architecture cell:** `callback-auth` + `transport`
**Map delta:** update required
**Map delta why:** `callback-auth` cell 文档要补 principal-conditioned threadId 规则（4 格允许/拒绝矩阵 + agent-key 不享有 F052 relay 语义）；`transport` cell 文档要把 `cross_post_message` 从残废工具升级为一等公民（含 targetCats）。两个 cell 文档更新放 Phase A 收尾任务。
**Architecture:** 两层 enforcement —— MCP handler 层（`packages/mcp-server`）做客户端早 reject 保护猫认知路径；API route 层（`packages/api/src/routes/callbacks.ts`）做服务端 hard check 保护安全边界。两层独立判断，重复防御正确（防止 MCP handler 被绕过直接 hit /api/callbacks）。
**Tech Stack:** TypeScript / Zod schema / Fastify route handler / node:test 测试框架 / 已有 callback-auth-* test infra
**前端验证:** No — Phase A 纯后端契约 + schema 改动，无 UI 改动

```typescript
// packages/mcp-server/src/tools/callback-tools.ts:355-366 修改 crossPostMessageInputSchema
export const crossPostMessageInputSchema = {
  threadId: z.string().min(1).describe('Target thread ID to post into'),
  content: z.string().min(1).describe('The message content to post'),
  targetCats: z
    .array(z.string().min(1))
    .optional()
    .describe(
      'Cat handles to route the cross-thread notification to (triggers their session in target thread). ' +
        'Required if content has no line-start @mention — server fail-closes when both are missing. ' +
        'F193 KD-1: this is the route layer, not relay metadata; agent-key callers do not inherit F052 sourceThreadId semantics.',
    ),
  replyTo: z.string().optional().describe('Optional message ID to reply to'),
  clientMessageId: z
    .string()
    .min(1)
    .max(200)
    .optional()
    .describe('Optional idempotency key for at-least-once delivery de-duplication'),
  agentKeyCatId: agentKeyCatIdSchema,
};
```

**Step 1.4: handler 透传 targetCats**

```typescript
// packages/mcp-server/src/tools/callback-tools.ts:564-578 修改 handleCrossPostMessage
export async function handleCrossPostMessage(input: {
  threadId: string;
  content: string;
  targetCats?: string[] | undefined;
  replyTo?: string | undefined;
  clientMessageId?: string | undefined;
  agentKeyCatId?: string | undefined;
}): Promise<ToolResult> {
  return handlePostMessage({
    threadId: input.threadId,
    content: input.content,
    ...(input.replyTo ? { replyTo: input.replyTo } : {}),
    ...(input.clientMessageId ? { clientMessageId: input.clientMessageId } : {}),
    ...(input.agentKeyCatId ? { agentKeyCatId: input.agentKeyCatId } : {}),
    ...(input.targetCats?.length ? { targetCats: input.targetCats } : {}),
  });
}
```
