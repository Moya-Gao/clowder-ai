# F193 Phase D Implementation Plan

**Goal:** 清理 F193 audit 阶段识别的 3 个废弃工具 / 配置项，让 SystemPromptBuilder 工具列表与实际注册一致，避免猫看到"假工具"调用失败。

- AC-D3: `.mcp.json` / `.codex/config.toml` 中 `probe-connected` / `probe-env` / `probe-off` 因为 gitignored 走 migration doc user-action（同 Phase C 模式）

**Architecture cell:** `mcp-tools` (no map delta — pure removal)
**Map delta:** none
**Map delta why:** 纯减法，工具表/SystemPromptBuilder/tool-registration test 都在已存在的 cell 内调整，不引入新 architecture 边界。

**Architecture:** Phase D 是 Phase A/B/C 之后的清理收尾。三个 AC 各自独立、不相互依赖：D1 删 reflect tool，D2 删 guide_resolve legacy alias，D3 通过 migration doc 让 user 自更新本地 .mcp.json/.codex/config.toml（同 Phase C 模式）。tool-registration.test.js 是核心守护——任何"幽灵"工具会被它接住。

**Tech Stack:** TypeScript, node:test, Phase C 已验证的 split-only canonical state

**前端验证:** No — pure backend tool registration cleanup. SystemPromptBuilder 改动不影响前端，影响的是 cat agent 的 system prompt 内容（Cat agent 集成测试覆盖即可）。
