- AC-E4: cron 注册（检测 `claude --version` 变更触发 audit；用项目 scheduler，非 GitHub Action——CI runner 无 claude/codex 二进制）
- AC-E5: 同款 SOP 对 Codex CLI 适用（脚本 `--cli codex` 参数化 + `docs/audits/codex-system-prompt-v*.md` 归档）
**Architecture cell:** harness/system-prompt-injection（与 Phase C/D 同 cell）
**Map delta:** none（加 audit 脚本 + SOP doc + cron 注册，不改注入链/runtime 架构；无新 Store/Queue/Router）
**Map delta why:** Phase E 是"版本漂移检测工具 + 流程"，纯 tooling/SOP 增量，注入链 Phase C 已定。
**Architecture:** `audit-claude-code-system-prompt.mjs` 纯 Node：`strings <binary>` → 按已知 section anchor 正则提取关键段（身份行/Doing tasks/工具/safety/section 清单）→ 输出 markdown（与 `cc-system-prompt-v2.1.143.md` 同结构）；`--diff <prev-doc>` 比对上一版本，新增功能性 anchor → 非 0 退出 + 提示提案 L0 更新。cron（项目 scheduler）周期跑 `--check`：`claude --version` ≠ 最新归档版本 → 触发 audit + 发消息提醒猫做 SOP。
**Tech Stack:** Node (node:child_process strings/execFile, node:fs) + node:test（fixture 驱动，不依赖真二进制）+ cat_cafe_register_scheduled_task（cron）
**前端验证:** No（纯脚本 + SOP doc + cron）

## Straight-Line Check

- **B**：`audit-claude-code-system-prompt.mjs --cli claude|codex [--diff <prev>] [--check]` 可跑：提取 section anchors、diff 上一版本、flag 新功能性指令；SOP doc 写明何时/怎么/提案；cron 注册周期检测版本变更。
- **终态 schema**：脚本 3 模式——`--emit`（提取→stdout/文件 markdown）/ `--diff <prevDoc>`（对比，新 anchor → exit 1 + 列差异）/ `--check`（版本对比，变了 → 触发 emit + 退出码信号）。fixture 驱动测试（`test/fixtures/cc-strings-sample.txt`）不依赖真二进制（CI 无 claude）。
- **NOT building**：不自动重写 L0（SOP = 提案 PR，猫/CVO 决）；不语义解析全 prompt（只 section-anchor 提取 + diff）；不做常驻 daemon（周期 cron）；不在 GitHub Action 跑（runner 无二进制）。
