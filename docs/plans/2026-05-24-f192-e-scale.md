# F192 E-scale: eval:memory Adapter Implementation Plan

**Feature:** F192 — `docs/features/F192-socio-technical-harness-eval.md`
**Goal:** Scale unified eval runtime to `eval:memory` domain — connecting F200 recall eval + F188 library health governance into the Eval Hub alongside existing `eval:a2a`.
**Acceptance Criteria:**
- AC-E11: Unified Eval Runtime accepts `eval:memory` adapter (F200 recall + F188 health sources)
- AC-E12: Bidirectional jump links between Eval Hub and F188 health/repair surfaces
- AC-E13: Legacy scheduled-task inventory for F200/F188 + dry-run cleanup report proving no double-trigger
**Architecture cell:** harness-eval
**Map delta:** none
**Map delta why:** Extending existing harness-eval cell with a second domain adapter — no new cell, no boundary change.
**Architecture:** Generalize E-pilot's `eval:a2a`-only schemas to domain-union types, then add a parallel `eval-memory-adapter.ts` that consumes F200 `RecallMetricsComputer` + F188 `computeLibraryHealth` data sources → standard `VerdictHandoffPacket`. Frontend gets bidirectional jump links (Eval Hub ↔ F188 health surfaces).
**Tech Stack:** Zod (schema generalization), Node.js test runner, React (HubEvalTab jump links)
**前端验证:** Yes — Eval Hub jump links + F188 health backlink

**Step 3: Implement eval-memory-adapter.ts**

The adapter mirrors `eval-a2a-adapter.ts` structure:

```typescript
// Key interfaces:
interface MemoryRecallMetrics {
  mrr: number;
  precisionAt3: number;
  precisionAt5: number;
  abandonmentRate: number;
  fellBackToGrepRate: number;
  totalEvents: number;
  windowDays: number;
}

interface MemoryLibraryHealth {
  orphanEdgeCount: number;
  staleAnchorCount: number;
  verificationDebtCount: number;
  totalDocs: number;
  searchQualityScore: number;
}

interface MemoryFinding {
  id: string;
  signal: { type: string; severity: 'low' | 'medium' | 'high'; confidence: number };
  primaryLayer: string;
  evidence: Array<{ type: string; anchor: string; excerpt: string }>;
  proposedAction: Array<{ action: string; target: string; rationale: string }>;
}

interface BuildMemoryVerdictInput {
  domain: EvalDomainRegistryEntry;
  recallMetrics: MemoryRecallMetrics;
  libraryHealth: MemoryLibraryHealth;
  finding?: MemoryFinding;          // present → fix/build verdict
  noFindingRecord?: { reason: string; evidence: string }; // present → keep_observe
}

export function buildMemoryVerdictHandoff(input: BuildMemoryVerdictInput): VerdictHandoffPacket
```

Key design decisions:
- **No business data copying**: Adapter receives pre-computed metrics, not raw DB rows (AC-E11 spec: "不 copy 业务数据")
- **Snapshot-equivalent**: `recallMetrics` + `libraryHealth` serve the same role as A2A's `components[]` snapshot
- **Reuses verdict-handoff.ts**: Same `parseVerdictHandoffPacket` validation + `assertCanCrossThreadHandoff`
- **Finding → verdict mapping**: orphan/stale issues → `fix`; missing coverage → `build`; no issues → `keep_observe`

function loadDomains(harnessFeedbackRoot: string): Map<string, EvalDomainRegistryEntry> {
  const domainsDir = join(harnessFeedbackRoot, 'eval-domains');
  const domains = new Map<string, EvalDomainRegistryEntry>();
  for (const file of readdirSync(domainsDir).filter(f => f.endsWith('.yaml'))) {
    const parsed = parseYaml(readFileSync(join(domainsDir, file), 'utf8'));
    const entry = parseEvalDomainRegistryFile(parsed);
    domains.set(entry.domainId, entry);
  }
  return domains;
}
