# F192 E-community Implementation Plan

**Feature:** F192 — `docs/features/F192-socio-technical-harness-eval.md`
**Goal:** Enable community instances to export sanitized eval findings as issue packets, and register custom eval domains without forking Cat Cafe core
**Acceptance Criteria:**
- AC-E14: Community path — sanitized issue packet export + custom eval domain registration
- AC-E15: Community dogfood — at least 1 sanitized issue packet fixture + 1 custom domain fixture passes schema validation
**Architecture cell:** harness-eval
**Map delta:** none
**Map delta why:** Extends existing harness-eval cell with community-facing schemas and export functions; no new architecture cells or boundary changes
**Architecture:** Build on existing VerdictHandoffPacket + EvalDomainRegistryEntry contracts. Add deidentification layer (strip internal thread/cat/user refs), community domain schema (relaxed domainId/sourceAdapter enums), and filesystem-based community domain loader.
**Tech Stack:** Zod schemas, TypeScript, YAML, vitest
**前端验证:** No — pure backend schema + adapter layer

---

## Straight-Line Check

**Finish line:** Community projects can (1) receive a sanitized version of any eval verdict that strips Cat Cafe internals, and (2) register their own eval domains via YAML without touching Cat Cafe source code. Both validated by fixtures passing Zod schemas.

**NOT building:** Community web UI, community domain runtime execution, community issue tracker integration, community auth/permission layer.

**Terminal schema:**
- `SanitizedIssuePacket` — deidentified export of VerdictHandoffPacket
- `CommunityEvalDomainEntry` — relaxed registry entry for custom domains
- `sanitizeVerdictForExport()` — transform function
- `loadCommunityDomains()` — filesystem loader for community YAML

The sanitized issue packet strips internal references from a VerdictHandoffPacket:
- `domainId` → kept (domain names are public)
- `phenomenon` → kept
- `harnessUnderEval.featureId` → replaced with opaque `feature-NNN` 
- `harnessUnderEval.componentId/name` → kept (generic harness component names)
- `evidencePacket.*Refs` → replaced with `["[redacted:N refs]"]` count-only references
- `dailyTrend` → kept (numeric, no PII)
- `rootCauseHypothesis` → kept (analytical text, no internal names)
- `verdict` → kept
- `ownerAsk.targetFeatureId` → opaque
- `ownerAsk.targetOwnerCatId` → replaced with role label `"feature-owner"`
- `ownerAsk.requestedAction` → kept
- `governance` → kept
- `acceptanceReevalPlan` → kept
- `counterarguments` → kept
- Internal fields (thread IDs, user IDs, cat model names) → stripped

### Task 2: CommunityEvalDomainEntry schema + loader

**Files:**
- Create: `packages/api/src/infrastructure/harness-eval/community-eval-domain.ts`
- Test: `packages/api/test/infrastructure/harness-eval/community-eval-domain.test.ts`

Community domains use a relaxed version of EvalDomainRegistryEntry:
- `domainId` → any `string` matching `eval:<namespace>` pattern (not restricted to internal enum)
- `sourceAdapter` → `"community-custom"` literal (community adapter doesn't map to Cat Cafe internal adapters)
- `handoffTargetResolver` → optional (community domains may not have Cat Cafe feature threads)
- Rest of schema same as internal (displayName, systemThreadId, evalCat, frequency, threadPolicy, sla)

Plus a `loadCommunityDomains()` function that reads community YAML from a configurable directory.

```typescript
const communityEvalDomainEntrySchema = z.object({
  domainId: z.string().regex(/^eval:[a-z][a-z0-9_-]*$/, 'domainId must start with eval: followed by lowercase alphanumeric'),
  displayName: z.string().min(1),
  systemThreadId: z.string().min(1),
  evalCat: z.object({ catId: z.string().min(1), handle: z.string().min(1), model: z.string().min(1) }),
  frequency: z.enum(['daily', 'weekly']),
  sourceAdapter: z.literal('community-custom'),
  threadPolicy: z.object({
    role: z.literal('working-home'),
    stateSot: z.literal('registry'),
    allowedContent: z.array(z.string().min(1)).min(1),
  }),
  legacyScheduledTaskIds: z.array(z.string()).default([]),
  handoffTargetResolver: z.object({
    featureId: z.string().min(1),
    ownerCatId: z.string().min(1),
    threadLookup: z.literal('feature-thread'),
  }).optional(),
  sla: z.object({
    acknowledgeHours: z.number().int().positive(),
    reevalWithinHours: z.number().int().positive(),
  }),
});

function loadCommunityDomains(communityDomainsDir: string): CommunityEvalDomainEntry[] { ... }
```
