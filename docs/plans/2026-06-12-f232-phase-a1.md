## AC-A7：点击看内容（灵魂）

### 状态机（ArtifactsPanel 内部）
- **state**: `selected: ThreadArtifactDTO | null` — `null`=列表视图；非 null=内容详情视图（覆盖列表）
- **转移**: 列表项点击 → `setSelected(a)`；详情 ←返回 → `setSelected(null)`
- **不变量**: selected≠null 时只渲染详情（列表隐藏）；返回按钮始终可达；filter/搜索不影响已打开的 detail（返回列表才重过滤）

### view 分类（纯函数 `classifyArtifactView(a)` — 核心可测点）
| 条件 | view | 渲染策略 |
|------|------|---------|
| `image` && url | `image` | `<img src={resolveUrl(url)}>` |
| `audio` && url | `audio` | `<audio controls>` |
| `pr` | `pr` | PR 卡 + 「GitHub 打开 ↗」（ref=`org/repo#123` → `https://github.com/org/repo/pull/123`） |
| `file`/`code` && 文本扩展名 | `text` | fetch 内容 → `MarkdownContent`(.md) / `CodeViewer`(其他) |
| `file` && url && 二进制扩展名(.pdf/.docx/.png…) | `download` | 「下载 / 新标签打开」 |
| 无任何内容源（无 url 无 ref） | `fallback` | 「跳回原消息」(teleport) |

文本扩展名集合：`.md .txt .log .json .ts .tsx .js .jsx .css .html .yml .yaml .sh .py .mjs .cjs`（无扩展名 → 当文本试）

### 内容获取子状态机（view=text）
- **数据源判定**: 有 url（uploads 文本）→ `fetch(resolveUrl(url))`；无 url 有 ref（repo 文件，如 backlog）→ `/api/workspace/file?worktreeId=&path=ref`（返回 `FileData{content,mime,binary}`）
- **worktreeId 来源**: `chatStore.workspaceWorktreeId`（用户当前 workspace 选中；主仓场景成立）
- **状态**: idle → loading → loaded(content) / error
- **stale 防护**: fetch 期间切 selected → 旧请求结果用 cancelled flag 丢弃（不覆盖新）

### 对抗场景（必测/必防）
- repo 文件但 `workspaceWorktreeId` 为空（用户没开过 workspace）→ 优雅降级到 `fallback`（跳回消息），不崩
- ref 文件不在当前 worktree（跨 repo）→ workspace API 404 → error 态 → 显示「无法加载，跳回原消息」
- 二进制误判成文本（扩展名骗过）→ CodeViewer 显示乱码但不崩（可接受）
- selected 的 source message 在窗口外 → 返回列表正常（teleport 走已有 jump-with-load）

### 技术判断（⚠️ reviewer 重点攻击点）
- spec KD-4 字面写「复用 `FileContentRenderer`」。但实读代码：`FileContentRenderer` 整体紧耦合 workspace `FileData` + `rawUrl`（走 `/api/workspace/file/raw?worktreeId=`，对 uploads url 不适用）+ 一堆 workspace-specific props（mdContainerRef/markdownRendered/...）。
- **决策**：复用其**底层渲染器** `MarkdownContent`(content/basePath/worktreeId) 和 `CodeViewer`(content/mime/path)——它们是 `FileContentRenderer` 的内脏、接口干净——满足「复用查看器、不重造 markdown/code 渲染」的真不变量（F206 归一精神）。
- **撤回条件**：若 reviewer 论证 repo 文件类直接走 workspace `setOpenFile`（整体复用 FileContentRenderer + workspace toolbar）体验更一致且不增耦合 → 改 repo 文件类走 workspace；uploads/image/audio 仍走轻量分发。

## AC-A8：UX 收敛

### 现状
- `chatStore.rightPanelMode`: status|workspace|transcript|artifacts；`ChatContainer.statusPanelOpen`: boolean
- header 两按钮（都 `hidden lg:block` → 小屏无入口）：`RightPanelToggle`(status↔workspace) + `ArtifactsToggle`(artifacts↔status)
- 其他 mode 功能入口（**保留不动**）：`ChatVoiceFeatureControls`→transcript、`WorkspacePanel`→workspace
- 小屏：`MobileStatusSheet`（只 status）

### 收敛设计
- **header**: 删 `RightPanelToggle` + `ArtifactsToggle`，换**一个** `PanelToggle`（开/关 panel；小屏也可见，去掉 `hidden lg:block`）
- **panel 顶部**: 新增 `PanelTabs`（状态/工作区/产物/转录 4 tab），点 tab → `setRightPanelMode(tab)` + 保证 `statusPanelOpen=true`；高亮当前 mode
- 外部功能入口切 mode 后 tab 高亮跟随（不冲突）
- **小屏 fallback**: PanelToggle 小屏可见；点击打开含 4 tab 的 panel（实现时定：扩展 `MobileStatusSheet` 加 tab vs 桌面 panel 小屏渲染）

### 状态机（纯函数）
- `panelToggle(open) → !open`
- selectTab(mode): `setRightPanelMode(mode)` + `setStatusPanelOpen(true)`（恒等开）

### 对抗场景（必测）
- 删两按钮 → 现有 `artifacts-toggle-transition` / `right-panel-toggle-cycle` 测试更新/替换为新纯函数
- tab 切换恒保持 panel open；关 panel 再开 → 恢复上次 mode
- 小屏点 PanelToggle → 4 tab 可达（产物入口小屏可达 = AC-A8 验收点）
- 语音切 transcript → tab 高亮 transcript
