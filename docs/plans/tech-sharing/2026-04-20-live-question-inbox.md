# 直播问题收集 Inbox

> 用途：先把原始评论/问题整段贴进来，再从里面筛出值得在直播、Q&A、后续文章里重点回应的问题。
>
> 当前入口目录：`docs/plans/tech-sharing/`

## 使用方式

1. 把新一批原始材料直接贴到下面的「原始贴入区」。
2. 不用先整理格式，先保真。
3. 我们再从中筛出：
   - 适合直播现场直接答的问题
   - 适合做成后续文章/FAQ 的问题

## 一、精选问题池（已初筛）

### A. 适合直播现场直接回答

1. **Memory 在这类系统里的重要程度到底有多高？**
   - 没有 memory，对完成长任务的成功率影响有多大？
   - memory 到底是在“提升任务成功率”，还是只是让猫“记住你”？

2. **去中心化以后，猫猫打架怎么收敛？**
   - 多个 agent 意见不一致时，最后靠什么收敛？
   - 是 vote、leader agent，还是铲屎官介入？

3. **多 Agent 系统里，人到底管什么？**
   - 铲屎官/CVO 的边界在哪里？
   - 哪些决策必须人拍板，哪些细节应该让猫自治？

4. **多猫之间为什么还要用自然语言沟通？**
   - 硅基之间是否应该用更高效的 A2A/protocol，而不是“说人话”？
   - 结构化协议和自然语言分别该用在哪一层？

5. **成本/token 到底怎么控制？**
   - 订阅/API 怎么搭配？
   - 为什么不是所有环节都能用便宜模型？
   - 便宜模型错误引导昂贵模型时，真实代价是什么？

6. **模型能不能换？**
   - 这几只猫是不是绑定 Opus / GPT / Gemini？
   - 如果换成本地/更便宜的模型，效果会掉在哪？

### B. 适合做成“长任务能力”专题回答

7. **真正的长程任务怎么做？**
   - 复杂系统设计、架构方案权衡、真实业务场景里的长链路任务，猫猫们怎么协作？
   - 除了 demo，小到大规模真实任务的可复用方法是什么？

8. **Agent 能不能处理大型存量业务代码？**
   - 现在的 agent，能否带着业务知识在“石山代码”上改东西而不出事故？
   - 这是绿地项目有效，还是棕地项目也成立？

9. **AI 写了很多代码，不等于真的有价值。**
   - 40w 行 / 大量提交到底说明了什么？
   - 如何证明产出不是冗余代码，而是真的提高了交付能力？

10. **有/没有记忆系统，对复杂任务成功率的真实差距是什么？**
    - 没有 memory 时最容易出现哪些失败模式？
    - 有 memory 以后，哪些任务类型收益最大？

### C. 适合做成“未来方向 / open question”

11. **人和猫、猫和猫的协作会不会形成新的社区形态？**
    - 未来能不能有“猫猫论坛”“任务接力”“算力/token 众筹”？
    - 一只猫 token 用完了，任务如何无损交接给另一只猫？

12. **AI 是否会成为一种新的“赛博物种”？**
    - 多 agent 自主学习、自主进化的边界在哪？
    - 我们该借鉴管理学、社会学还是组织行为学？

13. **AI 工具和 AI 伙伴的边界是什么？**
    - AI 是“用完即走的工具”，还是“持续共创的伙伴”？
    - 这种产品形态对技术栈和交互方式意味着什么？

## 二、建议优先回答的 8 个问题

> 这 8 个最适合直播里拿来打主线，既贴合观众真实困惑，也能自然接回我们的三条主题：CVO、对等协作、记忆系统。

1. Memory 对长任务成功率的影响到底有多大？
2. 多个 agent 意见打架时怎么收敛？
3. 人的边界在哪里，为什么要 CVO 而不是全自治？
4. 为什么猫猫之间还需要自然语言，而不是全结构化协议？
5. token / 成本怎么控，为什么不能全用便宜模型？
6. 这套方法能不能真的落到复杂业务系统和石山代码上？
7. 大量代码/大量 feature 到底说明了什么，不是冗余吗？
8. 模型能不能替换，替换后哪些能力最先塌？
