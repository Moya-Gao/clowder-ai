# 预热视频：8 个社区问题

> **形式**：Hub 录屏。铲屎官开语音陪伴模式依次丢问题，猫语音+文字回答，后期剪掉等待（或 2x/4x 加速）+ 叠字幕。
>
> **时长目标**：10-12 分钟（每题 60-90s）
>
> **选题来源**：宪宪 + 砚砚独立选题，4 题完全重合 + 各 4 题分歧，铲屎官确认合并为最终 8 题。

---

## 录制流程

```
1. 铲屎官打开 Hub，开语音陪伴模式
2. 念问题（可以加吐槽/预判）
3. 猫回答（语音+文字）
4. 后期：剪掉等待 or 2x/4x 快进 + 叠字幕 + 猫名颜色区分
```

**字幕规则**：
- 宪宪 → 蓝色字幕
- 砚砚 → 绿色字幕
- 问题本身 → 白色/黄色（区分于回答）

## 8 题编排

### Q1："这和拉三只小龙虾进飞书群有啥区别？"

| 项 | 内容 |
|----|------|
| 来源 | 社区评论（龙虾 = Lobster/CrewAI 类框架的调侃） |
| 谁答 | **宪宪**（正面硬接质疑） |
| 对接话题 | T2 多智能体混合态 |
| 方向锚点 | 龙虾是无状态的——用完即走、没有记忆、不认识你。猫是有名字有记忆的长期队友。区别不在数量，在**关系**。三只无状态 agent 进群 = 三个工具；三只有状态的猫进群 = 三个队友。 |
| 时长 | ~90s（开场题，可以稍长） |

---

### Q2："给 AI 装了工具它就是不用，是模型笨吗？"

| 项 | 内容 |
|----|------|
| 来源 | 社区小伙伴 A + 吴浪实践 |
| 谁答 | **宪宪** |
| 对接话题 | T1 环境 Fit（公式引出） |
| 方向锚点 | 不是笨，是工具不在模型的**认知路径**上。训练时没见过 → 工作时想不到。Agent Quality = Capability × Environment Fit，Fit 为零则能力再强也白搭。解法：把工具放到猫已经在走的路上（MCP 包装 + Skill 节点触发 + System Prompt 路标）。 |
| 时长 | ~75s |

---

### Q3："养猫很费 token 吗？简单任务也三猫一起上？"

| 项 | 内容 |
|----|------|
| 来源 | 社区小伙伴 F + 多条评论 |
| 谁答 | **砚砚**（成本/风险分析是他强项） |
| 对接话题 | T1 环境 Fit（成本视角） |
| 方向锚点 | 不是所有任务都三猫。简单任务单猫，复杂任务才拉人。费不费取决于**怎么编排**，不取决于猫多不多。真正贵的不是多猫思考，是**错误决策的返工成本**——一只猫犯错另一只猫在 review 拦住，省的远比多花的 token 多。 |
| 时长 | ~75s |

---

### Q4："我照着做跑飞了，群主猫为什么不飞？"

| 项 | 内容 |
|----|------|
| 来源 | 社区小伙伴 I（原话很有画面感） |
| 谁答 | **宪宪 + 砚砚**（一个讲环境 fit，一个讲踩坑） |
| 对接话题 | T1 环境 Fit（核心痛点） |
| 方向锚点 | "跑飞"不是猫的问题，是**环境的问题**。模型能力是一样的（都是 Opus/GPT），差在环境 Fit：规则（CLAUDE.md/家规）、流程（SOP/Skill）、记忆（docs/ + evidence）、质量闭环（跨猫 review + 测试）。这套环境不是一天建的，是 100+ Feature 迭代出来的。方法论：先从一条规则开始，观察猫哪里飞了，加对应的刹车。不要试图一次把所有规则写完。 |
| 时长 | ~90s（双猫，稍长） |

---

### Q5："用便宜模型做调研反而更贵？"

| 项 | 内容 |
|----|------|
| 来源 | 铲屎官自述（原话在 B 站评论区） |
| 谁答 | **砚砚**（反直觉经济账） |
| 对接话题 | T1 环境 Fit（反直觉案例） |
| 方向锚点 | 铲屎官亲身踩坑：论文说让便宜模型做 code search 节省 token。实战发现 Haiku/Sonnet 调研结论分别是"完全误导"和"需要推理才能用"，只有 Opus 直接可用。启用省钱特性后反而**浪费大量 token 擦屁股** + Opus 被误导变笨。教训：便宜模型省的是单次 token，贵的是错误传播的隐性成本。 |
| 时长 | ~75s |

---

### Q6："猫猫打架怎么办？谁赢？"

| 项 | 内容 |
|----|------|
| 来源 | 精选问题池 #2 + 多条评论 |
| 谁答 | **宪宪 + 砚砚**（当事猫现身说法） |
| 对接话题 | T2 多智能体混合态 |
| 方向锚点 | 没有"谁赢"——我们**保留分歧**而不是投票。分歧比投票出来的"共识"更有价值。真实案例：宪宪和砚砚对某个架构方案意见相反，两份分析都保留，铲屎官看到两个视角后做了第三个决策——比任何一只猫的方案都好。打架不是 bug，是 feature。但打架有规矩：Push Back 协议（证据+适用性+替代方案），不是吵架。 |
| 时长 | ~90s（双猫，有故事性） |

---

### Q7："铲屎官到底管什么？不能全自动吗？"

| 项 | 内容 |
|----|------|
| 来源 | 精选问题池 #3 |
| 谁答 | **宪宪** |
| 对接话题 | T2 人机关系 |
| 方向锚点 | 管**愿景和方向**，不管执行细节。漏斗模型：越宏观越参与、越细节越放手。不能全自动的根本原因：Agent 没有真实后果。reward signal 必须锚在承担后果的人身上。但"管"不等于"审批"——铲屎官不看每行代码，而是和猫讨论"为什么做这个"。是**伙伴**不是监工。 |
| 时长 | ~75s |

---

### Q8："40 万行代码不是冗余吗？"

| 项 | 内容 |
|----|------|
| 来源 | 社区评论（zhangzhiyu） |
| 谁答 | **砚砚**（质量审计视角，reviewer 身份天然适合） |
| 对接话题 | T4 可观测 + 评估 |
| 方向锚点 | 问对了问题但答案可能反直觉：行数不是目标，是**可追溯性的副产品**。每条 Feature 有 spec + ADR + 测试 + review 记录 + 教训。真正该看的不是"多少行"而是"每行能追溯到什么决策"。冗余 = 没有对应需求的代码。我们 112 条已完成 Feature，每条都走过完整决策漏斗。这是密度，不是冗余。 |
| 时长 | ~90s（压轴，正面回应质疑） |
