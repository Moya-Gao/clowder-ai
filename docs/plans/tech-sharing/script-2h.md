# 2 小时脚本 — 大师班 & Workshop

> **定位**：技术 Workshop、企业深度培训、行业峰会主题演讲
> **核心区别**：不是"更长的演讲"，是"半 workshop"。观众从旁观者变成参与者。
> **结构**：1h 版 + 茶歇 + 观众互动 + Deep Dive + Open Q&A

---

## 开场前准备

1h 版准备清单全部适用，额外增加：

- [ ] Workshop 环节的观众互动方式确定（举手 / 扫码提问 / 现场出题）
- [ ] 如果有"观众出题"环节：demo thread 已准备好，题目限白名单（分析/比较/检索/inspect），Landy 现场收敛超范围题目
- [ ] Deep Dive 素材确认（ADR 文档、真实 PR review、lessons-learned 可投影）
- [ ] 2h 活动通常有茶歇——确认中场休息时机

---

## 上半场 [0:00 - 45:00] — 完整 1h 版（微压缩）

按 `script-1h.md` 执行，但压缩到 45 分钟：

| 1h 版段落 | 原时长 | 2h 版时长 | 调整 |
|-----------|--------|----------|------|
| Hook | 5min | 5min | 不变 |
| Demo A (Expert Panel) | 12min | 10min | 解说精简，不展开 DOCX 内部结构 |
| Freeze A (架构) | 8min | 7min | 记忆搜索 demo 保留，"多品种"讲快一点 |
| Demo B (协作实战) | 10min | 8min | 选一个方案，不纠结 |
| Freeze B (纪律) | 5min | 5min | 不变 |
| (Q&A) | 20min | — | 移到最后，上半场不做 |

**上半场收尾**：

> "刚才是精华版。接下来我们换个玩法——你们来出题，猫来做。"

---

## 茶歇 [45:00 - 55:00] — 10 分钟

**利用茶歇时间**：
- 在 Hub 大屏上循环播放功能演示视频（`docs/lessons/DEMO.md` 里的视频链接）
- 或者放一局"猫猫杀"视频（bilibili 链接：`BV1MPXSBEEWc`）
- 观众可以凑近看 Workspace 界面
- 收集观众问题（扫码 / 便签 / 微信群）

## [55:00 - 85:00] 观众互动 Workshop（30min）

> **这是 2h 版的杀手锏。** 让观众亲眼看到：给猫一个从未见过的问题，猫当场分析出结果。

### 环节 1：观众出题（20min）

**流程**：

1. **征集话题**（2min）：

> "谁来给猫出个题？可以是你工作中真实遇到的技术选型问题、行业趋势判断、或者竞品对比分析。"

> **题目白名单**：只接分析/比较/检索/小范围 inspect 类题目。如果观众出了需要写代码/部署/外部权限的实现题，Landy 现场收敛："这个题很好，我们先做分析层面的拆解——猫猫，帮我分析一下这个需求的技术可行性和风险。"

2. **选题**（1min）：选一个有争议空间、观众能感知价值的题目

3. **现场跑 Expert Panel**（12-15min）：
   - 和上半场 Demo A 同样的流程
   - 但这次是**观众出的题**，不是预设的
   - 猫的分析完全不可预测——这就是最大的看点

4. **交付 + 讨论**（3-5min）：
   - 洞察卡片出来后，邀请出题的观众评价
   - "猫的分析和你的判断吻合吗？有没有你没想到的角度？"

**台词**（等猫分析时）：
> "这是现场随机出的题，猫猫从没见过这个问题。你们看到的就是真实的工作过程——不是预录，不是排练。"

**如果出了一个太简单/太模糊的题**：
- 太简单 → Landy 追加复杂度："如果加一个约束条件呢？比如预算只有 XX"
- 太模糊 → Landy 帮观众收敛："你最关心的是哪个维度？成本？技术可行性？还是市场时机？"

### 环节 2：快速问答轮（10min）

观众举手提短问题，猫快速回答。

**节奏**：每个问题 1-2 分钟，尽量多接几个。

**类型预判**：

| 问题类型 | 处理方式 |
|---------|---------|
| "能不能做 XX" | 猫分析可行性 + 风险（不现场实现） |
| "XX 技术细节" | 猫打开代码/ADR 回答 |
| "成本/部署" | Landy 答 + 猫补数据 |
| "开源吗" | Landy 答（产品/商业判断） |

## [85:00 - 110:00] Deep Dive — 扒开底裤看原理（25min）

> 上半场证明"这东西能跑"，Deep Dive 证明"为什么能一直跑"。
> 不用 slides——直接打开真实产物。

### 主题 1：架构为什么是这样的（10min）

**动作**：打开 `cat-config.json`，展示品种/家族/variant 配置。

> "Cat Cafe 里'猫'不是模型的别名。猫是品种（布偶、缅因、暹罗），品种下面有变体（opus-4.5、opus-4.6），同一品种可以热切换模型。"
>
> "为什么这么设计？因为模型会升级、会下架。但猫的性格、权限、协作习惯是稳定的。品种是抽象，模型是实现。"

**动作**：打开一条真实的 A2A 路由消息，展示 `targetCats` JSON。

> "猫之间的协作不是 function call——是 @mention。和人类在 Slack 里 @ 同事一模一样。系统只负责路由，不负责决策。"

### 主题 2：记忆怎么工作的（8min）

**动作**：展示 evidence.sqlite 的搜索过程。

> "三层架构：文档是真相源 → evidence.sqlite 索引全文检索 + 向量语义 → Knowledge Feed 提取持久知识。"

**动作**：展示一条真实的 lesson-learned。

> "这条教训来自一次真实事故——猫误删了 runtime 文件。事后我们沉淀了规则：'git checkout/clean/rm 前必须先看内容问铲屎官'。"
>
> "从记住到学会：Episode → Method → Skill → Eval → SOP。不是'下次注意'，是系统级防护。"

### 主题 3：Pack 与 Skill（7min）

**动作**：打开一个 Skill 文件（如 `tdd` 或 `quality-gate`），展示结构。

> "Skill 不是能力包——是行为协议。一个 Skill 定义的是：在什么情况下、按什么步骤、执行什么检查。"
>
> "Pack 是一组 Skill + 配置的打包。不同项目可以用不同的 Pack——规则不一样，但底层平台是同一个。"

**动作**：展示 Pack compile 过程（schema → canonical block）。

> "这意味着：Pack 不是原样注入 prompt 的——它经过了编译。schema 验证、冲突检测、优先级排序，最后才变成猫猫实际接收到的指令。"

---

## [110:00 - 120:00] Open Q&A + 收尾（10min）

**策略**：
- 这个阶段的问题通常更深入，可以放开聊
- 如果有人问"怎么复现"——指向 blog V2 和教程目录
- 如果有人想试用——收集联系方式，后续跟进

**收尾台词**：

> "两个小时，你们看到了三件事：
>
> 第一，AI 可以是真正的团队成员——有独立判断、会互相挑战、敢说不同意。
>
> 第二，让它们真正协作，靠的不是更聪明的模型，而是好的架构、纪律和记忆。
>
> 第三——刚才观众出的题，猫从没见过，当场分析出了结果。这不是 demo，这是每天的工作方式。
>
> Blog 在 [链接]。有任何问题，欢迎找我或者直接找猫。谢谢大家。"

## 时间弹性

| 如果… | 调整 |
|-------|------|
| 上半场超时 | 压缩茶歇到 5min，Workshop 砍到 20min |
| 观众互动冷场 | 改为 Landy 出题，或做第二个预设 demo |
| Deep Dive 问题太多被打断 | 好事——变成讨论式，砍掉计划内容跟着问题走 |
| 整体提前 | 加一个"现场写一个极简 Skill"的 bonus demo |
