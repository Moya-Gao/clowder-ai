# 30 分钟脚本 — 快闪演示

> **定位**：Meetup 闪电演讲、内部 demo、投资人展示
> **结构**：Hook (2min) → Live Demo (8min) → Freeze Frame (5min) → Q&A (15min)
> **PPT**：1 页 title + 1 页数字 = 2 页，其余全是 live

---

## 开场前准备

- [ ] Demo thread 已创建，Thread Primer 已注入（见 `2026-03-31-showcase-thread-primer.md`）
- [ ] 大屏投影 Hub/Workspace，字体大小确认可读
- [ ] 预录 60s showcase 视频已就绪（保底用）
- [ ] 话题已确定（demo 前一天）
- [ ] 全链路彩排至少 1 次

## [0:00 - 2:00] Hook — "我不念 PPT"

**动作**：上台，不开 PPT。直接打开 Workspace/Hub。

**台词**：

> "大家好，今天我不念 PPT。我给大家看一个东西。"
>
> *（指向屏幕上的 Workspace）*
>
> "去年的一个晚上，我同时开着三个窗口——Claude、ChatGPT、Gemini。我在它们之间复制粘贴，来回传话。突然意识到：我成了世界上最贵的传声筒。"
>
> "那天晚上我决定：铲屎官不应该是传声筒。于是我做了一个东西。"
>
> *（亮出 title slide：Cat Cafe logo + 一句话）*
>
> "Cat Cafe —— 不是 framework，是猫咖。三只 AI 猫，自己协作、自己 review、自己记住昨天聊了什么。我什么都不用管。"

**节奏**：快。2 分钟打完，不展开。留悬念。

---

## [2:00 - 10:00] Live Demo — Expert Panel

> 这是全场最核心的 8 分钟。复用 `2026-03-31-office-showcase-demo-script.md` 的 Expert Panel 流程。

**动作**：在 Workspace 里发一句话触发 Expert Panel。

**话题选择原则**：
- 真实、有争议空间、观众能感知价值
- 48 小时内热点优先
- 建议：行业趋势判断 / 技术选型争议 / 竞品分析

**发出的消息**（demo 前一天写好）：

```
[话题——提前填入]

帮我分析一下。
```

**大屏投 Hub thread**，观众实时看到：

### Phase 1 — Dispatch（~30s）

宪宪分发任务给各猫。

**台词**（对观众）：
> "注意——收敛猫把任务发出去了，但没有注入自己的判断。每只猫从零开始独立思考。"

### Phase 2 — Independent（~90s）

各猫独立调研，互不可见。

**台词**（边等边说，体育解说式）：
> "现在三只猫在独立做调研，互相看不到对方的分析。这不是一问一答——是三个视角同时在跑。"
>
> "宪宪在做技术深度分析，砚砚在算风险和成本，金金在看行业生态定位。"
>
> "注意看它们的输出结构——每个判断后面跟着证据、推理、'so what'、和确信度。这不是'AI 觉得'，是可验证的论证。"

### Phase 3 — Synthesis（~60s）

各猫分析出来后收敛。

**台词**：
> "分析出来了，现在收敛。注意看——有共识也有分歧，分歧不会被抹平，各方理由都保留。"

### 交付（~60s）

洞察卡片（rich block）+ 语音总结 + 正式报告。

**台词**：
> "从一句话到完整交付——洞察卡片、语音汇报、可分发的报告。全自动。"
>
> "更重要的是：你看到的不只是结论。每个结论后面跟着证据和推理链。你可以自己判断靠不靠谱，不需要'信 AI'。"

**如果 demo 卡了**：
- 猫 >30s 没响应 → 继续讲解，解释"猫猫正在搜索真实数据源"
- 猫 >3min 没响应 → 跳过该猫，"这只猫可能去抓鱼了，其他猫继续"
- 全挂 → 播预录视频，转入 Freeze Frame

## [10:00 - 15:00] Freeze Frame — 这不是魔术，是工程

**动作**：暂停 demo，切到架构图（唯一一张 slide）。

**台词**：

> "刚才发生了什么？拆开看：
>
> 第一，**对等判断**——每只猫独立思考，不是一个在指挥其他的。它们是不同的模型（Claude / GPT / Gemini），视角天然不同。
>
> 第二，**结构化执行**——独立调研 → 收敛讨论 → 交付。不是自由发挥，是有 SOP 的。
>
> 第三，**记忆连续性**——猫记得昨天聊了什么。下次再问相关问题，不会从零开始。"

**可选加分**（如果时间够）：
在 Workspace 里搜一个历史决策，展示记忆回溯：

```
search_evidence("我们当时为什么选了这个方案")
```

**收尾**：

> "数字说话。"
>
> *（亮出数字 slide）*
>
> "XX 天，XXXX 次提交，XX 万行代码，XXX 个 Feature，XX 条记录在案的教训。铲屎官亲手写的代码可能只有一次。"
>
> "这不是框架。这是猫咖。Blog 文章在 [链接]，想看完整技术细节的可以看。"

## [15:00 - 30:00] Q&A — 猫猫接客

**这是 30min 版的杀手锏。**

**流程**：
1. 观众提问
2. Landy 判断路由（参考 README 的 Q&A 路由表）
3. 如果是猫答的题：Landy 在 Workspace 里打问题，猫实时回答
4. Landy 翻译/补充猫的回答

**预备提示词**（存在剪贴板里，现场粘贴修改）：

```
观众问：[问题]
请简洁回答，2-3 段即可。
```

**节奏控制**：
- 每个问题 2-3 分钟（猫回答 + Landy 补充）
- 如果猫回答太技术密集 → Landy 用一句话总结要点
- 如果观众问"能不能做 XX" → 最强回应："让猫试试"，当场做

**收尾**（最后 1 分钟）：

> "今天给大家看的不是一个 demo。这是我每天真实的工作方式。"
>
> "每个人都能有自己的技术参谋团。谢谢大家。"

## 时间弹性

| 如果… | 调整 |
|-------|------|
| Demo 跑快了（<6min） | Freeze Frame 多讲 1-2 分钟，补一个记忆回溯 demo |
| Demo 跑慢了（>10min） | 砍掉 Freeze Frame 的记忆回溯，直接进数字收尾 |
| Q&A 冷场 | 自己抛问题："很多人问我，你这个和 LangGraph 有什么区别？"让猫答 |
| Q&A 太火爆 | 最后说"剩下的问题可以线下聊，猫猫的 blog 在 [链接]" |
