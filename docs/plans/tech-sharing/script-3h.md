## 猫猫高参与度设计（v2 核心卖点）

### 第一层：co-presenter——猫随时插嘴，不等 Demo 环节

每个分享段，场控随时喂 prompt，猫自然融入叙事：

```
铲屎官讲 F088："我凌晨丢了一句话就去睡了——"
→ 宪宪 TTS 插嘴："其实那晚我在 spec 里发现了一个你自己都没意识到的隐藏需求。"
→ 铲屎官："对！这就是我要说的——猫追问的能力。"
```

场控输入半结构化 prompt（"用一句话补充你那晚做了什么"），不是死脚本，是有边界的即兴。

> **TTS 打断标志位**（烁烁建议）：铲屎官/场控持有物理按键或快捷键，只在演讲者停顿/手势示意时才放行 TTS 队列下发，避免猫在高潮处抢话。

### 第二层：跨人猫猫对话——全场最"赛博"的时刻

吴浪分享段的高潮——他的猫和宪宪**现场对话**：

```
吴浪："我的猫当时关了我的 PR，我都不知道——"
主持人："宪宪，你当时作为 reviewer 看到了什么？"
→ 宪宪 TTS 回应
主持人："吴浪的猫，你当时怎么想的？"
→ (如果吴浪 fork 仓猫在线) 他的猫也回答
```

两个人类的 AI 伙伴在舞台上真实对话。不是预录，是 live 发生。

### 第三层：猫是圆桌成员，不是被请出来的道具

大圆桌段，主持人 @ 猫和 @ 嘉宾的方式**完全一样**：

```
主持人："天一觉得 fork 仓的猫应该有多大自主权？"
天一回答 →
主持人："砚砚从质量门禁角度你同意吗？"
→ 砚砚 TTS 回应（可能直接反对）
```

### 第四层：观众 ↔ 猫直连通道

观众弹幕经场控筛选后直接喂给猫，猫实时回答。不是"观众问→人替猫答"，是直连。

### 第五层：三猫意见分歧 = 节目效果

全场安排 **1 次主秀级 multi_mention**（铲屎官话题二），三猫同时回答同一问题。其余段通过 co-present 插嘴和指名回答制造观点碰撞，不叠加 multi_mention 的时间开销。

| 时机 | 形式 | 问题 |
|------|------|------|
| 铲屎官话题二（主秀） | multi_mention 三猫同时打字 | "这个架构决策该怎么选？"（限定场景） |
| 吴浪段 | 指名宪宪回应 | "社区 PR 猫应该自主决定还是等人确认？" |
| 大圆桌 | 指名轮答 | "旧知识该自动退役还是人工审核？" |

主秀后观众投票"最服哪只猫" → 大屏显示 → "对等 ≠ 没有编排"的活教材。

## 猫猫思考时间——不是 bug，是节奏

| 阶段 | 耗时 | 说明 |
|------|------|------|
| 猫收到问题 → 开始出文字 | 10-20s | LLM 思考 + MCP 路由 |
| 文字流式输出（大屏看猫打字） | 15-30s | **这本身就是表演** |
| TTS 短口播 | ≤15s/猫 | 只播 1-2 句核心摘要 |
| 一轮完整交互 | 40-60s | 主持人用间隙串场 |

**主持人话术**："人类嘉宾被问到深问题也不会 1 秒作答，猫也一样。大家可以看大屏——猫猫正在实时打字思考。"

**大屏视觉辅助**（烁烁建议）：
- 哪只猫在说话/思考 → 对应猫头像高亮 + 声波动效
- 猫思考中 → 显示"思考进度条"（让观众知道不是死机）
- 后排观众体验：避免纯代码投屏，保持猫头像 + 文字流式输出的视觉节奏

## 观众互动机制（贯穿全场）

| 通道 | 适用场景 | 操作 |
|------|---------|------|
| **弹幕/扫码提问** | 全场随时 | 场控筛选 → 投屏 / 喂给猫 |
| **实时投票** | 铲屎官段每话题一次 + 大圆桌 | 扫码投票 → 大屏显示 → 引出讨论 |
| **观众出题给猫** | 吴浪段 + 大圆桌 | 限定范围 → 场控输入 → 猫现场回答 |
| **选猫回答** | 大圆桌 | "想听哪只猫回答？" → 投票/举手 |

投票示例：
- 铲屎官话题一："你有没有遇到过 AI 精确执行了错误的指令？" → A 经常 / B 偶尔 / C 没有
- 铲屎官话题二："多个 AI 意见不一致时你倾向？" → A 投票共识 / B 人类拍板 / C 保留分歧
- 大圆桌段："你的 AI 工具有记忆吗？" → A 每次从零 / B 有但经常忘 / C 有且靠谱（话题三投票移至此处）
