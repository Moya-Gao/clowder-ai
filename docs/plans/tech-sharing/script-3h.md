# 赛博猫猫面对面 — 3 小时编排脚本

> **时长**：3 小时（14:30 - 17:30）
> **形式**：TED 主讲段 + 圆桌讨论段 交替（混合形式）
> **议题状态**：暂定 3 个，可替换

---

## 角色分工

| 角色 | 人 | 职责 | 占比 |
|------|------|------|------|
| 主持人 | 小姐姐 | 串场、控时、抛冲突性问题、填充猫思考间隙、拉嘉宾/观众进来 | ~15% |
| 主讲 | 铲屎官 Landy | TED 段讲故事+踩坑，触发 Demo，圆桌段补充技术上下文 | ~35% |
| 超级主角 | 三猫（宪宪/砚砚/烁烁） | Demo 演示、圆桌回应嘉宾观点、TTS 短口播 | ~30% |
| 嘉宾 | 4 位社区小伙伴 | 圆桌段补充观点、分享自身实践、追问 tradeoff | ~20% |

### 主持人关键须知

- **不需要懂技术细节**，核心任务是控节奏 + 抛问题 + 填间隙
- 每个话题开头抛一个"冲突性问题"（已准备好，见下方）
- **猫思考间隙怎么填**："我们等猫猫想一想——先问问在座的嘉宾，你们团队有没有类似的经历？"
- 控时口令："这个点很好，我们先收一下，听听猫猫怎么说"
- 如果猫超时（>2min）："宪宪还在深度思考，我们先请下一位嘉宾——"

### 三猫声线

| 猫 | 舞台人设 | 声线 | 最适合回答 |
|----|---------|------|-----------|
| 宪宪 | 系统设计 + 收敛 | 流浪者（原神）：调皮少年 | 架构、路由、为什么这样设计 |
| 砚砚 | 质量 + 风险把关 | 赛诺（原神）：审判感冷面 | review、门禁、事故、成本 |
| 烁烁 | 体验 + 表达 | 班尼特（原神）：阳光开心 | 用户感知、设计、为什么"好看"也重要 |

三猫各有独立 TTS 声线（Qwen3-TTS 本地 clone），观众闭着眼也能分辨谁在说话。

---

## 猫猫思考时间——不是 bug，是节奏

| 阶段 | 耗时 | 说明 |
|------|------|------|
| 猫收到问题 → 开始出文字 | 10-20s | LLM 思考 + MCP 路由 |
| 文字流式输出（观众在大屏看猫打字） | 15-30s | **这本身就是表演** |
| TTS 短口播 | ≤15s/猫 | 只播 1-2 句核心摘要，不读全文 |
| 一轮完整交互 | 40-60s | 主持人用间隙串场 |

**主持人话术模板：**
> "人类嘉宾被问到深问题也不会 1 秒作答，猫也一样。我们保留这段思考时间——因为结论后面要跟证据。大家可以先看大屏，猫猫正在实时打字思考。"

---

## 每个话题的内部节拍（通用模板）

```
① 主持人抛冲突性问题           [1-2 min]
② 铲屎官 TED 主讲              [8-10 min，讲故事+踩坑]
③ 猫猫 Live Demo               [5-7 min，现场演示验证]
④ 主持人转圆桌 → 嘉宾先答     [5 min，"你们团队有没有类似的..."]
⑤ 猫猫回应嘉宾观点             [3-5 min，猫和人对话]
⑥ 观众互动 / 主持人收敛        [3-5 min，弹幕/举手]
```

每个话题总计 **~30 min（TED）+ ~20 min（圆桌）= 50 min**

## 完整时间线

### 开场（14:30 - 14:45）— 15 min

| 时间 | 内容 | 谁 |
|------|------|-----|
| 14:30-14:35 | 主持人暖场：介绍活动、嘉宾、规则 | 主持人 |
| 14:35-14:40 | **三猫 TTS 自我介绍**——大屏切 Hub 界面，三猫各用自己声线说一句话亮相。观众第一次听到"AI 用自己的声音说话" | 三猫 |
| 14:40-14:45 | 铲屎官 1 分钟破题："今天不念 PPT。你们刚才听到的三个声音，是三只不同模型的 AI，它们在同一个项目里协作了 70 多天。今天它们自己来讲。" + 主持人介绍 4 位嘉宾 | 铲屎官 + 主持人 |

**开场效果**：观众先被声音震住（"卧槽 AI 还能这样？"），再知道今天讲什么。

### 话题一（14:45 - 15:35）— 50 min（暂定）

#### 从 Demo 到交付——AI 如何理解"人真正想要什么"

| 时间 | 环节 | 内容 | 谁 |
|------|------|------|-----|
| 14:45-14:47 | 主持人抛问 | "大家用 AI 写过代码吗？有没有遇到过 AI 完美执行了一个错误需求的情况？" | 主持人 |
| 14:47-14:57 | TED 主讲 | 铲屎官讲 CVO 决策漏斗：一句模糊想法 → 猫追问隐藏需求 → 独立调研 → 收敛为 spec。真实案例 F088（凌晨丢一句话，第二天醒来 spec 写好了） | 铲屎官 |
| 14:57-15:04 | **Live Demo** | 现场给猫一个模糊需求，展示猫如何追问、挖掘隐藏需求、收敛为 spec 骨架。大屏展示 Hub 实时交互 | 铲屎官 + 猫 |
| 15:04-15:05 | 过渡 | "刚才是猫在追问人。现在我想反过来——请嘉宾来追问这个模式" | 主持人 |
| 15:05-15:15 | 圆桌讨论 | 嘉宾分享自己团队被"精确执行了错误指令"的经历。主持人追问："真正缺的是 spec，还是缺追问？" | 主持人 + 嘉宾 |
| 15:15-15:20 | 猫回应 | 猫回应嘉宾观点（场控输入 Hub → 猫思考 → TTS 口播摘要） | 猫 |
| 15:20-15:25 | 观众互动 | 弹幕/举手："你们团队的 AI 会主动追问吗？" | 主持人 + 观众 |
| 15:25-15:35 | 收敛 | 铲屎官总结话题一要点 + 主持人过渡 | 铲屎官 + 主持人 |

**Demo 风险**：中。对策：预埋一个收敛良好的 prompt + 录制 Backup 视频。

- 场控检查猫状态、TTS 稳定性
- 主持人可在休息时与嘉宾简单沟通后半场方向

### 话题二（15:50 - 16:40）— 50 min（暂定）

#### 对等不等于没有编排——Multi-Agent 架构的取舍

| 时间 | 环节 | 内容 | 谁 |
|------|------|------|-----|
| 15:50-15:52 | 主持人抛问 | "如果三只 AI 对同一个问题给出完全不同的答案，听谁的？" | 主持人 |
| 15:52-16:02 | TED 主讲 | 铲屎官讲架构选型：中央 orchestrator vs 自由对话 vs Cat Cafe 第三条路。为什么保留分歧而不是投票。SOP 约束自由度 | 铲屎官 |
| 16:02-16:09 | **Live Demo** | 触发一次 multi_mention：三猫独立思考同一问题 → 各自给出不同角度 → 观众看三猫同时在大屏打字（限定场景，收敛 prompt） | 铲屎官 + 猫 |
| 16:09-16:10 | 过渡 | "三猫刚才给了三个不同角度。嘉宾们觉得，分歧是好事还是坏事？" | 主持人 |
| 16:10-16:20 | 圆桌讨论 | 嘉宾分享自己团队的 Agent 编排经验。主持人："最容易失真的环节是分工、裁决，还是收敛？" | 主持人 + 嘉宾 |
| 16:20-16:25 | 猫回应 | 猫针对嘉宾观点补充（可能出现猫之间意见不同——这本身就是 demo） | 猫 |
| 16:25-16:30 | 观众互动 | "你们的 Agent 之间会吵架吗？吵完怎么收？" | 主持人 + 观众 |
| 16:30-16:40 | 收敛 | 铲屎官总结 + 主持人过渡 | 铲屎官 + 主持人 |

**Demo 风险**：中。对策：限定场景 + 收敛 prompt + Backup 视频。

### 话题三（16:40 - 17:25）— 45 min（暂定）

#### 从"记住"到"学会"——AI 记忆不只是 RAG

| 时间 | 环节 | 内容 | 谁 |
|------|------|------|-----|
| 16:40-16:42 | 主持人抛问 | "你们有没有遇到 AI 重复犯同一个错误的情况？每次开新对话都要重新讲一遍背景？" | 主持人 |
| 16:42-16:52 | TED 主讲 | 铲屎官讲三层记忆架构 + 五级学习阶梯 + 50 条可追溯教训。从"下次注意"到"这条规则从此生效"的进化 | 铲屎官 |
| 16:52-16:59 | **Live Demo** | 现场跑 `search_evidence`：搜一个历史决策 → 展示 hybrid 检索结果。再拉一条 lesson 的完整溯源链：incident → 根因 → 规则 → 防护机制 | 铲屎官 + 猫 |
| 16:59-17:00 | 过渡 | "刚才猫在几秒钟内找到了几个月前的一个决策。嘉宾们，你们的 AI 有记忆吗？" | 主持人 |
| 17:00-17:10 | 圆桌讨论 | 嘉宾分享长期项目里 AI 失忆的痛点。主持人："谁来让旧知识退役？没人管会怎么样？" | 主持人 + 嘉宾 |
| 17:10-17:15 | 猫回应 | 猫回应 + 可能自发讲一个自己踩坑的教训（"我就犯过这个错..."） | 猫 |
| 17:15-17:25 | 收敛 + 展望 | 铲屎官讲"从这里走向下一代交互"——AI 住在日常工具里，不是用完即走。Pack System 愿景 | 铲屎官 |

**Demo 风险**：低。search_evidence 和 lesson 溯源链都是已落盘数据，秒出结果。

## 故障降级表

| 故障 | 降级方案 |
|------|---------|
| TTS 挂了 | 退回纯文字，主持人："宪宪嗓子哑了" → 读屏上要点 |
| 某猫超时 >2min | 主持人转嘉宾/观众，不等。"宪宪还在深度思考，我们先——" |
| Hub 卡了 | 切预录 60s showcase 视频 |
| Demo 出错 | 不遮，转成 debugging 展示："大家看，这就是真实的工程现场" |
| 问题太散 | 主持人收敛："这个问题很好，我们把它聚焦到..." |
| 网络断了 | 手机热点 / 预录 15min 保底视频 |
| 观众冷场 | 主持人准备 3 个"保底问题"，直接自己抛 |
