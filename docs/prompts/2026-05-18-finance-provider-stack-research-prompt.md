# Research Brief: 个人投资学习场景的金融数据 Provider Stack 选型

## 1. Problem Frame（任务边界）

**我们要回答的问题**：
一个非金融专业的个人长期投资者（FIRE 规划中），用 AI agent 团队（Claude Code + MCP 协议）辅助投资学习。目前 agent 无法获取当前金融数据（WebFetch 对金融网站大量 403，模型知识库过时）。我们需要选出一套 provider stack——哪些数据源做真相源，哪些开源工具做接入层，怎样组合成可被 AI agent 调用的个人投资学习基建。

**非目标（明确排除）**：
- 不做交易系统（不需要下单、撮合、实时 tick 数据）
- 不做机构级 Bloomberg/Reuters 终端替代品
- 不做量化回测框架（只需要简单历史收益率查询）
- 不自建数据源或爬虫（只用现成 API/SDK/MCP）
- 不需要分钟级或更高频率数据——日线级足够

**为什么现在要研究这个**：
用户在进行 FIRE 资产配置决策（E1 ESOP 评估、Bogleheads 组合设计、中美宏观环境判断），但我们连"当前国债收益率是多少""纳指当前 P/E 多少""OpenAI 最新 ARR"这些基本问题都无法可靠回答。信息基础设施缺失是当前最大阻塞。

## 2. Current Hypotheses（我们的假设）

我们目前的判断是：
1. **Yahoo Finance (yfinance)** 是美股/全球行情的最佳免费入口，覆盖股价+基本面+ETF
2. **Tushare Pro**（~500 元/年）是 A 股最适合个人使用的结构化数据源
3. **FRED** 是美国宏观数据的官方免费标准
4. **中国宏观数据**（人民银行利率、CPI、PMI）可能没有一个对标 FRED 的统一入口，可能需要多源拼接
5. **MCP 生态**已有一些 finance server（如 Alex2Yang97/yahoo-finance-mcp，286 stars），可能可以直接使用
6. **国内基金/ETF/QDII 数据**可能是最难获取的（天天基金？AKShare？没有明确最佳方案）
7. **私有公司估值**（OpenAI/Anthropic/字节）不可能有结构化 API，只能做新闻证据链追踪

**证据缺口**：
- yfinance 对中国市场（A 股 .SS/.SZ 后缀、港股 .HK）的实际覆盖度和可靠性如何？
- Tushare Pro 和 AKShare 的真实对比（稳定性、字段覆盖、社区活跃度）？
- 中国宏观数据的最佳免费/低成本入口到底是什么？
- 现有 finance MCP server 的实际质量如何（不只看 stars，看字段正确性、错误处理、维护状态）？
- QDII 基金的净值/费率/持仓数据从哪获取？
- 有没有我们作为金融外行完全没想到的重要数据类别？

> ⚠️ 这些是我们的初步假设，不是结论。请在调研中验证或推翻它们。

## 3. Disconfirm First（先找反例）

在给出支持性证据之前，请优先：
1. **寻找 yfinance/Tushare/AKShare 的已知问题**——rate limit、数据错误、突然下线、ToS 违规等案例
2. **寻找有人用不同方案（不是 Yahoo+Tushare）成功搭建个人金融数据基建的案例**——也许有更好的路径
3. **识别 finance MCP server 的常见坑**——字段口径不一致、复权处理错误、时区 bug、非官方 API 随时断等
4. **检验"MCP 生态已成熟到可直接用"的假设**——如果现有 MCP 都是 demo 级别，那"拿来就用"的策略就不成立
5. **检验"≤500 元/年预算够用"的假设**——如果关键数据源都需要付费，预算可能不够

## 4. Source Mix Quota（来源配额）

请确保来源覆盖以下类型：
- [ ] **官方文档**：yfinance/Tushare/AKShare/FRED 的官方文档和 changelog
- [ ] **工程博客/实录**：个人开发者搭建金融数据管道的一手经验（优先中文社区，如掘金/知乎/V2EX）
- [ ] **开源项目**：GitHub 上 finance MCP / CLI / SDK 项目的 README、issue 和最近 commit
- [ ] **金融数据行业报告**：数据提供商的功能对比、定价信息
- [ ] **失败案例**：开发者遇到的数据源问题（API 变更、反爬升级、数据质量问题等）

## 5. Local Constraints（我们的约束）

调研结论必须在以下约束下可行：
- **MCP 协议兼容**：最终工具必须能被 Claude Code 通过 MCP 调用（直接 MCP server 或 CLI/Python SDK 包装成 MCP）
- **个人非商业**：所有数据源必须允许个人非商业使用
- **预算 ≤500 元/年**：接受免费+一个付费源的组合；接受日线延迟数据
- **技术栈**：Node.js/TypeScript 优先，Python 可接受（家里已有 Python bridge 模式）
- **中国市场是硬需求**：只覆盖美股的方案不合格
- **新闻只索引不全文**：不绕 paywall，只存标题/摘要/链接/时间/来源
- **长期投资者视角**：不需要盘中实时数据、不需要 Level 2 行情、不需要期权定价
- **macOS 环境**：工具必须能在 macOS 上运行

## 7. Decision Interface（决策映射）

对于每个调研发现，请标注建议的行动：
- **采纳**：证据充分，建议直接集成到工具链
- **试点**：有潜力但需要先跑 spike 验证（API 实际可用性/数据质量）
- **搁置**：当前不适用或证据不足，记录但不行动

最终输出应能直接转化为工程任务：
- 哪些工具可以今天就 `npx`/`uvx`/`pip install` 跑起来？
- 哪些需要写薄包装层？大约多少工作量？
- 哪些需要先申请 API key？流程是什么？

## 8. Risk Register（如果结论错了）

如果我们基于本次调研结论做决策，最可能出错的地方是：
1. **Yahoo Finance 被封或限制**：yfinance 依赖非官方 API，Yahoo 可能随时变更 → 缓解：必须有 fallback 源
2. **Tushare Pro 数据质量不如预期**：付费≠可靠 → 缓解：先免费试用验证核心字段
3. **MCP server 是 demo 不是生产级**：stars 多不代表字段正确 → 缓解：spike 验证核心功能
4. **中国市场数据的法律灰区**：某些数据源可能违反交易所数据再分发协议 → 缓解：仅个人使用+不公开
5. **我们漏了关键数据类别**：作为金融外行，可能有盲区 → 缓解：调研明确要求"遗漏检查"

## 附录：用户真实工作流（MVP 设计锚点）

以下是用户日常会问的问题，MVP 应能回答其中至少前三个：
1. "今天我的配置环境变了吗？"（市场快照：指数涨跌+利率变化+汇率）
2. "某个公司现在贵不贵？"（公司基本面：财报+估值+最近新闻）
3. "宏观环境影响我的 FIRE 配置吗？"（利率/CPI/汇率趋势）
4. "这条新闻值得更新学习笔记吗？"（财经新闻摘要+来源链接）
