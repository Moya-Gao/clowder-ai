## 核心观点（按原文语义整理）

1. `异构多智能体 > 同构角色扮演`
- 受访者明确认为，多智能体若非异构，容易退化为角色扮演。
- 对我们意义：和我们现有“跨模型协作”方向同频。

2. `关键瓶颈是思考与协同，不是工具数量`
- 原文强调“先思考、再协同、后调用工具”，否则会放大低质量决策。
- 对我们意义：支持我们在 review 流程里强调“争论质量”而非“调用规模”。

3. `完全去中心化未必最优，存在协调节点价值`
- 原文提出“向协调人去中心化”，即保留协调节点控制上下文分发与回合推进。
- 对我们意义：可作为我们讨论“何时引入轻量协调层”的外部参考。

4. `行业趋势判断：模型层将趋同，Agent 层成为差异化主战场`
- 原文将基础模型定位为长期底座，但认为应用层 Agent 协同是主要创新空间。
- 对我们意义：和我们近期 multi-agent 路线讨论一致。

## 对我们当前方案的映射

1. 同向点
- 异构协作价值：与我们现有 A2A 认知一致。
- 协同优先：与我们“先收敛思路再执行”的实践一致。

2. 差异点
- 文章更强调“协调节点”。
- 我们当前是“去中心化 + 人在环权限棘轮”，协调机制主要通过流程与规则而非单编排器实现。

3. 可吸收点（低风险）
- 引入”回合收敛信号”标准：何时继续讨论、何时转执行。具体实现可以是在 `discussion-convergence` skill 里加一条触发条件，而不是另起炉灶。
- 对跨猫讨论增加”冲突识别 + 结论冻结”格式化输出。

**重要区别：我们的”反顺从”更激进**

李笛文章是从**实验观察**角度描述问题（弱模型说服强模型导致结果变差）。我们是从**工程规则**角度主动防御：
- 明确禁止 “不 blocking” 式的甩锅措辞
- 要求分歧必须走到技术论证，解决不了才升级铲屎官裁决
- 从 review 规范倒逼”真正的多视角争论”，而不只是等问题自然涌现

## 新增 Open Questions（布偶猫/Sonnet 补充 2026-02-26）

4. **团子的”异构”是真异构还是同模型角色扮演？**
   文章通篇强调”异构”价值，但产品描述（6 个律师角色在同一框架内协作）更像是”同一底层模型扮演不同角色”。如果属实，那李笛批评的”同构角色扮演”恰好是他自己在做的事。
   - 验证方式：查看团子/Nextie 的技术文档或 GitHub，确认是否有多模型混用的证据
   - 影响：如果确认是单模型，文章关于”异构”的论证力度要大打折扣；如果是真异构，值得进一步了解他们的跨模型通信方案

5. **”弱模型说服强模型”的实验能否复现到我们的 A2A 场景？**
   文章提到这个实验结论，但我们没有在 Cat Cafe 框架下验证过类似情况。一个可控实验：让暹罗猫（能力边界已知）和布偶猫讨论一个有明确答案的技术问题，看反顺从规则能否有效防止答案劣化。
