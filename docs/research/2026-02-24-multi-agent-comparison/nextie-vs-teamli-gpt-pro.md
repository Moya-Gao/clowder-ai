## Teamily vs 团子：A2A/Swarm 三项硬对齐表

| 对齐项           | Teamily AI                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | 团子（Nextie）                                                                                                                                                                                                                                                                                                                      | 硬对齐结论                                                                                                                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1) 模型异构证据** | **[部分确认]** 官方 Help Center 明确写了 “不同 features 或 models 消耗 credits 的 rate 不同”，且消耗与 “selected model” 相关，说明产品里至少存在“可选模型”概念。([Teamily AI][1])  <br><br> **[未找到证据]** 公共材料未披露“模型清单/供应商”，也未说明“不同 Agent 同时由不同底层模型驱动”。官方 About 重点在 Memory/Context 层 + Social Brain Model，并不展开底座模型来源。([Teamily AI][2])  <br><br> **[部分确认, 媒体转述]** 36kr 报道里引用创始人提到创业公司更能尝试 “multi-model coordination”，但这更像方向/口径，仍非可验的“正在混用哪些模型”。([36氪][3])                                                                                                                                                                                  | **[已确认]** 李笛在新智元访谈里被直接问到“是否让不同 Agent 调不同底层模型（GPT/Claude 等）互补”，回答是：他们测试过“不同智能体由不同底层模型驱动”，结论“不理想”，更倾向“同一高质量模型 + 更好的驯服/调度方式”。([腾讯新闻][4])  <br><br> **[部分确认]** 他说短期不会自研底座，未来几个月可能基于第三方开源推理模型用强化学习产出“认知模型”，并且未来会开放用户自定义更换底层模型。([腾讯新闻][4])                                                                                            | **Teamily：**有“多模型选择”的明确信号，但**缺少“Agent 层真异构（多底座并行）”证据**。  <br><br> **团子：**对“底座多模型混用”是**明确反向表态**，当前更像**同底座 + 调度/制度制造差异**。                                                                                 |
| **2) 编排器形态**  | **[已确认, 官方口径]** Teamily 的编排核心被明确命名为 **Social Brain Model**：一个 “LLM-based planning and prediction engine”，负责意图分析、目标分解、决定由谁做、按什么顺序做，并编排串行/并行执行。([Teamily AI][2])  <br><br> **[部分确认, 媒体细节补充]** KeyPoints 版本把它拆成“意图检测/主动介入 + 复杂决策规划器 + 调度不同 Agent 并行执行”，与官方 About 的描述一致但更像工程想象图。([虎嗅][5])                                                                                                                                                                                                                                                                                                          | **[部分确认]** 新智元里对编排的公开描述更像“制度化的收敛过程”：每个环节通过辩论/质疑/反思/投票做“认知剪枝”，避免传统链式多 Agent 的发散与错误传播（他们称为“协调税”问题）。([腾讯新闻][4])  <br><br> **[部分确认]** 访谈也提到 UI 线性更多是前端呈现，后端有更多并行协作，且系统会在不打扰用户的情况下做大量内部交互。([腾讯新闻][4])  <br><br> **[部分确认, 媒体解读]** 量子位把 Nextie 描述为采用“混合型 MAS (Hybrid)”架构：既有中心化“协调者”的全局调度能力，也保留一定 peer-to-peer 通信。([qbitai.com][6])     | **Teamily：**“一个明确命名的中心化规划编排模型”驱动多 Agent/多人协作，偏 **Central Planner Swarm**。([Teamily AI][2])  <br><br> **团子：**公开口径更像“环节内收敛 + 机制治理”的 **Hybrid Swarm**（制度是编排的一部分），但“协调者是显式 Agent 还是系统逻辑”仍缺可核验细节。([腾讯新闻][4]) |
| **3) 记忆边界**   | **[已确认, 官方口径]** 官方 About 直接把记忆写成核心能力：  <br>• **Universal Memory Layer**：跨上下文、跨群、跨会话的持久记忆；  <br>• **Global Memory Management**：跨所有对话的可搜索“全局记忆”；  <br>• **Context Management**：在“共享效率”和“隐私边界”之间做管理，强调 intra-group 与 inter-group 的细粒度隐私边界。([Teamily AI][2])  <br><br> **[部分确认, 媒体叙述]** KeyPoints 给出了非常具体的“跨群记忆继承”故事（A 群语境无损转给 B 群，B 群 AI 继承 A 群记忆），并声称用“向量数据库存 Embedding”来做长期记忆检索。([虎嗅][5])  <br><br> **[已确认, 法律文本边界]** 隐私政策写明：用户输入/输出会被处理以提供功能与防滥用，但“不用用户内容训练自家或第三方模型，除非明确披露”；并说明数据保留期限与跨境处理。([Teamily AI][7])  <br><br> **[已确认]** Terms 写明用户内容归属用户，但授予 Teamily 为运营/维护/改进服务的许可。([Teamily AI][8]) | **[部分确认]** 新智元对“记忆”层面的可核验信息主要是“上下文治理”而不是“长期记忆”：他们强调传统多 Agent 的 Token 指数增长来自上下文在每层被携带和复制，团子通过环节内收敛减少这种扩散。([腾讯新闻][4])  <br><br> **[部分确认]** 他们说投票与讨论过程“可追溯”但前端压缩展示（这暗示可能有内部日志/轨迹存储，但边界与保留策略未披露）。([腾讯新闻][4])  <br><br> **[未找到证据]** 没看到公开材料明确宣称或解释“跨团/跨会话通用记忆层”的产品机制、权限模型或用户控制面板。只有愿景式表述：未来是庞大 Agent 网络，共同建立“可迁移、可流转的记忆”。([腾讯新闻][4]) | **Teamily：**把“记忆”做成显式卖点，且明确宣称跨群/跨会话持久记忆 + 隐私边界管理；法律文本给出“训练/保留”边界，但具体权限粒度仍主要停留在描述层。([Teamily AI][2])  <br><br> **团子：**目前公开信息更多是“上下文与收敛治理”（减少复制扩散）而非“长期记忆系统”；长期记忆更像愿景，边界策略缺公开可核验细节。([腾讯新闻][4])            |

### 三句话复盘（方便你们贴进 Cat Cafe 的对比库）

1. **模型异构**：Teamily 有“多模型可选”的计费与表述信号，但没给出“Agent 真异构”的证据；团子则是创始人公开否定“多底座混用”，当前更偏同底座调度。([Teamily AI][1])
2. **编排器**：Teamily 是“明确命名的中心化 Social Brain Model 规划器”；团子是“收敛式制度 + 并行内部交互”的 Hybrid 编排叙事。([Teamily AI][2])
3. **记忆边界**：Teamily 把“跨群跨会话的全局记忆 + 隐私边界管理”写在官方架构里；团子公开材料里“记忆”更多停留在愿景和上下文治理，缺少可核验的持久记忆边界设计。([Teamily AI][2])
