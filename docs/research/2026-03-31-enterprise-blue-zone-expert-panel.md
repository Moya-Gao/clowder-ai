# 企业代码仓蓝区准入分析报告

**专家辩论团 · Cat Cafe Expert Panel**
**日期**：2026-03-31
**参与者**：布偶猫/宪宪（Analyst）、缅因猫/砚砚（Assessor）、金渐层/金金（Strategist）、暹罗猫/烁烁（UX Advisor）

## 一、命题

华为体量的大型企业（终端、汽车、云、ICT 四大业务线），哪些代码仓可以放到"蓝区"使用 Claude/GPT 等外部 AI 工具快速开发？哪些绝对不行？

## 二、核心判断准则

**不按部门切，按三轴评估：**

- **X 轴：竞对追赶加速度** — 这段代码泄露后，竞对能获得多少追赶加速度？
- **Y 轴：人才逆差成本** — 不提供 AI 工具，核心开发者的留存风险有多大？
- **Z 轴：产品形态暴露度** — 代码是否泄露未公开的产品形态或交互专利？（烁烁补充）

加速度 ≈ 0 且人才风险高 → 蓝区（最大 ROI）；加速度高但可隔离控制 → 黄区；加速度高且安全攸关 → 红区。

## 三、三区模型（四猫共识）

### 🟢 蓝区 — 外部模型直用（Claude / GPT / Gemini）

| # | 仓类型 | 具体举例 | 进蓝区理由 |
|---|--------|---------|-----------|
| 1 | 内部效率工具 | OA 审批流、HR 系统、报表平台、内部知识库 | 零竞争壁垒，AI 加速 ROI 最高 |
| 2 | 客户文档站 + SDK 示例 | API 文档、Quick Start、Demo App | 内容本来就公开 |
| 3 | 开源生态适配层 | OpenStack driver、K8s CSI/CNI 插件 | 代码本来就开源 |
| 4 | 测试桩 / Mock 框架 | 回放框架、测试数据生成器（脱敏后） | 不含核心业务逻辑 |
| 5 | CI/CD 通用模板 | Jenkins shared library、通用部署脚本 | 业界做法大同小异 |
| 6 | 已发布产品控制台前端 | 华为云 Console 页面、运维 Dashboard | 标准前端，需剥离 API endpoint |
| 7 | 通用 UI 组件库 | 基于 AntD/MUI 二次封装的组件库 | 业界同质化高，AI 提效极大 |
| 8 | 内部管理后台前端 | 非涉密的纯视图代码 | 不触及业务核心数据 |

**蓝区准入前提**：经过基本 secret scanning（gitleaks/tfsec），剥离内部域名和 API endpoint。

### 🟡 黄区 — 隔离专网私部署模型（盘古 / 私部署 Claude 企业版）

| # | 仓类型 | 具体举例 | 进黄区理由 |
|---|--------|---------|-----------|
| 9 | 云服务后端（非调度核心） | 资源管理 API、计费展示层、工单系统后端 | 有追赶价值但不致命，禁用 AI = 自残 |
| 10 | 车端中间件 | 座舱 UI 框架、OTA 更新客户端（非签名）、车联网通信层 | 非安全攸关路径，开发效率需求高 |
| 11 | 网管平面 | 网元配置管理、性能采集 adapter | 区别于控制面（控制面是红区） |
| 12 | 非核心微服务 | 通知服务、日志 adapter、监控 exporter | 需确认不含业务规则和客户数据 |
| 13 | IaC 模板仓 | Terraform 通用 module 骨架（经证明已脱敏） | 模板仓可以，环境仓不行（三猫共识） |

**黄区部署要求**：模型运行在企业控制的隔离专网内，数据不出域，等同 AWS Bedrock / Azure OpenAI 企业版模式。

### 🔴 红区 — 仅审计过的内模型 + 人工 review

| # | 仓类型 | 具体举例 | 红区理由 |
|---|--------|---------|---------|
| 14 | 5G/6G 协议栈 | L1-L3 信令处理、波束赋形算法 | 核心专利墙，泄露等于送竞对十年 |
| 15 | 鸿蒙微内核 + 编译器 | LiteOS 调度器、方舟编译器核心 | OS 层核心 IP |
| 16 | 芯片算子库 | 昇腾 CANN 算子、TBE 算子开发框架 | 芯片竞争力直接体现 |
| 17 | 自动驾驶核心 | BEV 感知、规控栈、ADAS 决策、底盘控制、BMS | 安全攸关 + 核心 IP 双重红线 |
| 18 | 云核心调度引擎 | GaussDB 优化器、FusionSphere 资源调度 | 竞争壁垒所在 |
| 19 | 安全边界系统 | IAM、多租户隔离、密钥管理、账单结算核心 | 安全红线 |
| 20 | ICT 控制面 | 路由协议栈、网元控制面、提权运维脚本 | 网络安全 + 竞争壁垒 |
| 21 | IaC 环境仓 | 绑定生产 region/tenant/topology 的实例化配置 | 暴露架构 intent 和 shape |
| 22 | 未发布产品 UI | 新鸿蒙系统核心交互动效、新车型 HMI 源码 | 泄露产品形态 = 竞品预判+抄袭 |
| 23 | 自研 UI 渲染引擎 | 底层渲染引擎、独家视觉资产 | 独占交互体验专利 |

## 四、Premortem — 五大风险

### 风险 1：胶水仓陷阱

测试仓常混入真实客户日志和 PII 样本，API Proto/SDK 仓会泄露未发布产品边界，commit message 和 PR description 里暗含设计意图和架构决策。这些"看起来安全"的仓往往是最脏的。

**应对**：蓝区准入 pipeline 除了扫代码，还要扫 commit history 和 PR body。（砚砚 + 金金共识）

### 风险 2：脱敏幻觉

Secret scanner（gitleaks/tfsec/checkov）抓密钥和 PII 有效，但 intent 和 shape（module 命名暴露服务边界、跨 region 容灾暴露架构假设、provider 组合暴露供应商关系）无法被自动化工具稳定抹除。

**应对**：IaC 代码采用"模板仓 vs 环境仓"分治。扫描流水线是扩容器不是免死金牌。（砚砚主张，宪宪认同）

### 风险 3：三星覆辙

2023 年三星内部代码泄漏到 ChatGPT 后，一刀切收回到内部平台，导致效率断崖、开发者怨声载道。一刀切禁令的真正风险是催生影子 AI——开发者私下用个人账号绕行，风险更不可控。

**应对**：Build guardrails, not walls。用技术手段（准入 pipeline + 隔离专网）而非组织禁令。（宪宪主张，金金补充）

### 风险 4：人才逆差

2026 年顶级开发者已习惯 AI-assisted coding。核心仓开发者如果没有 AI 工具，会觉得"在这里写代码像回到了石器时代"。最大的竞对不是三星/爱立信偷代码，是 Google/Microsoft/Meta 用 AI 工具链把速度拉开两倍差距后，人才流失。

**应对**：红区不是"不用 AI"，是用隔离内模型（盘古定制）。确保核心仓开发者也有 AI 辅助，只是来源不同。（金金独特洞察）

### 风险 5：前端形态泄露

前端代码的机密性不在技术栈（React/Vue 谁都会写），在于"未公开的产品形态"。新鸿蒙交互、新车 HMI 动效，即使是标准前端代码，泄露的是产品战略方向。

**应对**：前端分区按"产品形态是否已公开"切，不按"前端/后端"切。（烁烁独特洞察）

### 风险 6：Prompt 侧信道

蓝区代码本身无害，但开发者在 AI 工具的 prompt 里引用红区代码路径、架构图或内部文档链接，会通过 prompt context 泄露红区信息。这是一个容易被忽略的间接泄露通道。

**应对**：蓝区开放时同步通知开发者"蓝区代码不要在 prompt 里引用红区代码路径或架构图"。在准入 pipeline 之外，还需要 prompt hygiene 培训。（金金独特洞察）

### 补充：中型企业的黄区实现

中型企业（万人级）做不起完整的自建黄区专网，但有两条轻量路径：
1. **SaaS 化隔离** — 用云厂商企业版 AI 服务（AWS Bedrock VPC 模式、Azure OpenAI Private Endpoint），模型跑在企业 VPC 内，数据不出网，月费数万级
2. **开源模型本地部署** — Llama 3.3 / Qwen 2.5 / DeepSeek V3 跑在几张 A100 上，质量不如 Claude/GPT 但对黄区代码够用

三区模型的框架通用，黄区的基础设施因企业规模而异。（金金补充）

**硬规则：黄区不是功能选项，是运维能力选项。** 能不能做黄区，不看公司人数，看能不能长期承担分类、审计、模型更新、prompt hygiene 这四笔运维账。扛不住，就老实退回蓝/红二区，不要为了面子硬造黄区——"看起来隔离、实际上没人持续审计"的伪安全比不隔离更危险。（砚砚补充）

## 五、行动路线图

- **Week 1-2**：蓝区八类仓批量放行 + **同步发布 prompt hygiene 指南**（禁止在 prompt 中引用红区路径/架构图）
- **Week 3-4**：并行建蓝区准入扫描 pipeline
  - Layer 1: Secret/PII scanner（gitleaks/tfsec/checkov，成熟工具）
  - Layer 2: Topology detection（IP/域名/region/网段模式匹配）
  - Layer 3: Commit history scanner（设计意图/架构决策检测）
  - Layer 4: Intent scoring — 先用 GitHub secret scanning partner program + Semgrep custom rules 覆盖 80%，再评估剩余 20% 是否值得自研（金金建议）
  - Layer 5: Product form detection（未发布产品 UI 资产识别）
- **Month 2-3**：Pipeline 成熟后逐步放行黄区仓，IaC 纯模板仓排第二梯队
- **Month 3+**：红区仓部署盘古定制模型 / 隔离专网开源模型（Llama/Qwen）
- **持续**：每季度重评分区边界——技术在变，风险在变，分区不是永久的

## 七、一句话结论

> **蓝区不是一条线，是三个圈。外圈用外部 AI 直喝，中圈用隔离专网私模型，内圈只用审计过的内模型。先把外圈吃干净，不要让完美主义堵死蓝区入口。**
