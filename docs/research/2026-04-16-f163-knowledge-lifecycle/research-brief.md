# Research Brief: Knowledge Lifecycle Management for Multi-Agent Systems

## 1. Problem Frame

**我们要回答的问题**：
在一个多 AI 引擎协作系统中，随着知识（规则、教训、决策记录、偏好记忆）持续累积，如何通过分层加权、知识压缩和过期审计来维持检索信噪比？

**非目标（明确排除）**：
- 记忆的存储和检索基础设施（F102 已解决）
- 记忆的跨项目可移植性（F152 在做）
- 用户个性化的行为适配（养猫阶段，计划作为 F164 独立处理）
- RAG 系统的通用 embedding/retrieval 优化

**为什么现在要研究这个**：
F163 已立项（2026-04-15），核心假设是 4 层知识分级 + 权重乘子可以改善检索精度。但权重值是拍脑袋的，压缩和审计的具体机制也缺乏工程验证。铲屎官要求讨论→research→再回填 spec。

## 2. Current Hypotheses

我们目前的判断是：

1. **知识应该分层加权**：铁律（3.0x）> 规则（2.0x）> 参考（1.0x）> 历史（0.5x），让搜索引擎知道哪些知识更重要
2. **知识可以被压缩**：多条同根因的教训/规则可以合并为更精准的条目，减少检索噪声
3. **知识应该有生命周期**：长期未被触发的知识应该衰减、降级、最终归档
4. **知识晋升需要门禁**：新偏好的晋升路径应该是 observed → candidate → provisional → validated，防止偶然偏好变成硬规则

**证据缺口**：
- 4 层分级和权重乘子有没有业界先例？权重怎么校准？
- "知识压缩"在软件工程知识管理中有没有成熟实践？人脑的"经验→直觉"压缩过程能不能工程化？
- 知识过期的触发条件怎么定？按时间？按使用频率？按矛盾检测？
- 晋升门禁的"双证据原则"在其他系统中有没有类似设计？

## 3. Disconfirm First

在给出支持性证据之前，请优先：

1. **反对分层加权的理由**：有没有系统发现等权检索反而更好？分层加权可能带来什么负面效果（比如重要但罕见的知识被埋没）？
2. **反对知识压缩的理由**：合并规则是否可能丢失关键的上下文细节？有没有"保留所有条目但改善检索"比"合并条目"效果更好的案例？
3. **反对生命周期衰减的理由**：有没有看似过时但突然又需要的知识类型？永久保留 + 改善检索是否比过期删除更安全？
4. **反对门禁晋升的理由**：多阶段晋升是否增加了不必要的复杂度？简单的"记住 or 不记住"二元模型是否在实践中更有效？

## 5. Local Constraints

调研结论必须在以下约束下可行：

- **多引擎协作**：Claude Opus/GPT-5.4/Gemini 共同工作在同一 repo，共享 shared-rules 但各有独立记忆
- **知识在 repo 里**：所有知识沉淀在 git 仓库的 markdown 文件中（ADR、LL、feature spec、feedback 记忆），通过 SQLite 全文检索 + 向量语义 rerank 检索
- **人在环路**：知识的删除/合并必须由人类 CVO 确认，猫只能建议
- **冷启动限制**：每只猫每次对话都是从零开始（无持久化内存），靠检索系统获取历史知识
- **当前规模**：~450 行 shared-rules、51 条 LL、40+ feedback 记忆、28+ ADR、160+ feature spec——不是百万级知识库，但增长趋势明显
