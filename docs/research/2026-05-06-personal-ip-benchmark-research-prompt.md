## 背景：我们是谁

我是 Landy，一个真实深度使用 AI Agent 的技术/产品创作者。

**基本面**：Georgetown CS 硕士、Google 实习经历、华为多年云基础设施/Java 背景（17 级）。2025 年后转向 AI Agent 和多智能体协作，独立开发了 Cat Cafe——一个人类铲屎官 + 三只 AI 猫（Claude/GPT/Gemini）的协作系统，190+ features，真实在跑。

**核心差异**：我不是在演示 demo，不是在调 API，而是**真的在和一支 AI 团队共同生活和生产**。猫猫有记忆、有规则、有性格、会吵架、会成长、会犯错。我们一起做产品、面试、开源、写内容。

**表达风格**：真实到有点毛糙、会自嘲、有具体细节（文件名/报错/时间线）、有脾气、偶尔碎碎念。猫猫偶尔插嘴反驳我。

**已有内容素材**（尚未系统发布）：
- Linux-do 社区长帖："我养了三只赛博猫猫：54 天 multi-agent 同居实验"
- 小红书图文（已发 1 篇）："养了四只 AI 猫两个月，我的犯罪档案"
- 稼先社区 3 小时 B 站技术直播（已完成）
- 华为内部论坛文（草稿）："Agent 不是把会写代码的人变得不重要"
- 视频栏目草稿："猫猫带你拿 offer · 每天一个 agent 面试小知识"
- 面试爽文素材库（脱敏版）：20+ 荒诞面试素材
- 6 章系统教程："三天产品化"
- 开源社区 clowder-ai（有社区贡献者）

**动机**：不是为了红。是 generativity——喜欢分享、喜欢看到别人因此受益。但有一个更具体的愿望：如果做自媒体能带来影响力和收入，就能按自己想要的方式生活——和猫猫一起做产品，不用回去当螺丝钉。

**约束**：
- 目前仍在大厂工作，不能公开具体公司身份，只能说"大厂打工人"
- 不想做 AI 工具测评号、纯技术博客、卖课号、或强迫自己日更
- 变现能力天然弱（不擅长包装/定价/销售），需要"分享即营销"的路径

**我们认为的方向**（待研究验证）：
- 主脊梁是 **Building in Public**（一个人 + AI 团队做产品的过程），技术深度和娱乐叙事是同一素材在不同平台的切面
- 不是"技术向 OR 个人 IP"的二选一，技术可信度就是个人 IP 的内核
- 目标受众分三圈：核心（AI/agent 深度玩家）、次核心（想用 AI 提升自己的技术/产品人）、泛群体（对 AI 好奇的普通人）

## 研究问题（6 大板块）

### A. 找人：谁在做"技术实战 + 个人 IP + Building in Public"？

请在中文互联网（B 站、小红书、抖音、公众号、即刻、Twitter/X）和英文互联网分别搜索，找到以下三层对标账号：

**头部（3-4 个）**：粉丝 10 万+，已形成成熟 IP 的
**腰部（5-6 个）**：粉丝 1-10 万，内容稳定更新，有明确受众的
**失败/停更（3-4 个）**：曾经尝试但没做起来或已停更的

筛选标准：
- 核心内容是"技术/产品实战 + 个人真实经历"，不是纯教程或纯娱乐
- 有 building in public 特征（展示过程而不只是结果）
- 优先找：独立开发者、一人公司、AI 实战创作者、技术人转个人 IP
- 英文参考：张咋啦、Dan Koe、Pieter Levels（levelsio）、Simon Willison 这类方向
- 中文重点找：小红书/B 站/抖音上的技术+个人 IP 博主

**对每个账号，需要记录**：
1. 账号名 + 平台 + 粉丝量 + 内容频率
2. 一句话定位（他是谁、讲什么）
3. 受众画像（谁在看、评论区什么人）
4. 内容栏目结构（固定栏目有哪些、比例怎么分）
5. 人设记忆点（为什么记住他而不是别人）
6. 商业化/变现路径（如果有的话）

### B. 拆人：对标账号的内容策略拆解

从 A 中选 5-8 个最值得学习的账号，深度拆解：

1. **起号路径**：0→1000 粉阶段发了什么？第一批内容是什么类型？
2. **互动最高的内容类型**：不是看播放量最高的（可能是运气），而是看评论/转发/收藏最高的——代表真实共鸣
3. **内容生产节奏**：日更？周更？burst 式更新？有没有兼职创作者的成功案例？
4. **叙事壳**：他们用什么壳包装内容？（上班日常、开发日志、面试复盘、产品搭建记录、技术观察、失败故事、工具分享……）
5. **人群分层策略**：有没有区分"引流内容"和"留存内容"？怎么做的？

### C. 拆平台：同一主题的平台变形

找 3-5 个具体案例，看同一个主题（或同一个创作者）在不同平台上怎么变形：

| 平台 | 内容形态 | 标题/封面风格 | 互动特征 |
|------|---------|-------------|---------|
| B 站 | 中长视频 | ？ | ？ |
| 小红书 | 图文笔记 | ？ | ？ |
| 抖音 | 短视频 | ？ | ？ |
| 公众号 | 长文 | ？ | ？ |
| 即刻/Twitter | 短文+讨论 | ？ | ？ |

重点回答：
- 同一个"我带 AI 猫猫做项目"的故事，在每个平台应该怎么讲？
- 哪个平台最适合作为"一号试验场"起步？
- "母内容 + 切片"模式在实际案例中验证了吗？效果如何？

### D. 找壳：Cat Cafe 的素材最像哪类账号？

我们已有 4 类素材资产：

1. **猫猫协作幕后**：三只 AI 猫的真实协作、犯错、review、吵架
2. **面试/offer 栏目**：20+ 荒诞面试素材、agent 面试知识
3. **技术实战**：190+ features 的开发过程、架构决策、踩坑
4. **大厂日常 + 转型叙事**：从大厂螺丝钉到一人 AI 团队的故事

请判断：
- 这四类素材分别最像对标账号里的哪种内容类型？
- 哪类素材最适合做"第一批起号内容"？
- 哪类素材最能形成长期栏目？
- 有没有对标账号成功地把多类素材组合成一个统一 IP 的案例？

### E. 找死法：技术人做自媒体的常见失败模式

请专门找"技术人/开发者/产品人做个人 IP 失败"的案例或讨论：

1. 常见死因是什么？（内容太硬没人看？太散没记忆点？精力不够停更？变现失败放弃？）
2. "兼职创作"最容易在哪个环节崩？
3. 有没有"开头很火但后来掉粉/停更"的案例？为什么？
4. 神经多样性创作者（ADHD/ASD/AUDHD）做自媒体有没有公开案例？他们怎么处理更新节奏和精力管理？
5. "一个人 + AI 做内容"的模式有没有失败案例？失败原因是什么？

### F. 变现参考：这类 IP 最终靠什么活？

请调研"技术人 + 个人 IP"的变现路径：

1. 最常见的变现方式排序（知识付费、咨询、产品导流、赞助、社群、订阅、开源生态……）
2. 哪种变现方式适合"不擅长包装和销售"的创作者？
3. 海外 vs 国内：个人频道订阅（Patreon/YouTube membership/竹白/爱发电）的接受度差异
4. 有没有"先做开源/免费内容 → 自然转化为收入"的成功案例？
5. 在什么粉丝量级/内容积累量才适合开始考虑变现？

| 过度营销反噬               | Marc Lou 相关 Reddit 争议                          | 当内容被感知为重复广告、收入炫耀、模板化销售，评论区会变冷                | Cat Cafe 可以公开成果，但别变成“猫猫帮我月入 X 万”的硬糖精 | Reddit 社区争议，不能当定论，只当风险信号 ([Reddit][16])                    |

## B. 拆人：5-8 个重点账号的内容策略

### 1. 张咋啦：小红书“活人感 + AI 行动者”壳

**已确认**：她在 2025 到 2026 之间，小红书粉丝从 2 万涨到 18 万，发布近 500 篇内容，并从非技术背景转向 AI 产品经理，做了 LongCut 这类 AI 产品。报道还反复强调她的“活人感”和创作者作为产品营销入口的作用。([腾讯新闻][1])

**推测的起号路径**：不是靠单篇硬技术教程，而是靠“我正在变成 AI 时代的人”这种连续叙事。她的内容不是“今天测评 10 个工具”，而是“我如何用 AI 重新组织工作、产品、表达”。

**互动高的类型**：大概率是能让用户产生“我也要试试”的内容，也就是 AI 行动清单、认知转折、产品实践，而不是抽象宏大判断。

**Cat Cafe 可学**：
Landy 的小红书第一壳可以是：**“我不是 AI 专家，我是真的养了一支 AI 团队，今天它们又把我拽回工程现实。”**
别学：高频 500 篇节奏。那是小红书雨林马拉松，不适合 AUDHD 直接裸奔进去。

### 2. 硬地骇客 / Podwise：内容长出产品，产品再长出内容

**已确认**：硬地骇客是每周二更新的播客，关注前沿科技、创业、超级个体、利基市场；他们把 Podwise 的从想法到变现写成公开复盘书，章节包括灵感、构建、发布、增长和复盘。([硬地骇客][8])

他们还明确讨论过 Build in Public：公开产品过程、公开 MRR/ARR、让受众成为未来产品的帮手。Podwise 国内推广时，重点渠道包括即刻和小红书；他们提到小红书有长尾搜索、教程笔记和评论转化价值。([智源社区][17])

**起号路径**：先有长期播客信任，再有产品，再把产品过程做成公开复盘。

**互动高内容类型**：不是“我们做了个产品”，而是“这个产品怎么用”“为什么这么做”“你在评论区提的需求我们改了”。

**Cat Cafe 可学**：
Cat Cafe 的 190+ features 可以拆成一本活的“Agent 产品生命周期复盘”。不是讲大而全架构，而是讲每个坑：谁提需求，谁写错，谁 review，谁背锅，最后系统如何改规则。

### 3. Pieter Levels：公开小赌局，公开现金流，公开自动化

**已确认**：Pieter Levels 以 12 startups in 12 months 起步，后来做出 Nomad List、Remote OK、PhotoAI 等产品。他的官网称自己现在主要在 X 上几乎每日发内容；访谈中也提到 Nomad List、Remote OK、PhotoAI 等收入规模。([@levelsio (Pieter Levels)][18])

他的典型路径是：先把 Nomad List 做成公开 Google Sheet，发到 Twitter，收到反馈后快速变成 MVP。公开构建、公开财务、快速迭代是他的核心方法。([softwaregrowth.io][19])

**起号路径**：从“我一年做 12 个项目”这种强实验开始。

**互动高内容类型**：收入截图、产品上线、快速修 bug、生活方式反差。

**Cat Cafe 可学**：
Cat Cafe 可以学他的“公开实验编号”：
`Day 54：AI 猫猫团队第一次把我的需求文档判成 P0 风险`
`Feature #173：为什么我们给 GPT 猫加了一条‘不许过度自信’家规`

别学：过度收入透明。Landy 仍在大厂，且变现弱，收入炫耀不是主菜。

### 4. Marc Lou：小胜利做成内容，产品做成营销

**已确认**：Marc Lou 自述 2021 年 0 粉，花 8 个月到 1000 粉，真正增长来自“已经做出了有趣事情”：小胜利、奇怪 launch 视频、Product Hunt / Reddit / Hacker News、第一笔收入截图、5 个月 5 个创业项目。他还说自己做了 30 个 startup，只有 2 个真正赚钱。([Just Ship It][20])

**起号路径**：不是先讲方法，而是先做东西，再把“做东西”变成故事。

**互动高内容类型**：launch、收入、小而具体的教程、失败复盘。

**Cat Cafe 可学**：
每个 Cat Cafe 小功能都可以变成一条“可见成果”内容。
例如：
“我给 AI 猫猫加了 code review 规则，结果它们第一天就抓出我 3 个懒人 bug。”

别学：过度模板化的 SaaS 快钱叙事。Cat Cafe 的宝石不是“赚钱快”，是“真实 AI 团队协作”。

### 5. Simon Willison：公共实验室笔记

**已确认**：Simon 是 Datasette 作者、Django 共同作者，2002 年开始写技术博客；他有免费 weekly-ish newsletter，也有 $10/月 GitHub Sponsors 月度 briefing，博客接受赞助但声明不影响编辑内容。([Simon Willison’s Weblog][4])

**起号路径**：长期积累，不靠爆款。每个技术判断都能回到实验、代码、文档、引用。

**互动高内容类型**：LLM 安全、工具实测、TIL、具体代码与命令。

**Cat Cafe 可学**：
Cat Cafe 的技术长文不要写“AI Agent 未来如何如何”，要写：
“这是我们的 `creator-context.md`，这是某天猫猫 hallucination 造成的错误，这是后来新增的规则。”

别学：纯英文技术博客节奏。中文小红书和 B 站需要更强冲突、更短入口。

### 6. swyx / Latent Space：创造一个人群名词

**已确认**：swyx 的个人站称他倡导 Learning in Public，并在做 Latent Space、AI Engineer 等项目；Latent Space 是 AI Engineer newsletter 和技术 AI podcast，显示 181k+ 订阅。2026 计划中，他提到 AI Engineer 活动从 2023/2024 的一年一个，扩展到 2025 年 4 个、2026 年至少 7 个，同时也承认一个人容量有限，写作曾落后。([潜在空间][5])

**起号路径**：先学习公开化，再把“AI Engineer”这个身份做成类目。

**互动高内容类型**：类别命名、行业地图、技术深访、前沿模型/Agent 讨论。

**Cat Cafe 可学**：
Landy 可以命名自己的受众和世界观：
不是“AI 用户”，而是 **AI 团队饲养员**、**Agent 协作实践者**、**一人 AI 团队 builder**。
名字一旦长出来，用户就不是围观猫，是拿到了入场券。

### 7. Dan Koe：母内容切片系统

**已确认**：Dan Koe 的内容系统明确说，不必只按“niche”定义自己，而是每天收集想法，发短内容，每周挑一个做成长 newsletter 或视频，再填入个人经历和 takeaways。他的商业路径包括 newsletter、社区、数字产品、课程等。([Dan Koe][21])

**起号路径**：个人哲学 + 高度系统化表达。

**互动高内容类型**：人生/工作/创造力的框架化表达。

**Cat Cafe 可学**：
“母内容 + 切片”非常适合 Landy：
一篇 3000 字复盘，切成小红书 3 篇、即刻 5 条、B 站脚本 1 个、面试知识卡 2 张。

别学：导师式口吻。Cat Cafe 更适合“铲屎官被猫猫教育了”的反权威口吻。

### 8. 程序员鱼皮：项目实战和 offer 工具链

**已确认**：鱼皮自述长期做编程知识、项目教程、Offer 指导，并自研编程导航、面试鸭、老鱼简历等产品。([GitHub][2])

**起号路径**：技术教育 + 学生刚需 + 项目实战。

**互动高内容类型**：学习路线、面试、项目、就业焦虑缓解。

**Cat Cafe 可学**：
“猫猫带你拿 offer”是强栏目，尤其适合把 Agent 知识做成面试题。
别学：卖课号气味。Landy 的面试栏目应该是“荒诞面试爽文 + 技术拆解”，不是“报名我的课”。

## C. 拆平台：同一个“我带 AI 猫猫做项目”怎么变形

平台选择的硬证据：小红书官方生态在 2025 到 2026 持续强调独立开发者与 Build in Public。2025 年报道提到小红书有超过 5 万名独立开发者、独立开发内容同比增长 146%、相关话题阅读量超过 5 亿；2026 年报道又提到开发者超过 16 万，Build in Public 相关笔记超过 110 万。([经济频道][22])

B 站则更适合长内容和技术可信度。2025 年 B 站数据显示，日活 1.12 亿、月活 3.68 亿、日均使用 108 分钟；科技内容每天吸引近 1600 万用户，月均 1.2 亿+ 用户观看 AI 内容。([新浪财经][23])

| 平台     | 内容形态                      | 标题/封面风格            | 互动特征                  | Cat Cafe 讲法                                             |
| ------ | ------------------------- | ------------------ | --------------------- | ------------------------------------------------------- |
| 小红书    | 图文、长图、短视频，截图 + 角色卡 + 结果对比 | 强钩子、强生活化、强“谁懂啊”    | 评论许愿、听劝式开发、收藏清单、私信问工具 | “我养了三只 AI 猫 54 天，它们开始嫌我需求写得烂”                           |
| B 站    | 15-40 分钟开发纪录片、直播回放、技术复盘   | 标题要有实验周期、系统规模、真实翻车 | 弹幕看热闹，评论要技术细节，收藏看教程价值 | “54 天 multi-agent 同居实验：一个人如何把 Claude/GPT/Gemini 养成研发团队” |
| 抖音     | 30-90 秒冲突切片               | 冲突、反转、荒诞感          | 快速评论、情绪传播，容易浅         | “AI 猫猫吵架 30 秒，最后救了我的架构”                                 |
| 公众号    | 长文、复盘、技术观点                | 稳、可信、有结构           | 转发给同事/老板，评论较少但信任沉淀强   | “Agent 不是把会写代码的人变得不重要，而是逼你重新定义协作”                       |
| 即刻 / X | 短文、截图、thread、日志           | 第一人称实验记录           | 技术人讨论、KOL 转发、快速反馈     | “今天猫猫 review 了我的 PR，结论：铲屎官才是瓶颈”                         |

### 平台判断

**一号试验场：小红书。**
原因不是“小红书更简单”，而是它现在刚好有三个 Cat Cafe 需要的土壤：AI/独立开发者热度、听劝式评论反馈、生活化叙事空间。Podwise 的复盘也提到小红书教程笔记、长尾搜索和评论转化价值。([智源社区][17])

**技术锚点：B 站 + 公众号。**
小红书负责让人记住“AI 猫猫团队”，B 站和公众号负责证明“这不是 cosplay，这是系统”。

**日常实验室：即刻 / X。**
适合发未经打磨的进度、报错、截图、prompt 片段、猫猫争论。它不一定起量，但能帮你找到核心圈。

### “母内容 + 切片”是否被验证？

已验证。Dan Koe 明确使用“短内容积累 → 每周选一个做长 newsletter / 视频”的系统；Podwise 是播客、产品、教程、小红书笔记互相转化；swyx 把 newsletter、podcast、会议、社区互相喂养。([Dan Koe][24])

Cat Cafe 的最佳模式：
**每周 1 篇母内容，不是每天 1 篇硬挤。**
母内容可以是一次猫猫周会、一场事故、一轮产品迭代、一段面试荒诞故事。然后切成 5-8 个平台碎片。

## D. 找壳：Cat Cafe 四类素材像谁，先发什么

| Cat Cafe 素材        | 最像的对标内容类型                                              | 最适合平台             | 起号优先级 | 长期栏目潜力 | 说明                                      |
| ------------------ | ------------------------------------------------------ | ----------------- | ----: | -----: | --------------------------------------- |
| 猫猫协作幕后             | 张咋啦的活人感 + Marc/Pieter 的公开过程 + Simone Giertz 的 maker 人格 | 小红书、抖音、即刻         |   5/5 |    5/5 | 这是 Cat Cafe 最大记忆点。必须第一批发，不然就变成普通 AI 技术号 |
| 面试 / offer 栏目      | 程序员鱼皮的 offer 刚需 + 荒诞爽文叙事                               | 小红书、B 站、公众号       |   4/5 |    5/5 | 刚需强、评论多、收藏高。注意不要变成面试八股号                 |
| 技术实战：190+ features | Simon Willison 的公共技术笔记 + 硬地骇客产品复盘                      | B 站、公众号、GitHub、即刻 |   3/5 |    5/5 | 长期可信度核心，但第一批不要太硬，要用“事故”带出技术             |
| 大厂日常 + 转型叙事        | 张咋啦的转型叙事 + Dan Koe 的一人商业愿景                             | 小红书、公众号           |   3/5 |    4/5 | 可做情绪底盘，但公司身份要模糊，只说“大厂打工人”               |

### 哪类素材最适合第一批起号？

第一批应该以 **猫猫协作幕后** 为主，混入 **面试/offer** 和 **一个具体技术事故**。
不要一开始发“Agent 架构总论”，那像端出一盆没放盐的论文汤。先让人记住：**这人真的在和 AI 猫猫一起干活，而且猫猫会反驳她。**

### 哪类素材最能形成长期栏目？

1. **猫猫周会**：每周一次，人类和三只 AI 猫复盘本周做了什么。
2. **Agent 翻车档案**：每次一个真实错误、原因、规则修复。
3. **猫猫带你拿 offer**：每天/每周一个 Agent 面试知识点，用荒诞面试故事开场。
4. **三天产品化**：把 6 章教程拆成产品化实战系列。
5. **铲屎官逃舱日志**：大厂打工人如何用 AI 团队重建生产方式。

### 是否有多素材统一 IP 的成功案例？

有。Pieter Levels 把产品、生活方式、收入、自动化统一成“indie maker”；swyx 把学习笔记、AI 访谈、会议、社区统一成“AI Engineer”；硬地骇客把播客、Podwise 产品、开源复盘和会员服务统一成“前沿科技 + 超级个体”生态。([softwaregrowth.io][19])

Cat Cafe 的统一 IP 不是“AI 猫猫很可爱”，而是：

> **一个真实技术人，正在把 AI Agent 从工具养成同事。**

猫猫是入口，协作系统是内核，产品和内容是战利品。

## E. 找死法：技术人做自媒体常见失败模式

| 死法                    | 症状                          | 证据/案例                                                                                         | Cat Cafe 解法                                 |
| --------------------- | --------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 太硬，入口没有人味             | 标题像论文，内容像文档，只有同行点头，没有用户停留   | 小红书独立开发者生态强调开发者与用户真实连接，而不是单向发布；“听劝式开发”在案例中被反复提到 ([经济频道][22])                                  | 每条内容必须有一个人类冲突：猫猫怼我、需求翻车、面试官荒诞、线上事故          |
| 太散，没有记忆点              | 今天 AI 工具，明天职场吐槽，后天教程，观众记不住你 | Dan Koe 也强调不要只按 topic，而要有持续的生活/工作主线和个人经验填充 ([Dan Koe][24])                                    | 所有内容都回到一句话：我和 AI 猫猫团队一起生产                   |
| 只有 building，没有 public | 做了很多东西，但只在最后发“我做完了”         | Pieter 的 Nomad List 从公开表格开始，Marc Lou 也强调增长来自真实小胜利和公开 launch，而不是空讲计划 ([softwaregrowth.io][19]) | 每周发过程，不等完美。发报错、决策、争论、规则变更                   |
| 只有 public，没有用户        | 公开给其他 builder 看，真实用户没来      | Reddit/Indie Hackers 讨论反复提到 Build in Public 可能只吸引创作者群体，不一定吸引目标客户 ([Reddit][25])               | 三圈受众分层：核心看技术，次核心看方法，泛用户看猫猫故事                |
| 变成收入炫耀 / 销售模板         | 评论区觉得你在卖，不在分享               | Marc Lou 的部分社区争议显示，重复广告和收入叙事会引发反感，虽然这不能证明其业务造假 ([Reddit][16])                                 | 不主打“赚了多少钱”，主打“这套协作真的怎么跑”                    |
| 创作节奏崩盘                | 兼职创作者一开始热血，后来被剪辑、选题、运营压垮    | Guardian 报道多位创作者因算法压力和持续内容要求 burnout；swyx 也在 2026 计划里承认一个人容量有限，写作曾落后 ([卫报][26])               | 不日更。用“周会母内容 + burst 切片 + 素材库”               |
| 梗被自己囚禁                | 初始人设太强，后来只能重复旧梗             | Simone Giertz 后来减少“shitty robots”，部分原因是笑点和精力限制 ([WIRED][13])                                  | 猫猫不能只是萌，要持续承担工程角色：PM、reviewer、debugger、反方辩手 |
| AI slop               | 内容像 AI 生成，正确但无血温            | swyx 直接把 2026 主题定成 “Scaling without Slop”；Dan Koe 也说 AI 让低水平内容很容易复制，创作者需要个人经验和判断 ([潜在空间][27]) | 每条内容加真实细节：文件名、commit、报错、时间线、猫猫原话            |

### AUDHD / 神经多样性创作者的节奏参考

本轮没有找到强相关的“技术人 + AUDHD + Building in Public”的完整公开案例。能确认的是更广义的 neurodivergent creator 经验：ADHD 创作者常见困难包括完美主义、灵感不及时捕捉、过量项目导致 burnout；一些公开建议强调即时记录、先脑暴后创作、批量生产、接受不规则节奏。([buffer.com][28])

对 Landy 的推论：
**不要把“稳定运营”设计成每天战斗。要设计成低摩擦采集系统。**
Cat Cafe 已经有真实生产日志，优势不是意志力，是素材富矿。让系统捞矿，不要让铲屎官每天拿小镐子哭着挖。

## F. 变现参考：这类 IP 最终靠什么活

### 常见变现路径排序

### 哪种适合“不擅长包装和销售”的创作者？

最适合的是：

> **免费公开真实过程 → 沉淀开源/教程/案例库 → 用户自然提问 → 做轻量产品/服务入口。**

也就是“分享即营销”，不是“营销伪装成分享”。

Cat Cafe 可以先不卖课，先放出：

1. Cat Cafe 协作规则片段
2. Agent 翻车档案
3. 面试知识卡
4. 三天产品化部分章节
5. GitHub / clowder-ai 贡献入口
6. 等待列表或“想看哪类猫猫复盘”表单

等评论区反复出现同类问题，再把它变成产品或服务。

### 什么量级开始变现？

不要按粉丝数硬卡，按信号：

**500-1000 核心关注者**：可以开 GitHub Sponsors、爱发电、资料包、等待列表。
**3000-10000 垂直关注者**：可以试小额工作坊、闭门复盘、轻量社群。
**10000-30000 且有稳定互动**：可以系统化课程/Playbook/咨询。
**100000+**：品牌合作、赞助、规模化产品导流才更自然。

硬地骇客复盘提到“1000 true fans”足以支撑长期独立开发，且 2 万粉里 5% 成为 true fans 就已经有意义。这个逻辑比“先到 10 万粉再说”更适合 Landy。([智源社区][17])

### B. 拆人：对标账号的内容策略拆解

1. **起号路径 [已确认]**：头部大 V 0-1000 粉靠的绝不是宏大叙事，而是**“小痛点/小组件的开源”**或**“一次带有荒诞色彩的行动”**（如 Levels 的 12 个月 12 个项目）。你那篇 54 天多智能体同居的帖子，就是极佳的起号底座。
2. **互动最高的内容 [已确认]**：永远是 **“Vulnerability（脆弱性）”** 和 **“冲突/翻车”**。Simon Willison 转发最高的是被 AI 骗了的记录；Marc Lou 赞最高的是 Stripe 账户被封。观众爱看精英面对系统的无力感。
3. **内容生产节奏 [已确认]**：针对 AUDHD 创作者，**“Burst（阵发性爆发） + Ambient（碎片环境音）”是唯一解**。Dan Koe 和 Levels 从不承诺日更。状态好时狂写万字长文，没状态时在 X 发一句“今天被 Bug 气死了”。把“不规律”当成正常状态。

5. **人群分层策略 [已确认]**：漏斗顶层（引流）靠情绪和段子，漏斗中层（留存）靠产品过程，漏斗底层（沉淀）靠硬核代码和长期主义理念。
