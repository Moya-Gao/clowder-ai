# Research Brief: 全平台起号 + 跨平台分发实操策略

## 1. Problem Frame（任务边界）

**我们要回答的问题**：
一个零粉丝的技术/AI类个人IP，想做"技术实战+Building in Public+AI团队协作"方向的内容，在主要内容平台（小红书、X/Twitter、YouTube、B站、即刻、公众号、抖音）上分别怎么起号？以及如何设计一套"一份母内容→全平台分发→数据选平台"的实操流程？

**非目标（明确排除）**：
- 不研究"发什么内容"（已完成，见前序调研 `2026-05-06-personal-ip-benchmark-research-prompt.md`）
- 不研究"对标谁"（已完成）
- 不研究付费投流/广告投放（首阶段纯有机）
- 不研究MCN签约或品牌合作

**为什么现在要研究这个**：
我们已经完成了内容方向定义和对标账号拆解。之前四方一致推荐"小红书首发"，但铲屎官和做自媒体的朋友指出两个关键问题：(1) 我们完全不了解各平台的起号实操（新号发内容只有20-50曝光的冷启动现实）；(2) 朋友的建议是**全平台试水，用数据决定主阵地**，而不是靠推理选平台。所以我们需要补上"每个平台怎么起号"这门课，才能设计有效的全平台分发策略。

## 2. Current Hypotheses（我们的假设）

1. **全平台分发优于单平台押注**——先试再选，比理论推演更可靠
2. **同一内容需要平台适配**——不能直接搬运，标题/格式/长度/风格需要针对每个平台调整
3. **各平台的起号门槛差异很大**——有的平台新号友好（如即刻？X？），有的需要较长养号期（如小红书？抖音？）
4. **技术/AI垂类在不同平台的天花板不同**——可能某些平台对这类内容有系统性偏好或打压
5. **AUDHD创作者管不了7个平台**——全平台试水后，必须快速收敛到2-3个主力平台

**证据缺口**：
- 各平台新号的真实首条自然曝光量级
- 各平台起号的具体操作流程和时间线
- 技术/AI内容在各平台的推流友好度
- 全平台分发的实操工具和工作流
- "试水期"应该多长？多少数据点够做判断？

> ⚠️ 这些是初步假设，请在调研中验证或推翻。

## 3. Disconfirm First（先找反例）

1. 寻找**"全平台分发效果不好"**的案例——有没有创作者全平台铺开反而精力分散、哪个都没做好的？
2. 寻找**"单平台深耕比全平台分发更有效"**的证据——尤其在技术/AI垂类
3. 寻找**"某平台对技术内容系统性不友好"**的证据——避免浪费精力在死胡同里

## 4. Source Mix Quota（来源配额）

- [ ] **创作者一手复盘**：在各平台起号的实录（优先2025-2026年）
- [ ] **平台官方文档**：各平台的创作者指南、推荐算法说明
- [ ] **运营社群讨论**：即刻/知乎/生财有术/Indie Hackers 的实操经验
- [ ] **跨平台分发的方法论**：有没有成熟的"一内容多平台"工作流
- [ ] **技术/AI垂类特定**：这个类目在各平台的真实表现数据
- [ ] **海外平台**：X/YouTube 的起号策略（很多调研只覆盖国内平台）

**时效要求**：平台算法更新快，2024年以前的经验需要标注并谨慎使用。

## 5. Local Constraints（我们的约束）

- **兼职创作者**：铲屎官在大厂全职，每周可投入内容创作5-10小时
- **AUDHD**：burst式创作，不能日更，不能同时维护太多平台
- **不出镜**：起步阶段不真人出镜，以图文/截图/对话记录/屏幕录制为主
- **大厂合规**：不提公司名和具体业务
- **双语能力**：中英文都能写，但双语同时原创的精力成本需要评估
- **已有工具**：小红书MCP（自动发布/搜索/评论/互动）、图片生成、视频制作管线
- **三层受众**：泛用户（看热闹）、次核心（想学AI的技术人）、核心（Agent重度玩家）
- **试水后要快速收敛**：全平台试完后，最终主力平台不超过2-3个

## 7. Decision Interface（决策映射）

重点决策点：
1. 全平台同时铺开 vs 分批上线？如果分批，优先级？
2. 中文优先 vs 英文优先 vs 双语同时？
3. 矩阵号：哪些平台需要，哪些不需要？
4. 试水期多长？多少条内容够判断？
5. 收敛标准：什么信号说明"这个平台适合我"？

## 8. Risk Register（风险登记）

1. **精力分散**：7个平台同时起号可能哪个都做不好 → 缓解：设计最低有效动作，不追求每个平台都精细化
2. **平台规则变化**：2025年经验可能不适用于2026年 → 标注信息时间点
3. **幸存者偏差**：能找到的都是成功案例 → 主动搜索失败案例
4. **自动化风控**：用MCP/工具批量发布可能触发平台检测 → 调研各平台对自动化的态度
5. **双语精力翻倍**：中英同时做可能两边都半吊子 → 需要诚实评估英文内容创作的实际精力成本

### 前序调研结论
- 内容方向已定："一个大厂架构师和三只赛博猫的真实同居日记"
