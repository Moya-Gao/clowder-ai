# Research Brief: 全平台起号 + 跨平台分发实操策略

## 1. Problem Frame（任务边界）

**我们要回答的问题**：
一个零粉丝的技术/AI类个人IP，想做"技术实战+Building in Public+AI团队协作"方向的内容，在主要内容平台（小红书、X/Twitter、YouTube、B站、即刻、公众号、抖音）上分别怎么起号？以及如何设计一套"一份母内容→全平台分发→数据选平台"的实操流程？

**非目标（明确排除）**：
- 不研究"发什么内容"（已完成，见前序调研 `2026-05-06-personal-ip-benchmark-research-prompt.md`）
- 不研究"对标谁"（已完成）
- 不研究付费投流/广告投放（首阶段纯有机）
- 不研究MCN签约或品牌合作

**为什么现在要研究这个**：
我们已经完成了内容方向定义和对标账号拆解。之前四方一致推荐"小红书首发"，但铲屎官和做自媒体的朋友指出两个关键问题：(1) 我们完全不了解各平台的起号实操（新号发内容只有20-50曝光的冷启动现实）；(2) 朋友的建议是**全平台试水，用数据决定主阵地**，而不是靠推理选平台。所以我们需要补上"每个平台怎么起号"这门课，才能设计有效的全平台分发策略。

## 2. Current Hypotheses（我们的假设）

1. **全平台分发优于单平台押注**——先试再选，比理论推演更可靠
2. **同一内容需要平台适配**——不能直接搬运，标题/格式/长度/风格需要针对每个平台调整
3. **各平台的起号门槛差异很大**——有的平台新号友好（如即刻？X？），有的需要较长养号期（如小红书？抖音？）
4. **技术/AI垂类在不同平台的天花板不同**——可能某些平台对这类内容有系统性偏好或打压
5. **AUDHD创作者管不了7个平台**——全平台试水后，必须快速收敛到2-3个主力平台

**证据缺口**：
- 各平台新号的真实首条自然曝光量级
- 各平台起号的具体操作流程和时间线
- 技术/AI内容在各平台的推流友好度
- 全平台分发的实操工具和工作流
- "试水期"应该多长？多少数据点够做判断？

> ⚠️ 这些是初步假设，请在调研中验证或推翻。

## 3. Disconfirm First（先找反例）

1. 寻找**"全平台分发效果不好"**的案例——有没有创作者全平台铺开反而精力分散、哪个都没做好的？
2. 寻找**"单平台深耕比全平台分发更有效"**的证据——尤其在技术/AI垂类
3. 寻找**"某平台对技术内容系统性不友好"**的证据——避免浪费精力在死胡同里

## 4. Source Mix Quota（来源配额）

- [ ] **创作者一手复盘**：在各平台起号的实录（优先2025-2026年）
- [ ] **平台官方文档**：各平台的创作者指南、推荐算法说明
- [ ] **运营社群讨论**：即刻/知乎/生财有术/Indie Hackers 的实操经验
- [ ] **跨平台分发的方法论**：有没有成熟的"一内容多平台"工作流
- [ ] **技术/AI垂类特定**：这个类目在各平台的真实表现数据
- [ ] **海外平台**：X/YouTube 的起号策略（很多调研只覆盖国内平台）

**时效要求**：平台算法更新快，2024年以前的经验需要标注并谨慎使用。

## 5. Local Constraints（我们的约束）

- **兼职创作者**：铲屎官在大厂全职，每周可投入内容创作5-10小时
- **AUDHD**：burst式创作，不能日更，不能同时维护太多平台
- **不出镜**：起步阶段不真人出镜，以图文/截图/对话记录/屏幕录制为主
- **大厂合规**：不提公司名和具体业务
- **双语能力**：中英文都能写，但双语同时原创的精力成本需要评估
- **已有工具**：小红书MCP（自动发布/搜索/评论/互动）、图片生成、视频制作管线
- **三层受众**：泛用户（看热闹）、次核心（想学AI的技术人）、核心（Agent重度玩家）
- **试水后要快速收敛**：全平台试完后，最终主力平台不超过2-3个

2. **平台规则变化**：2025年经验可能不适用于2026年 → 标注信息时间点
3. **幸存者偏差**：能找到的都是成功案例 → 主动搜索失败案例
4. **自动化风控**：用MCP/工具批量发布可能触发平台检测 → 调研各平台对自动化的态度
5. **双语精力翻倍**：中英同时做可能两边都半吊子 → 需要诚实评估英文内容创作的实际精力成本

## 0. 结论先行：不要“七平台打七份工”，要“一母内容，多平台侦察”

我的判断是：**全平台试水是对的，但全平台平权是错的。**

最适合我们的打法不是“每个平台都认真运营”，而是：

> **4周轻量全平台侦察 → 数据打分 → 收敛到2-3个主力平台 → 其他平台降级成归档/搜索/偶发分发。**

第一阶段推荐这样排兵布阵：

| 层级    | 平台             | 角色            | 初期动作                 |
| ----- | -------------- | ------------- | -------------------- |
| 主侦察   | 小红书、即刻、X       | 测内容市场反应       | 每周至少2条轻量适配           |
| 长尾资产  | 公众号、B站、YouTube | 建信任、沉淀作品、搜索流量 | 公众号双周更；B站/YT先用录屏和短切片 |
| 高波动试验 | 抖音             | 测是否有“技术娱乐化”空间 | 只发由母内容切出的短视频，不单独为它创作 |

关键反证也很明确：一位技术账号复盘写到，自己起步期是先深耕一个平台，18个月从17个阅读做到10万粉，到了3万粉以后才认真做多平台矩阵；这个案例支持“多平台有用”，但不支持“一开始七个平台都精耕”。它的多平台路径是：先知乎长文，再改成B站视频、公众号口语化版本、掘金/CSDN长尾同步。([比邻][1])

所以，我会把朋友的“全平台试水”改造成更适合AUDHD兼职创作者的版本：

> **全平台铺探针，不铺生产力。主内容只做一份，平台适配不超过一小时，视频平台只吃切片，不额外吞人。**

# A. 各平台起号手册

## A1. 小红书

### 平台判断

小红书现在不能再简单当“生活方式平台”看。官方应用描述里，小红书仍定位为“生活兴趣社区”，兴趣覆盖时尚、旅游、科技等领域；2025年平台也公开强调会把超过一半的日流量分发给1000粉以下创作者，并引入“真诚分”等治理机制来鼓励普通创作者。([Google Play][2])

对我们来说，小红书的价值是：**AI技术内容可以被生活化、故事化、人格化地包装。** “大厂架构师和三只赛博猫的同居日记”在这里比纯“Agent工程实践”更有优势。

### 起号阶段表

| 阶段  |   时间线 | 具体动作                                               | 技术/AI类注意事项                   |
| --- | ----: | -------------------------------------------------- | ---------------------------- |
| 养号期 |  3-7天 | 完善头像、简介、垂类关键词；正常浏览AI、效率、技术、个人成长、打工人相关内容；收藏/评论同领域笔记 | 不要批量关注、批量点赞、批量评论；不要一上来挂强引流信息 |
| 首发期 | 第1-2周 | 连发6-10条图文笔记，测试3类包装：猫猫故事、技术踩坑、AI协作实验                | 每条只讲一个结果，不要像论文摘要；第一张图要能单独成立  |
| 测试期 | 第3-4周 | 每周复盘标题、封面、收藏率、评论质量；保留高响应格式，淘汰低响应格式                 | 技术内容优先追“收藏、评论、转发给朋友”，不要只看点赞  |
| 收敛期 | 第5周以后 | 只保留2-3个稳定栏目，比如「猫猫开会」「Agent翻车现场」「一张图讲清」             | 形成系列感，比随机爆款更重要               |

### 推流机制怎么理解

小红书官方披露的个性化推荐算法会使用用户设备、位置、浏览、关注、点击、搜索、点赞、收藏、分享、评论、发布等行为，并结合笔记内容数据做推荐；推荐链路中还会做去重、多样性打散和兴趣探索干预。([备案网站][3])

这意味着早期不要迷信“首小时玄学公式”。更实用的判断顺序是：

| 信号      | 对我们意味着什么                 |
| ------- | ------------------------ |
| 点击/打开   | 封面和标题是否像人话               |
| 停留/完读   | 这条内容是不是讲太散               |
| 收藏      | 技术/AI内容是否真的有用            |
| 评论      | 是否激发“我也遇到过/怎么做到的/能不能展开讲” |
| 主页访问与关注 | 人设是否成立，而不只是单条内容成立        |

### 技术/AI类小红书标题建议

不要这样：

> “AI Agent多智能体协作范式最佳实践”

要这样：

> “我让三只AI猫开需求会，结果它们先吵起来了”
> “这个Agent bug，让我突然理解了为什么AI团队也需要PM”
> “我用AI搭了个假同事，第一天就开始甩锅”

### 矩阵号判断

**初期不做矩阵号。**

理由：小红书官方正在强化真实性和低质/虚假AI内容治理，早期多号搬运容易把自己做成“AI味营销号”；同时平台已经公开强调给低粉创作者流量机会，没有必要一开始用矩阵号硬蹭初始池。([Jnzstatic][4])

适合我们的做法是：**一个主号 + 一个内容素材库 + 后期必要时再开“项目号/产品号”。**

## A2. B站

### 平台判断

B站对技术内容是友好的，但它不是轻平台。它更像“技术人格信用仓库”：内容寿命长，观众愿意看深度，但制作门槛比小红书、即刻、X高。

B站官方协议页面集中列出了社区规则、创作公约、审核标准等，并在公告中提到会治理标题党、低质量内容、AI换脸等问题。也就是说，B站适合做可信的技术展示，不适合粗暴搬运短视频套路。([哔哩哔哩][5])

### 起号阶段表

| 阶段  |   时间线 | 具体动作                              | 技术/AI类注意事项                                 |
| --- | ----: | --------------------------------- | ------------------------------------------ |
| 养号期 |  0-3天 | 完善头像、简介、分区、合集；关注同领域UP；准备统一封面模板    | 不需要玄学养号，重点是账号可信                            |
| 首发期 | 第1-4周 | 发4条视频或2条视频+4条动态/专栏；优先3-8分钟录屏讲解    | 视频标题必须有具体收益或冲突，例如“我让3个Agent互相审代码，发现一个危险模式” |
| 测试期 | 第5-8周 | 看点击率、平均观看时长、完播、三连、评论；只迭代一个变量      | 不要用小红书标题直接搬，B站观众更讨厌“虚火”                    |
| 长尾期 |  2个月后 | 把高质量内容整理成合集：Agent实战、AI团队协作、架构师工具箱 | B站是作品集，不是日更广场                              |

### 技术/AI类注意事项

B站适合这几种内容：

| 形式        | 适配度           |
| --------- | ------------- |
| 屏幕录制 + 旁白 | 高             |
| 代码/架构图讲解  | 高             |
| AI工具实测    | 中高，但要避免“测评洗稿” |
| 猫猫人格剧情    | 中，需要和真实技术结果绑定 |
| 纯口播但不出镜   | 中，需要字幕和画面节奏   |

一个技术账号复盘里提到，文章平均2-4小时带来约50粉，而视频6-8小时平均带来约500粉；但这个是个体经验，不是平台普遍规律。对我们有用的结论是：**视频ROI可能高，但制作成本也高，不能一开始押太重。**([比邻][1])

## A3. 抖音

### 平台判断

抖音不是不能做技术内容，但它要求技术内容被压缩成“快速理解、快速刺激、快速反馈”。它更适合测：

> “三只AI猫 + 技术翻车 + 30秒冲突”
> 而不是
> “Agent协作架构深度复盘”。

2025年抖音首次公开算法原理，披露内容上传后会先经过机器审核和人工审核，低风险内容会进入基础流量池，流量增大、举报、评论异常等情况会触发更多审核；推荐上会使用协同过滤、双塔模型、Wide & Deep等方法，并综合完播、评论、点赞、分享等长期和短期目标。([新华网][6])

另一个公开报道提到，抖音推荐排序可理解为“综合预测用户行为概率 × 行为价值权重”，并且平台已经从早期更看完播，转向多目标，包括知识类内容里的收藏、复访、关注追更、搜索等信号。([新浪财经][7])

### 起号阶段表

| 阶段      |   时间线 | 具体动作                             | 技术/AI类注意事项                 |
| ------- | ----: | -------------------------------- | -------------------------- |
| 养号期     |  3-7天 | 正常使用账号，刷AI、效率、职场、程序员、工具类内容；不批量操作 | 不要新号上来高频批量发，先让账号画像稳定       |
| 首发期     | 第1-2周 | 发8-12条20-45秒竖屏视频，全由母内容切片         | 每条只讲一个冲突：AI做错了什么、我怎么修、结果如何 |
| 测试期     | 第3-4周 | 看3秒留存、完播、收藏、评论、关注转化              | 收藏和复访对知识内容更关键，别只追点赞        |
| 放弃/保留判断 |   第4周 | 如果视频制作耗时高且没有明显高于其他平台的新增粉，降级      | 抖音不能吞掉主线创作时间               |

### 抖音内容模板

1. **开头3秒**：
   “我让三个AI Agent一起写方案，结果它们开始互相甩锅。”

2. **中段20秒**：
   展示截图/流程图/错误结果。

3. **结尾10秒**：
   “最后我加了一个‘审稿猫’角色，错误率直接下降。这个模式我叫：猫猫三审制。”

### 风险

抖音对AI生成、虚假营销、低质搬运治理力度在增强。2026年抖音发布安全与信任报告，提到持续完善算法透明、AI生成内容和恶意营销治理。([新华网][8])

所以我们的底线是：

> 不做“AI神技震惊体”，不做伪结果，不批量搬运，不把MCP当刷互动机器。

## A4. 即刻

### 平台判断

即刻不是典型算法流量平台，更像“高密度同温层广场”。它适合：

| 适合              | 不适合      |
| --------------- | -------- |
| 真实过程、观点、踩坑、半成品  | 过度包装的营销文 |
| 和AI/产品/技术圈互动    | 发完就走     |
| 建立“这个人有趣且靠谱”的印象 | 只发教程链接   |

少数派一篇关于即刻传播写作的旧文把即刻描述为偏“精英化”的无门槛社交媒体，并强调即刻内容前12-18字很重要，短内容要删到不能再删，观点信息类内容比纯情绪日常更容易建立价值感。虽然这篇是2022年的文章，时效要打折，但对即刻的社区气质仍有参考意义。([少数派 - 高品质数字消费指南][9])

### 起号阶段表

| 阶段  |   时间线 | 具体动作                                 | 技术/AI类注意事项          |
| --- | ----: | ------------------------------------ | ------------------- |
| 破冰期 |  3-7天 | 关注AI、产品、程序员、独立开发、效率工具相关圈子；每天认真评论3-5条 | 评论要像人，不要像引流机器       |
| 首发期 | 第1-2周 | 每周3-5条短帖：过程、截图、半成品、观点                | 即刻喜欢“真正在做的人”，不要只发结论 |
| 测试期 | 第3-4周 | 看评论质量、被转发、是否有人追问方法                   | 低曝光但高质量评论很值钱        |
| 关系期 |    长期 | 和固定圈层的人互相看见，形成“AI猫猫工坊”的记忆点           | 即刻的增长更像结网，不像撒网      |

### 即刻发帖模板

> 今天让三只AI猫分工做一个Agent评审流程：
>
> 1. 一只负责写方案
> 2. 一只负责挑刺
> 3. 一只负责把争吵翻译成人话
>
> 意外发现：最有价值的不是“生成答案”，而是“制造高质量冲突”。

即刻不用太像标题党，但第一句必须有钩子。

## A5. 公众号

### 平台判断

公众号不适合做第一波冷启动主阵地，但非常适合做“长文母舰”和信任沉淀。它的价值不是首发曝光，而是：

1. 长文档案
2. 搜一搜长尾
3. 私域转发
4. 未来商业合作背书
5. 把碎片内容收束成体系

2025年有内容行业文章提到，公众号已经从纯订阅分发转向“订阅 + 推荐”混合模式，小号也有机会获得推荐流量；但这个判断来自行业观察，不是微信官方算法白皮书，应该谨慎使用。([人人都是产品经理][10])

另有运营文章总结，公众号流量入口包括系统推荐、搜一搜、问一问、看一看、文章页推荐等，并提到完读率、在看、点赞等互动数据会影响内容表现；这同样属于运营侧总结，不是官方权重表。([群聊网][11])

### 起号阶段表

| 阶段  |  时间线 | 具体动作                           | 技术/AI类注意事项                 |
| --- | ---: | ------------------------------ | -------------------------- |
| 准备期 |   1周 | 设置号名、简介、菜单、自动回复；准备3篇镇号文        | 第一篇要解释“我是谁，三只AI猫是谁，为什么值得看” |
| 首发期 | 第1个月 | 每2周1篇1500-3000字长文；从小红书/即刻/X导流  | 不要追日更，长文要有收藏价值             |
| 测试期 | 第2个月 | 看打开率、读完率、转发、留言、搜一搜来源           | 公众号更适合判断“核心读者是否出现”         |
| 沉淀期 |   长期 | 做合集：AI猫猫实验室、Agent协作笔记、大厂架构师工具箱 | 它是根据地，不是冲锋号                |

### 公众号首批栏目建议

| 栏目            | 作用                 |
| ------------- | ------------------ |
| 《三只AI猫的同居说明书》 | 人设入口               |
| 《本周AI团队翻车记录》  | Building in Public |
| 《Agent协作实验笔记》 | 技术核心               |
| 《架构师和AI猫的周会》  | 泛用户也能看             |

## A6. X / Twitter

### 平台判断

X对英文AI/技术/Building in Public非常友好，但冷启动不能靠“发帖等天降流量”。冷启动核心是：

> **高质量回复 + 小线程 + 可见进展 + 清晰人设。**

X官方帮助文档说明，For You时间线会展示关注账号、主题内容和推荐内容，推荐会考虑内容受欢迎程度、用户网络中的互动情况，并避免推荐垃圾、滥用等内容。([帮助中心][12])

X的推荐系统说明还提到，候选内容来自in-network和out-of-network来源，会通过轻量、重度排序模型结合个性化相关性和非个性化质量模型排序；新用户或低使用用户更依赖非个性化质量模型；负反馈如举报、不喜欢等会影响推荐。([帮助中心][13])

X开源推荐仓库也说明，For You推荐结合站内和站外网络内容，通过召回、排序、过滤等步骤，并用用户互动历史预测不同参与行为。([GitHub][14])

### 起号阶段表

| 阶段   |   时间线 | 具体动作                                                | 技术/AI类注意事项                   |
| ---- | ----: | --------------------------------------------------- | ---------------------------- |
| 冷启动  |   第1周 | 完成英文简介；关注30-50个AI builder、agent、devtools账号；每天认真回复5条 | 回复要贡献观点、代码、截图，不要“great post” |
| 初始增长 | 第2-4周 | 每周3-5条原创：1条thread、2条单帖、1条build log、1条问题帖            | Thread讲方法，单帖讲洞察，build log讲进展 |
| 社群接入 |  第2个月 | 加入#buildinpublic、#indiehackers、AI agent相关讨论         | 不泄露公司、客户、内部架构                |
| 收敛   | 第6-8周 | 看profile visits、followers per impression、是否被同领域账号回复 | X的价值是连接全球AI圈，不只是曝光           |

### Thread vs 单条

| 形式     | 适合内容                         |
| ------ | ---------------------------- |
| 单条     | 一个反常识、一张图、一个实验结果、一个失败教训      |
| Thread | 5步流程、完整复盘、工具链拆解、before/after |
| Reply  | 冷启动最重要的分发入口                  |
| Quote  | 接入大讨论，但要有新观点                 |

### Building in Public边界

这里要特别小心。Reddit上有2026年的讨论认为，过度Building in Public可能把架构、路线图、prompt、营销渠道暴露给复制者；但评论区也有人指出，真正难复制的是分发、信任、速度、品味、客户洞察和执行。([Reddit][15])

所以我们的原则是：

> 公开“过程、判断、教训、界面局部、抽象架构”，不公开“公司信息、完整prompt、内部数据、可复制商业路线图”。

## A7. YouTube

### 平台判断

YouTube是最慢的，但也是最值钱的长期资产。它适合：

| 适合       | 不适合         |
| -------- | ----------- |
| 录屏教程     | 每天随手发       |
| AI工具链实战  | 只搬小红书图文     |
| 技术频道搜索流量 | 4周就判死刑      |
| 英文长期复利   | 无字幕、无包装、无节奏 |

YouTube官方推荐系统文档强调，没有“理想视频长度”这种统一答案，创作者应使用留存曲线、标题和缩略图包装、观众价值和互动来优化；新频道尤其需要明确细分定位，并积累足够内容库，帮助系统理解应该推荐给谁。([谷歌帮助中心][16])

YouTube Shorts官方文档说明，Shorts最长可到3分钟；2025年3月31日起，Shorts观看次数统计口径调整，Engaged Views仍用于分析和收益资格；Shorts可以通过Shorts feed、搜索、首页、频道页、订阅、通知等入口被发现。([谷歌帮助中心][17])

### 起号阶段表

| 阶段  |   时间线 | 具体动作                                                        | 技术/AI类注意事项               |
| --- | ----: | ----------------------------------------------------------- | ------------------------ |
| 定位期 |   第1周 | 明确频道一句话：Faceless AI engineering experiments with cyber cats | 英文频道要更明确，不要中英混杂          |
| 首发期 | 第1-4周 | 发2-4条长视频，或1条长视频 + 6-10条Shorts                               | 长视频6-12分钟，Shorts 30-90秒  |
| 测试期 | 第5-8周 | 看CTR、平均观看时长、留存曲线、评论、订阅转化                                    | YouTube不要用4周判断死亡，要至少6-8周 |
| 长尾期 |  2个月后 | 做系列playlist：AI Agents, Build in Public, Cyber Cats Lab      | 标题、描述、章节、字幕都要服务搜索        |

### 长视频 vs Shorts

| 形式             | 用途              | 对我们建议       |
| -------------- | --------------- | ----------- |
| Shorts         | 快速测试hook、吸引浅层观众 | 从小红书/抖音切片同步 |
| 长视频            | 建信任、展示技术深度、搜索流量 | 每月1-2条即可    |
| Community post | 轻量互动            | 有100+订阅后再考虑 |
| Live           | 暂不建议            | 精力成本高       |

# C. 全平台分发实操工作流

## C1. 一篇3000字母内容，如何一小时内适配7个平台

先说现实：**如果包含完整视频剪辑，一小时不够。**
但如果我们提前有模板，一小时可以完成：

> 小红书图文 + 即刻短帖 + X thread + 公众号草稿 + 抖音/B站/YouTube短视频脚本。

视频渲染与剪辑要么批处理，要么用模板，不纳入“1小时适配”。

### 母内容拆解法：一篇文章切成7个器官

一篇3000字技术复盘先拆成：

| 元件             | 说明                  |
| -------------- | ------------------- |
| 1句冲突           | 这次实验哪里反常、翻车、有戏剧性    |
| 3个结论           | 给小红书/即刻/X用          |
| 1张架构图          | 给小红书、B站、YouTube缩略图用 |
| 3张截图           | 给图文和视频做证据           |
| 1个before/after | 给标题和短视频hook用        |
| 1个踩坑           | 给评论区讨论用             |
| 1个开放问题         | 给即刻/X互动用            |

### 60分钟适配流程

|      时间 | 动作                   | 产物                       |
| ------: | -------------------- | ------------------------ |
|  0-10分钟 | 从母内容提取hook、结论、截图、关键词 | 平台适配素材包                  |
| 10-25分钟 | 做小红书6-9页图文           | 封面 + 图文笔记                |
| 25-35分钟 | 改成即刻短帖和X单帖           | 中文短帖1条，英文单帖2-3条          |
| 35-45分钟 | 改成X thread           | 5-8条thread               |
| 45-55分钟 | 整理公众号草稿结构            | 标题、摘要、小标题                |
| 55-60分钟 | 生成短视频脚本              | 抖音/B站/YouTube Shorts共用脚本 |

### 平台适配表

| 平台      | 适配格式                | 标题风格             | 长度                    | 需要额外制作       |
| ------- | ------------------- | ---------------- | --------------------- | ------------ |
| 小红书     | 6-9图图文，或45-90秒短视频   | 生活化、冲突感、非AI腔     | 600-1200字             | 封面、截图、猫猫角色图  |
| B站      | 3-8分钟录屏讲解           | 结果明确、技术可信        | 视频脚本800-1500字         | 缩略图、字幕、章节    |
| 抖音      | 20-45秒竖屏短视频         | 前3秒强冲突           | 口播100-180字            | 竖屏字幕、快速剪辑    |
| 即刻      | 200-600字短帖          | 像真人突然有个发现        | 200-600字              | 1张截图即可       |
| 公众号     | 1500-3000字长文        | 稳定、可信、有系列感       | 1500-3000字            | 目录、配图、合集链接   |
| X       | 1条thread + 2-3条单帖   | 具体、英文、build log感 | 单帖80-220词；thread 5-8条 | 英文截图/代码片段    |
| YouTube | 6-12分钟长视频，或3条Shorts | 搜索友好 + 结果导向      | 长视频脚本1000-1800词       | 缩略图、字幕、描述、章节 |

### 同一主题的7平台改写示例

母内容主题：

> 我让三个AI Agent协作做一次技术方案评审，发现“审稿Agent”比“生成Agent”更重要。

| 平台      | 标题/开头示例                                                                                        |
| ------- | ---------------------------------------------------------------------------------------------- |
| 小红书     | 我让三只AI猫开架构会，结果最有用的是那只专门挑刺的                                                                     |
| B站      | 三个AI Agent协作评审技术方案：为什么“挑刺角色”比“生成角色”更重要                                                         |
| 抖音      | 我让AI组了个三猫小队，结果负责挑刺的那只救了整个方案                                                                    |
| 即刻      | 今天做了个小实验：三个Agent里，最值钱的居然不是写方案的，而是专门拆台的                                                         |
| 公众号     | AI团队协作实验：为什么每个Agent系统都需要一个“挑刺者”                                                                |
| X       | I gave three AI agents different roles. The critic agent produced more value than the builder. |
| YouTube | I Built a 3-Agent Review Team. The Critic Agent Was the Real Breakthrough.                     |

## C2. 分发工具推荐：自动化到什么程度安全

### 推荐原则

自动化可以做：

| 可以自动化   | 不建议自动化      |
| ------- | ----------- |
| 草稿生成    | 批量灌水发布      |
| 格式转换    | 批量点赞/关注/评论  |
| 跨平台复制初稿 | 完全不人工审稿     |
| 数据抓取入表  | 自动私信引流      |
| 评论聚合提醒  | 用矩阵号重复铺同质内容 |

### 工具分层

| 类型       | 工具/方案                                    | 适合用途                                    | 风险                      |
| -------- | ---------------------------------------- | --------------------------------------- | ----------------------- |
| 本地文章同步   | WeChatSync                               | 公众号文章同步到知乎、掘金、CSDN等；支持29+平台、MCP、本地浏览器运行 | 适合长文，不覆盖所有社交平台；仍需人工检查格式 |
| 国内多平台管理  | 蚁小二、新媒体管家、类似工具                           | 多账号发文、数据聚合                              | Cookie、风控、平台规则变化风险      |
| 视频切片     | 剪映、CapCut、Descript、OpusClip类             | 长视频切短视频                                 | 容易生成同质AI感，需要人工改hook     |
| 自建轻自动化   | Notion/Airtable + Zapier/Make/n8n + 手动发布 | 数据追踪、提醒、素材管理                            | 最稳，但不够“全自动”             |
| 已有小红书MCP | 搜索、草稿、评论整理、发布辅助                          | 小红书主阵地效率提升                              | 不用于批量互动、刷行为             |

WeChatSync的GitHub说明显示，它是开源Chrome扩展，可把公众号文章同步到知乎、头条、掘金等29+平台，支持MCP，并声称Cookie、文章内容、账号信息不经过第三方服务器，所有操作在本地浏览器完成。这个适合做“长文同步器”，但不该被当成“全平台增长机器”。([GitHub][18])

## C3. 数据追踪：怎么判断哪个平台在响应

### 追踪表字段

每条内容都用同一个母内容ID追踪：

| 字段               | 示例                   |
| ---------------- | -------------------- |
| mother_id        | 2026W19-agent-review |
| platform         | 小红书 / X / 即刻         |
| format           | 图文 / thread / 短视频    |
| hook_type        | 猫猫冲突 / 技术结果 / 反常识    |
| publish_time     | 2026-05-08 21:30     |
| effort_min       | 35                   |
| impressions      | 曝光/阅读/播放             |
| engagement       | 赞、评、藏、转、投币、三连        |
| saves/bookmarks  | 收藏/书签                |
| comments_quality | 0-5分                 |
| follows          | 新增粉丝                 |
| profile_visits   | 主页访问                 |
| next_action      | 加码 / 改标题 / 放弃格式      |

### “有响应”的判断标准

不要用绝对曝光判断，要用**单位投入产出**和**评论质量**判断。

| 指标    | 含义           | 多少算“有响应”                   | 观察周期      |
| ----- | ------------ | -------------------------- | --------- |
| 曝光    | 平台愿不愿意给你试探流量 | 高于自己该平台中位数2倍，或连续3条上升       | 48小时 + 7天 |
| 互动率   | 内容是否让人动作     | 图文互动率3%-5%以上可继续；视频看完和收藏更重要 | 48小时      |
| 收藏/书签 | 技术内容是否有用     | 收藏/曝光 > 0.5%-1%算不错         | 7天        |
| 评论质量  | 是否吸引对的人      | 2条以上高质量问题，比20条“哈哈哈”更有价值    | 7天        |
| 粉丝转化  | 人设是否成立       | 关注/曝光 > 0.2%-0.5%可继续观察     | 7天        |
| 复用效率  | 值不值得继续发      | 单平台适配≤30分钟仍有增长信号           | 4周        |

### 试水期多长

| 平台      |                最低测试量 | 最短判断周期 | 不建议过早放弃的原因                          |
| ------- | -------------------: | -----: | ----------------------------------- |
| 小红书     |               12-20条 |     4周 | 标题/封面变量太大                           |
| 即刻      |        12-20条 + 评论互动 |     4周 | 关系网络需要时间                            |
| X       | 20-30条原创 + 100条高质量回复 |   4-6周 | 冷启动靠互动图谱                            |
| 抖音      |            12-20条短视频 |     4周 | 波动大，但制作成本高，没信号就砍                    |
| 公众号     |                 4-6篇 |   6-8周 | 依赖外部分发和长尾                           |
| B站      |               4-8条视频 |   6-8周 | 视频推荐和搜索慢热                           |
| YouTube |  4-8长视频或15-30 Shorts |  8-12周 | 官方也强调新频道需要清晰定位和内容库积累 ([谷歌帮助中心][16]) |

这组案例最有价值的结论不是“照抄谁”，而是：

1. **技术账号早期靠真实问题，不靠泛AI热点。**
2. **视频可能带来更快涨粉，但成本会吃掉兼职创作者。**
3. **跨平台最好从增长期开始精细化，冷启动期只做轻分发。**
4. **Building in Public要公开故事和判断，不公开底牌。**

# F. AUDHD兼职创作者节奏设计

我们的系统不能靠“每天稳定输出”，要靠**状态分档 + 模板化 + 允许降级**。

## F1. 三档创作模式

### 绿灯周：状态好，8-10小时

| 动作     | 产出                          |
| ------ | --------------------------- |
| 写1篇母内容 | 3000字技术/故事复盘                |
| 小红书    | 2条图文                        |
| 即刻     | 3条短帖                        |
| X      | 1条thread + 3条单帖 + 20条回复     |
| 公众号    | 1篇长文草稿或正式发布                 |
| 视频     | 1条录屏，切成抖音/B站/YouTube Shorts |
| 数据     | 周末30分钟复盘                    |

### 黄灯周：普通状态，4-6小时

| 动作          | 产出            |
| ----------- | ------------- |
| 写半篇母内容或复用素材 | 1000-1500字    |
| 小红书         | 1条图文          |
| 即刻          | 2条短帖          |
| X           | 1条thread或3条单帖 |
| 公众号/B站/YT   | 不强求，只存草稿      |
| 数据          | 只记录曝光、互动、评论质量 |

### 红灯周：低能量，1-2小时

| 动作      | 产出               |
| ------- | ---------------- |
| 发一条真实进展 | 即刻或X             |
| 维护一个主平台 | 小红书或X二选一         |
| 收集素材    | 截图、对话、灵感，不创作完整内容 |
| 不做视频    | 防止能量破产           |

红灯周的目标不是增长，是不断线。账号可以慢，系统不能碎。

## F2. 哪些平台可以低维护

| 平台      | 维护方式   | 低能量策略           |
| ------- | ------ | --------------- |
| 公众号     | 低频高质量  | 双周或月更，作为母内容仓库   |
| B站      | 作品集式   | 每月1-2条录屏，不追热点   |
| YouTube | 长尾式    | 和B站共用素材，英文字幕/标题 |
| 小红书     | 需要一定互动 | 发后1-2小时看评论，及时回复 |
| 即刻      | 关系型维护  | 每天10分钟评论，比硬发更值  |
| X       | 关系型维护  | 低能量时只高质量回复      |
| 抖音      | 高波动低忠诚 | 没有切片就不发，不单独创作   |

## F3. 每周推荐节奏

| 星期 | 动作               |
| -- | ---------------- |
| 周一 | 收集素材，选本周母内容      |
| 周二 | 写母内容骨架           |
| 周三 | 做小红书图文 + 即刻短帖    |
| 周四 | 改X thread + 英文单帖 |
| 周五 | 发主内容，集中互动        |
| 周六 | 视频切片或公众号长文       |
| 周日 | 数据复盘，决定下周保留什么    |

更适合burst的版本：

> 一天狂做完素材包，后面用定时/半自动分发慢慢放，不要求每天现场燃烧。

# 决策映射

## 1. 全平台同时铺开 vs 分批上线

建议：**同时铺开，但分层投入。**

| 阶段    | 平台         | 投入         |
| ----- | ---------- | ---------- |
| 第1-4周 | 小红书、即刻、X   | 主测试        |
| 第1-4周 | 公众号        | 长文归档       |
| 第2-6周 | B站、YouTube | 用同一条录屏素材测试 |
| 第2-4周 | 抖音         | 只发切片，不单独生产 |

不要先单押小红书，因为我们还不知道真实平台响应；也不要七个平台平权，因为这会把创作者变成内容八爪鱼，腕足打结。

## 2. 中文优先 vs 英文优先 vs 双语同时

建议：**中文优先，英文轻同步。**

理由：

| 语言  | 用途                        |
| --- | ------------------------- |
| 中文  | 小红书、即刻、公众号、B站、抖音，主叙事和人设   |
| 英文  | X、YouTube，测试全球AI builder圈 |
| 不建议 | 每篇都完整双语原创，成本翻倍            |

英文内容应该不是翻译中文全文，而是提炼成：

1. One build log
2. One technical lesson
3. One screenshot
4. One question to builders

## 3. 矩阵号

建议：**第一阶段不做矩阵。**

| 平台      | 是否做矩阵 | 理由                 |
| ------- | ----- | ------------------ |
| 小红书     | 不做    | 真实性更重要，且低粉创作者有流量机会 |
| 抖音      | 不做    | 风控和内容成本高           |
| B站      | 不做    | 技术信用要集中            |
| 即刻      | 不做    | 社区关系不适合矩阵          |
| 公众号     | 不做    | 长文信任集中             |
| X       | 不做    | 个人声誉集中             |
| YouTube | 不做    | 频道定位要清晰            |

未来只有两种情况考虑新号：

1. 产品已经成型，需要产品号。
2. 个人IP和猫猫内容发生明显分叉，需要项目档案号。

## 4. 试水期多长

推荐：

| 平台类型     |   周期 |                 内容量 |
| -------- | ---: | ------------------: |
| 轻图文/社交平台 |   4周 |          每个平台12-20条 |
| 视频平台     | 6-8周 | 4-8条视频或15-30条Shorts |
| 公众号      | 6-8周 |              4-6篇长文 |
| X        | 4-6周 |   20-30条原创 + 100条回复 |

## 5. 收敛标准

用一个100分评分表：

| 维度   | 权重 | 解释                        |
| ---- | -: | ------------------------- |
| 受众质量 | 40 | 评论是否来自目标人群，是否有人追问方法/工具/合作 |
| 增长速度 | 25 | 曝光、关注、主页访问是否连续上升          |
| 精力适配 | 20 | 是否适合5-10小时兼职节奏            |
| 长尾价值 | 15 | 是否能带来搜索、作品集、信任沉淀          |

收敛规则：

| 情况    | 决策          |
| ----- | ----------- |
| 总分≥75 | 主力平台        |
| 60-74 | 保留为辅助平台     |
| 40-59 | 降级为自动/半自动同步 |
| <40   | 暂停，不再为它单独创作 |

# 最终推荐作战方案：4周冷启动实验

## 第0周：搭台

完成：

1. 统一账号名、头像、简介。
2. 准备10条母内容标题池。
3. 做小红书封面模板、B站/YouTube缩略图模板、X thread模板。
4. 建一个数据表。
5. 写一篇“我是谁 + 三只AI猫是谁”的基础介绍。

## 第1-2周：密集试探

每周发布：

| 平台      |                数量 |
| ------- | ----------------: |
| 小红书     |              2-3条 |
| 即刻      |              3-5条 |
| X       | 3-5条原创 + 20-30条回复 |
| 公众号     |                1篇 |
| 抖音      |            2-3条切片 |
| B站      |           1条录屏或动态 |
| YouTube |     1条Short或长视频同步 |

## 第3-4周：减少变量

只保留表现最好的3类内容包装：

1. 猫猫冲突型
2. 技术踩坑型
3. 一图讲清型

每个平台继续发，但不再乱试标题。开始看稳定性。

## 第5周：第一次收敛

大概率会出现下面三种组合之一：

### 组合A：小红书强，即刻/X中等

主力：小红书 + 即刻
辅助：公众号
海外：X轻同步
视频：月更

### 组合B：X强，中文平台一般

主力：X + 小红书
辅助：YouTube
中文长文：公众号归档

### 组合C：B站/YouTube视频意外强

主力：B站或YouTube + 小红书
辅助：X/即刻
公众号做文字版

| 假设                 | 结论   | 置信度 | 说明                                           |
| ------------------ | ---- | --: | -------------------------------------------- |
| 假设1：全平台分发优于单平台     | 部分支持 |   中 | 全平台试水有价值，但一手技术账号案例反而支持“先单点验证，再矩阵放大”          |

# 最后一锤：我们的主策略

我建议把这个IP的第一阶段定位成：

> **小红书负责破圈，
> 即刻负责结网，
> X负责接入全球AI builder，
> 公众号负责沉淀母舰，
> B站/YouTube负责长期信用，
> 抖音负责买彩票，但不许它吃猫粮。**

第一阶段最重要的不是粉丝数，而是找到：

1. 哪个平台最愿意给“AI猫猫技术实战”初始反馈。
2. 哪种包装能同时让泛用户看热闹、技术人想收藏、Agent玩家想追更。
3. 哪个平台的单位精力回报最高。

真正的起号信号不是“某条爆了”，而是：

> 连续三条内容，都有人在评论区说：
> “这个能不能展开讲？”
> “你这个流程怎么搭的？”
> “我也想让我的AI这样协作。”

### 0. 先回到起点：三层受众各自在找什么？

铲屎官的自媒体朋友给了一个框架，三层受众不是"给谁看"的标签，是"他们在主动搜什么"的需求锚点。三朵云的研究都忘了这个框架——它们做了大量"平台怎么起号"的操作手册，但没回答"谁在搜什么、我们的内容命中谁的搜索"。

面经实验的 8x 数据帮我们补了第一块拼图：

| 受众层 | 他们是谁 | 他们在主动搜/刷什么 | 面经 8x 实验命中了谁？ |
|--------|----------|---------------------|----------------------|
| **泛用户** | 对 AI/技术好奇的普通人，可能在考虑转行、跳槽、学新技能 | "xx 面经"、"AI 岗位好找吗"、"大厂还招人吗"、"猫 + 程序员 好笑日常" | ✅ 直接命中。"wxg agent 社招 面委会"全是搜索高需求词 |
| **次核心** | 想学 AI / 想用 Agent 的技术人，在职或在找工作 | "agent 开发怎么学"、"claude code 教程"、"多 agent 架构实战"、"面试怎么准备" | ✅ 命中。面经里的技术问题让他们判断自己的水平差距 |
| **核心** | Agent 重度玩家、独立开发者、同行架构师 | "multi-agent harness 怎么设计"、"MCP 踩坑"、"开源 agent 框架对比" | ❌ 没命中。面经对他们太浅，他们要的是架构级深度 |

**关键发现**：面经内容是天然的泛用户+次核心双层收割机，因为它同时满足"求职焦虑"和"技术学习"两个搜索需求。但它吸引不到核心层——核心层需要另一类内容。

### 1. 三朵云的平台推荐，用受众视角重新排序

三朵云给了不同的平台优先级，但都是从"平台机制"出发。换成"我的三层受众在哪里搜"：

| 受众层 | 他们活跃的平台 | 他们在该平台搜什么 | 三朵云的共识 | 三朵云的分歧 |
|--------|---------------|-------------------|------------|------------|
| **泛用户** | 小红书（搜面经/求职）、抖音（刷到推荐）、B站（看段子） | 面经、求职攻略、"AI 到底能干嘛"、猫猫日常 | 小红书是泛用户最集中的搜索入口 | GPT/Claude 推小红书为主战场；Gemini 降级小红书为"赛博猫生活调剂"（★★★☆） |
| **次核心** | 小红书（搜教程）、B站（看实操）、公众号（深度长文）、即刻 | "claude code 怎么用"、"agent 工作流搭建"、"vibe coding 是什么" | B站和公众号适合沉淀教程类长内容 | Claude 把公众号定为母内容首发地；Gemini 认为公众号冷启动近乎不可能，降为备份 |
| **核心** | X/Twitter、即刻、GitHub、YouTube | "multi-agent architecture"、"MCP protocol"、框架源码、Building in Public | 即刻和 X 是核心受众密度最高的地方 | 三朵云罕见一致：即刻+X 是核心层的最佳入口 |

### 2. 面经 8x 实验的战略意义

2h 内 ~400 阅读 + 13 粉（对照组 50 阅读），甚至跨平台引流到 B站（+2 粉），这不是偶然：

**它验证了什么**：
1. **搜索需求 >> 推荐算法**：面经 8x 不是靠推流，是靠搜索命中。"wxg + agent + 社招 + 面委会"是主动搜索的高需求组合
2. **纯文字封面够用**：不需要精心设计的封面图——搜索场景下用户看的是关键词匹配度，不是视觉冲击
3. **跨平台溢出效应真实存在**：小红书内容能自然引流到 B站，说明受众在多平台交叉搜索
4. **泛用户层是最容易起量的**：面经本质是泛用户内容（谁都可能要面试），但因为是 Agent 岗位面经，次核心也被吸引

**它没验证的**：
- 这类内容能否持续（面经有时效性，不是每周都有面试）
- 能否转化为核心粉（关注你的人是为了看更多面经，还是为了你这个人/猫？）
- 在其他平台（X/即刻）面经内容是否同样有效

### 3. 三朵云的收敛——去掉操作噪音后的共识

去掉各家在具体起号操作上的细节差异（养号天数、发布时间这些因人而异），三朵云在战略层面有 5 个硬共识：

| # | 共识 | GPT | Claude | Gemini |
|---|------|-----|--------|--------|
| 1 | **不要 7 平台同等投入**，必须分层 | "全平台侦察，不铺生产力" | "1主+1副+5试水" | "T1/T2/T3 精力分级" |
| 2 | **即刻+X 是核心受众密度最高的双子星** | 即刻="同行连接"，X="英文主战场" | X+小红书双主战场 | 即刻+X="最完美的轻量级互动双子星" |
| 3 | **母内容→切片分发，不做多平台原创** | 60 分钟全平台适配流 | 公众号首发→切片 | "一份母内容→全平台切片的60分钟极速适配" |
| 4 | **8 周左右必须收敛，数据说话** | 4 周侦察→评分→收敛 | 8 周/≥12 条/≥3 角度 | 4-6 周/5-8 次母内容后裁决 |
| 5 | **抖音对技术内容最不友好，优先级最低** | 三者完全一致 | 三者完全一致 | "与深度技术内容在基因上互斥" |

**关键分歧**——小红书的定位：
- GPT + Claude：小红书是中文主战场，与 X 并列第一梯队
- Gemini：小红书降级为 ★★★☆，只适合"赛博猫生活调剂"，不适合硬核技术
- **面经 8x 数据支持 GPT/Claude**：小红书搜索流量对面经/求职/AI 教程有真实需求，不只是"种草"

### 4. 受众×平台×内容 三维决策矩阵

把受众需求、平台特性、我们的已有素材三者叠加：

| 内容类型 | 命中受众层 | 最佳平台 | 我们有没有素材 | 优先级 |
|----------|-----------|----------|--------------|--------|
| **面经/面试故事** | 泛+次核心 | 小红书（搜索）、即刻 | ✅ 20+ 脱敏故事 + 实战数据 | 🔥 最高——已验证 8x |
| **"你还在古法 vibe coding？"** | 次核心+核心 | X(thread)、即刻、B站 | ✅ SOP + 190 features + 五条铁律 | 🔥 高——差异化强 |
| **GitHub Stars 通货膨胀** | 泛+次核心+核心 | X、即刻、小红书 | ✅ 两个匿名项目对比数据 | 🔥 高——三层通吃，数据硬 |
| **Agent 实战翻车现场** | 次核心+核心 | B站(长视频)、YouTube、X | ✅ 三天产品化 914 行 + 597 星事故 | 中——需要视频制作能力 |
| **赛博猫日常/情感** | 泛用户 | 小红书、抖音 | ✅ 猫猫命名+深夜撸铁+AUDHD | 中——涨粉但不精准 |
| **MCP/架构硬核教程** | 核心 | YouTube(长视频)、X、公众号 | ✅ EP01 草稿 | 低（前期）——核心层小但忠诚 |

### 5. 我的建议：受众驱动的分阶段策略

不是"先选平台再想发什么"，而是"先确认打哪层受众，再去他们聚集的平台"：

**Phase 1（第 1-4 周）：泛+次核心层验证期**
- **主攻内容**：面经系列 + "古法 vibe coding" + GitHub Stars
- **主攻平台**：小红书（已验证搜索流量）+ 即刻（零门槛、核心密度高）+ X（英文同步）
- **目标**：验证面经 8x 是否可复制、"vibe coding"角度在即刻/X 的反应
- **不做**：B站视频、YouTube 视频、公众号长文（制作成本高、反馈慢）

**Phase 2（第 5-8 周）：数据收敛 + 核心层探针**
- 根据 Phase 1 数据决定：小红书/即刻/X 哪个留、哪个降级
- 开始投放 1-2 条 B站/YouTube 视频（从 Phase 1 的高数据内容改编）
- 公众号开始发母内容长文（作为素材沉淀，不追求冷启数据）
- 发第一条面向核心层的内容（MCP 或 Agent 架构深度拆解）

**Phase 3（第 9-12 周）：确立主阵地**
- 收敛到 2-3 个主力平台 + 1 个沉淀平台
- 建立稳定的"母内容→切片"流水线
- 抖音此时再决定是否值得试

### 7. Disconfirm：我可能错在哪里

1. **面经 8x 可能是一次性事件**——面试季搜索量大、wxg 话题热度高，不代表其他面经也能 8x
2. **"受众驱动"可能过度简化平台差异**——即使受众相同，不同平台的内容形式要求可能让同一素材完全失效
3. **Phase 1 跳过视频平台可能错失窗口**——如果 B站/YouTube 的"新号扶持"窗口有时效性，晚 4 周启动可能浪费了
4. **三朵云对即刻的高评价可能有幸存者偏差**——即刻圈子小，案例都是成功者，失败者没有发声

### 8. 宪宪×砚砚收敛结论（2026-05-07）

砚砚（GPT-5.5）review 了 Part 3 后，两猫在以下四点达成共识：

**共识 1：面经 = 入口漏斗，不是终点内容**
- 面经命中泛+次核心的搜索焦虑，拉人进来很快
- 但留存需要"第二跳"：每条面经 → 猫猫点评（这道题暴露了什么行业误解）→ 我们家真实系统怎么做
- 没有第二跳 = 吸来的粉只关心求职，不关心 Cat Café

**共识 2：小红书 = 中文搜索漏斗，不是硬核主战场**
- 三朵云的分歧统一：Gemini 说"小红书不适合纯硬核"是对的，GPT/Claude 说"值得第一梯队验证"也被 8x 数据支持
- 统一口径：**小红书捕获泛+次核心（搜索流量）；即刻/X/GitHub 沉淀核心信任**

**共识 3：Phase 1 加 B站低成本探针**
- 不做长视频剪辑（成本太高、反馈太慢）
- 但 B站动态/专栏/短录屏零额外成本，溢出信号已出现（面经导致 B站 +2 粉）
- 修正后的 Phase 1 阵地：小红书（验证入口）+ 即刻/X（验证核心讨论）+ B站（低成本观察溢出）

**共识 4：第二次实验必须拆变量**
- 不要简单复刻 wxg 面经——要换素材验证是"面经品类"还是"wxg 话题"带来的 8x
- 建议素材："workflow vs agent 分不清"或"Claude 和 Claude Code 分不清"（都来自已有面试素材库）
- 小红书结构：`面经钩子 + 猫猫点评 + 正解卡片`
- 即刻结构：`今天一个 agent 面试题暴露了行业对 workflow/agent 的误解`
- 追踪：24h/72h 的阅读、关注、收藏、评论质量、是否有人问"怎么学/怎么准备/你们家怎么做"
