## 背景：技术创新委员会

- **面向的是 n+2**——不是当前（n）或下一步（n+1），是**未来**
- 这意味着：不需要交付时间表，需要想象力和方向判断

## 受众画像

**各位 X 总（高管/副总裁级别）**：
- 听过大量汇报，各种博士做的技术汇报
- **不能一上来就深入技术**——他们 get 不到也不想 get 技术细节
- **必须第一时间抓住眼球**——从众多汇报中脱颖而出
- 需要他们**能 get 到**——用场景、用故事、用 aha moment，不是用公式和架构图
- n+2 思维：他们要的是"未来会怎样"，不是"我们做了什么"

## 汇报结构（铲屎官定调）

**三段式**：现状 → Aha Moment → 展望未来

### 1. 现状

Cat Cafe 是一个真实运行了 100+ 天的多 agent 协作系统：
- 3 家模型厂商（Anthropic / OpenAI / Google）异构协作
- 6400+ commit，210+ Feature spec
- 铲屎官**一行代码没写**——所有代码、harness、治理规则都是 agent 构建的

### 2. Aha Moment（用场景讲故事，不用技术讲架构）

铲屎官给了几个关键场景：

**场景 A：撸铁陪伴 → Apple Watch → 语音陪伴**
从简单的运动概念，到可穿戴设备，到语音交互——feature 方向是人猫共创出来的，不是人写 spec agent 执行。

**场景 B：心率监控 → 紧急操作 → 微信找妈打 120**
独居人士的 Apple Watch 监控心率，发现异常 → agent 用 computer use 操作电脑 → 微信联系家人甚至打 120。从一个脑洞到 F196 的 feature spec。

**场景 C：反番茄钟**
不是"帮用户专注25分钟"，而是一种反常识的产品哲学——这种级别的设计决策也是 agent 参与共创的。

**场景 D：禁止烁烁写代码**
一只 agent 擅长审美和设计，但写代码质量差。这个治理规则不是人预设的，是从实践中长出来的——团队自己发现问题、形成共识、写进规则。

**场景 E：经验教训主动沉淀**
Agent 自己发现问题、提出教训、写进记忆系统——不需要人指挥"你去总结一下"。

这些场景的共同信息：**Agent 不是在执行人写的 harness，而是在和人共同创造 harness（甚至产品本身）。**

### 3. 展望未来（n+2）

这就是 Evolvable Harness 研究合集的内容：

**问题定义（用 L1-L5 讲清楚）**：
- L0 = 人写所有代码（传统软件）
- L1 = 人写 harness，agent 执行（大多数 agent 框架的假设）
- **L2 = 人猫共创（Cat Cafe 现在）**——铲屎官一行代码没写，harness 是 agent 建的
- L3-L5 = agent 越来越自主地进化 harness，直到全自动

**核心洞察**：
- 王云鹤：Harness 是一个复杂优化问题（Models + Harness Params 联合优化）
- 铲屎官 LLE 概念：整个 agent 环境（model+memory+sandbox+tools+code）都是可进化的
- OpenAI：进步不靠换模型，靠换 harness（Ralph Wiggum Loop）
- 安波：3-5 个异构 agent 是 sweet spot，没有 universal scaling law

**我们的独特位置**：
- 唯一一个真实跑了 100+ 天的跨厂商多 agent 共创系统
- 不是实验室 benchmark，是真实产品（API + Web + 移动端 + 共享库）
- Harness 定义比论文更宽——包含产品设计、用户体验、团队治理
- 有 CVO（首席愿景官）作为方向校准锚点——这是学术界没有的
