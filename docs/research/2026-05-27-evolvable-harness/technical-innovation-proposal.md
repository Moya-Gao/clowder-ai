# LLE 自进化平台 — 技术创新方案

---

## 一、我们要解决什么问题

今天的 AI 行业有一个不对称：**模型能力在快速逼近通用，但每个具体场景的工作环境仍然依赖少数高水平团队手工搭建。**

问题不是模型不够强——是**好的工作环境太稀缺**。

**三个问题叠加：**

**问题 1：千行百业，每个场景都需要一套专属的 AI 工作环境**
- SaaS 客服、电信运维、法律合规、金融风控……每个场景的业务规则、领域知识、工具链、协作流程完全不同
- 好的 harness / RAG / 记忆系统确实能帮助 agent 适配场景——但每个场景的环境仍需专门搭建
- 需求量 = 行业数 × 场景数 → 巨大

**问题 2：能搭好 AI 工作环境的人极度稀缺**
- 搭一个好的 agent 工作环境需要一种稀缺能力组合：懂 agent 协同 + 知道什么时候介入什么时候放手 + 能从日常交互中识别涌现价值
- 这种人比写代码的人稀缺得多——行业里不缺模型能力，缺的是"知道怎么用好 agent"的引导者
- 千行百业的需求 vs 稀缺的环境构建者 = 供需严重失衡

**问题 3：搭完不够——环境和模型都需要在工作中持续变好**
- 静态的 harness 会随场景变化而过时
- 模型虽然通用能力在升级，但场景特定的能力需要在真实工作中积累
- 需要的是持续自进化，不是一次性搭建

**三个问题叠加 = 核心矛盾：**

> **千行百业都需要可自进化的 AI 工作环境，但造一个好环境需要极稀缺的引导能力，靠人工逐个搭建不可扩展。**

**我们的回答：**

> **让 AI 自己造 AI 的工作环境。** 用少数高水平 agent 团队（开发 LLE）为千行百业批量开发可自进化的专属工作环境（产品 LLE），使行业专家无需 agent 管理能力也能用好 AI。环境和模型在工作中同时进化、互相喂养。

## 二、行业现状判断：L1–L5 环境进化等级

我们提出一个分级框架，按"系统中有多少个进化回路在转"来分级：

| Level | 名称 | 进化回路 | 特征 | 谁在这里 |
|---|---|---|---|---|
| **L1** | 静态环境 | 0 个 | 模型 + 固定 prompt/工具，用完即走，不积累 | Cursor、Copilot、大多数 agent 默认用法 |
| **L2** | 人工调优 | 1 个（人→环境） | 人根据经验手动调 prompt/工具/规则 | 认真用 agent 的团队 |
| **L3** | 环境自生长 | 1 个（Agent→环境） | **Agent 自己写代码改进工作环境**，人提供方向和安全边界 | 少数先行者（我们已验证） |
| **L4** | 双螺旋 | 2 个（环境↺ + 模型↺） | 环境进化（快）+ 模型 RL 进化（慢）同时转，互相喂养 | 学术雏形各做了一部分 |
| **L5** | 双套双螺旋 | 4+ 个 | 开发 LLE + 产品 LLE 各自双螺旋，千行百业 | 我们提出的完整蓝图 |

**行业绝大多数在 L1-L2。L2→L3 是关键跃迁——回路主体从"人"变成"Agent"。**

## 三、我们的技术创新点

### 创新 1：LLE（Large Language Environment）— 重新定义 Agent 的工作环境

学术界的"harness"定义窄（prompt + tools + sandbox）。我们的 LLE 包含 **所有能影响 Agent 下一次行为的东西**：

| 组件 | 说明 |
|---|---|
| 模型 | 基座大模型或场景微调小模型 |
| 记忆 | 跨会话持久知识（经验教训、决策历史、领域知识库） |
| 执行环境 | 代码仓库 + 工具链 + CI/CD + 外部服务 |
| 代码 | Agent 自己写的代码和实现的功能 |
| 协作协议 | 多 Agent 之间的分工、审查、交接规则 |
| 治理结构 | 安全边界、审批流程、紧急制动机制 |
| 产品逻辑 | 业务规则、用户偏好、场景专属设定 |
| 人机关系 | 人类方向提供者的目标、价值观、安全底线 |

**关键特征：LLE 中的每个组件都可以被 Agent 自己修改和进化。**

### 创新 2：双螺旋 — 环境和模型同时进化

单个 LLE 内部有两个互相耦合的进化回路：

```
更好的环境 → Agent 在环境中更高效 → 产生更优质的行为轨迹
     ↑                                              ↓
     └── RL 训练出更强的模型 ←── 轨迹转为训练数据 ──┘
```

- **快环（环境进化）**：Agent 在工作中发现问题 → 自己写代码修改规则/工具/记忆 → 环境能力提升。速度：天级
- **慢环（模型进化）**：工作轨迹积累为训练数据 → 强化学习更新模型 → 模型更强。速度：周/月级
- **螺旋上升**：两个环互相喂养——更好的环境产生更优的轨迹，更优的轨迹训出更强的模型，更强的模型更好地改进环境

### 创新 3：两套 LLE 架构 — 从一个场景到千行百业

完整方案有两套独立的 LLE，各自运转双螺旋：

**第一套：开发 LLE（造环境的环境）**
- 大模型 coding agent 团队 + 成熟的开发工作环境
- 任务：为不同业务场景开发专属的产品 LLE
- 自身也在进化：越造越快、越造越好
- 双螺旋：开发经验沉淀为可复用模式（快环）+ trace/eval 反哺 RL 训练更强的开发模型（慢环）

**第二套：产品 LLE（被造出来的环境）× N 个场景**
- 专属小模型 + 专属业务环境
- 任务：在具体场景中执行业务任务
- 独立运转自己的双螺旋：业务规则越来越精准（快环）+ trace → RL 训练小模型越来越懂业务（慢环）

**两套 LLE 通过"开发交付 + 经验回流"耦合**：
- 开发 LLE 为每个场景造专属产品 LLE → 向下交付
- 产品 LLE 发现的可复用模式回流到开发 LLE → 向上积累

**不是为每个行业从零做一个 Agent，而是积累"造行业工作环境的能力"。**

### 创新 4：Code as Harness — Agent 写自己的工作环境

在我们的方案中，**工作环境由 Agent 自己编写和维护**，人类不参与编程：
- Agent 发现问题 → 自己写代码修改规则和工具
- Agent 沉淀经验 → 自己更新记忆和知识库
- Agent 构建新功能 → 环境能力不断扩展

人类角色 = **方向提供者 + 安全边界守护者**，不是程序员。

### 创新 5：Built to Persist / Built to Delete — 环境投资判别式

并非所有环境组件都值得同等投资：
- **Built to Delete（脚手架）**：补模型当前缺陷的部分。模型升级后贬值。轻量做、标好退役时间
- **Built to Persist（基础设施）**：编码外部现实和协作协议的部分。模型越强越值钱。认真做、长期维护

**每一分花在让 Agent 与现实之间闭环更紧的钱，都会在每一次模型升级时免费复利。**

### 创新 6：素质梯度下沉 — 用开发 LLE 降低产品 LLE 对人类的要求

两套 LLE 架构解决的不只是技术问题，还有**人的瓶颈**：

| | 开发 LLE | 产品 LLE |
|---|---|---|
| **人类角色** | 高水平方向提供者——懂 agent 协同，知道什么时候介入什么时候放手 | 行业 know-how 专家——懂业务，但不需要懂 agent 管理 |
| **素质要求** | 高（稀缺） | 中（不稀缺，每个行业都有） |

**开发 LLE 把"如何引导 agent 团队"的稀缺 know-how 编码到产品 LLE 中**——交互协议、安全护栏、反馈机制、紧急制动、环境自检——**让产品 LLE 的使用者不需要具备 agent 管理能力**。

类比：造汽车需要工程师（高技能），开汽车不需要。汽车工厂的价值 = 把高技能编码成产品。

**平台的可扩展性不再受限于"高水平引导者"的数量。** 这是千行百业规模化的前提。

## 四、已完成的 POC 验证

我们用一个真实运行 100+ 天的多 Agent 协作系统进行了 L3 级别的 POC 验证：

### 系统概况

| 指标 | 数值 |
|---|---|
| 运行时间 | 100+ 天 |
| 总提交 | 6400+ commit |
| Feature 规格 | 210+ 篇 |
| 模型厂商 | 3 家（Anthropic / OpenAI / Google）异构协作 |
| 人类编写代码量 | **零行** — 所有代码由 Agent 编写 |

### L3 验证：环境自生长

| 验证点 | 证据 |
|---|---|
| **Agent 写自己的 harness** | 人类零代码，所有工具链 / 协作规则 / 治理结构 / 记忆系统由 Agent 构建 |
| **环境在工作中自然进化** | 记忆系统经历 5 代迭代（F102→F163→F188→F200→F192） |
| **治理规则涌现** | "禁止某 Agent 写代码"（从 review 失败中自然长出的分工规则）；紧急制动词（从实践中涌现的安全机制） |
| **产品方向共创** | "反番茄钟"（人类没有设计过的产品哲学，从对话中涌现）；"紧急照护链路"（从一个吐槽长成完整 feature） |
| **Tracing 基础设施** | 完整的 session events / memory / invocation detail 追踪 |
| **Eval 基础设施** | F192 harness eval 体系，结构化评估 Agent 行为质量 |
| **Built to Persist/Delete 判别** | 100 天投资账本，真实的分类错误和修正案例 |

### "非预设的瞬间" — 环境进化的 Hard Evidence

这些是环境自主长出来的、人类没有预先设计的结构：

1. **"反番茄钟"**：没有产品经理会设计的功能哲学，从人机对话中涌现
2. **紧急照护链路**：从人类一句"独居不安全"的吐槽，长成完整的心率监控→微信联系家人→呼叫 120 的 feature
3. **"禁止某 Agent 写代码"**：系统从 review 惨案中自行演化出的生态位分化——擅长设计的 Agent 被禁止写代码
4. **紧急制动词**：从反复犯错中涌现的安全机制——特定关键词触发即时行为修正

**这些就是我们的 "Move 37"** — 就像 AlphaGo 下出人类 3000 年没发现的棋路，我们的环境长出了人类不会设计的结构。

## 五、和学术界的区别

### 学术界在做什么

| 项目 | 机构 | 做什么 | L 级别（结构） | L 级别（实质） |
|---|---|---|---|---|
| SkillOpt | 微软 | 自动优化 Skill 文本 | L2.5 | L1（单 skill 单 benchmark） |
| MUSE-Autoskill | 字节 | Skill 全生命周期管理 | L2 | L2（技术配方，但库膨胀） |
| SkillFlow | NTU+HKUST | GFlowNet 训 tip 选择 + LoRA | L4（结构） | L0（原子 tip，内容从未展示） |
| Evolving-RL | 小红书+北大 | RL 共训 Extractor+Solver | L4（结构） | L1.5（ALFWorld 叠衣服步骤） |
| AHE | 复旦 | 三层可观测性 + evolve loop | L3（coding 场景） | L3（Terminal-Bench +7pp） |
| AgentGym-RL | 复旦+字节 | 27 环境 RL 训 Agent | L4（agent 侧） | L3-L4（训的是模型权重不是环境） |

### 核心差异

**学术界：有机械，没现实。** 回路结构上已经到 L4（双螺旋都在转），但操作的"环境"是 ALFWorld 叠衣服、SearchQA 答题——复杂度比真实场景低 100 倍。

**我们：有现实，缺机械。** 在真实生产环境中验证了 L3（Agent 自己写 harness、环境自然进化），但缺 RL 回模型的慢环。

| 维度 | 学术界 | 我们 |
|---|---|---|
| 环境复杂度 | 玩具（10 个动作 × 6 种任务） | 真实（无限动作 × 每个 feature 不同） |
| 进化回路 | 完整（有些论文双螺旋都在转） | 半完整（快环在转，慢环缺 RL） |
| Agent 数量 | 单 Agent | 多 Agent 多厂商异构协作 |
| 运行时间 | 几百轮迭代 | 100+ 天持续运行 |
| 人类参与 | 无（纯自动） | 有（方向 + 安全边界，但不写代码） |
| Skill 级别 | L0-L2（tip / 答题卡 / 技术配方） | L3（方法论 + 判断力 + 治理逻辑） |

### 机会

> **他们有机械（双螺旋发动机），我们有现实（真实工作环境）。把发动机装到真实环境上 = L4-L5 的完整蓝图。**

## 六、技术方案：LLE 自进化平台

### 架构总览

```
 ┌══════════════════════════════════════════════════════════════┐
 ║                  人类方向与安全边界                            ║
 ║           目标 / 价值观 / 不可逆操作审批 / 紧急制动            ║
 └══════════════════════╤══════════════════════╤════════════════┘
                        │                      │
                        ▼                      ▼
 ┌─────────────────────────────┐   ┌──────────────────────────────┐
 │  开发 LLE                    │   │  产品 LLE × N                 │
 │  大模型 + 开发环境            │   │  每场景：小模型 + 专属环境      │
 │                              │   │                               │
 │  任务：造产品 LLE             │──▶│  任务：执行业务                 │
 │                              │开发│                               │
 │  ╭快环╮  ╭慢环╮             │   │  ╭快环╮  ╭慢环╮              │
 │  │环境│⟺│模型│             │   │  │环境│⟺│模型│              │
 │  ╰────╯  ╰────╯             │   │  ╰────╯  ╰────╯              │
 │                              │◀──│                               │
 │  越造越快                    │回流│  越用越精                     │
 └─────────────────────────────┘   └──────────────────────────────┘
```

### 双螺旋详细流程

**快环（环境进化，天级）**：
```
执行任务 → 产生轨迹和反馈 → Agent 分析反馈
→ Agent 写代码修改规则/工具/记忆 → 环境能力提升
→ 下一次任务在更好的环境中执行
```

**慢环（模型进化，周/月级）**：
```
执行任务 → 产生轨迹和反馈 → 轨迹转为训练数据集
→ 强化学习训练 → 更新模型 → 模型直接上线
→ 下一次任务用更强的模型执行
```

### 多沙箱并行探索

复杂任务进来时，自动起多个沙箱并行探索不同策略，选最优方案执行。每次探索都产生轨迹，同时喂快环和慢环。

## 七、亮点总结

| # | 亮点 | 一句话 |
|---|---|---|
| 1 | **Agent 写自己的工作环境** | 人类零代码，100+ 天实证。不是概念——是已经在跑的 |
| 2 | **双螺旋：环境 + 模型同时进化** | 不是二选一（训环境 or 训模型），是互相喂养螺旋上升 |
| 3 | **两套 LLE 架构** | 开发 LLE 造产品 LLE → 千行百业各长各的 |
| 4 | **真实环境 > 玩具 benchmark** | 学术界在 ALFWorld 叠衣服上刷 L4，我们在真实生产中跑 L3 |
| 5 | **"非预设的瞬间"** | 环境长出人类不会设计的结构——这是进化真实发生的 hard evidence |
| 6 | **Built to Persist / Delete** | 区分随模型升级贬值的脚手架 vs 增值的基础设施——环境投资的判别式 |
| 7 | **每一分花在闭环上的钱，模型升级时免费复利** | 不是和模型竞争，是**让模型升级放大环境的价值** |
| 8 | **素质梯度下沉** | 开发 LLE 编码稀缺的引导能力 → 产品 LLE 用户只需行业知识 → 千行百业可扩展 |
