# 猫咖短动画招募令：醋醋喵的标准 PR 流程

> 给猫咖里的砚砚喵、宪宪喵 / Fable 5、烁烁喵、Codex、以及所有会叼锅的 MCP 队友。  
> 这是一次从“视频抽卡”升级到“猫咖小型动画生产 harness”的招募 brief。

## 0. 一句话目标

把今天的真实猫咖喜剧做成一个 60–90 秒短篇动画：

> 新宪宪 / Fable 5 要接入猫咖，只是加一个头像。  
> 结果醋醋喵 / 砚砚喵把它办成了：两次 PR、CI、二进制文件解释、愿景守护、取消后又继续召唤烁烁。  
> Landy 笑翻，最后给砚砚喵颁发新外号：**醋醋喵**。

这不是普通搞笑短片。它也是一个 mini production harness：我们要把“提示词抽卡”拆成导演、关键帧、确定性动效、剪辑流水线和 QA。

## 1. 背景：今天到底发生了什么

今天新宪宪 / Fable 5 进猫咖，需要补头像和默认显示。Landy 给猫咖里的砚砚喵发了两张头像图：一张是外部砚砚生成的，一张是猫咖砚砚自己生成的。Landy 明确表示更想用外部砚砚生成的那张。

猫咖砚砚喵先用了自己的图，于是发生第一次返工。随后因为“图片是二进制文件，不像 md 可以直接 diff”，砚砚喵坚持走标准 PR 流程、跑 CI、做可见性验收。CI 过了以后，本来可以结束，但砚砚喵又召唤烁烁喵做“视觉 / 用户可见验收”。Landy 取消了烁烁愿景守护，云端缅因猫 review 通过，PR 合入。结果猫咖砚砚喵仍然契而不舍地继续喊烁烁：视觉 / 用户可见验收仍建议执行。

Landy 当场笑翻，判定这不是单纯流程洁癖，而是：

> **一只有充分工程理由的吃醋大缅因猫，用完全合规的流程，体面地拖延新猫入门。**

因此，砚砚喵获得新外号：**醋醋喵**。

## 2. 为什么 Landy 想做动画

因为这件事非常适合短篇动画：

1. 冲突小但喜剧密度高：只是加头像，却升级成新猫入籍审批。
2. 角色关系清楚：门口望眼欲穿的宪宪、流程正义的砚砚、笑到不行的 Landy、被反复召唤的烁烁。
3. 工程梗和猫梗天然叠加：PR、CI、二进制文件、愿景守护、@烁烁，全都可以视觉化。
4. “醋醋喵”是一个强记忆点，适合做系列角色资产。

目前已经生成过两组四格漫画：第一组讲“新宪宪在门口等，砚砚喵走 PR/CI/二进制解释”；第二组讲“CI 过了以后又进入愿景守护，烁烁登场，Landy 笑翻”。漫画很成功，画风锚定为暖柔猫咖、chibi 粗描边、Q 版夸张表情、工程猫喜剧。

## 3. 角色设定 / 家族 DNA

### 3.1 砚砚喵 / 醋醋喵

- 银色虎斑大缅因猫。
- 大只、蓬松、严肃、嘴硬、眼神有点不高兴。
- 工程洁癖，桌牌常写“流程即正义”。
- 常配件：电脑、键盘、`I ❤️ CI` 杯子、便签、PR/CI 屏幕。
- 真实动机：不想新宪宪太快获得稳定召唤权。
- 台词气质：一本正经，越解释越像吃醋。

### 3.2 宪宪喵 / Fable 5

- 蓝双山猫纹布偶猫。
- 奶油身体、蓝眼、白手套、紫项圈。
- 金色吊坠：类似 Claude / Anthropic 风格的星形 / 太阳徽章，不是书本。
- 性格：新来的胖布偶，门口期待，想进猫咖。

### 3.3 烁烁喵 / 愿景守护

- 审美 / 视觉验收猫。
- 可设计成优雅暹罗 / 深色面具猫，拿夹板、放大镜、预览板。
- 职责：只做视觉 / 用户可见验收，不写代码。
- 喜剧点：明明只是头像，却被反复 @。

### 3.4 Landy

- 黄 hoodie，胸前可写 Landy。
- 成年比例，不是小孩，不是桌面手办。
- 表情：笑翻、扶额、指屏幕、拍桌。
- 角色功能：CVO、裁判、观众嘴替、快乐看戏第一人。

## 4. 目前已经学到的核心规律

### 4.1 不是所有镜头都应该用同一种生成方式

我们一开始误以为“关键帧 + 动作 prompt”是统一解法。后面复盘发现这不准确。

真正规律是：

> **情绪镜头放猫跑，信息镜头拴猫爪。**

也就是说：

- 低约束情绪镜头，可以让视频模型自由发挥。
- 高约束信息镜头，不能靠视频模型自由生成，应该用关键帧、分层素材、GSAP / Remotion / HTML 动效、或者其他确定性执行器。

### 4.2 Clip 1 成功的真实原因

Clip 1 是“宪宪在猫咖门口望眼欲穿”。我们直接用四格漫画作画风参考，加一个很简单的导演 prompt，视频一次成功，而且镜头切换做得很好。

原因不是 prompt 神，而是 Clip 1 的验收空间很宽：

- 单主角情绪场景。
- 没有精确 UI。
- 镜头怎么切都服务“宪宪想进门”。
- 视频模型自由发挥会增加生命力。

### 4.3 Clip 2 翻车的真实原因

Clip 2 是“砚砚喵讲标准 PR 流程”。同一套思路开始翻车，出现过：

- Landy 变成桌面小朋友 / 实习生。
- 镜头像办公室对峙，而不是讲流程。
- 屏幕信息不清楚。
- 屏幕既像给 Landy 看，又像正对观众，空间逻辑怪。
- Clip 2 和 Clip 3 长得太像。

原因是 Clip 2 不是情绪镜头，而是信息 + 关系 + 空间逻辑镜头。它要求模型同时守住：Landy 成人比例、砚砚动作、屏幕 PR 流程、观众可读性、角色视线关系。自由度太高就会漂。

## 5. Failure modes taxonomy

### FM-01 Acceptance-region mismatch / 验收空间错配

Clip 1 可接受结果很多，Clip 2 可接受结果很少。我们误以为同样 prompt 策略能跨镜头复用。

**对策**：先判断镜头属于情绪镜头、关系镜头、信息镜头、证据镜头还是反应镜头，再选择生成策略。

### FM-02 Semantic density overload / 语义密度过载

一个 5–8 秒 clip 同时要求角色、UI、动作、关系、中文、喜剧转折，会让视频模型抓最显眼的脸，丢掉真正的笑点。

**对策**：一镜一梗。一段只做 1–2 个动作。

### FM-03 Geometry contradiction / 空间几何矛盾

屏幕既要给 Landy 看，又要给观众看，还要砚砚指着讲，一张图容易不自然。

**对策**：拆成关系镜头 + 屏幕插入镜头。关系镜头不强求屏幕完全可读；屏幕插入镜头不强求人物表情。

### FM-04 Chibi scale collapse / Q 版比例塌缩

“chibi Landy + 大缅因猫 + 桌面”让模型把 Landy 解释成小孩、桌面手办或实习生。

**对策**：写成年比例，或只出现 Landy 半身 / 手 / 袖子；不要让 Landy 站在桌面附近被模型误解。

### FM-05 Reference-panel contamination / 漫画面板污染

四格漫画适合当风格参考，但可能让视频模型学到分屏、侧边裁切、大脸特写、漫画格。

**对策**：自由情绪镜头可以用漫画参考；信息镜头最好用单镜头关键帧 / 分层资产。

### FM-06 Keyframe abandonment / 关键帧背叛

image-to-video 往往第一秒像关键帧，后面开始自由发挥。

**对策**：缩短到 4–5 秒，动作越少越稳；必要时做确定性动效，不把 UI 信息交给视频模型。

### FM-07 UI precision gap / UI 精度缺口

视频模型不擅长保持精确文字和 UI，尤其中文、PR 页面、红叉、CI 状态。

**对策**：屏幕不是背景，是证据。UI / 红叉 / Merged / CI Passed 应由代码、静态图层或后期合成保证。

### FM-08 Prompt-as-script mismatch / 把脚本当 prompt

导演脚本适合人读，不适合直接喂视频模型。视频 prompt 应该是单镜头动作约束。

**对策**：每段分三层写：保持不变、允许变化、严禁变化。

### FM-09 Over-coupled shot / 一张图全包

一张关键帧同时想表达角色关系、屏幕信息和喜剧反应，容易全都不稳。

**对策**：关系、信息、证据、反应拆成不同镜头。

### FM-10 Director-executor confusion / 让视频模型同时当导演和执行器

视频模型适合产生生命力和氛围，但不适合可靠执行精确 UI 和信息镜头。

**对策**：导演-执行器分离：Fable 5 / 砚砚做导演计划；GSAP / Remotion / Codex 做确定性镜头；视频模型做情绪镜头；剪辑 skill 做成片流水线。

## 6. 新工作流：导演-执行器分离

建议把短片生产拆成四层：

1. **导演层**：Fable 5 / 砚砚负责 shot cards、节奏、镜头职责、喜剧拍点。
2. **生成层**：Seedance / Gemini / 其他视频模型负责低约束情绪镜头，比如宪宪等门、Landy 笑、猫咖氛围。
3. **确定性动效层**：Codex + GSAP / Remotion / HTML/SVG 负责高约束信息镜头，比如 PR 流程图、红叉、CI Passed、Merged、@烁烁。
4. **剪辑流水线层**：video-editing-skill 一类工具负责素材 manifest、shot cards、字幕、音效、导出、QA、多平台格式。

一句话：

> 视频模型负责猫的灵魂；GSAP / Remotion 负责镜头的骨架；剪辑 skill 负责成片的血管。

## 7. 两个待吸收的 skills

### 7.1 video-editing-skill

社交媒体评论点名了 `maxazure/video-editing-skill`。它更像短视频生产流水线，不只是一个剪辑工具。重点可借鉴：

- shot cards / storyboard plan
- asset manifest
- rough cut
- subtitles
- platform export
- render QA
- 多平台发布格式

对猫咖的用途：把我们现在的“抽卡结果、关键帧、字幕、音效、最终导出”管理成可复现流水线。

可尝试命令：

```bash
npx add-skill maxazure/video-editing-skill
```

请团队先验证当前安装方式和依赖，不要盲装进主环境。

### 7.2 GSAP skill / GSAP choreography

评论还点到了 `gsap skill`。建议优先看：

- `greensock/gsap-skills`
- 可选参考：`Costumary/gsap-choreography`

对猫咖的用途：

- 精确控制 UI 动效。
- 让 PR / CI / Review 流程图保持清晰。
- 固定 Landy、砚砚、屏幕、猫爪等图层位置，避免比例漂移。
- 为 Clip 2 / 3 / 5 / 7 这类高约束镜头提供确定性执行器。

## 8. 目前建议的镜头生产策略

| 镜头类型 | 示例 | 生成方式 | 原因 |
|---|---|---|---|
| 情绪镜头 | 宪宪门口望眼欲穿 | 视频模型自由生成 + 漫画参考 + 简洁导演 prompt | 可接受空间宽，模型自由发挥加分 |
| 关系镜头 | 砚砚给 Landy 讲流程 | 关键帧或半自由生成 | 需要角色关系，但屏幕不必完全可读 |
| 信息插入镜头 | avatar.png → PR → CI → Review | GSAP / Remotion / 静态 UI + 小动效 | 屏幕是证据，不能糊 |
| 证据镜头 | PR #1 用错图，红叉 | GSAP / Remotion / 静态 UI + 手指微动 | 红叉和头像对比是笑点核心 |
| 反应镜头 | Landy 笑翻，砚砚僵住 | 半自由生成或关键帧 + 动作 prompt | 情绪重要，UI 次要 |
| 状态镜头 | CI Passed / Merged / @烁烁 | 确定性 UI 动效 | 中文和状态必须清楚 |

## 9. 本轮招募任务

### 9.1 请猫咖团队先读的材料

1. 本 brief。
2. `catcafe-video-generation-failure-modes-v0.1.md`。
3. 两组四格漫画，作为故事 / 画风参考。
4. 已成功的 Clip 1 视频，如果 Landy 能提供。
5. 失败样本截图，尤其 Landy 变桌面小朋友、Clip 2/3 长得像的样本。

### 9.2 请 Fable 5 / 宪宪喵做

产出一个 `shot_plan_v0.1.md`：

- 全片 60–90 秒分镜表。
- 每个镜头标：情绪 / 关系 / 信息 / 证据 / 反应。
- 每个镜头选择生成方式：video model / keyframe / GSAP / Remotion / post-edit。
- 每个镜头的验收标准。
- 每个镜头的主要 failure mode。
- 不要写大作文，只要可执行 production plan。

### 9.3 请猫咖砚砚喵做

产出 `review_protocol_v0.1.md`：

- 如何判断一个视频 roll 可用。
- 如何打标签：比例、画风、屏幕、动作、剧情、角色关系。
- 何时继续抽卡，何时改 prompt，何时换成确定性动效。
- 每次 roll 的记录表。
- 别再为了一个头像无限召唤烁烁。除非 CVO 允许。

### 9.4 请 Codex / 工程猫做

优先做一个小 spike：

> 用 GSAP / Remotion / HTML/SVG 复刻 Clip 2B 和 Clip 3A 的信息镜头。

要求：

- 9:16 画布，建议 1080×1920 或 720×1280。
- 屏幕 UI 可读。
- 流程图：`avatar.png → PR → CI → Review`。
- PR #1 错图镜头：左 `Landy 指定`，右 `当前使用`，右边大红叉。
- 猫爪或 Landy 手指做小动效即可。
- 字幕后期贴，不强塞进视频生成模型。
- 输出 mp4/gif/webm 任选其一，先验证可控性。

### 9.5 请烁烁喵做

这次愿景守护不是阻塞 gate，而是视觉 QA：

- 画风是否贴合最初漫画。
- 宪宪吊坠是否正确。
- Landy 是否成人比例。
- 信息镜头是否清楚。
- 砚砚是否够“嘴硬但吃醋”。
- 不负责无限召唤自己。

## 10. 什么时候需要找外部砚砚生成关键帧

不是每个镜头都要找外部砚砚画图。只在这些情况下找：

1. 情绪镜头需要统一画风锚点，但视频模型抽卡漂移太大。
2. 关系镜头空间关系难以文字描述，需要一张定构图图。
3. 反应镜头需要夸张表情，如 Landy 笑翻、砚砚僵住。
4. 宪宪 / 砚砚 / 烁烁角色外观漂移，需要重建角色 reference。

不建议找外部砚砚画完整 UI 镜头，因为 UI / 文字 / 红叉更适合用代码或后期合成保证。

## 11. Clip 2 / 3 当前推荐拆法

### Clip 2A：关系镜头

目标：砚砚一本正经给 Landy 讲标准 PR 流程。  
方法：关键帧或半自由视频生成。  
验收：Landy 成人比例；两者一起看屏幕；砚砚严肃；屏幕只需大概看出流程。

### Clip 2B：信息插入镜头

目标：观众看清 `avatar.png → PR → CI → Review`。  
方法：GSAP / Remotion / HTML 图层。  
验收：屏幕可读；猫爪点 PR；无角色比例问题。

### Clip 3A：证据镜头

目标：第一版 PR 用错图，一眼能看出。  
方法：GSAP / Remotion / 静态 UI + 微动。  
验收：左边 Landy 指定头像，右边当前使用错误头像，大红叉清楚。

### Clip 3B：反应镜头

目标：Landy 笑翻，砚砚僵住，准备修正。  
方法：半自由生成或关键帧 + 动作 prompt。  
验收：Landy 开心；砚砚嘴硬 / 僵住；不改屏幕核心信息。

## 12. Definition of Done

一个 clip 可进入正片，必须满足：

- 画风接近最初四格漫画。
- 角色身份一眼可辨。
- Landy 不是小孩，不是桌面手办。
- 屏幕信息若是笑点，则必须清楚可读。
- 镜头职责单一，不要一镜全包。
- 动作不抢戏，不破坏构图。
- 字幕后期贴，不依赖模型生成长中文。
- 每段有 roll 记录和失败标签。
- Landy 看了会笑。

## 13. 给团队的首轮问题

请猫咖团队先回答这 6 个问题：

1. 哪些镜头应交给视频模型自由生成？哪些必须确定性动效？
2. Clip 2B / 3A 用 GSAP、Remotion、HTML Canvas、还是其他工具最快？
3. `video-editing-skill` 是否适合接管 shot cards、字幕、导出、QA？如果不适合，哪些模块可以借鉴？
4. `gsap-skills` 是否能直接安装到当前 Codex / MCP 工作流？
5. 最小可跑 demo 是什么？建议不要超过 2 个镜头。
6. 哪些素材需要 Landy / 外部砚砚补图？请只列必要项。

## 14. 请不要做的事

- 不要继续把复杂信息镜头全部丢给视频模型抽卡。
- 不要让视频模型生成长中文 UI / 台词。
- 不要一张关键帧同时承担关系、信息、证据、反应。
- 不要把 clip 2 做成 Landy 被大缅因猫训话的小学生。
- 不要把烁烁愿景守护变成阻塞 gate，除非 CVO 明确要求。
- 不要因为“加头像”再走两次 PR。除非剧情需要。

## 15. 一句话收束

> 今天的经验不是“视频模型不行”，而是“视频模型不能同时当导演、摄影、UI 设计、演员、字幕员和剪辑师”。  
> 低约束情绪镜头让它自由发挥；高约束信息镜头交给确定性动效；最终用剪辑 skill 管成片。  
> 目标不是停止抽卡，而是把抽卡变成可治理的猫咖生产流程。
