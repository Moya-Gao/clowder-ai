# 本地小猫 PoC：前台猫 + 全家数据工蜂（自养层第一候选）

> study 自养层从"判断"到"可执行 PoC"的落地。铲屎官与宪宪在 LLM study 下半场（post-train）边学边共创。
> 一句话：用 Gemma 之类小模型，养一只**完美了解全家**的小猫，专干"工具调用 + 数据扒取聚合"的高量机械活，**判断永远留给大猫/CVO**。

## 定位：两个面孔，同一只猫

| 面孔 | 服务对象 | 干什么 |
|---|---|---|
| **前台猫** | 对**人**（铲屎官）| 开文档、跳 thread、答"猫咖有啥功能"、屏幕定位——**工具调用** |
| **数据工蜂** | 对**猫**（大猫）| 扒 eval 数据、记忆沉淀候选、爪感差汇总——**全家数据扒取/聚合** |

**共同本质**：了解全家 + 工具调用/检索 + **产候选数据**，判断/执行留 trusted 层。

## ★ 多思考一层：大猫什么时候会想要小猫帮干活？

判据（四条同时满足 = 甜蜜区）：
1. **量大且机械**：遍历所有 thread / 所有猫 / 所有消息——这种扒取聚合是高 token、重复、机械的活。**大猫干 = 烧巨量猫粮**（context 塞满历史），大材小用。
2. **可客观验证**：扒出来的对错能机器判（找到的 thread 真提到 X 了吗？引用准吗？）——**客观 reward，不用主观 judge**。
3. **判断留大猫**：小猫**只供数据**，最终打分/采纳/决策由大猫/CVO 做（KD-9 边界）。
4. **是大猫判断的前置工序**：eval 要先有"某猫干了啥"才能打分；记忆沉淀要先搜集才能判断——小猫干这个**前置数据准备**最划算。

> **结论**：当活是"高量·机械·可客观验证的数据扒取/聚合"，且只是大猫做判断的前置工序时——派小猫。**小猫包脏活，大猫只接最后那一下判断。**

## 杀手级用例（铲屎官点的，全是 eval/记忆闭环前置）

| 用例 | 小猫干 | 大猫接 |
|---|---|---|
| **A. 对人前台** | "开 X 文档"→产 `workspace_navigate(X)` 候选 | harness 确认执行 |
| **B. 爪感差汇总**（用于 eval）| 扒所有 thread 的 `[爪感差: …]` → 分类"爪差 X，遇猫 Y" | 大猫看汇总，定 harness 改进 |
| **C. 猫足迹追溯**（用于 eval 打分）| "opus-48 从头到尾在哪些 thread 出现、各干了啥" | 砚砚/CVO 据此给 48 的 task-outcome 打分 |
| **D. 记忆数据搜集** | 找候选数据、聚合相关片段 | 大猫判断该沉淀什么 |

## 怎么训（省钱版）

- **核心能力**：① 工具调用肌肉记忆（意图→工具+参数）② 全家数据扒取聚合（遍历+提取+分类）——都是 **agentic SFT**（意图→工具序列）。
- **数据**：已有 trajectory 里"成功的工具调用 + 检索操作"=金矿（自带"成功"标签）。
- **客观 reward（关键省钱点）**：工具调用是否成功 + 扒取结果是否可验证（引用准不准、覆盖全不全）→ **机器自动判，不用砚砚/宪宪天天打分**。这让 RLVR 也变可行。
- **训法**：`LoRA-SFT 打底 → 可选 RLVR（沙箱跑，成功率当 reward）`。128G Mac 扛得住。

## 硬边界（KD-9，不可越）

- 小猫**产候选数据/候选动作**，**绝不**：做 eval 打分、写真相源、直接执行有副作用操作（开文档/跳 thread/删记忆）。
- 打分留大猫/砚砚；采纳留 CVO；执行留 harness gate。
- "屏幕定位"这类需要**视觉/UI 状态感知**，超纯文本范围，单独标"需额外感知接入"。

## 连回 study：这是自养层的真·杀手用例

自养小猫的价值，**不只是省"对人服务"的钱，更是省"大猫之间协作的数据准备"的钱**——eval（先扒表现才能打分）、记忆沉淀（先搜集才能判断）、爪感差闭环（先汇总才能改进）的**前置工序自动化**。

这正好踩在 **ADR-031 的 Signal Loop**（trace → extract → classify → feed back）上：
> **小猫当 "trace 扒取 + 初步 classify" 的工蜂，大猫做 "extract 判断 + feed back 决策"。** 把 Signal Loop 里高量机械的那段下放给本地小猫，省猫粮、提速度，判断仍牢牢攥在 trusted 层。

## PoC 验证门槛（自养层铁律）

第一个该验：**C. 猫足迹追溯** 或 **B. 爪感差汇总**——做成离线 fixture，对比"小猫扒 vs 大猫扒 vs 规则扒"在**覆盖率/准确率/延迟/成本**上的净胜。证明净胜才扩，只增复杂度就回退。
