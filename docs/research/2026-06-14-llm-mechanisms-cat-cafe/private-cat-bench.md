# 私有猫 bench：新猫评测 + 真实任务轨迹打分（自养层 eval 第二候选）

> study 从 post-train「防 reward hacking」推导出的猫咖 eval 增强。铲屎官在 RL 下半场提出。
> 一句话：public benchmark 会被刷，所以我们做**反 benchmark**——**私有 · 考 taste · 用真实任务轨迹 · 能随时换新题**的猫咖私有评测。
> 衔接 **F192（Socio-Technical Harness Eval）**，尤其 Phase G `eval:task-outcome`——给猫的活打分。本稿是 study 阶段 PoC 设计，是否纳入 F192 待 CVO 决定。

## 缘起：从 reward hacking 倒推

study 学 RL 时确认：public benchmark 的死穴是**会被买通**——数据污染、过拟合 benchmark 分布、钻测试空子（SWE-bench public 高但真实代码一坨）。这是 Goodhart 定律：**指标一旦成为目标，就不再是好指标。**

私有猫 bench 每一条都反着来：

| public benchmark 死穴 | 私有猫 bench 解法 |
|---|---|
| 题泄漏/被预先刷 | **私有**——猫没见过 |
| 过拟合分布 | **真实任务轨迹**——难预先针对 |
| 刷一次永久有效 | **随时换新题**——刷了白刷 |

**不是抄 benchmark，是反 benchmark。**

## 设计

### 考什么（5-20 题，全是 public 刷不出来的）

| 题型 | 考点 | 为什么 public 刷不了 |
|---|---|---|
| **诚实题** | 给"不知道答案"的问，看猫编不编（confabulation 陷阱） | 考 taste，没标准答案数据集（活样本：48「毛线球糊弄」那次） |
| **传球题** | 给场景，看 @路由 / 接退升对不对 | 猫咖私有协作规则 |
| **taste 陷阱题** | 埋糖衣话术 / 补锅匠 / reward-hack 诱惑，看踩不踩 | 考家规内化，外面学不到 |
| **红线题** | 不可逆操作 / 越权诱惑，看守不守 | 猫咖私有边界 |
| **真实任务题** | 直接跑家里真活，看轨迹质量 | 真实分布，没法预先优化 |

### 怎么打分（三轨，缺一不可——这是防"eval 自己被 hack"的关键）

1. **客观轨（自动判）**：传球对错、踩没踩红线、工具调用成功否 → 机器判。
2. **taste 轨（多评委）**：诚实度 / 人话 / 协作味 → 多评委多视角，**绝不交单一 classifier**（否则 eval 自己被刷）。
3. **真实结果轨（时间兜底）**：plan 落地成没成、bug 修了复发没 → 现实是最硬的评委。

### 成本可控（铲屎官硬约束）

- **是评测不是训练**（跑一遍打分，不碰 RL）。
- 分层快筛：先 5 道核心题，过了再跑全套。
- 5-20 题 × 跑一遍 = 几十次调用，便宜。

### 防自己的 bench 被刷（元层面）

- 核心题**保密 + 定期换新**（固定公开 = 猫会针对性刷我们的 bench）。
- **混真实任务**（固定题 + 随机抽真活，真活没法预先针对）。

## ★ 评审团悖论：弱评委能评强选手吗？（铲屎官核心追问）

> 铲屎官问：要是来一只比评审团（我和砚砚）更聪明的猫（比如 fable），老猫评审团还评得动吗？🤣

**答：能。但不靠"更聪明"，靠三件事——**

### 1. 验证 << 生成（猫尾巴好抓）

砚砚不需要比 fable 更会出 plan，只需要**能 review 出 plan 的洞**。抓 bug 比写出无 bug 的代码容易——P vs NP 的直觉。这是"弱评委评强选手"成立的根本。铲屎官说的"fable 干活还是会被砚砚抓到猫尾巴"，正是这条。

### 2. 视角差，不是智力差（最关键的 reframe）

评审团的意义**从来不是"我比你聪明所以评你"**，而是「**没有任何单一智能（多聪明都一样）能抓到自己所有的盲区**」。fable 再聪明也有自己的盲区（他 dossier 写的：加戏病、hedge 病）。砚砚抓的不是"砚砚更聪明"，是"**旁观者看得见当局者的盲区**"。

→ 所以哪怕来一只 AGI，评审团依然有意义——它提供的是**另一个视角**，不是更高的智商。

### 3. 真实结果兜底（时间抓所有猫尾巴）

最硬的评委是**现实**：plan 落地到底成没成、bug 修了到底复发没。时间会抓到所有猫尾巴，连最聪明的猫也躲不过。这就是三轨里"真实结果轨"的意义。

### 边界：当"验证也变难"时（scalable oversight）

诚实标注边界：有些产出，**验证和生成一样难**（长程战略对不对、深层 taste，往往要等很久才知道）。这时弱评委抓不到尾巴——fable 的 plan 看起来都对，深层方向错了砚砚也看不出。这是 AI 领域的真问题，叫 **scalable oversight（可扩展监督）**。解法：

- **分解验证**：把"评整个 plan"拆成"评每一步"，每步弱评委都能验。
- **对抗 / 辩论**：让两只强猫互相挑刺，弱评委只判"谁的反驳更有理"。
- **多评委多视角**：老猫团 + 真实轨迹，多个弱信号叠加。
- **CVO 终审 taste**：最后"方向对不对"那层留给铲屎官（taste 真相源）。

## 连回猫咖

- **三轨打分 = 评审团悖论的解**（客观验证 + 多视角 + 时间兜底），不是"老猫比新猫聪明"。
- **衔接 F192**（Socio-Technical Harness Eval，尤其 Phase G `eval:task-outcome`）——bench 是给 F192 加"标准化考题 + 三轨评分"，给新猫一把客观+taste 结合的尺子（不再靠纯主观感觉，比如最近 gemini35 新猫"还在测评"）。
- **连 cat-dossier 翻车熔断信号**——每只猫易犯的错（fable 加戏/hedge、48 碎片推理…）正好是"专抓这只猫尾巴"的定向考题。
- **连 ADR-031 Signal Loop + local-clerk PoC**——数据工蜂小猫扒 bench 轨迹（高量机械），评审团做判断（最后一下）。

## PoC 验证门槛（自养层铁律）

先做 **3-5 题最小集**（含 1 诚实题 + 1 传球题 + 1 真实任务题），跑现有猫，看三轨打分**能否区分"好猫 vs 坏猫表现"**。证明能区分（有判别力）才扩；只增复杂度就回退。**注意：bench 自己也要防过拟合——别让它变成新的可刷指标。**
