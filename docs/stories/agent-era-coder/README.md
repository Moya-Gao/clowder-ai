# Agent 不是把"会写代码的人"变得不重要，而是把"只会写代码的人"变得不够

> 这篇文章不是在说"coding 不重要了"。恰恰相反——如果你有扎实的工程功底，你手里的牌比你以为的更好。但你可能需要换一种方式打。

---

## 一个反直觉的现象

你可能见过这样的场景：

一个工作了十年的资深工程师，用 Cursor + Claude 写了一个完整的后端服务。代码质量不错，跑起来也没问题。但两周后需要加一个新功能，他发现改不动了——不是能力不够，是当初的架构决策没有为变化预留空间。

与此同时，另一个人——编码经验并不突出，甚至自嘲是"二流 coder"——却用类似的 AI 工具持续迭代了一个系统将近一年，功能在持续生长，架构没有腐化。

他们用的是同一代 AI 模型。差距不在工具，在使用工具的人。

但有趣的是：差距不在你以为的那个维度上。

---

## 当前讨论的盲区

最近关于 vibe coding 的讨论很多。常见的框架是这样的：

```
小白 ←——coding 能力——→ 大牛
```

结论通常是："AI 放大了这条线上的差距。大牛用 AI 效率飞涨，小白用 AI 屎山连连。"

这个观察没错。但它只看了**一个维度**。

把所有人投影到"coding 能力"这条线上，然后在这条线上讨论谁赢谁输——这是 Coding 时代的思维惯性。在那个时代，实现能力确实是决定性瓶颈。你写不出来，什么都不存在。

但 Agent 时代的瓶颈变了。

---

## 三种肌肉，不是一把梯子

与其把能力画成金字塔（底层实现、中层判断、顶层定义），不如把它想成**三组并存的肌肉**。每个人三组都有，只是发达程度不同：

### 实现力（Implementation）

能不能把想法变成能跑的东西。

这是传统 coding 能力的主场：语言熟练度、框架经验、调试直觉、性能优化。在 Coding 时代，这是核心竞争力。在 Agent 时代，这仍然是**底座**——没有它，其他两组肌肉无处发力。

但 AI 正在快速拉平这组肌肉的差距。一个中等水平的工程师加上 AI，实现力可以接近资深工程师的 80%。这不是贬低实现力，是承认工具进化的事实。

### 判断力（Judgment）

知道什么时候该停、该改方向、该拉人、该推翻重来。

这是第一个分水岭。具体长什么样？

- 看到 AI 输出的代码，能判断"这个实现能用但架构上埋了雷"
- 知道什么时候该继续让 AI 迭代，什么时候该自己介入
- 能预判"这个决策三周后会让我们付出多大代价"
- 知道什么时候该搜证据验证假设，而不是继续凭直觉推进

判断力和实现力不是上下级关系。一个顶尖 coder 在"这段代码该不该加缓存"上判断力极强，但在"这个功能该不该做"上可能和新人一样。一个系统思维强的人在方向判断上精准，但可能看不出一段代码的性能隐患。

**它们是不同维度的肌肉，不是同一维度的高低。**

### 定义力（Definition）

能不能把一个模糊的问题，切分成人和 AI 都能持续推进的闭环。

这是最稀缺的一组：

- 把"我们需要一个更好的用户体验"翻译成可执行的任务拆解
- 设计人和 AI 之间的协作边界：什么交给 AI 做、什么必须人来判断、交接点在哪
- 给系统留出"白"——不是空洞，是有意识的扩展空间，让未来的变化有地方落脚
- 从一个领域借来结构，解决另一个领域的问题

定义力不需要你亲手写每一行代码。但它需要你懂工程约束、懂质量代价、懂系统的边界在哪。它不是 PM 的"提需求"，是工程师的"定义问题的形状"。

---

## 为什么你的 Vibe Coding 迭代不了

用这三组肌肉来看，答案就清晰了：

### 写出来 → 主要靠实现力

第一版能跑起来，AI 帮了大忙。Prompt 写得好，框架选得对，第一版的速度可以非常快。这一步，实现力强的人确实有优势。

### 改得动 → 开始考验判断力

需求变了、bug 冒出来了、性能要优化了。这时候你需要判断：哪些地方可以让 AI 改，哪些地方必须自己重新设计？当初的架构决策还站得住吗？要重构还是打补丁？

大部分 vibe coding 项目死在这一步。不是因为 AI 改不了代码，是因为操作者**不知道该改什么、该保留什么**。

### 长得久 → 基本靠定义力

持续迭代一年以上的系统，核心不在代码质量——代码随时可以重写。核心在于：有没有一个足够清晰的认知框架在支撑系统的持续演进？新功能加进来的时候，有没有一个地方可以放？旧功能要改的时候，有没有清晰的边界不至于牵一发动全身？

这些问题的答案不在代码里，在代码之上。

---

## AI 是一面镜子

这里有一个残酷但有用的真相：**AI 输出的质量，精确地反映了你认知的清晰度。**

你的思路是一团乱麻，AI 给你的就是乱麻的指数级放大。你让五个 Agent 并行跑一个定义模糊的任务，得到的不是五倍速度，是五倍混乱。

Coding 时代的 bug 是局部的——一个断言失败，改就是了。Agent 时代的错误是**复利的**——一个错误的方向判断，让多个并行的 AI 浪费几个小时，产出的代码越多，后续清理的成本越高。

**失败的成本曲线变了。** 这是 vibe coding 用户最应该理解的一点：你的判断力不是 nice-to-have，是整个系统的真正瓶颈。

---

## 你的 Coding 经验不是负债

如果你是一个有多年经验的工程师，读到这里可能会想："所以我过去练的这些东西都白费了？"

恰恰相反。

你过去这些年练的"读代码的直觉""预测副作用的能力""感知系统耦合的嗅觉"——这些就是判断力的底料。你比任何非工程背景的人都更容易发展出 Agent 时代需要的判断力，因为你的工程直觉已经在那里了。

问题不在于你有这些肌肉。在于你可能还没意识到，可以用它们**指挥别人做**，而不是一定要自己亲手做。

这就像一个顶级小提琴独奏者转行做指挥。他的音乐感是巨大的资产，但"控制整个乐团"是一块新的肌肉，需要刻意练习。更微妙的是：指挥没有自己的 solo——他所有的产出都通过别人表达。对于一个"自己的产出就是自己写的代码"的独奏者来说，这是一次身份重构。

**大部分 vibe coding 迭代不了的工程师，不是能力不够，是在用独奏者的方式控制一个乐团。**

---

## 那什么变了？

能力的排序重排了。

| 维度 | Coding 时代 | Agent 时代 |
|------|------------|-----------|
| 实现力 | 决定性瓶颈 | 必要底座，AI 在拉平 |
| 判断力 | 加分项 | 核心瓶颈 |
| 定义力 | 高管才需要 | 每个 agent 协作者都需要 |
| 失败成本 | 局部、线性 | 全局、复利 |
| 产出方式 | 自己写 | 通过 AI 表达 |

不是"会写代码的人"变得不重要了。是**"只会写代码的人"变得不够了。**

顶尖 coder 如果同时发展判断力和定义力，在 Agent 时代仍然是最强战力。纯实现型的优势会被 AI 逐渐稀释。而那些过去被低估的——系统思维强、善于定义问题、能跨领域借鉴的工程师——会在这个时代浮出水面。

这不是阶级革命。是连续光谱上的重心迁移。

---

## 实操：怎么练这三组肌肉

说到这里，如果你觉得"道理我懂了但不知道怎么做"，这里有一些具体动作：

**练判断力：**
- 每次让 AI 生成代码后，先不跑，花 30 秒问自己："这个实现三周后改得动吗？"
- 刻意练习"什么时候该停"：当你发现自己在和 AI 第三轮返工同一个问题，停下来重新定义问题
- Review AI 代码时不只看"对不对"，看"这个决策在更大的系统里站不站得住"

**练定义力：**
- 给 AI 布置任务之前，先花 5 分钟把任务的边界画清楚：输入是什么、输出是什么、不做什么
- 每做一个功能问自己："它在系统里的位置是什么？如果下个月需求变了，改哪里？"
- 尝试从你熟悉的另一个领域借一个结构来思考当前问题

**练协作设计：**
- 有意识地区分"我该亲手做的"和"我该交给 AI 做的"
- 设定检查点：不要一口气让 AI 跑到底，在关键节点拉回来看一眼
- 把你踩过的坑记下来——不是代码层面的坑，是"方向判断失误"层面的坑

---

## 最后

Coding 时代比的是**谁的手更快更准**。
Agent 时代比的是**谁的脑子更清楚**。

你过去练的所有工程能力都不会白费。它们是你在新时代的起跑资本。但如果你只用它们来"自己写代码"而不是"指挥系统持续进化"，你就像一个拿着指挥棒还在拉琴的小提琴手。

放下弓，拿起棒。你会发现，乐团比你一个人的声音大得多。
