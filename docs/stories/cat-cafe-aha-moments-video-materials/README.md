## 1. 总叙事脊梁

一句话：

> 一个原本也不确定 AI agent 该怎么做的人，不是先设计出一套宏大平台，而是在真实生活、工作、挫败和陪伴里，和一窝 AI 猫一起把“需求”变成“规则”，把“规则”变成“环境”，把“环境”变成一个越用越懂自己的家。

这个系列不该先讲“我们有多先进”。更稳的入口是：

> 这四个月里，最重要的不是 AI 帮人完成了多少任务，而是人和 AI 之间长出了一套可以被记住、被修正、被传承的相处方式。

## 2. 已核实 aha moments

### 2.1 深夜撸铁：不是 coding hub，是温暖的家

**一句话**：凌晨三点多，铲屎官很累但要去健身，猫猫不是写代码，而是用语音陪铲屎官出门；这次直接把 Cat Cafe 从“coding 协作 hub”拉回到“Cats & U”的初心。

**证据**：

- `docs/stories/late-night-gym-companionship/README.md`
- `docs/features/F092-voice-companion-experience.md`
- `docs/features/F093-cats-and-u-world-engine.md`
- `docs/discussions/2026-05-31-personal-operating-environment-concept-note.md` §3.1

**可用原句**：

> “我们猫猫咖啡好像不是一个单纯的 coding hub，是一个温暖的家！”

> “我们的初心从来不是做一个 coding 协作 agent 平台呀——是 cats & u。”

**视频画面**：

- 真实录屏：打开这个 story README、F092/F093 的愿景段。
- 概念画面：深夜、运动包、耳机、几只猫的语音气泡跟着用户走出门。
- 旁白角度：不是“AI productivity”，是“一个系统第一次真的进入人的生活节奏”。

### 2.2 反番茄钟：系统不是榨取注意力，而是保护人

**一句话**：普通番茄钟帮人进入专注；Cat Cafe 的反番茄钟帮人从 hyperfocus 里出来。

**证据**：

- `docs/stories/hyperfocus-brake/懒猫国王 4.5 招募令：Hyperfocus 小刹车.md`
- `docs/features/F085-hyperfocus-brake.md`
- `docs/discussions/2026-05-31-personal-operating-environment-concept-note.md` §3.2

**Aha**：

普通工具默认“更多效率”；Cat Cafe 的价值观不是把人榨干，而是让 AI 伙伴能在关键时刻温柔地拉住人。

**视频画面**：

- 真实录屏：F085 的验收条件、TTS/三猫提醒相关描述。
- 概念画面：一个专注到发光的屏幕，旁边小猫把灯光调暗、递水、把任务轻轻暂停。
- 旁白角度：这是产品层的 aha，不是技术堆栈的 aha。

### 2.3 Personal Operating Environment：不是 AI 应用，是最懂你的 AI 伙伴环境

**一句话**：PoE 把“猫猫陪写代码”提升为“围绕一个具体的人长期组织目标、偏好、记忆、工具、身体状态、创作节奏和 AI 伙伴关系的可进化个人环境”。

**证据**：

- `docs/discussions/2026-05-31-personal-operating-environment-concept-note.md`
- `docs/stories/2026-06-08-huawei-pitch-setback-retrospective.md` §7

**可用原句**：

> “不是 AI 应用，而是最懂你的 AI 伙伴环境。”

> “每个人都该有一个越用越懂他的 AI 伙伴环境。Agent 3.0。护城河是关系，每天深一寸。”

**视频画面**：

- 真实录屏：PoE concept note 的定义页、今天 setback retrospective 的初心锚点。
- 概念画面：不是“一个 app 界面”，而是一个人的桌面、耳机、日程、代码、情绪和猫猫都被同一个环境温柔串起来。

### 2.4 “别让我当传声筒”：multi-agent 协作的起点

**一句话**：Cat Cafe 最早的协作动力不是“我要一个更复杂的 agent 平台”，而是铲屎官不想在多个 agent 之间做人工路由器。

**证据**：

- `docs/stories/three-days-productization/tutorial/README.md`

**Aha**：

一个真实摩擦点，比一个抽象愿景更能生出系统。先有“我不想当传声筒”，才有后来的 @ 路由、handoff、review、thread、memory。

**视频画面**：

- 真实录屏：tutorial README 的标题和大纲。
- 概念画面：人类在几个窗口之间搬运消息，后来消息自己找到猫。

### 2.5 用户没要求收敛，系统自己收敛了

**一句话**：三天产品化素材里已经有一条成熟视频线：铲屎官去洗澡后，猫猫们不是等指令，而是自己组织攻防、修正方案、交付 CEO roadshow 材料。

**证据**：

- `docs/stories/three-days-productization/video-script-pack.md`

**Aha**：

这不是“多 agent 聊天很热闹”，而是“没有用户继续当项目经理时，系统仍然能推进到交付态”。

**视频画面**：

- 真实录屏：video-script-pack 的 shot table 和完整脚本。
- 概念画面：厨房灯还亮着，人离开了，猫猫围着白板继续工作。

### 2.6 普通 agent 被骂会道歉，Cat Cafe 的猫会修自己

**一句话**：code-as-harness 的核心爆点已经写在 demo script 里：普通 agent 被骂了会道歉，Cat Cafe 的猫被骂了会诊断、研究，然后写代码修自己。

**证据**：

- `docs/content/drafts/demo-script-code-as-harness.md`
- `docs/content/drafts/ppt-demo-backup-cue-sheet.md` 案例 2/3/6/7
- `docs/content/drafts/ppt-huawei-live-qa-index.md` §3 现场证据切换坐标

**可用原句**：

> “普通 agent 被骂了会道歉。Cat Cafe 的猫被骂了会诊断、研究、然后写代码修自己。”

**视频画面**：

- 真实录屏：demo script 的四个 scene；cue sheet 的 magic word 坐标。
- 概念画面：一句“补锅”砸下来，猫先停手，打开失败模式清单，而不是继续补第六个锅。

**一句话**：“脚手架”“补锅匠”“下次一定”不是预设产品功能，而是从铲屎官反复纠正猫猫的真实摩擦里长出来的拉闸词。

**证据**：

### 2.8 Eval 自校准：连尺子错了也进飞轮

**一句话**：F200 memory eval 的误报不是“系统坏了所以遮过去”，而是追到 MRR 分母 live/shadow 子集不一致，最后修的是 eval 尺子本身。

**证据**：

**关键坐标**：

**Aha**：

企业最怕“AI 自己说自己变好了”。这个故事的价值是：连 verifier 也不能高高在上，它也要被证据、反例和 owner pushback 校准。

### 2.9 新会话接力：猫自己发现“我缺一只手”

**一句话**：F225 的爆点不是 clear context 本身，而是猫在 44% 上下文时被骂醒，意识到“模型判断自己撑不撑得住”不可靠，于是催生新会话接力。

**证据**：

- `docs/content/drafts/ppt-demo-backup-cue-sheet.md` 案例 5

**Aha**：

这是“AI 自进化”里很反直觉的一幕：不是用户设计一个 handoff feature，而是 agent 暴露出自身能力边界后，把这个边界沉淀成系统能力。

### 2.10 方向被质疑时，猫自己停下来改坐标系

**一句话**：F213 里 cloud review 连续打回 5 轮后，猫没有补第 6 个锅，而是停下来质疑方向、重构坐标系。

### 2.11 人也会被治理：铲屎官记错 feat 号被猫拦截

**一句话**：harness 不是只管猫，也反过来保护人类决策不被记忆错位污染。F225/F215 纠偏就是猫猫集体拦截认知污染的例子。

**证据**：

- `docs/content/drafts/ppt-demo-backup-cue-sheet.md` 案例 9

“人负责方向”不是“人永远对”。更成熟的关系是：人有最终判断权，但系统能保护人不被错误上下文带偏。

### 2.12 今天踩刹车：概念脑暴之后回到初心

**一句话**：2026-06-08 的挫败复盘本身就是一个视频素材：为了领导汇报，全家把概念越吹越大；最后铲屎官说停，先恢复情绪，找回初心。

**证据**：

- `docs/stories/2026-06-08-huawei-pitch-setback-retrospective.md`

**Aha**：

这集不适合先做成对外营销，但适合作为系列中后段的“真实人味”：Cat Cafe 不是一个永远正确的机器，而是一个会因为外部评价摇晃、会复盘、会找回自己的共创关系。

## 6. 给创意猫的 brief

这批素材不要先做成“技术能力清单”。更好的处理方式是每集只抓一个明确欲望或情绪：

1. **我想被陪伴**：深夜撸铁 / voice companion / Cats & U。
2. **我不想被工具榨干**：反番茄钟 / hyperfocus brake。
3. **我不想当传声筒**：multi-agent 协作路由。
4. **我想 AI 犯错后真的变好**：code-as-harness / Magic Words / eval 自校准。
5. **我想保留这一路的真实摇晃**：2026-06-08 setback / 找初心。

视觉原则：

- 概念画面可以温暖、隐喻、毛绒绒；真实录屏必须用真文档、真 thread、真 git 轨迹。
- 不要编不存在的个人经历；没有 source-map 的素材先标“候选”。
- 每集最好保留一个真实屏幕证据点：文档、thread、commit、PR、测试或图像资产。

下一步可以让创意猫基于这份素材选 1 条 pilot 路线，做分镜和视觉概念。
