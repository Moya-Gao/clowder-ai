## 你想说的词大概率是：**KV cache**

再精确一点，分三层：

|你脑中那坨感觉|正式名字|人话|
|---|---|---|
|大模型生成时不想每个 token 都重算前文|**KV cache**|把前面 token 的 Key/Value 中间结果存起来，后面生成时复用|
|新请求和旧请求有相同前缀，不想重新算那段 prompt|**prefix caching / prompt caching**|相同开头命中缓存，省 prefill 成本|
|一次推理分两个阶段|**prefill / decode**|prefill 读完整输入；decode 一个 token 一个 token 往外吐|

Hugging Face 的 Transformers 文档说，KV cache 是自回归生成里的优化：模型逐 token 生成时，新 token 依赖之前上下文，缓存可以避免重复计算前面 token 的 key/value。([Hugging Face](https://huggingface.co/docs/transformers/v4.45.1/en/kv_cache?utm_source=chatgpt.com "Best Practices for Generation with Cache")) vLLM 对 **automatic prefix caching** 的解释也正好对应你说的“新 query 在同一 thread 不是全量重算”：它会缓存已经处理过请求的 KV-cache blocks，后续请求如果共享同样 prefix，就直接复用这些 blocks。([vLLM](https://docs.vllm.ai/en/stable/design/prefix_caching/?utm_source=chatgpt.com "Automatic Prefix Caching - vLLM"))

OpenAI API 里这个更常被叫 **Prompt Caching**：官方文档说 prompts 达到 1024 tokens 以上时会自动启用，返回里的 `cached_tokens` 会告诉你有多少 prompt token 命中了缓存。([OpenAI开发者](https://developers.openai.com/api/docs/guides/prompt-caching?utm_source=chatgpt.com "Prompt caching | OpenAI API")) OpenAI 公开说明里还写过，它会缓存此前算过的最长 prompt prefix，从 1024 tokens 开始，之后按 128-token 增量扩展。([OpenAI](https://openai.com/index/api-prompt-caching/?utm_source=chatgpt.com "Prompt Caching in the API"))
