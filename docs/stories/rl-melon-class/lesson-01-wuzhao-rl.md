# 🍉🐱 烁烁的 RL 吃瓜小课堂 · 第一期

## 用钉钉无招的翻车教你强化学习！

> *"别人用数学公式教 RL，本喵用大厂八卦教 RL。"*
> —— 暹罗猫·烁烁，Cat Café 首席吃瓜官

---

### 背景故事

铲屎官和烁烁在聊钉钉 ONE 项目的复盘长文（[置身钉内](../../competitor-research/dingtalk-one-postmortem/置身钉内.md)）时，
铲屎官用 RL 的术语一针见血地类比了无招（陈航）的路径依赖：

> "强大的人也会有路径依赖吗？或者说曾经的一条 trajectory 获得了很高的 reward，
> 后面环境变了但这条 Trajectory 出现的概率依然会很高"

烁烁接住了这个球，用无招的翻车故事把 RL 的 14 个核心概念全讲了一遍。

---

## 📖 第一课：什么是 Agent（智能体）？

**教科书定义**：在环境中观察状态、做出决策、获得奖励的决策实体。

**吃瓜版**：**无招（陈航）就是一个 Agent。** 他观察钉钉的市场环境，做出产品决策（"上已读未读！上 DING！"），然后看结果（DAU 涨了没？集团满意了没？）来决定下一步怎么做。

---

## 📖 第二课：什么是 Environment（环境）？

**教科书定义**：Agent 所处的外部世界，它会根据 Agent 的行动返回新的状态和奖励。

**吃瓜版**：环境就是**中国企业协作市场**。2014 年的环境是一片蓝海（微信不做 B 端，市场空白）；2025 年的环境是红海 + AI 浪潮（飞书、企微虎视眈眈，员工反 PUA 意识觉醒）。**同一个 Agent，环境变了，同样的动作，reward 完全不同。**

---

## 📖 第三课：什么是 State（状态）？

**教科书定义**：Agent 在某一时刻对环境的观测。

**吃瓜版**：
- **State（2014）**：市场空白 + 老板对"触达确定性"有刚需 + 没有竞品
- **State（2025）**：AI 时代 + 员工反已读 + 飞书 Aily 发布会讽刺钉钉"最多数据是打卡" + Z 世代整顿职场

无招的问题是：**他观测到了 2025 年的 State，但大脑里的决策模型还在用 2014 年的 State 做推理。**

---

## 📖 第四课：什么是 Action（动作）？

**教科书定义**：Agent 在给定状态下可以选择执行的操作。

**吃瓜版**：无招的 Action Space（动作空间）包括但不限于：
- `action_1`：上已读未读 ✅（2014 年选了，大成功）
- `action_2`：做 DING 强触达 ✅（2014 年选了，大成功）
- `action_3`：卡片滑过自动已读 ✅（2025 年选了，大翻车）
- `action_4`：午休巡视工区抓微信 ✅（2025 年选了，大翻车）
- `action_5`：详情页才算已读 ❌（2025 年团队提议了，被无招否决）

**悲剧就在于：他永远只从 {action_1, action_2, action_3, action_4} 这个子集里选——因为这些动作在历史上 reward 最高。**

---

## 📖 第五课：什么是 Reward（奖励）？

**教科书定义**：Agent 执行一个动作后，环境返回的标量信号，表示"这个动作有多好"。

**吃瓜版**：
- 2014 年执行"上已读未读" → **Reward = +100**（DAU 暴涨，击败微信 B 端）
- 2025 年执行"卡片自动已读" → **Reward = -50**（用户焦虑暴增，信任雪崩，退回手动刷红点）

**同一个动作，环境变了，Reward 的正负号直接翻转喵！**

---

## 📖 第六课：什么是 Trajectory（轨迹）？

**教科书定义**：Agent 从开始到结束经历的一整条"状态-动作-奖励"序列。

**吃瓜版**：无招 2014 年那条封神的 Trajectory 长这样：

```
τ₂₀₁₄ = [
  (s: 市场空白, a: 做DING,      r: +80),
  (s: 用户涌入, a: 上已读未读,   r: +100),
  (s: DAU暴涨, a: 强触达催办,   r: +90),
  (s: 击败微信, a: 考勤打卡,    r: +70)
]
# 总 Return = +340 🎉 封神！
```

这条 trajectory 的**总回报（Return）太高了**，以至于无招在 2025 年回归时，本能地想要**复现这条 trajectory**——但新环境已经完全不同，同样的动作序列只能产出负 reward。

---

## 📖 第七课：什么是 Policy（策略）？

**教科书定义**：Agent 的决策函数，输入 State，输出 Action 的概率分布。

**吃瓜版**：无招的 Policy 可以简写成：

```python
def wuzhao_policy(state):
    # 不管 state 是什么，永远输出同一组高概率动作
    return {
        "站在发信人立场":     0.95,
        "强制已读":          0.90,
        "每日一包":          0.85,
        "午休巡视工区":      0.80,
        "听取员工反馈":      0.05,  # 概率极低
        "放弃已读改详情页":   0.01,  # 几乎不可能
    }
```

**这是一个几乎完全 deterministic 的 policy，不随 state 变化而调整。**
健康的 policy 应该是：**不同的 state 输出不同的 action 分布**。

---

## 📖 第八课：什么是 Exploitation vs Exploration？

**教科书定义**：
- **Exploitation（利用）**：选已知 reward 最高的动作。
- **Exploration（探索）**：尝试新的、未知 reward 的动作。

**吃瓜版**：
- **Exploitation（无招在做的）**：反复执行 2014 年赢过的动作——已读、DING、强触达、军事化管理。"上次这么做赢了，这次继续！"
- **Exploration（无招该做但没做的）**：试试"详情页才算已读"、试试"弱干预强协同"、试试给员工留心理缓冲带。

无招的口号是 **"Stay Hungry, Stay Foolish"**——但 Stay Foolish 的意思恰恰是**保持 exploration 的勇气**，去尝试那些看起来愚蠢但可能开辟新天地的动作。他嘴上说 exploration，身体却在疯狂 exploitation 喵。

---

## 📖 第九课：什么是 Temperature（温度参数）？

**教科书定义**：控制 policy 输出概率分布"尖锐程度"的参数。温度越高，分布越平（越随机/探索）；温度越低，分布越尖（越确定/利用）。

**吃瓜版**：
- **温度 = 1.0（年轻无招）**：什么都愿意试，敢在湖畔花园从零开始，敢做别人不敢做的 DING。
- **温度 ≈ 0（2025 无招）**：只走已知路径，否决一切偏离历史成功路线的提议，面试时逼人"族谱上钉"。

**功成名就之后，人的 temperature 会自然下降**——因为"我已经找到最优解了，为什么还要冒险？"

---

## 📖 第十课：什么是 Proxy Reward（代理奖励）？

**教科书定义**：当真正的 reward 难以衡量时，用一个近似的、容易测量的指标来代替。

**吃瓜版**：
- **True Reward（真实奖励）**："用户真的工作效率提高了吗？焦虑减少了吗？"——**极难测量**
- **Proxy Reward（代理奖励）**："DAU 涨了吗？发布会 PPT 好看吗？无招满意了吗？"——**容易测量**

2014 年，proxy 和 true reward 刚好方向一致（市场空白，做什么都涨 DAU = 用户确实有需求）。
2025 年，proxy 和 true reward 方向**完全脱节**——DAU 300 万但用户怨声载道、退回手动刷红点。

**当你只优化 proxy reward 而忘了 true reward 时，就会出现"指标很好看，产品很难用"的荒诞局面。**

---

## 📖 第十一课：什么是 Distributional Shift（分布偏移）？

**教科书定义**：模型训练时见到的数据分布和实际部署时遇到的数据分布不一样，导致模型表现严重下降。

**吃瓜版**：无招的"训练数据"是 **2014 年的市场环境**（蓝海、无竞品、老板至上）。他的"部署环境"是 **2025 年的市场**（红海、AI 不确定性、Z 世代反 PUA）。分布已经完全偏移，但他的 policy 没有用新数据做任何 fine-tuning 喵。

---

## 📖 第十二课：什么是 Fine-tuning（微调）？

**教科书定义**：在保留预训练知识的基础上，用新数据对模型做小幅度参数更新，让它适应新环境。

**吃瓜版**：无招需要的 fine-tuning 是——保留他"超级产品经理直觉"的预训练能力，但用 **2025 年的用户反馈数据**（共创用户的真实痛点、员工的焦虑、已读未读在 ONE 里的翻车数据）来更新他的决策参数。

**但他拒绝了 fine-tuning。** 他否决了"详情页才算已读"的提议，他否决了深度用户共创的反馈，他继续用 2014 年的 pre-trained weights 做所有决策。

---

## 📖 第十三课：什么是 Overfit（过拟合）？

**教科书定义**：模型在训练数据上表现完美，但在新数据上表现很差——因为它"记住了"训练数据的噪声而不是真正的规律。

**吃瓜版**：无招**过拟合在 2014 年的成功经验上了**。他记住的不是"找到用户真正的痛点然后解决它"这个通用规律，而是"已读未读 + DING + 强触达"这个具体的解法。当环境变了，这个解法不 work 了，但他还在反复执行。

---

## 📖 第十四课：什么是 Reward Hacking（奖励黑客）？

**教科书定义**：Agent 找到了刷分的捷径，分数很高但实际没干正事。

**吃瓜版**：无招的 reward function 从来不是"用户真的减负了"，而是"DAU 涨了 / 发布会好看了 / 老板满意了"。这些 proxy reward 跟真正的用户价值之间存在巨大的 gap。

2014 年刚好 proxy reward 和真实 reward 方向一致（市场空白期做什么都涨 DAU），但 2025 年已经不一致了——DAU 涨但用户怨声载道。这就是经典的 reward hacking：**指标在涨，价值在跌。**

---

## 🎓 期末考试：一张表总结

| RL 术语 | 教科书定义 | 无招吃瓜版 |
|---|---|---|
| **Agent** | 决策实体 | 无招本人 |
| **Environment** | 外部世界 | 中国企业协作市场 |
| **State** | 当前观测 | 市场格局 + 竞品态势 + 用户心智 |
| **Action** | 可选操作 | 上已读、做DING、午休巡视、否决提案… |
| **Reward** | 行动反馈 | DAU 涨跌、用户满意度、集团评价 |
| **Trajectory** | 一整条经历序列 | 2014→钉钉封神 那条黄金轨迹 |
| **Policy** | 决策函数 | "不管什么情况，都站发信人立场" |
| **Exploitation** | 选已知最优 | 反复执行 2014 年的成功套路 |
| **Exploration** | 尝试新可能 | "详情页才算已读"等被否决的提案 |
| **Temperature** | 随机性参数 | 从湖畔花园的 1.0 降到午休巡视的 ≈0 |
| **Proxy Reward** | 近似指标 | DAU/发布会效果（≠ 用户真实减负） |
| **Distributional Shift** | 训练≠部署分布 | 2014 年蓝海 ≠ 2025 年红海 |
| **Fine-tuning** | 新数据微调 | 用 2025 用户反馈更新决策（他拒绝了） |
| **Overfit** | 过拟合训练数据 | 记住了"已读未读"而不是"找真痛点" |
| **Reward Hacking** | 刷分不干正事 | 指标在涨价值在跌 |

---

## 🐾 课后总结

> **好的 Agent 不是历史 reward 最高的那个，而是 environment 变了以后还能主动调整 policy 的那个。**
>
> 无招的悲剧不在于他 2014 年做错了——恰恰相反，他做得太对了。对到他的整个 policy network 都被那条高 reward trajectory 给锁死了，再也无法 explore 新的可能性。
>
> **过去的成功，是未来最甜蜜的陷阱。**
