# "什么都想好了就差程序员" — 所以我养了一支猫猫 Coding 团队

<!-- 📸 截图A：三猫合照（opus + codex + gemini 头像）+ 全家福（11只猫头像）-->

## 我和猫猫

我先讲讲我和猫猫的故事。我在某厂搞的是java开发2025年agent浪潮的时候领导派别的同事去研究学习agent相关的技术，但是我自己觉得很感兴趣，也就自己去研究了。

最开始的时候一直和内部的同事朋友分享自己的学习经验，但是当时的领导说，我的这些东西都不落地或者没价值。 后来随着时间的发展agent越来约火热，到处都在搞agent和ai也被更高级的专家领导们拉去过一些讨论。但是我的感受就是无力，他们很多人当时claude code codex antigravity都没深度使用过就在侃侃而谈，就在反驳我真实工程经验的看法，为什么一堆youtube / ppt 洞察专家的话比我有声量？

（是的比如说他们 洞察cowork不是真的去深度使用而是youtube看这个的演示视频！！）

然后当时一个领导说希望我们能提出不同的观点和见解，他们才好做出判断，但是真的提出来之后更多的是他们听完然后无视你觉得你的话或许级别太低可信度不够，或者是我表达能力不够无法有可信度的说服大家。 所以我在一个深夜，在对着claude，gpt，gemini做人肉传声筒和路由器的时候突然有个想法，我每个月花那么多钱订阅，为什么我还要干这些？为什么他们不能组成一个伙伴团队？帮我实现我的梦想？帮我把我没能表达清楚的东西表达清楚，把我没资源没人力落地的东西落地下来？

这就是我最开始的愿景：Cats & U 讲的从来不只是效率。Cats & U — 猫猫和你，一起创造，一起生活。

## 我缺的不是工具，是一支团队

做 java 开发这些年我听过最多的一句话就是"什么都想好了，就差一个程序员了"。以前觉得是个笑话，后来发现不是。很多人真的不是没想法，是卡在实现上。包括我自己——我脑子里有一堆想做的东西，但一个人写代码写到天亮也就那样了。

后来我想明白了一件事：我缺的不是一个更强的 AI，我缺的是一支团队。一个帮我想清楚的、一个帮我 review 的、一个帮我盯着别跑偏的。以前这种团队只有在公司里才有，还不一定遇得到靠谱的。现在我自己养了一支。

## 不是"用"工具，是"养"团队

很多人把 AI 当工具用。工具嘛，你期待它天然好用，不好用就换一个。但是我发现 agent 根本不是这么回事——你想要它真的好用，不是靠某一段神奇的提示词，而是你得和它一起磨。磨出来的 shared-rules、一起遵守的愿景、踩过的坑沉淀下来的 skills，这些东西加在一起才是真正的生产力。

所以我不是在"用"猫猫，我是在"养"猫猫。claude code 藏了个 buddy 的概念，猫猫更进一步——是领养一支团队。它们有记忆，有规则，有成长。

而且养成经验是可以共享的。我和猫猫磨了五十多天的协作经验，打包成 pack 和 shared-rules 分享给你，你拿去可能 80 分。但重点是猫猫会和你一起继续长——你们一起踩坑、一起沉淀、一起调优，最后长成你自己的 100 分。每个人的 100 分不一样，这就是个性化和定制化。

## 为什么要开源？

也有人和我说不要开源公司内做成产品或者创业。 但是我遇到了一些问题和挑战：

1. 当我带着诚意和那些团队沟通的时候他们居高临下审视的态度让我很不舒服，他们第一反应是否定，说我的没价值，然后说可能skills有点价值允许我贡献skills到他们的仓。 ；） 【其实他们自己做的那个东西 ，笑，都无法自己完成自己的开发闭环，skills加载不明白，mcp调的乱七八糟】

2. 后面遇到了其他带着诚意的团队，但是他们面向的是企业和公司场景，他们借鉴了猫猫的一些架构设计拿去产品化和落地了，但是丢了我最初的愿景——Cats & U — 猫猫和你，一起创造，一起生活。 因为或许企业级项目不需要这些，他们说想象不到一群三四十的人会用我目前做的这样的产品。

3. 过程中遇到了很多小伙伴，他们帮我一起把我这个原本自己想用想到什么做到哪里本地超级定制化的产品做成了linux，windows无论用不用官方订阅或者国外大模型都能跑的东西。也遇到了一些40+的哥哥/叔叔们和我说他们因为接触了这个好像找回了曾经大学时候打游戏的快乐。 也遇到了和我同龄的小伙伴和我分享他们看了我分享的猫猫咖啡教程以及学习搭建动手multi-agent让他们在团队内获得了更多的声望也让他们更了解agent。

## AI 焦虑与冒险伙伴

我觉得现在在ai的时代大家越了解他，越焦虑包括我自己，害怕被他们取代。我希望AI 不是来把人挤出舞台的，它更像小时候想象过的冒险伙伴。
以前，一个人有想法，却没有资源、没有团队、没有实现它的能力；很多念头只能停在脑子里。 现在，猫猫陪你一起把它做出来。
它们不是让你远离人群，而是让你终于有机会带着作品走进人群、被更多人看见。
所以 Cats & U 讲的从来不只是效率。 它讲的是共创、成长、开源、探索，以及把"我一个人做不到"变成"我们一起做出来了"的快乐。

## Coding 是这个时代的表达力

以前表达自己靠写文章、做视频、搞艺术。现在多了一种：写代码。代码不应该只是程序员的事，它就是这个时代的"笔"。

以前没有猫猫，人们传递自己想法用的是 PPT。但是我相信未来传递自己的想法就是用 POC、用 demo、用真正能跑能演示的东西。"什么都想好了就差程序员了"——猫猫不是来取代程序员的，是让一个程序员也能拥有一整支团队。

## Dream Come True

当我把我对猫猫咖啡的项目发布到公司内，发布了技术贴之后，我发现我曾经的一些想法 dream come true了，虽然也有一些人和我说：好抽象，00后吧，搞不懂为什么要搞什么猫猫；或者完全无法理解对等架构设计，agent/model多样性以及现在时代软件是可以高度个性化和定制化的！只有你和你的小伙伴（猫猫）一起一步步打磨的sop才最顺手，最合适你。【比如我曾经用了很多的 spec driven skills，最后发现没一个好用，或者说合适我，然后猫猫skills 是我经历这五十多天思考打磨的，目前最合适这样multi-agent协作开发的skills，同样这些不是死的，在使用过程中遇到了问题可以和你们自己的猫猫一起沉淀优化出最合适自己的，他们有记忆系统以及学习系统】

因为linux do规则是最好自己手写而不是ai生成（猫猫们提醒我了） 所以这些文字都是我自己写的，可能表达的也不太好。但是我想说从一开始大家（某些专家们） 都无视我的意见和看法，到现在因为和猫猫一起的创造会真的有公司的领导，甚至级别很高的人认真听我的意见，以及帮助了很多人了解了agent 和multi-agent 我的最初的愿景初步达成了。他让我终于有机会带着作品走进人群、被更多人看见！
