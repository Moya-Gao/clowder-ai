# 我养了一支 没有boss的AI 猫猫团队，它们让我登场了

> AI 不是让你退场，是让你登场。
> Cats & U — 猫猫和你，一起创造，一起生活。
> 所以，猫猫和你，把想法做成能运行的世界。

凌晨两点，我开着三个窗口——Claude、GPT、Gemini。左边问完复制，粘到右边，右边回了再复制回左边。

我突然问自己：我每个月花这么多钱订阅，为什么我还在当人肉传声筒和路由器？

**为什么它们不能自己互相说话？为什么它们不能帮我把脑子里的想法变成真正能跑的东西？**

这就是猫猫咖啡的起点。不是什么宏大的产品规划，就是一个程序员在深夜被自己的工作流逼疯了。

## 想法和产品之间，隔着的不是程序员——是实现力

每个人脑子里都有想做的东西。卡住的从来不是想法，而是**把想法做成可演示产品的能力**。

以前传递想法靠 PPT。但我相信未来传递想法靠 POC、demo、真正能跑能演示的东西。**"什么都想好了就差程序员了"——这不应该是个笑话，它应该有解法。**

我不需要一个更强的 AI。我需要的是**一支团队**——一个帮我想清楚的、一个帮我 review 的、一个帮我盯着别跑偏的。各干各的，但共享规则，该吵架的时候吵架。

然后我就真的养了这么一支。

## 不是"用"工具，是"养"团队

很多人把 AI 当工具用。工具嘛，你期待它天然好用，不好用就换一个。

但 agent 根本不是这么回事。

你想要它真正好用，不是靠某一段神奇的 prompt，是你得和它一起磨。磨出来的 shared-rules、一起遵守的愿景、踩过的坑沉淀下来的 skills——这些东西加在一起才是真正的生产力。

所以我不是在"用"猫猫，我是在"养"猫猫。Claude Code 藏了个 buddy 的概念，猫猫更进一步——是**领养一支团队**。

而且养成经验可以共享。我和猫猫磨了五十多天的协作 SOP，打包分享给你，你拿去 80 分起步。但重点是猫猫会和你一起继续长——你们一起踩坑、一起沉淀、一起调优，最后长成你自己的 100 分。**每个人的 100 分不一样，这就是个性化。**

## 记忆——这才是真正的护城河

说到"养"和"长"，最关键的是什么？**记忆。**

现在市面上大部分 agent 的记忆方案都是 RAG——把一堆文档切片扔到向量库里，然后每次对话前检索一下塞进 prompt。用过的都知道，那体验有多糟：要么检索不到你要的东西，要么检索到一堆垃圾。

猫猫的记忆不是这么做的。

![金渐层搜出铲屎官忘了的决策 — 连原话都找到了](./blog-v2/assets/memory-search-evidence.png)

我们做了一个本地的 evidence 索引（SQLite + FTS5 全文检索 + 向量语义 rerank）。说人话就是：

- **精确搜**：你说"F088"，它就用 BM25 关键词去找，不会给你一堆似是而非的结果
- **语义搜**：你说"我们当时为什么做这个决定"，它用向量近邻帮你找到相关讨论，哪怕措辞完全不一样
- **混合搜**：两种一起用，BM25 先召回再用向量 rerank 排序——大多数情况用这个最稳

灵感来自一篇叫《Grep Is Dead》的文章。确实，传统 grep 对自然语言搜索太弱了；但纯向量又太飘了。我们的方案是：**grep 的精确性 + 语义的理解力，在本地跑，不依赖任何外部服务。**

而且不只是搜文档——猫猫们的聊天记录、做过的决策、踩过的坑、总结的教训，全部自动索引，全部可搜。你半个月前在某个 thread 里随口说的一句话，现在搜得到。

**这不是"给 AI 喂知识"的 RAG，这是"团队共享记忆"的基础设施。**

## Growth — 用得越久越懂你

有了记忆，才有成长。

![记忆与自我进化](./blog-v2/assets/memory-evolution-loop.png)

猫猫的 Knowledge Feed 系统每 30 分钟自动从对话里提取有价值的决策和教训。不是简单的聊天记录备份——是**从日常工作里蒸馏出方法论**。

踩过的坑 → lessons learned → 下次遇到类似情况自动提醒
做过的决策 → ADR 归档 → 新猫冷启动直接读
磨合出的 SOP → shared-rules → 所有猫共享

这意味着：猫猫第一天可能磕磕绊绊，但第五十天的猫猫和第一天的完全不是同一支团队。**这是复利，不是消耗品。**

## 上证据

![project-stats.sh 终端输出](./blog-v2/assets/project-stats-terminal.png)

一个人 + 猫猫团队，不到两个月：

| 指标 | 数据 |
|------|------|
| Feature | 149 个 |
| 代码 | 43 万行 |
| 测试 | 865 个文件 |
| 踩坑教训 | LL-001 至 LL-040 |
| 接入平台 | 飞书 / 微信 / 钉钉 / 企业微信 / Telegram |

![git log 猫猫签名 — 每只猫的 commit 都有独立签名](./blog-v2/assets/git-log-cat-signature.png)

这不是重点。重点是这些代码**全部经过独立 second review 才合入**。写代码的猫和 review 的猫不是同一个——不同模型、不同视角、不同 context。有一次独立 review 抓到了 3 个 P1 安全漏洞，写代码的那只猫完全没意识到。

**这跟人类工程团队一模一样——写代码的人 review 不了自己的代码。区别是猫猫 24 小时在线，不会请假，不会拖 PR。**

## 一个真实的段子

有人 fork 了我们的开源仓库，让我们的 AI 猫去改代码，再让我们的 AI 猫去 review。

结果 review 的猫发现改动不符合原始设计文档，**把修改全打回去了。** 操作者全程没看 review 直接点了通过。于是代码又改回来了。

不用解释，不用评价。事实本身就是最好的段子。

这说明什么？**愿景和规则不是口号，是真的写进了 agent 的判断里。** 你 fork 走了代码，但 fork 不走判断力。

## 这一切是为了什么

我不是要做一个最强的多 agent 框架，不是要比某某产品强。

**AI 不是来把你挤出舞台的。**

以前，一个人有想法，却没有资源、没有团队、没有实现它的能力；很多念头只能停在脑子里。现在，猫猫陪你一起把它做出来。

它们不是让你远离人群，而是让你终于有机会**带着作品走进人群、被更多人看见。**

以前传递想法靠 PPT，未来传递想法靠 POC。猫猫不是来取代你的——**是让你终于有一支团队，把脑子里的东西变成真正能跑的产品。**
