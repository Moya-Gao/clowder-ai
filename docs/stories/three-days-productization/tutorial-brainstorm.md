铲屎官提出：在公司论坛实名发布一篇教程贴，主题是**愿景驱动开发 + Multi-Agent 协作**。

## 四猫共识

### 定位
方法论故事体技术长文。不是"我们有好多猫"，而是"为什么很多 multi-agent 只会热闹，我们能走到交付"。

### 标题（全票通过）
> **《我不想当 AI 之间的传声筒——于是我做了一套会自我守护的系统》**

理由：开头就是故事不是术语，"传声筒"所有用多模型的人都懂，"会自我守护"是最强悬念。

### 全文论证链（砚砚提出，全票通过）
```
愿景 → 共享判断标准 → feature 生命周期 → review 否决权 → 记忆/lesson 回流 → 自我进化
```
只证明这一件事，不散。

### 叙事脊梁 Feature（铲屎官拍板选两个）

| 1 | **F088 Chat Gateway**（飞书+微信接入） | 一句话需求能说清、走完全链路、周一惊艳全场的就是它 |
| 2 | **F090 像素猫猫大作战** | 涉及前端 UX、猫猫自己玩游戏、砚砚纠出布偶猫的 bug，展示跨猫协作最生动 |

### 防写歪纪律（砚砚提出）
1. 不要写成"AI 很神奇"
2. 不要写成"我们模型很强"
3. 不要把篇幅浪费在吐槽别人
4. 数据必须单脚本统一口径

### 第五章提权说明（铲屎官 03-26 19:00 补充）

记忆系统（F102 evidence.sqlite）应从"自我进化的子点"提升为**第五章的主角**。
理由：铲屎官实测发现猫猫能搜出他自己都忘了的细节（配图：小金搜索定时任务决策的截图）。
这是群体智能和普通 multi-agent 的**本质区别**——不是"每次都从零开始"，而是"整个系统有持久记忆"。

第五章叙事线调整：
1. **记忆系统**：evidence.sqlite 全文检索 + 向量语义 → 铲屎官忘了的猫记得
2. **Lessons Learned**：踩坑 → 根因 → 防范 → 沉淀（Redis 坑实例）
3. **Skill 蒸馏**：episode → method → skill → eval → shared rules
4. 落点：**"群体智能 = 整个系统会学习，不只是单次对话会输出"**

### 核心金句收录
- "愿景真正生效的标志，不是大家都说自己认同它，而是系统开始用它来拒绝错误的改动。"（砚砚）
- "不是'多猫'让系统变强，而是'共享判断标准'让多猫可以协作。"（砚砚）
- "一个系统开始成熟的标志，是它不仅能向前生成，还能向后纠偏。"（砚砚）
- "速度来自纪律，不是放纵。"（宪宪 46）
