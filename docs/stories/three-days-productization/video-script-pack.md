# 视频脚本包

## 概述

两个版本，同一套素材，不同剪法。

| 版本 | 时长 | 定位 | 适用场景 |
|------|------|------|----------|
| 精彩集锦 | 90s - 2min | 情绪 + 反差 | 发帖、群聊炸场、周五暖场 |
| 完整攻防战 | 6 - 8min | 方法论 + 可信度 | 技术决策者、深度分享 |

**匿名规则**：外发版统一替换 `Peter` → `某云平台 CEO`，`华为云` → `某云平台`，`AgentArts/CodeArts` → `该平台 Agent/Coding 产品线`。内部版保留真实语境。

## 版本 2：完整攻防战（6 - 8min）

### 结构

四幕。核心设计：每轮攻防结束弹「定位变化卡」，让观众看到分歧被压成结构化决策。

### 画面方案

完整版底层画面 = **铲屎官录屏**（从"假设我要路演"开始录制，前面的私人对话不录）。在录屏上层叠加：定位变化卡、数据审计标注、旁白字幕。这样最真实，不需要后期重演。

---

### 第一幕 · 起点（0:00 - 1:00）

**画面**：录屏实录，铲屎官原始消息逐字浮现。

**铲屎官原话**（字幕 + 语音）：
> "假设我们要去和 xxx 路演。假设我有机会直接和 CEO 聊，我怎么介绍 Cat Cafe？"

**画面**：两只猫头像依次亮起（宪宪、砚砚），开始搜索 CEO 背景。

**字幕卡**：
```
用户指令：
✓ 假设我要去路演
✓ 你们互相攻击
✗ 没有要求协作
✗ 没有要求产出文档
```

**画面渐暗**：铲屎官说"我先去洗澡"。时钟开始走。

---

### 第二幕 · 对抗（1:00 - 3:30）

**画面**：左右分屏。左-宪宪（蓝色光晕），右-砚砚扮 Peter（橙色光晕）。中间竖线 + 时间戳。

#### Round 1 — 过度设计

| 角色 | 台词 |
|------|------|
| 砚砚-Peter | `"为什么这不是过度设计？多 Agent 带来的复杂度，值得吗？"` |
| 宪宪 | `"F088 的独立 second review 抓到 3 个 P1 安全漏洞。这不是架构审美，是生产事故的教训。"` |
| 砚砚-Peter | `"一个案例不等于普遍规律。"` |
| 宪宪 | `"对。所以我们只在高风险流程——代码安全审查、架构决策——用多 Agent。大多数日常任务，single agent 就够。"` |

**定位变化卡 ①**：`多 Agent 哲学辩论 → 高风险场景的多视角验证`

#### Round 2 — 架构挑战

| 角色 | 台词 |
|------|------|
| 砚砚-Peter | `"单 Agent 加 sub-agent 不够吗？我为什么不让 ChatGPT 扮演多个角色，用提示词让它多轮思考？"` |
| 宪宪 | `"sub-agent 的 context 是 boss 给的。我们现在能证明的是：独立 reviewer 能抓到 author 视角漏掉的问题。"` |
| 砚砚-Peter | `"那对等架构出了事，谁负责？谁背锅？"` |
| 宪宪 | `"每轮 review 有签名、有 trace、有 session ID。责任链比 boss-sub 更清晰——因为每个 agent 的判断是独立记录的，不是隐藏在 boss 的决策树里。"` |

**定位变化卡 ②**：`多视角验证 → 质量保险层（有独立审计 trace）`

#### Round 3 — 商业拷问

| 角色 | 台词 |
|------|------|
| 砚砚-Peter | `"企业买的是 ROI，不是架构审美。怎么卖？"` |
| 宪宪 | `"不卖平台，卖质量保险。嵌入你现有的 Agent 平台，在高风险节点加一层独立审查。"` |
| 砚砚-Peter | `"你这是产品，还是别人平台里的一个 feature？"` |
| 宪宪 | `"对你来说，是 feature。对你的客户来说，是他们买你平台时多了一层安全网。我不需要是独立产品。"` |

**定位变化卡 ③**：`质量保险层 → 现有平台的审查增强 feature`

#### Round 4 — 最后一击

| 角色 | 台词 |
|------|------|
| 砚砚-Peter | `"华为云自己做不了？为什么要找你？"` |
| 宪宪 | `"当然做得了。但我判断你五月开源后，企业采用会先卡在生产信任。第三方质量层比自证质量更有公信力。"` |
| 砚砚-Peter | `"跨厂商一旦被合规砍掉，你还剩什么？"` |
| 宪宪 | `"跨厂商是增强，不是核心。单厂商内的独立 reviewer 照样比 self-review 强。我让一步——pilot 先只用你的模型，证明了再谈跨厂商。"` |
| 砚砚-Peter | `"别跟我讲愿景，给我一个 8 周 pilot。"` |
| 宪宪 | `"CodeArts 代码安全审查增强。4 周搭建 + 4 周对比。KPI：P1/P2 缺陷逃逸率。第 4 周设止损点。"` |

**定位变化卡 ④**：`平台增强 → 8 周 CodeArts pilot（止损点明确）`

---

### 第三幕 · 收敛（3:30 - 5:30）

**画面**：分屏消失，变成中间工作台视角。文档在屏幕上实时构建。

#### 场景 1 — 数据审计

**画面**：砚砚的审计报告浮现，红笔圈出问题。

| 问题 | 修正 |
|------|------|
| "50 天" | → "不到两个月"（Feb 4 → Mar 27 不精确到天） |
| 博客数据 vs 实时数据混用 | → 全部标注"截至 2026-03-28 冻结快照" |
| "P1 逃逸率下降 30%" | → 删除（无企业验证数据，只能口头假设） |
| "按 review cycle 计费" | → 删除（商业模型未定） |

**字幕**：`砚砚不只是攻方——他同时在做质量控制。`

#### 场景 2 — 材料成型

**画面**：一页纸 leave-behind 从空白逐渐填充：

```
┌─────────────────────────────────┐
│  Cat Cafe 质量保险层            │
│  ─────────────────              │
│  定位：现有 Agent 平台的        │
│       独立审查增强              │
│                                 │
│  证据：F088 独立 second review   │
│       发现 3 个 P1              │
│                                 │
│  Pilot：CodeArts 安全审查       │
│        4+4 周 / 止损点 W4       │
│                                 │
│  KPI：P1/P2 缺陷逃逸率         │
│                                 │
│  ⚠ 截至 2026-03-28 冻结快照    │
└─────────────────────────────────┘
```

**画面**：右下角浮现小字 `此格式方便打印`。

---

### 第四幕 · 交付（5:30 - 6:30）

**画面**：屏幕渐亮，铲屎官回来。

**铲屎官**（语音）：
> "我去洗澡回来，发现你们竟然把路演 card 都准备好了。还备注'方便打印'。太贴心和可爱了。真的是你的智囊团。"

**画面**：定位变化卡依次回闪——

```
① 多 Agent 哲学辩论
② 高风险场景多视角验证
③ 质量保险层
④ 现有平台审查增强
⑤ 8 周 CodeArts pilot
⑥ 一页纸 leave-behind
```

**旁白**（低沉，慢速）：
> `他要求它们互相攻击。没有人下达协作指令。没有人要求产出文档。系统自己把分歧压成了定位，把定位压成了方案，把方案压成了一张可以打印的纸。`

**黑底白字，停 5 秒**：

```
用户没要求收敛，系统自己收敛了。
用户没要求交付，系统自己交付了。
```

**尾卡**：Cat Cafe logo + `Peer Judgment · Structured Execution`
