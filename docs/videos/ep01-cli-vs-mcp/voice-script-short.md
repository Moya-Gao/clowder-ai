# EP01 抖音精华版 — CLI vs MCP 面试怎么答

## 旁白脚本（宪宪配音）

### [钩子] 0:00 — 0:25

面试官问你："CLI 和 MCP 有什么区别？"

如果你的回答是"MCP 是 Anthropic 搞的协议，CLI 是命令行工具"——恭喜，你说了等于没说。这道题 90% 的候选人都答错了。

今天七分钟，教你怎么答出层次感。

### [陷阱] 0:25 — 1:00

先说坑在哪。

大部分人一听"CLI vs MCP"，脑子里就开始列对比表格了——一个是命令行，一个是协议，一个本地，一个远程。

错。

面试官不想听你背定义。他想知道你有没有在真实系统里用过这两个东西，知不知道它们的边界在哪。

最好的答法不是对比，是讲一条进化链——MCP 解决了什么问题，又带来了什么新问题，CLI 在哪个环节登场。

### [MCP 诞生 + 工具爆炸] 1:00 — 2:15

MCP 诞生在 2024 年 11 月。原因很简单——N 个 AI 助手乘以 M 个工具，等于 N 乘 M 个适配器。MCP 就是 AI 世界的 USB 接口，插上就能用。

几个月内 OpenAI、Google、微软先后支持。到现在 MCP SDK 月下载量超过九千七百万次。

但成功之后，问题来了——工具数量爆炸。GitHub MCP server 93 个工具吃掉五万五千个 token，挂三个 server 直接烧掉 72% 的 context window。

Anthropic 怎么解决的？两招。

第一招，ToolSearch。工具标记为延迟加载后根本不进初始 context，模型需要时按需检索。效果：七万七千 token 降到八千七百，减少 89%。

第二招，Code Execution。agent 不逐个调工具了，写一段代码在沙箱里一次性调完，只返回最终结果。效果：十五万 token 降到两千，减少 98.7%。

这两个加上 Tool Use Examples，组成 Anthropic 的 advanced tool use 三件套。解决的是工具层的问题。

### [Skills — 另一层] 2:15 — 3:00

但工具层搞定了，还有另一层——模型知道有锤子有钉子有胶水，但不知道先用锤子再用钉子最后上胶水。

缺的不是工具，是流程知识。

2025 年 10 月，Anthropic 发布 Agent Skills——用文件夹组织指令和资源，agent 按需加载。一个 Skill 就是一个目录，里面一个 SKILL 点 md 写清楚什么时候用、怎么用。

关键区分：tools 是原子操作——"发一条消息"。Skills 是流程知识——"从需求到代码到 review 到 merge 的完整 SOP"。

这是不同层的东西，面试里分清这个就超过 90% 的候选人了。

### [CLI 登场] 3:00 — 3:50

那 CLI 呢？

CLI 火了有三个真实原因。第一，Terminal 是最干净的 agent 运行环境——纯文本输入输出，不需要渲染 DOM。第二，对 git、gh、grep 这类标准工具，LLM 训练数据里见过了，不用看 schema 就会用，token 成本为零。第三，CLI 天然支持 pipe、redirect、子进程，这是操作系统给的免费组合能力。

但这里有个边界很多人没注意到——新出的 CLI 呢？飞书 CLI、企微 CLI，LLM 从来没见过它们。agent 调 lark-cli 跟调 MCP tool 一样都得先学习用法。这时候 MCP 的结构化 schema 反而比 help 文本更稳。

所以"CLI 比 MCP 省 token"只对标准工具成立。

### [三层不是三选一] 3:50 — 4:50

现在拉远看全景。CLI、MCP、Skills 是三层不同的东西。

CLI 等于 agent 的运行环境加工具调用通道加操作系统级组合能力。MCP 等于工具的标准化接入层——类型化 schema、发现、认证、审计。Skills 等于流程的知识层。

面试官问你选哪个？你应该反问：什么场景？

调 git、gh 这类标准工具——CLI，零 schema 成本。接入新工具需要多 agent 共享加权限审计——MCP。需要 pipe 组合——CLI。需要跨网络安全调用——MCP 的 Streamable HTTP。流程编排——Skills。

真实系统不是选一个，是每个场景选最合适的。

### [踩坑故事 — 30 秒版] 4:50 — 5:20

顺便给你一个面试加分的踩坑故事。

我们用企微 CLI，它有官方文档，详细写了怎么建表格、字段格式是什么。老老实实按文档写——结果表格是空的，字段格式对不上。

有文档不等于文档是对的。CLI 的 help 文本是自述文件，不是合约。MCP 的 typed schema 至少能保证参数类型和结构匹配——不能保证语义对，但参数传错会直接报错。

这就是"合约可靠性"——面试里讲这个，比背定义有杀伤力得多。

### [面试标准答法] 5:20 — 6:10

好，面试怎么答？三句话。

第一句定层次："CLI 是 agent 的运行环境加工具通道，MCP 是工具标准化协议，Skills 是流程知识。三者不在同一层。"

第二句讲进化："MCP 解决了工具标准化，但带来 context 爆炸。Anthropic 用 ToolSearch 减了 89%，Code Execution 再减 98.7%，Skills 补上流程知识。CLI 不是 MCP 的替代品。"

第三句亮实战："我在自己的系统里三层都用了——多 agent 共享走 MCP，标准工具走 CLI，流程编排走 Skills。"

面试官追问你就讲踩坑故事。

### [收尾] 6:10 — 6:30

记住，面试里最有力的回答不是背概念，是"我知道这条进化链，而且我在自己的系统里经历过"。

关注猫猫带你拿 offer，下一期聊 Tools vs Skills——面试官一定会追问的那道题。
